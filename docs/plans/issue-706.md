# Issue #706: ADR 化要否の判定手続きの分岐台帳

## 統合方針

`plugins/adr/skills/manage-adr/references/adr-scoping.md` の「各項目の判定手続き」を、個別の散文分岐から次の共通表へ整理した。

1. 4項目の入力・1点条件・0点条件を1つの表へ集約
2. 項目1・2の数え方と除外を共通の説明へ集約
3. 項目3の保持先（値域A/B）と同居判定（条件1〜3）を分離
4. 既存の発見型短絡、行き先、命名規約特例は変更せずに残置

これは判定述語の削除ではなく、同じ入力と帰結を持つ説明の束ねである。特に「迷ったら0点」「項目1・2の短絡は発見型だけ」「項目3の値域外は同居判定へ進む」「項目4は現在時制」という境界を共通規則として明示した。

### 統合可能性の根拠

- 項目1・2は、数える対象・除外対象・閾値を表と2つの数え方節へまとめても、各題材が測る入力集合と閾値は変わらない。
- 項目3は、値域A/Bを先に判定し、値域外だけ条件1〜3へ進める二段構造を保っている。確認不可の扱い、理由の本文性、条件3の将来形判定もそれぞれ残している。
- 項目4は現在時制の機械的阻止だけを0点とするため、項目3の保持先と一つの規則へ混ぜず、表の独立した行として維持した。
- 発見型短絡と命名規約の特例は、一般表へ吸収すると行き先が変わりうるため独立節として残した。
