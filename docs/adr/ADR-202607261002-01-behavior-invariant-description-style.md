# ADR-202607261002-01: 実行主体の挙動への対処をモデル版非依存の不変条件として記述する

## Context

モデル系統の更新に伴い、スキルの実行主体の挙動が変化する。観測されているのは、指示がなくとも自分の作業を検証する、依頼より広い範囲へ踏み込む、応答と成果物が長くなる、といった方向の変化である。

このチューニングは3層に分かれる。実行パラメータ層（S1）は ADR-202607251922-01 / ADR-202607251922-02 で決着した。本 ADR が扱うのはプロンプト適応層（S2）、すなわちスキル本文とサブエージェント定義の記述をどう書くかである。

本リポジトリの成果物は配布プラグインであり、利用者の親セッションがどのモデルで動作しているかは不定である。起票時点（2026-07-26）のベンダの移行ガイドは特定バージョン向けのチューニングを推奨していたが、その文言をそのまま配布物へ書き込むと、(a) バージョン更新のたびに全文言が陳腐化し、(b) 別のモデルで動作している利用者に対して誤った前提の指示が適用される。

S1 では、前回のモデル選定の根拠が残っていなかったために検討を一からやり直している。記述様式そのものを決定として残さなければ、次回の更新でも同じ再議論が発生する。

## Decision

実行主体の挙動に対処する記述は、モデル名・モデルバージョンを直書きせず、**挙動として観測される不変条件**の形で書く。特定のバージョンに紐づく数値・閾値を置かない。

この様式は S2 の成果物（`plugins/dev-workflow/references/behavior-invariants.md`）に適用し、同ファイル自身にも様式として明記する。

## Consequences

- モデルバージョンが更新されても文言を書き直す必要がない。利用者のモデルが何であれ、不変条件としては有害にならない。
- 引き換えに、特定バージョンでのみ有効な強い最適化は採用できない。効果の検証もバージョン横断の粒度でしか行えず、個別バージョンへの最適化余地は放棄する。
- 記述が抽象化されるぶん、個々の症状に対する効きは弱くなりうる。効きが不足する場合は、構造側（手順・出力形式テンプレート）へ寄せて解決し、バージョン固有の文言追加では解決しない。
- 条項のうち「結論を先に置き選択的に書く」「依頼された範囲を超えて変更しない」「自己訂正を語り過ぎない」「進行の実況を目的化しない」は、起票時点（2026-07-26）の Claude Code のハーネス既定（システムプロンプト）とほぼ同内容であった。配布先ハーネスが Claude Code とは限らないため保険として残すが、この重複は陳腐化の依存先をモデル版から**ハーネス版**へ移し替えたものであり、ハーネス既定が更新されれば同じ drift が起きる。ハーネス既定と重複する文言も陳腐化源として扱い、次回のモデル・ハーネス更新時の再検討対象とする。
- 配布環境で効く保護の方針を扱う #364 は、症状セットが異なる（捏造・エスカレーション阻害・割り込み無視）ため独立に進む。ただし記述様式の論点は共通しており、#364 は本決定を継承・一般化できる。
