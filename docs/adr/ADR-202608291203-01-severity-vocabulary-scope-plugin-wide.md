# ADR-202608291203-01: 深刻度2段ラベルの値域正本の射程をプラグイン全体へ広げる

## Context

dev-workflow プラグインのレビュー系は、深刻度の語彙が成果物ごとに割れていた。起票時点の実測では、`agents/plan-reviewer.md` がプランレビューの重大度を3段（High / Medium / Low）で定義し、`agents/code-reviewer.md`「4. 重大度の分類」がコードレビューの重大度を2段（ブロッカー／改善提案）で定義していた。後者は起票時点で射程を implementation 系に限定したうえで、plan 側の3段との不統一が節の外に残ることを自ら限界として述べていた。

Issue #798 で plan 側を2段へ統一するにあたり、統一後の値域の正本をどこに置くかが問われた。判断材料となる制約は次の2点である。

- `code-reviewer` は直接起動されるエージェントであり、スキル配下 references のパスを受け取る経路を持たない。スキル側を正本にすると、エージェント定義から正本への参照が到達不能になる。
- 2段ラベルの該当条件（バグ・セキュリティ脆弱性・要件未充足・テスト品質等）はコード差分に固有であり、プランレビューへ写像できない。

本 ADR は深刻度**ラベルの値域**の置き場所を決めるものであり、成果物ごとに「どの指摘がブロッカーに当たるか」という該当条件そのものは決めない（各検査観点の責務）。

## Decision

1. `code-reviewer.md`「4. 重大度の分類」のうち、**(a) 2段ラベルの名前と意味**と**(c) タイブレーク規則（迷う場合はブロッカー側に倒す）**を、プラグイン全体が用いる深刻度の値域の正本とする。値域を再掲する必要が生じた箇所は、内容を複製せず同節を参照する。
2. **(b) 該当条件の列挙は implementation 系のコード差分に固有**であることを同節内で明示的に限定する。他の成果物のレビューは、それぞれの検査観点が定めるブロッカー条件に従う。
3. plan 側の「どの指摘がブロッカーか」は plan-issue の検査観点へ置き、値域は複製しない。

採らなかった選択肢と却下理由:

- **射程を implementation 系に据え置き、plan 側には「同節のラベルに準拠する」とだけ書く案**: 値域の正本が implementation 系（同節）と plan 系（不定）の2箇所に見える状態が残るため却下した。
- **射程を全体へ広げ、(b) の該当条件もそのまま共有する案**: (b) はコード差分に固有でプランレビューへ写像できず、射程宣言が実態より広い形になる。同型の欠陥は先行 PR のレビューで是正済みであり、再発させないため却下した。
- **値域の正本をエージェント定義ではない第三の場所（共有 references 配下等）へ置く案**: 前掲の制約により `code-reviewer` から当該正本への参照が到達不能になり、同節が値域を複製し直すほかなくなるため却下した。

## Consequences

- 正本を参照する側への供給経路: `plan-reviewer` は読み取り専用ツールのみを持ちプラグインルートを自力で解決できないため、参照はパスではなく本文の受け渡しで満たす。`plan-issue` スキルが規範・検査観点と同じ経路で「4. 重大度の分類」節を読み込み、レビュアーへ渡す起動プロンプトへマージする。エージェント定義・検査観点の側にパスを直書きしない（プラグインルートを指す変数はスキル本文・エージェント定義では展開されず、参照が到達不能になるため）。
- 受容したコスト: エージェント定義が値域という規範を持ち続ける。層の分け方（エージェント定義＝姿勢・ツール制限・入出力契約／規範ファイル＝値域・構造・不合格条件）からは外れるが、到達性の制約を優先した結果として受け入れる。
- 得られた利益: 深刻度ラベルの定義が1箇所になり、成果物ごとに語彙が分岐しない。レビュー結果の合否判定を呼び出し側が同じラベルで解釈できる。
- `ADR-202606280940-01` 決定3（`plan-reviewer` と `code-reviewer` は対象成果物・必要力量が異なる別能力として保つ）との関係: 本決定の後も両者はエージェント定義・起動・力量のいずれも分かれたまま、値域ラベルの定義だけを共有する。同決定が禁じているのは複数の成果物のレビューを1つの能力へ潰すことであり、本決定はこれに当たらない（直交する関係と読んだ）。同決定は反転しないため編集せず、本 ADR から関連として参照する。
- 強制の状態は `検査なし` である。3段語彙の再混入を阻止する常設ゲートは置かない（行番号固定・据え置き型の検査を増やさない方針による）。再混入は人のレビューで捕捉する。
