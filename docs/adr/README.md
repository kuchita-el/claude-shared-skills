# ADR（Architecture Decision Records）

本ディレクトリは本リポジトリの ADR を置く場所。`docs/development/event-storming.md` の「技術的意思決定」集約の実体であり、同集約の状態遷移・コマンド・イベント定義と整合する。

## 対象 ADR ディレクトリ

本リポジトリの ADR ディレクトリは `docs/adr`。`adr` プラグインの既定値と一致するため、上書きせず既定のまま使う（上書きの方法は `adr` プラグインの README が持つ）。

## 運用ルールの所在

ADR 化要否の判定・採番・起票・承認・上書き・廃止・却下・編集の各手順は `adr` プラグインの `manage-adr` スキルが実体を持つ。本 README はこれらを再掲しない。

`/adr:manage-adr` で起動する。各手順とその詳細を記した参照ファイルはスキル本体から辿る。

## 旧「モデル制約由来の設計判断インデックス」を廃止した理由

本 README が内蔵していた「モデル制約由来の設計判断インデックス」（設計要素別の人手キュレーションによる意味索引・15件）は、モデル更新時の再評価トリガーとして設計されていた。廃止の根拠は、その再評価フローが実運用で回っていなかったという観察である。人手キュレーションである以上、本文と索引が乖離する手動 drift 源でもあり、ADR 運用を「手動 drift 源を排する」方向で再設計する主眼と衝突した。

代替方針は次のとおり。設計要素から決定を引く**意味逆引きは各 ADR 本文**（`## Context` / `## Decision`）で行う。決定の網羅性を俯瞰する**ギャップ地図**が必要になった場合は、索引を復活させず別 Issue として扱う。

## 退役した ADR の扱い（2026-07-30）

前掲「運用ルールの出所」のうち ADR-202607261459-01（決定1・決定2）と ADR-202607261503-02（決定1）は、2026-07-30 に `validity: 廃止済み` へ退役した。現行の ADR 化要否基準に照らして ADR として保持する要件を満たさなくなったためであり、決定が覆ったわけではない。両 ADR が担っていた採用理由は、退役に先立って規定の置き場所——`manage-adr` スキルの雛形（`references/template.md`）、`adr` プラグイン同梱スクリプト（`gen-adr-index.sh`・`lint-adr.sh`）、および本 README の前節——へ併記した（状態モデルの参照ファイル `references/adr-model.md` は、退役以前から2軸の値域と定義を保持している）。前掲の一覧は決定の出所を辿るための履歴であり、現在の規定はスキル側とスクリプト側が持つ。
