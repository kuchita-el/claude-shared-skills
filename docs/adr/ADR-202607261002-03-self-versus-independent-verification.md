# ADR-202607261002-03: 抑制対象を同一文脈の再確認に限り、独立文脈の検証機構を保護する

## Context

スキルの実行主体は、指示がなくとも自分の作業を検証する。このため「検証せよ」型の指示は過剰な検証を誘発する。ベンダの移行ガイドは、検証を求める指示の削除、ハーネス側の検証ステップの削除、およびサブエージェントへの検証委譲の禁止（検証はメインのループに属するという指針）を推奨している。

一方 dev-workflow は、これと衝突する機構を意図的に持っている。

- `code-reviewer` / `plan-reviewer` / `test-spec-validator` は、**初見・独立文脈**の敵対的検証として設計されている。`implementation` の SKILL.md はセルフレビューを本スキルの主要な付加価値と明記している。
- `superpowers:verification-before-completion` に委譲する検証ゲートは、型チェック・lint・テストを実行して**証拠**を確認する機構である。
- `completion-judgment.md` の「全項目を列挙して評価する」原則は、一部項目の充足で全体を完了と判定する**早期収束**を防ぐために置かれている。

推奨をそのまま適用すると、これらを一括で失う。実測でも、リポジトリ内に「自分が書いたものを自分で読み直せ」型の指示はほぼ存在せず、削除候補は1件にとどまった。すなわち推奨の主対象は本リポジトリにはほぼ無く、衝突する部分だけが残る。

## Decision

抑制対象は「**自コンテキストで書いたものを自コンテキストで読み直す**」型の確認に限る。この型の確認ステップを、スキルおよびサブエージェント定義へ新たに追加しない。

次の3つは保護し、削減対象としない。

1. 別文脈が差分・要件を初見で読む独立検証（`code-reviewer` / `plan-reviewer` / `test-spec-validator`）
2. コマンドを実行して証拠を得る検証ゲート
3. 完了判定における全項目の列挙（`completion-judgment.md`）

判断基準は「自コンテキストで見落としたものは自コンテキストでは見つからない」であり、上記3つはいずれも自己検証の重複ではなく、別の失敗（見落とし・証拠なき完了主張・早期収束）を防ぐ機構である。

## Consequences

- 削除の可否をその場の印象で決めず、文脈が同一かどうかという基準で判定できる。将来ベンダ推奨を読んだ担当者が独立レビュアーを一括削除する事故を防ぐ。
- ベンダ推奨と部分的に不一致になる。推奨に従えば得られたはずのトークン削減の一部を放棄する。
- 独立検証が実際に新規の指摘を出しているか（＝メインループの自己検証と重複していないか）は未実測である。実測で重複が示された場合、本決定は再検討の対象になる。その場合は独立検証の役割定義を扱う既存の決定とあわせて上書き手続きを要する。
- `implementation` の「完了報告前のプランAC確認」は、同一文脈での再確認と全項目列挙の両方の性質を持つ。本決定では保護対象3の側に分類し、変更しない。
