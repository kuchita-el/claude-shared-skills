# ADR-202608281232-01: サブエージェント実行パラメータ規約を作者向け文書として配布物の外へ置く

## Context

先行 ADR-202607251922-01 は、サブエージェントの `model` と `effort` を front-matter で固定値として明示し、役割ごとの必要水準として値を選ぶと決めた。その際、規約の正本の置き場所を `plugins/dev-workflow/references/subagent-execution-parameters.md`、現行値の一覧を `plugins/dev-workflow/README.md` とし、値そのものは各サブエージェント定義の front-matter を権威として正本には転記しないと定めた。

2026-08-28 時点の実測で、この正本は配布物の中のどのスキル定義・サブエージェント定義からも参照されていない。参照が無いのは設計どおりでもある — 同 ADR は値の権威をサブエージェント定義の front-matter に置き、定義側から正本への逆参照を持たせない構造を選んでいる。したがって正本を読むのは実行主体ではなく、本リポジトリでサブエージェントを追加・変更する作者に限られる。同ファイル自身も「本リポジトリでエージェントを追加・変更する者」を読者として宣言している。

読者が作者である文書を配布物の中に置くと、配布先の利用者には到達経路のない文書が同梱され、文書が持つ相対リンク（`../../../docs/`）も配布先で解決できない。

配置の再検討にあたっては、読者別配置（実行主体が実行時に読むものは配布物の内側、作者だけが読むものは外側）という軸を採る。この軸は `docs/distribution-boundary.md` の軸①（配布先で参照が解決できるか）・軸③（その定義なしに配布物の手順が評価不能になるか）と整合する。同方向の記述は ADR-202607261002-02 決定4 にもあるが、同 ADR は起票時点で `status: 提案中`（承認軸の確定は #633 の射程）であるため、本 ADR は同 ADR を根拠に用いず独立の判断として決める。

## Decision

サブエージェント実行パラメータ規約の正本を `docs/references/subagent-execution-parameters.md` に置く。

- 先行 ADR-202607251922-01 の決定の実質はすべて維持する。すなわち、`model` と `effort` を親セッションから継承させず front-matter で固定値として明示すること、値を役割ごとの必要最小水準（定型性が高く処理量が出る役割については許容最大水準）として選ぶこと、規約の正本を単一出典として持つこと、値そのものは各サブエージェント定義の front-matter を権威とし正本には転記しないこと、現行値の一覧を `plugins/dev-workflow/README.md` に置くことは、いずれも不変である。本 ADR が改めるのは**正本の配置だけ**である。
- 本規約は配布物（プラグイン）の外に置く。読者が本リポジトリの作者に限られるためであり、プラグインルート `references/` 集約原則（ADR-202606040737-01）は「複数スキルが**共有する参照資源**」を述語とするため、実行主体からの参照を持たない本規約には及ばない。同原則は反転しない。
- CLAUDE.md「サブエージェントの実行パラメータ」節からのポインタは新パス `docs/references/subagent-execution-parameters.md` を指す。ADR から規範実体へ辿れなくなる型を作らないため、本 ADR も決定文に新パスを明記する。
- 現行値の一覧（`plugins/dev-workflow/README.md`）は配布物の中に残す。README は配布先の利用者が読む文書であり、読者別配置の軸で内側に属する。
- 統制点をサブエージェント定義へ集約する決定（ADR-202607251922-02）は本 ADR の対象外であり、そのまま有効である。

### 不採用案

- **案①: 現状維持（プラグイン共有 references に置き続ける）** — 参照0件のまま配布され続け、配布物が実行主体から到達不能な文書を同梱する状態が固定される。解決できない相対リンクも残る。不採用。
- **案②: 各サブエージェント定義から正本への逆参照を張って配布物内に残す** — 先行 ADR が意図して排した構造（値の権威を front-matter に一本化し、定義側に正本への参照を持たせない）を崩す。8本の定義すべてに同趣旨の1行が増え、正本と定義の二重管理の入口になる。不採用。
- **案③: 規約本文を CLAUDE.md へ取り込む** — 216行を CLAUDE.md 本体へ置くと常時ロードされ、CLAUDE.md の可読性と token 規律の双方を損なう。CLAUDE.md からポインタで参照する `docs/` 側のファイルという形を採る。不採用。

## Consequences

- 配布物（`plugins/dev-workflow`）の共有 references が、実行主体から到達可能な参照を持つファイルのみになる。
- 規約の内容・単一出典性・転記禁止・README 現行値一覧はいずれも不変であるため、既存のサブエージェント定義とその追加手順は変わらない。本 ADR は挙動を変えない。
- 進行中の条文改訂トラック（#776 / #777 / #780）は同ファイルを対象とする。要求の内容は変わらないが、Issue 本文が指すパスは陳腐化するため、実施時にパス変更を通知する。
- 旧パスへの参照が凍結記録（旧 ADR 決定文・過去の設計 spec）に残る。これらは当時の事実の記録であり書き換えない。現行有効な文書からの参照は新パスへ張り替え、旧パスが現行文書に再混入しないことを常設の検査で固定する。
- 配置が配布物の外へ出たことで、プラグインを単体で配布した相手はこの規約を読めなくなる。読者を作者に限る判断の帰結として受容する。
