# ADR-202608011353-01: 格下げ判定が使える運用実績のうち、被参照と再燃を条件に採らない

## Context

格下げ判定は起票判定と違い、記録された後の運用実績を観測できる（ADR-202608011351-01 決定1）。観測しうる入力として次の4種が候補に挙がった。

- 被参照の実績（他の ADR・文書からどれだけ指されているか）
- 強制機構が規範を引き取った実績
- 正本が ADR の外へ移った実績
- 問いが再燃した実績（同じ問いが独立に何度立ち上がったか）

判定形式が必要条件の連言であるため（ADR-202608011351-01 決定2）、条件を1つ増やすことは退役の成立要件を1つ増やすことにあたる。安全側が「迷ったら残す」であるため（同決定3）、発火しにくい条件を加えると全体が存置へ倒れる。どれを条件に採るかは、条件の数の問題ではなく、その条件が現に判定を分けるかの問題である。

## Decision

前掲4種の採否を次のとおり定める。

| 入力 | 採否 |
|---|---|
| 被参照の実績 | 採らない |
| 強制機構が規範を引き取った実績 | 規範本文の所在を問う条件へ統合する |
| 正本が ADR 外へ移った実績 | 規範本文の所在を問う条件そのものとする |
| 問いが再燃した実績 | 採らない |

**被参照を採らない理由**: 被参照は決定の性質ではなく記録の消費面の状態である。退役は記録の削除ではなく index からの除去であり、有効な記録が退役した記録を現行の出典として指し続けることは drift 検査が禁じるため、被参照は参照側の付け替えで解消される。参照されていること自体は、その ADR が却下代替を持つことも、規範本文の正本であることも意味しない。

**強制機構と正本の移転を独立の条件としない理由**: いずれも規範本文がどこに在るかを述べる入力であり、強制機構は規範本文の置き場所の一種である。独立の条件へ分けると、同じことを2回問うことになる。

**再燃を採らない理由**: 2つある。

第一に、走査面が閉じていない。却下代替の不在と規範本文の所在は「無いこと」の判定でありながら実行可能だが、それは走査面が閉じているためである（ADR は識別子を持ち、追跡下ファイルへの走査が対象集合に対して網羅的になる）。再燃には対応する識別子が無く、「同じ問い」の同一性は主題の一致判断であって照合ではない。走査面も Issue・PR コメント・クローズ済みの議論へ散り、追跡下に閉じない。

第二に、安全側の向きと構造的に両立しない。連言では「再燃の不在」が退役の成立要件になる。安全側（迷えば不成立）を当てると、再燃していないと確信できるかを毎回問うことになるが、否定的存在命題であるため通常は確信できない。結果としてこの条件はほぼ常に不成立となり、全 ADR が存置へ倒れる。発火しない条件は条件として働かない。

## Consequences

**得られた利益**:

- 格下げ判定の条件が2つに収まり、いずれも走査面が閉じた判定になる。判定者が変わっても走査すべき範囲が同じになる
- 発火しない条件を持たないため、判定が「常に存置」へ縮退しない

**却下した代替案**:

| 却下した案 | 却下理由 |
|---|---|
| 被参照の実績を条件に採り、参照されていない記録を退役候補とする | 被参照は記録の消費面の状態であって決定の性質ではない。退役に伴う参照の付け替えは退役手続きが担うため、参照の存在は存置の理由にならない |
| 再燃の実績を条件に採り、再燃していない記録を退役候補とする | 走査面が Issue・PR・クローズ済みの議論へ散り閉じない。加えて「再燃の不在」は否定的存在命題であり、安全側を当てるとほぼ常に不成立となって全件が存置へ倒れる |
| 再燃を逆向きに書き、「再燃の記録が現に在る場合に限り存置」とする | この形なら発火するが、再燃を確認できないケースを退役側へ倒すことになり、安全側の向き（迷ったら残す）と矛盾する |
| 強制機構の引取を独立の条件として立てる | 強制機構は規範本文の置き場所の一種であり、規範本文の所在を問う条件と同じことを2回問うことになる |

**受容したコスト**:

- 同じ問いが繰り返し立ち上がる記録を、判定が直接は捉えない。この懸念は、改訂回数という別の観測量が担う余地がある（本 ADR はその採否を決めていない）
- 起票判定の昇格フロー（他の機能でも同じ問いが出てきた時点で ADR へ昇格させる）とは再燃の扱いが揃わない。昇格フローで再燃が機能するのは判定者が2回目の場面に居合わせて直接観測するためであり、過去へ遡って再構成する格下げとは条件が異なる

## 保留した決定

- 改訂回数（当該 ADR の系譜・変更履歴・担う資産の改訂を合算した回数）を格下げの入力へ採るか。走査面は閉じているが、閾値の置き方と、規範本文を資産へ移す作業との順序が未検討である（想定継承先: #634）
