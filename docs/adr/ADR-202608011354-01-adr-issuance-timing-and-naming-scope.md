# ADR-202608011354-01: ADR 起票のタイミングと命名規約の ADR 化基準

## Context

本 ADR は ADR-202607191825-01 の分割によって生じた後継である。同 ADR は「ADR 化判断の3基準」と「記録の参照原則」の4決定を束ねており、そのうち決定1（粒度判定基準）が ADR-202608011350-01 によって反転した。反転しない決定を後継へ救出するにあたり、本 ADR は決定2（起票のタイミングとエスカレーション）と決定3（命名規約の ADR 化基準）を引き継ぐ。決定4（記録の参照原則）は独立した横断規範であるため別の後継が引き継ぐ。

- 決定本文中に残る原 ADR 向けの参照（決定番号）は、分割中に決定内容を変えない規約に従い原文のまま残した。読み替えは後掲のとおり
- `## Consequences` は、決定4 に由来する記述（記録の参照原則の効果、適用限界の実例、適用有無の判定基準）を除き、決定1〜3 に対応する記述を保持した。決定1 が反転したことに伴い、原文が「3基準」と述べていた範囲は本 ADR では決定1・決定2 の2つになる

**決定本文に残る原 ADR への自己言及（読み替え）**:

決定本文を改変していないため、本文中の決定番号は原 ADR を指したままである。先頭番号を振り直した結果、**本 ADR 自身の決定番号と字面が衝突する**ので、次のとおり読み替える。

- 決定1 本文の「決定1の粒度判定基準」は、**原 ADR の決定1** を指す。本 ADR の決定1（起票のタイミングとエスカレーション）ではない。原 ADR の決定1 は ADR-202608011350-01 が反転しており、反転後の判定は同系譜の現行 ADR（ADR-202608011651-01 決定1）が保持する
- 決定2 本文の「決定1の項目4（ツールで自動強制できない）」も、同じく**原 ADR の決定1** の項目4 を指す。本 ADR の決定1 に項目4 は無い

**本 ADR が保持する決定は却下代替を持たない**（分割手順の欠落ではなく、原 ADR にも存在しない）。原 ADR の決定2・決定3 は、いずれも採らなかった選択肢とその却下理由の対を本文に持たない。決定2 は「最初から ADR にしようとせず」で却下案を名指しするが却下理由が本文に無く、決定3 は却下案の名指し自体が無い。原 ADR 自身が Context で「3基準は運用ドキュメントが唯一の出所であり、これを決定として記録した ADR が corpus に存在しない」と述べているとおり、これらは運用文書に蓄積した散文を決定として記録したものであり、却下代替を伴う審議の記録が存在しない。復元できないため、後継へ書けば創作になる。

本 ADR の起票時点（2026-08-01）で、本 ADR が保持する2決定の規範本文を実務手順として運用する実体は、`adr` プラグインの `manage-adr` スキルの参照ファイルに在った。

## Decision

### 1. 起票のタイミングとエスカレーション

ADR 化要否の判定と「いつ起票するか」は別の問題として扱う。最初から ADR にしようとせず、特定機能の決定はまず PR の説明に書く。後から他の機能でも同じ問いが出てきた時点で ADR へ昇格させる。

ADR 化を検討すべき決定が発生したことを示す実務シグナルは次の3つとし、いずれかに該当したら決定1の粒度判定基準で要否を判定する。

- 複数の選択肢を検討して片方を却下した
- トレードオフを受け入れた
- 制約や前提条件がある

### 2. 命名規約の ADR 化基準

命名規約は、構造的か書式的かで ADR 化対象を振り分ける。

| 種別 | 特徴 | 例 | 配置 |
|---|---|---|---|
| 構造的命名規約 | 横断・後戻りコスト高 | ファイル配置規約、集約名、ドメイン用語統一 | ADR 化（`docs/adr/`） |
| 書式的命名規約 | 局所・ツール強制可能 | 変数命名、import 順、空白・改行 | Linter／フォーマッタ規約として配置（ADR 外） |

ツールで自動強制できる規約は ADR 外とする。判断に迷う場合は、決定1の項目4（ツールで自動強制できない）に照らして振り分ける。

## Consequences

**得られた利益**:

- 起票のタイミングと命名規約の振り分け軸が決定として corpus に入り、実務手順の置き場所とは独立に根拠が保存される。原 ADR の起票時点（2026-07-19）で、これらの基準を実務手順として運用する実体は `manage-adr` スキルの参照ファイルへ移されており、記録は決定に徹する。以後、実務手順の所在や表現が変わっても、決定の骨子は本 ADR が保持する。

**受容したトレードオフ**:

- 本 ADR の2決定の実質は実務手順側と同内容を持つ。原 ADR は記録の参照原則の自己完結性要求に従い、参照ではなく実質の再記述を選んだ。両者の間には表現の乖離が起こりうるが、記録側は決定の骨子（昇格フロー・実務シグナル・振り分け軸）のみを保持し、運用上の記法や補足は実務手順側が担うため、乖離は骨子の外に限られる。

**射程外是正による dangling の解消**:

3基準を運用ドキュメントから移設すると、凍結 ADR 3本（`ADR-202605110956-01-technical-decision-aggregate-foundation`、`ADR-202605312147-01-workflow-design-rationale-hub`、`ADR-202607111014-01-store-state-model-captures-stateless`）が持つ運用ドキュメントへの参照が指し先を失う。当初はこれを、凍結原則により修復手段のない dangling として想定していた。

しかし該当3箇所はいずれも各 ADR の `## Decision` の外（`## Context` および状態記述行）にあり、決定内容に触れず情報の総体が保存される是正であるため、凍結原則の射程外である。よって原 ADR を起票した Issue はこの3箇所を射程外是正の対象とし、同一の変更セットで是正した。当初想定されていた「修復手段のない dangling」は、これにより概ね解消された。

`plugins/growth/` 配下からの参照は #532 で修復されるため、恒久的 dangling には当たらない。
