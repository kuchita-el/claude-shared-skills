# ADR-202611140053-01: shared-memory の立ち上げを、配布カタログへ登録するまで直接コミットで回す

## Context

ADR-202609110017-01 の決定5 は、転換期間中に `dev-workflow` の工程（Issue・プラン・レビュー契約）を通さず直接コミットで回してよい変更を、2種類に限った。統治機構の縮小作業と、新方式（Spec-as-Code）プラグインの立ち上げである。存続する配布物の機能変更は、従来どおりレビュー契約を通すと定めた。利用者へ配る資産が無レビューで変わることを避けるためである。

ADR-202611140016-01 は、独立プラグイン `shared-memory` を起こすと決めた。このプラグインは新方式のプラグインではなく、存続する配布物でもない。決定5 が挙げたどちらにも当たらず、決定5 の文面のままでは、立ち上げをレビュー契約に通すことになる。

リポジトリの所有者は 2026-11-14 に、立ち上げを直接コミットで回すと決めた。これは決定5 が限った範囲を広げる判断であるため、記録する。

**射程の限定**: 本 ADR は `shared-memory` の立ち上げだけを扱う。以後に起こす別のプラグインの扱いは決めない。

## Decision

- `shared-memory` の立ち上げは、`dev-workflow` の工程を通さず直接コミットで回す。
- 対象は、次の3つの配下と、このプラグインの ADR である。`plugins/shared-memory/`、`tools/shared-memory/`、`docs/development/shared-memory/`。
- 境目は、`.claude-plugin/marketplace.json` へ `shared-memory` を登録する変更とする。登録する変更そのものと、それ以後の機能変更は、存続する配布物と同じくレビュー契約を通す。
- 対象の外にある資産を変える場合は、決定5 の区分に従う。存続する配布物の機能を変えるなら、登録の前であってもレビュー契約を通す。
- commit ゲートは、直接コミットで回す間も働かせる。
- ADR-202609110017-01 は上書きしない。決定5 が挙げた範囲へ、本 ADR が1件を足す。

**却下した代替**:

- **立ち上げもレビュー契約を通す**: レビュー契約が守るのは、利用者が既に使っている資産である。配布カタログへ登録するまで、このプラグインを導入している利用者はいない。記録の形式は、クラウド環境での検証の結果で何度も作り直す見込みである。その都度レビュー契約を通すと、まだ誰も使っていない形式の整合に工程を費やす。
- **決定5 の「新方式プラグイン」を、新規のプラグイン全般と読み替える**: 以後に起こすプラグインが、理由を検討しないまま直接コミットの範囲へ入る。範囲を広げる判断を、1件ずつ記録できなくなる。
- **境目を「最初の利用者が現れた時点」とする**: リポジトリの中の事実として観測できない。判定する人によって、切り替える時点が変わる。配布カタログへの登録は、1つの変更として観測できる。

## Consequences

- 登録までの間、`shared-memory` の設計の誤りは、レビューを経ずに入りうる。登録する変更のレビューで、プラグインの全体を見ることになる。
- 登録の前は、配布カタログの経由でプラグインを読み込めない。試すときは、プラグインのディレクトリを直接指定して起動する。
- 以後に新しいプラグインを起こすときは、どの工程で回すかを、その都度決めて記録する。
