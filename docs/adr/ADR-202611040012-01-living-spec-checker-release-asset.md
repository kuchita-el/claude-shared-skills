# ADR-202611040012-01: living-spec の検査器をコミット SHA で名指す GitHub Release の添付物として配る

## Context

living-spec の検査器（`tools/living-spec`）は、プラグインと分けて利用するリポジトリが持つ道具として入れる。導入経路は手元でも CI でもソースからのビルドだけであり、利用者は pnpm を用意して `pnpm install && pnpm build` を実行する必要がある。PR #900 は導入経路を決めた際に、生成物のプラグインへの同梱を却下し、npm への公開を「利用者が増えたら検討する」として先送りした。この判断は ADR ではなく PR の説明に記録されている。

別リポジトリでの試用（#918）で、導入が最大のコストになった。所要の半分が導入に掛かり、ソースビルドが AI 側の権限分類器に外部コードの実行として止められて利用者の手動実行になり、corepack のキャッシュ破損で pnpm が起動しない環境差にも当たった。

ビルドの生成物 `dist/living-spec.mjs` は依存を同梱した1ファイルで、Node 22 以上があれば単体で動く（`tools/living-spec/package.json` の `build`）。二人目の利用者が出たことで、PR #900 の先送りの条件は満たされた。

**射程の限定**: 本 ADR は配布の形（どこに、どう名指して置くか）を決める。Release を切る契機と手順は、配布の形と独立に変えられるため本 ADR に含めず、工場側の Release 手順の文書と、それを実行する CI の定義に置く。中継（`scripts/run.mjs`）の探索順、検査器の入口と終了コードの契約は変えない。

## Decision

- 検査器の配布物は、本リポジトリの GitHub Release に添付する、依存を同梱した1ファイルの `living-spec-<40桁のコミット SHA>.mjs` とする。版はビルド元のコミット SHA だけで同定し、semver も人が付ける名前による同定も持たない。Release に伴うタグは `living-spec-<40桁のコミット SHA>` とし、SHA 以外の情報を持たせず、その SHA のコミットを指す
- 公開した Release は、リポジトリの Immutable Releases の設定で変更不可にする。公開後はタグと添付物を差し替えられず、SHA の名前が同じ中身を指し続ける。公開を取り消した SHA のタグ名は再利用できないため、その場合は別のコミット SHA で切り直す
- 添付物は認証なしで取得できることを前提にする。本リポジトリは公開であり、利用者の CI が追加の資格情報なしに取れる
- 利用者は添付物を取得して使う。手元では既存の環境変数 `LIVING_SPEC_BIN` で指して中継から呼び、CI では `node` で直接走らせる。ソースビルドは開発者向けの経路として残し、利用者の導入経路から外す

**却下した代替**:

- **npm への公開**: スコープとアカウントの確認に加え、パッケージの版に semver の運用が要る。本リポジトリの配布物は版をコミット SHA で同定しており（ADR-202609061416-01）、検査器だけに別の版体系を持ち込むことになるため採用しない
- **生成物をプラグインへ同梱する**: 依存を詰めた約1.8万行の生成物を git に置き、検査器を変えるたびに作り直してコミットする規律が要る。PR #900 で却下した理由は変わっていないため採用しない
- **`LIVING_SPEC_BIN` に URL を許し、中継が実行時に取得する**: 編集のたびに走るフックへネットワーク依存が入り、オフラインや取得の失敗がフックの失敗として表れるため採用しない
- **公開後の改ざんをタグのルールセットで止める**: `refs/tags/living-spec-*` を保護の対象に足す案。タグの付け替えと削除は止まるが添付物の差し替えは止まらず、SHA の名前が同じ中身を指す保証にならないため採用しない
- **チェックサムを添付し、利用者に照合させる**: 差し替えに気づけるが止めはせず、照合の手間と手順を利用者へ負わせるため採用しない
- **ソースビルドの手順を整えて残す**: pnpm・corepack とビルドが利用者の経路に残る限り、環境差と権限分類器による停止という試用で観測したコストが消えないため採用しない

## Consequences

- 利用者の導入は取得と配置の2段になり、pnpm・corepack・ビルドが利用者の経路から消える
- 添付物のファイル名がそのまま版になるため、利用者の CI はコミット SHA で取得先を固定できる。README の `LIVING_SPEC_REF` と同じ固定のしかたになる
- 工場側に、指定したコミット SHA でビルドし、生成物で試験を通してから添付する仕組みと、その手順の文書を持つ。手作業で作ったファイルを添付しない
- 変更不可の設定は、有効にした後に公開した Release にだけ掛かる。初回の Release より前に有効にしておく必要があり、ワークフローの権限では設定を読めないため、確かめは保守者の手順が担う
- 公開を取り消すと、その SHA では二度と切り直せない
- 利用者は Release のある版しか取れない。検査器を変えたコミットでも、Release を切るまでは利用者へ届かない
- 版の名前は人が読んで新旧を判断できる文字列ではなく、どの版を使うかの手がかりは Release の一覧と変更の記録に頼る
- 添付物の取得と実行が権限分類器に止められるかは環境に依存する。止められる場合は README に手動の手順を併記する
- 利用者の CI が添付物の URL を名指すため、配布の形を変えると利用者の手順が壊れる
