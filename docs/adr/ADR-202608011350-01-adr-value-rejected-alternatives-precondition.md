# ADR-202608011350-01: ADR の固有価値を却下代替に定め、起票の必要条件として前置する

## Context

2026-07-30 の既存 ADR 適格性監査は、ADR 化要否の粒度判定基準（ADR-202607191825-01 決定1 の4項目チェックリストとスコア境界）を既存 ADR へ遡及適用して退役の可否を決めた。2026-07-31 に第2群5本へ独立の再採点を行ったところ、監査の非該当判定を再現できたのは1本のみで4本が該当側へ戻った。

原因を試行のばらつきに帰さず、基準の側を測った。粒度判定基準の実体を保持する運用文書について、判定手続きを導入したコミット以降その層だけへの当て直しが17件あり、うち9件が項目3（採用理由が時間経過で揮発しやすい）に集中する。継ぎ足しを解消して項目3を単一パスで書き直したコミットの後も、当て直しは続いている。規則を網羅的に述べきれない粒度で書いたため、適用のたびに新しい曖昧性が現れて個別に塞ぐ反復が起きている。

したがって、同じ抽象度で第2の判定基準を新設すれば同じ反復をもう1本量産することになる。基準の軸そのものを置き換える必要がある。

軸を定めるにあたり、既存 ADR 59本を1本ずつ読ませて「自分の決定について、採らなかった選択肢とその却下理由を本文に書いているか」を実測した（2026-08-01）。記載あり43本・部分的10本・記載なし6本であり、7割超が却下代替を本文に持つ。規範内容を資産側へ、採用決定と却下した代替案の根拠を ADR 側へ置く二層構造は、本リポジトリの原則文書が定めるところであり、実務がおおむね履行している。

## Decision

### 1. ADR 化要否は、却下代替の必要条件を満たした場合に限り粒度判定基準で判定する

**ADR の固有価値は、採らなかった選択肢とその却下理由（なぜ他ではないか）を保持することに在る。** 何が正しいかを述べる規範本文は、共有規約文書・spec・実装・スキーマ等、現在の正しさを保持し続ける資産の責務である。

この定義を ADR 化要否の判定へ、粒度判定基準に**前置する必要条件**として置く。

**必要条件**: 当該決定について、採らなかった選択肢とその却下理由が在ること。却下した選択肢の名指しと却下理由が対として特定できることを要し、代替案の名指しだけ、あるいはトレードオフや受け入れたコストの記述だけでは成立しない。意図的に決めなかった面（保留した決定）は却下代替に当たらない。**成立するか迷う場合は不成立とする。**

**不成立の場合は点数を数えず ADR 化しない。** 却下代替を持たない決定は資産側へ書けば足りる。

**粒度判定基準**: 必要条件は十分条件ではない。成立した場合に限り粒度判定基準へ進み、次の4項目チェックリストで判定する。各項目に該当すれば1点とする。

1. 後戻りコストが高い
2. 複数モジュール・複数開発者に波及する
3. 採用理由が時間経過で揮発しやすい
4. ツールで自動強制できない

判定ルールは従前のとおり変更しない。**3点以上**で ADR 化を推奨、**2点以下**で ADR 化しない、**判断に迷ったら ADR 化しない**（原則として ADR 化しない方向に倒し、後から必要性が判明した時点で遡及して ADR 化する）。

必要条件の同点処理の向きは、スコア境界の向きおよび項目単位の同点処理と一致する。いずれも「書かない」側へ倒す。

**適用範囲**: 本必要条件は、**まだ記録されていない決定を新たに ADR として記録すべきか**の判定に掛かる。多決定 ADR の分割による後継への re-home は、既に記録された決定をファイル間で再配置する構造操作であり、新たな記録の判定ではないため本条件の対象外である。分割時に後継が満たすべき条件は分割手続きの側の規範であり、ADR-202607261501-01 決定1 が定める。したがって却下代替を持たない決定が分割後継として corpus に現れうる。その後継を退役させるかは、起票の判定ではなく既存 ADR の格下げ判定が扱う。

本決定は ADR-202607191825-01 決定1 を反転する。同決定は4項目チェックリストとスコア境界のみで ADR 化要否を確定させており、必要条件の前置は項目の追加ではなく判定構造の変更にあたる。4項目の名称・値域・スコア境界・「判断に迷ったら ADR 化しない」の向きは同決定から変更していない。

## Consequences

**得られた利益**:

- ADR 化要否の判定が、規則を網羅的に述べきれない粒度の項目群だけに依らなくなる。却下代替の有無は当該 ADR 本文のみを走査面とする閉じた判定であり、判定者間で結論が収束しやすい
- ADR と資産の役割分担が判定基準の側から言えるようになる。規範本文しか持たない記録は資産の写しであり、index に置く固有の価値を持たない

**却下した代替案**:

| 却下した案 | 却下理由 |
|---|---|
| 起票基準と同じ抽象度で第2の判定基準を新設し、格下げ専用に使う | 粒度判定基準の改訂履歴が示すとおり、この抽象度の規則は適用のたびに新しい曖昧性が現れて個別に塞ぐ反復を招く。第2基準を立てれば同じ反復をもう1本量産する |
| 設計判断型（なぜそう構造化したかが資産に現れない）と機能要件型（正本が構成上、資産側にあるのが自然）で仕分ける軸を前置する | 43本を仕分けた実測で内訳がバッチ間で大きく偏り、境界が判定者によって動いた。加えて機能要件型であることが退役可否と対応しない。二層構造の下では規範内容が資産側に在ることは設計上の意図であって欠陥ではなく、機能要件型と判定された記録の多くは資産側が明示的に根拠を ADR へ委譲している |
| 二層構造（規範内容は資産側、採用決定と却下代替は ADR 側）そのものを反転し、ADR に規範本文の保持を認める | 59本の実測で7割超が却下代替を本文に持ち、二層構造は現に履行されている。是正すべきは構造ではなく履行していない側である |

**受容したコスト**:

- 却下代替を持たない決定は、粒度判定基準の4項目が3点以上でも ADR 化しない。従前なら ADR 化していた決定の一部が資産側へ回る
- 必要条件の判定は本文の読解を伴い、機械検査できない。この点は粒度判定基準の4項目と同じである

本 ADR 起票時点（2026-08-01）で、この必要条件と粒度判定基準を実務手順として運用する実体は `adr` プラグインの `manage-adr` スキルの参照ファイルへ置かれた。以後、実務手順の所在や表現が変わっても、決定の骨子は本 ADR が保持する。
