# ADR-202608281231-01: スキル実行時のコンテキスト予算規約を作者向け文書として配布物の外へ置く

## Context

先行 ADR-202606270040-01 は、スキル実行時のコンテキスト予算規約を単一出典化すると決め、その置き場所をプラグイン共有 references（当時のパスは `plugins/dev-workflow/references/context-budget.md`）とした。同 ADR は配置の根拠として、複数スキルが共有する参照資源はプラグインルート `references/` へ集約するという原則（ADR-202606040737-01）を引いている。

その後の実測で、この規約は配布物の中のどのスキル定義・サブエージェント定義・README からも参照されていないことが確認された（2026-08-28 時点。参照0件は反証レビューでも追認されている）。ADR-202607261002-02 の Context も、起票時点（2026-07-26）で参照していたのは CLAUDE.md のみであったことを記録している。すなわち規約の実際の読者は、配布先でスキルを実行する主体ではなく、本リポジトリでスキルを設計・改修する作者である。

読者が作者である文書を配布物の中に置くと2つの不都合が生じる。第一に、配布先の利用者には到達経路のない文書が同梱され、配布物が「実行主体から到達可能な参照を持つ文書の集合」という性質を失う。第二に、文書が持つ相対リンク（`../../../docs/`）は配布先で解決できず、配布物の内側から外側を指す参照になる。

配置の再検討にあたっては、読者別配置（実行主体が実行時に読むものは配布物の内側、作者だけが読むものは外側）という軸を採る。この軸は `docs/distribution-boundary.md` の軸①（配布先で参照が解決できるか）・軸③（その定義なしに配布物の手順が評価不能になるか）と整合する。同方向の記述は ADR-202607261002-02 決定4 にもあるが、同 ADR は起票時点で `status: 提案中`（承認軸の確定は #633 の射程）であるため、本 ADR は同 ADR を根拠に用いず独立の判断として決める。

## Decision

スキル実行時のコンテキスト予算規約の正本を `docs/references/context-budget.md` に置く。

- 先行 ADR-202606270040-01 の決定の実質はすべて維持する。すなわち、規約の**内容**（パス渡し原則・生ツール出力のファイル化・サブエージェント返却のサマリ化・滞留カテゴリ規則）は単一出典の reference が保持し、ADR は決定を記録する。token 軸を作成時静的／実行時フローの2軸に分離し、CLAUDE.md にはフロー軸への委譲ポインタのみを置いて規約本文を二重化しない。起動後ピーク context の上限はスカラーで定めず滞留カテゴリ規則で導出する。本 ADR が改めるのは**配置だけ**である。
- 本規約は配布物（プラグイン）の外に置く。読者が本リポジトリの作者に限られるためであり、プラグインルート `references/` 集約原則（ADR-202606040737-01）は「複数スキルが**共有する参照資源**」を述語とするため、実行主体からの参照を持たない本規約には及ばない。同原則は反転しない。
- CLAUDE.md「スキル設計の token 規律」からのポインタは新パス `docs/references/context-budget.md` を指す。ADR から規範実体へ辿れなくなる型を作らないため、本 ADR も決定文に新パスを明記する。
- 将来この規約が配布物の実行主体から参照される設計へ変わった場合（スキル本文からの `${CLAUDE_PLUGIN_ROOT}/references/` 参照を持つ形になった場合）は、本決定を再検討し配布物内への再配置を検討する。

### 不採用案

- **案①: 現状維持（プラグイン共有 references に置き続ける）** — 参照0件のまま配布され続け、配布物が実行主体から到達不能な文書を同梱する状態が固定される。解決できない相対リンクも残る。不採用。
- **案②: 規約本文を CLAUDE.md へ取り込む** — 先行 ADR-202606270040-01 が案①として不採用にした理由（規約本文が常時ロードされ context 節約という目的と自己矛盾する）がそのまま成立する。加えて分量（69行）が CLAUDE.md の可読性を損なう。不採用。
- **案③: 実行主体から参照される形へ結線して配布物内に残す** — 各 SKILL.md に本規約へのポインタを足す案。規約の内容は作者が設計時に従うものであり、実行時に読ませても実行の分岐を変えない。結線の必要が生じた時点で本決定を再検討する形とし、現時点では不採用。

## Consequences

- 配布物（`plugins/dev-workflow`）の共有 references が、実行主体から到達可能な参照を持つファイルのみになる。配布先の利用者へ到達経路のない文書が届かなくなる。
- 規約の内容・単一出典性・転記禁止は不変であるため、既存のスキル設計・レビューが参照する基準は変わらない。本 ADR は挙動を変えない。
- CLAUDE.md からのポインタが `docs/` 配下を指す形になる。CLAUDE.md は配布物に同梱されないため、規約とポインタの双方が作者側に揃う。
- 旧パスへの参照が凍結記録（旧 ADR 決定文・過去の観測記録・監査記録）に残る。これらは当時の事実の記録であり書き換えない。現行有効な文書からの参照は新パスへ張り替え、旧パスが現行文書に再混入しないことを常設の検査で固定する。
- 配置が配布物の外へ出たことで、プラグインを単体で配布した相手はこの規約を読めなくなる。読者を作者に限る判断の帰結として受容する。
