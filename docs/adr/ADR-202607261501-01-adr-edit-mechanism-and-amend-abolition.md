# ADR-202607261501-01: ADR の編集機構（3段構え・凍結原則・ADR分割）と Amended 機構の廃止

## Context

本 ADR は ADR-202607112231-01-adr-two-axis-status-validity-model（以下、原 ADR）の分割により生じた後継のひとつである。決定内容は原 ADR で承認済みのものを逐語 restate したものであり、内容の再決定ではない。

### 分割の経緯

原 ADR は8つの決定を束ねる多決定 ADR だった。そのうち決定8「採番方式・配置」の採番方式項が ID 形式の単一化（#550）で core 反転したため、原 ADR 決定3 が定める多決定 ADR の部分 core 反転手続き（ADR分割）に従い、生存決定を独立に反転しうるクラスタごとの後継へ逐語 restate し、原 ADR を `上書き済み` へ退役させた。本 ADR が担う決定3 は、その分割手続き自身の出典でもある。

後継は6本である。本 ADR は原 ADR の**決定3（3段構えの編集機構・凍結原則・ADR分割・既得権条項）・決定4（Amended 機構の廃止）**を担う。この2決定を一体のクラスタとしたのは、決定4 が Amend 廃止後の受け皿を決定3 の「非core＝直接編集＋変更履歴」枝に置いており、決定3 の枝構成の反転が決定4 の成立条件を崩す一方、決定4 の反転（Amend の復活）は決定3 へ第4の分類の追加を要求するためである。波及は双方向であり、片方だけを独立に反転できない。残る決定は ADR-202607261459-01（決定1・2・5）、ADR-202607261503-01（決定6）、ADR-202607261503-02（決定7）、ADR-202607261503-03（決定8 の配置項）が担い、反転した採番方式は ADR-202607261504-01 が新決定として置き換える。

### 原 ADR からの改変箇所と理由（開示）

1. **見出しの先頭番号の振り直し**: 原 ADR の `### 3.` / `### 4.` を本 ADR では `### 1.` / `### 2.` とした。番号は原 ADR 内での決定の並び順を示すものであり、後継では自身の決定集合における位置へ振り直す。見出しタイトルと決定本文は変更していない。
2. **`## Consequences` の取捨**: 本 ADR が担う決定3・4 に対応する記述のみを原 ADR から保持した（得られる利益1項・受容したトレードオフ1項・将来の留保事項1項）。複数の決定にまたがる項目は文を切らず全文のまま保持したため、同じ文が他の後継にも現れる。配分の全体像は分割を実施した #570 が持つ。

### 決定本文に残る原 ADR への自己言及（読み替え）

逐語 restate の不変条件により決定本文は改変していないため、本文中の「本 ADR」および決定番号は原 ADR を指したままである。決定1 の既得権条項がいう「本 ADR 自身の8決定」は原 ADR の8決定を指し、本 ADR の決定数ではない。決定2 が引く「決定3 の凍結原則」は原 ADR の決定3、すなわち本 ADR の決定1 を指す。`## Consequences`「得られる利益」の項がいう「本 ADR 自体が…実例になっている（ADR-202605110956-01 を全体 Supersede）」も同様に原 ADR を指す（ADR-202605110956-01 を上書きしたのは原 ADR である）。

## Decision

### 1. 編集機構（3段構え）と判定フロー

有効性が可変性のゲートを兼ねる。`有効` の ADR は生きた文書として本文を直接編集してよい。`上書き済み` / `廃止済み` に退役した ADR は凍結された歴史的成果物として編集しない。

**この凍結原則の射程は決定内容の編集である。** front-matter（状態）にも `## Decision`（内容）にも触れず、状態の重複表示を消すだけの是正は、決定の記録を書き換えないため射程外であり、退役 ADR に対しても実施してよい。除去しようとする表示が固有の情報を持つ場合、それを `## 関連ADR` へ移してから除去する操作（＝移設。除去の直前に重複を作る）も、情報の総体が保存され決定の記録が変わらない限り同じく射程外である。逆に、決定内容に触れる編集は退役 ADR に加えてはならない。以下の判定フローは、`有効` な ADR への決定内容の編集を振り分けるものである。

`有効` な ADR への変更は、次の decision tree で core / 非core / 些末 を判定する。境界アンカーは「その変更に再承認が要るか」。

```
1. その編集で「決定の結論・方向・前提」が変わるか？
   YES（結論の反転・前提の失効・後継への置換）
      → core = 再承認が要る
      → 新規 ADR を起票し、旧 ADR の validity を「上書き済み」に
        （旧 ADR が多決定で生存決定が残る場合は下記「多決定 ADR の部分 core 反転（ADR分割）」へ）
   NO → 2 へ
2. 決定内容に触れるか？（パラメータ値・適用範囲・条件・理由付け）
   YES（骨子は保つが決定関連情報を更新）
      → 非core = 既承認の枠内
      → 直接編集 ＋ 本文「## 変更履歴」に1行
   NO（typo・整形・リンク・語句・体裁のみ、決定内容ゼロ）
      → 些末 → 直接編集、履歴は git のみ
```

| 変更の性質 | 対応 | 変更履歴の在り処 |
|---|---|---|
| 些末（typo・整形・リンク修正、決定内容ゼロ） | 直接編集 | git のみ |
| 非core かつ決定に関わる（パラメータ・適用範囲＋理由） | 直接編集＋`## 変更履歴` に1行 | ファイル内 |
| core（再承認が要る） | 有効性を `上書き済み` にし、新規 ADR を起票（旧 ADR が多決定で生存決定が残る場合は下記「ADR分割」へ） | 別 ADR ファイル＋相互参照 |

**安全則: 判定に迷ったら core 寄り（新規 ADR）に倒す。** core を非core と誤判定すると、再承認イベントを飛ばして core 変更を権威記録に焼き込む不可逆な不整合が残る。逆に非core を core と誤って新規 ADR にしても過剰なだけで可逆（後で統合できる）。可逆性の非対称から core 寄りが安全である。

**多決定 ADR の部分 core 反転（ADR分割）**

上表の core 行「有効性を `上書き済み` にし、新規 ADR を起票」は、ADR 全体が反転される場合を前提とする。**複数の決定を束ねた ADR の一部決定だけが core 反転され、残りの決定が生存する**場合、原 ADR 全体をそのまま `上書き済み` にすると生存決定を誤って退役させる。このケースは次の構造操作「ADR分割（extract）」を経由する。

ADR分割は判定木（core / 非core / 些末）の第4分類ではない。決定の**ファイル間再配置**という別軸の構造操作であり、本文編集の分類ではなくリファクタリングに相当する。

- **前提**: 1本の多決定 ADR。0本以上の決定が core 反転中。
- **手順**: 生存決定を後継 ADR（一体反転するクラスタ単位で1本以上）へ**逐語 restate** する。反転中の決定はそれ自身の後継 ADR が担う。原 ADR の `validity` を `上書き済み` にし、`superseded-by` に全後継を列挙する。各後継は本文 `## 関連ADR` に `Supersedes: 原ADR` を宣言する。
- **不変条件**: 分割中に決定内容を変えない（逐語 restate ＝振る舞い保存）。決定内容の変更が要る場合は、分割とは別に core / 非core 編集として分離する。
- **restate の射程**: 逐語 restate と上記不変条件の射程は `## Decision` の決定本文である。トップレベル項目の先頭番号は後継での単独可読性のため振り直してよく、保存対象に含めない。他の節は次のとおり扱う。`## Context` は後継の文脈での新規記述とする。`## Consequences` は生存決定に対応する記述を保持し、退役する決定に由来して無効となる記述のみ除く（帰結記述の整理であり、決定内容の変更にはあたらない）。`## 関連ADR` は後継が保持する決定集合に照らして書き下ろし、原 ADR の `Related:` を機械的に引き継がない。原 ADR 側の `Related:` は退役時点のスナップショットとして残置し、分割の一環としては編集しない（分割以外の文脈での編集可否は、上記の凍結原則の射程に従う）。
- **開示義務**: 原 ADR から改変した箇所（決定本文の先頭番号の振り直し、`## Consequences` の調整）がある場合、後継 ADR の `## Context` に改変箇所と理由を記載する。後継のみを読む読者が、改変が意図的な調整か restate の取りこぼしかを判別できる必要があるため。

呼び出しは2トリガ。(a) **反転駆動**: ある決定が core 反転し、対象が多決定 ADR で生存決定が残るとき、生存決定を分割で救出する。(b) **衛生的**: 反転なしに legacy の束ね ADR を予防的に分解する（任意）。

**grandfather**: 既存の多決定 ADR（本 ADR 自身の8決定を含む）は遡及分割しない。凍結し、部分 core 反転が実際に当たったときにのみ分割駆動する。新規 ADR は、独立に反転しうる core を1本に束ねない。束ねが必要な場合は、束ねた塊が一体で反転する抽象度まで上げる（独立に反転する決定は、そもそも同一 core ではない）。

原則: ADR ファイルは、あらゆる consumption 面（Wiki・Confluence・artifact・抽出ファイル）に対して自己完結する。git は repo の実装詳細であり、決定関連情報の SSoT にはしない。決定粒度の変更履歴（git の commit 粒度とは別物）はファイル内 `## 変更履歴` に持つ。

### 2. Amended 機構を廃止する

ADR-202605110956-01 系の運用にあった Amended（別 ADR 起票で facet のみ改訂し旧 ADR を Accepted 維持）機構は廃止する。パラメータ・適用範囲の改訂は上記「非core = 直接編集＋`## 変更履歴`」で扱い、決定の骨子を覆す改訂は core = 新規 ADR で扱う。

既存の `Amends:` / `Amended by:` 相互参照は、本文 `## 関連ADR` に凍結保持する（遡及編集しない）扱いを採らず、生存語彙へ移行したうえで corpus から除去する。方針は3点。(a) live な Amend 関係は生存語彙（`Supersedes:` / `Superseded by:` / `Related:` および `## 変更履歴`）へ移行する。(b) 既に退役済み（retired）の Amend 関係は後継 ADR の supersede 連鎖へ吸収する。退役済み ADR のファイルから当該 `Amends:` / `Amended by:` 行を除去する操作は、決定内容に触れず情報の総体が supersede 連鎖へ保存されるため、決定3 の凍結原則（退役 ADR は編集しない）の射程外である。(c) `Amends:` / `Amended by:` の語彙は corpus から除去する。新スキーマに `amends` キーは設けない。具体の移行手順（対象エッジの分類と個別の移し替え）は Issue #496（親）とその子が担い、本決定は方針の宣言に留める。移行対象は本数でなくエッジ（関係）単位で列挙する。移行計画の時点で、1ファイルが複数の `Amends:` を宣言するケース（例: ADR-202606071222-01 が2つの親 ADR を改訂対象に挙げていた）があり、さらに `Amends:`（forward）と `Amended by:`（backward）は後続の Supersede によって非対称になりうる（改訂先が supersede 連鎖で別 ADR へ差し替わると、forward と backward の指す先が食い違う）ため、本数指定では移行を取りこぼす。エッジ単位の列挙はこの取りこぼしを防ぐ。

## Consequences

**得られる利益**:

- 本 ADR 自体が、新モデルの編集判定フロー（core 変更＝新規 ADR で旧 ADR を上書き）を自分自身に適用した実例になっている（ADR-202605110956-01 を全体 Supersede）。

**受容したトレードオフ**:

- ADR-202605110956-01 の採番方式・配置は不変だが、Amended 機構を廃止したため部分改訂ができず、全体 Supersede ＋ restate の形を取る。不変部分の再掲という冗長を、自己完結原則の対価として受容する。

**将来の留保事項（本 ADR のスコープ外＝ downstream）**:

- 移行（全 ADR への front-matter 付与、`ADR-202605312147-01` の Superseded 実例の validity 移設、既存 `Amends:` / `Amended by:` 関係の生存語彙への移行（live は `Supersedes:` / `Superseded by:` / `Related:` / `## 変更履歴` へ移し、retired は後継の supersede 連鎖へ吸収して Amend 語彙を corpus から除去する。凍結して grandfather 固定はしない。取りこぼしを防ぐため移行対象はファイル数でなくエッジ単位で列挙し、1ファイルが複数の `Amends:` を宣言するケースを含める）、英語状態名から日本語ユビキタス言語への移行、`docs/development/event-storming.md`「技術的意思決定」集約の状態機械の作り替え〔英文4状態→2軸・`却下` 終端追加〕、index 初期生成）は Issue #463 フェーズ3に委ねる。
