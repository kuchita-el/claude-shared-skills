# ADR-202611140741-01: adr プラグインの言語に依存する語を、導入先が行単位の設定ファイルで定められるようにする

## Context

`adr` プラグインは、どの GitHub リポジトリへも導入できることを目的に切り出された。しかし、本リポジトリの日本語の規約が検査器に焼き込まれている。英語で ADR を書くリポジトリは、lint を通れない。

2026-11-14 時点で、同梱のスクリプトが導入先のリポジトリへ書き込む語、または導入先の ADR に要求する語のうち、言語に依存するものは次の5つである。

- `status` の値（`提案中` / `承認済み` / `却下`）
- `validity` の値（`有効` / `上書き済み` / `廃止済み`）
- 相互参照を置く節の見出し（`## 関連ADR`）
- 生成する index の題名
- 生成する index の冒頭に書く、生成物であることを示す注記

manage-adr スキルの手順も、`status` と `validity` の値を ADR の front-matter へ書き込む。値は、スキルの手順書と参照ファイルに直接書かれている。

節名の `Context` / `Decision` / `Consequences` は、もとから英語である。関係のラベル `Supersedes:` / `Superseded by:` / `Related:` も同じである。lint のメッセージは日本語だが、導入先のリポジトリには残らない。

方針は先に決まっている。言語に中立にし、導入先のリポジトリごとに単一の言語で一貫させる。1つの状態に日英2つの綴りを許す案は、1つの概念を1つの綴りで表す原則を崩し、綴りの食い違いを生むため採らない。本 ADR は、この方針を実装できる粒度まで具体化する。

値を日本語で確定するという記録は、いま `plugins/adr/skills/manage-adr/references/adr-model.md` と雛形の注記にある。導入先ごとの上書きを範囲外とする記録は、`plugins/adr/README.md` にある。もとの決定を記録した ADR は上書き済みで、その後継は廃止済みである。そのため、本 ADR が上書きする有効な ADR は無い。

**射程の限定**: 本 ADR は、設定の形式・置き場・範囲・例外・誤りの扱いを決める。設定を読む実装、検査器とスキルからの語の切り離し、文書の書き換えは決めない。lint のメッセージをどの言語で出すかも決めない。

## Decision

1. **形式**: 設定は、`key: value` を1行ずつ並べたファイルで定める。1つのキーは1つの役割を表し、値を1つだけ持つ。役割の例は、承認軸の「承認前」「承認」「却下」である。値と役割の対応は、キーの名前で取る。並び順には意味を持たせない。lint は、front-matter と同じ行の走査でこのファイルを読む。シェルとして読み込まず、外部のパーサも要しない。
2. **置き場と解決の順**: 導入先リポジトリの git のトップレベルにある `.claude/adr/config` を先に見て、無ければプラグインに同梱した既定値を使う。
   - 単体のスクリプトは、ADR ディレクトリを引数で受け取ったときは、そのディレクトリから git のトップレベルを決める。引数を省いたときは、カレントディレクトリから決める。
   - commit ゲートは、commit を実行する作業ディレクトリから git のトップレベルを決める。
   - manage-adr スキルは、対象の ADR ディレクトリから、同梱のスクリプトと同じ順で決める。
   - git のトップレベルを決められない場合は、既定値だけを使う。
3. **範囲**: 設定できるのは次の2群に限る。
   - **語の群**: `status` の3値、`validity` の3値、相互参照の節の見出し、index の題名、index の冒頭の注記。
   - **ADR ディレクトリ**: 検査・生成・発番の対象とする ADR ディレクトリ。単体のスクリプトでは、引数で渡した ADR ディレクトリがこのキーより優先する。引数を省いたときにこのキーを使い、キーも無ければ既定の `docs/adr` を使う。commit ゲートはこのキーを使い、無ければ `docs/adr` を使う。このキーの値と既定の `docs/adr` は、git のトップレベルからの相対パスとして読む。git のトップレベルを決められないときは、カレントディレクトリからの相対パスとして読む。
4. **語の群は揃えて置く**: 導入先の設定に語の群のキーが1つでもあれば、語の群の全キーを置くことを求める。語の群で既定値へ戻ることは許さない。一部だけを置くと、1つのリポジトリの中で2つの言語が混ざるためである。ADR ディレクトリのキーは、語の群と独立に置いてよい。
5. **設定の誤り**: 次の場合は、原因を示して exit 2 で止める。設定の誤りを、ADR の違反として報告しない。
   - 知らないキーがある（綴りの誤りを含む）
   - 同じキーが2回ある
   - 値が空である
   - 語の群の一部だけがある
   - `status` と `validity` の6つの値に重複がある
6. **英語に固定する例外**: 次の語は、導入先の言語によらず英語に固定し、設定の対象にしない。ADR の分野でほぼ共通に使われる語だからである。front-matter のキー名（`status` / `validity` / `superseded-by`）も英語のままとする。
   - 節名の `Context` / `Decision` / `Consequences`
   - 関係のラベル `Supersedes:` / `Superseded by:` / `Related:`
7. **スキル**: manage-adr スキルの手順と参照ファイルは、状態を役割の名前で書く。front-matter へ書き込む値は、設定から読む。
8. **本リポジトリの扱い**: 同梱の既定値は、いまの日本語の値・見出し・題名・注記にする。本リポジトリの既存の ADR と雛形は、書き換えない。
9. **正本**: 語の値の正本は、同梱の既定値のファイルとする。`adr-model.md` は役割と意味を定め、値はそのファイルを指す。

**却下した代替**:

- **シェルとして読み込む定義ファイル**: 実装は最も簡単である。しかし commit のたびに、導入先リポジトリのファイルをコードとしてフックの中で実行することになる。今の配布物は、導入先の内容をコードとして実行しない。この境界を、語を変えるためだけに崩すことになる。
- **YAML などの構造化ファイル**: bash から読むには外部のパーサが要り、導入先へ依存を1つ課す。要るのは平たいキーと値だけで、構造化の利点が無い。
- **`adr-model.md` の中の機械可読ブロック**: 正本は1つになる。しかし導入先が上書きするには、規約の文書全体を差し替えることになり、文書と設定が混ざる。
- **1つのキーにカンマ区切りで3値を並べる**: キーの数は減る。しかし値と役割の対応が並び順に依存し、順の誤りが黙って役割の取り違えになる。
- **ADR ディレクトリの中に置く**: git に依存しない利点がある。しかし、どの ADR ディレクトリを検査するかを、そのファイル自身では指定できない。
- **環境変数だけで渡す**: 利用者がフックの環境を整える必要があり、リポジトリと一緒に配れない。
- **語の群でもキーごとに既定値へ戻す**: 設定を短く書ける。しかし、一部の語だけを英語にしたリポジトリが、日本語と英語の混ざったまま lint を通る。
- **設定の誤りを警告にとどめ、既定値で続ける**: 綴りの誤ったキーが黙って既定値へ戻り、英語の ADR が全件、語彙の違反として報告される。利用者は、原因が設定にあると気づけない。
- **関係のラベルも設定の対象にする**: 設定の項目と検査の分岐が増える。英語のリポジトリが運用するのに必要ない。
- **節名も厳格に単一言語にする**: 一貫性は最も高い。しかし節名まで設定の対象になる。本リポジトリの既存の ADR と雛形の書き換えも要る。lint は節名を検査しておらず、得るものが少ない。

## Consequences

- 英語で ADR を書くリポジトリは、設定ファイルを1つ置けば、lint・ゲート・スキルを使える。第3の言語も同じ仕組みで扱える。
- lint のメッセージの言語は本 ADR の射程の外にあり、当面は日本語のまま届く。英語の利用者にとっては障壁として残る。
- 設定ファイルの形式とキーは、利用者が書く面になる。変えるときは利用者への影響を伴う。
- 実装では、次の作業が要る。
  - 設定を読む仕組みを、lint・index の生成器・発番器・commit ゲートで共有する。設定の誤りの検査も含む。
  - 各スクリプトから語を切り離す。
  - manage-adr の `SKILL.md` と参照ファイルの手順を、役割の名前で書き直す。参照ファイルには `transitions.md`・`adr-demotion.md`・`adr-scoping.md` などがある。書き込む値は設定から読むようにする。
  - `adr-model.md`・`README.md`・雛形の注記を本 ADR に合わせて書き換える。値を日本語で確定するという記述と、上書きを範囲外とする記述が対象である。
  - これらは存続する配布物の変更なので、レビュー契約を通す。
- ADR ディレクトリを設定で指定できるので、既定以外の場所に ADR を置く導入先でも、引数を渡さずにゲートとスクリプトが働くようになる。
