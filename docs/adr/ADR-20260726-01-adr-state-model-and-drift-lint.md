# ADR-20260726-01: ADR の状態モデル（承認軸と有効性軸の2軸分離・導出ビュー index）と drift-lint

## Context

本 ADR は ADR-20260711-3-adr-two-axis-status-validity-model（以下、原 ADR）の分割により生じた後継のひとつである。決定内容は原 ADR で承認済みのものを逐語 restate したものであり、内容の再決定ではない。

### 分割の経緯

原 ADR は8つの決定を束ねる多決定 ADR だった。そのうち決定8「採番方式・配置」の採番方式項が ID 形式の単一化（#550）で core 反転したため、原 ADR 決定3 が定める多決定 ADR の部分 core 反転手続き（ADR分割）に従い、生存決定を独立に反転しうるクラスタごとの後継へ逐語 restate し、原 ADR を `上書き済み` へ退役させた。

後継は6本である。本 ADR は原 ADR の**決定1（2軸分離）・決定2（front-matter 権威と導出ビュー index）・決定5（drift-lint 3レイヤと合流先）**を担う。この3決定を一体のクラスタとしたのは、決定2 の front-matter スキーマ必須ルール表が決定1 の値集合を各行に持ち、決定5 のレイヤ1（スキーマ検証）・レイヤ2（index 同期）が front-matter 権威と index 導出を前提に定義されているためである。いずれか1つの反転は残り2つの決定本文の書き換えを強制する。残る決定は ADR-20260726-02（決定3・4）、ADR-20260726-03（決定6）、ADR-20260726-04（決定7）、ADR-20260726-05（決定8 の配置項）が担い、反転した採番方式は ADR-20260726-06 が新決定として置き換える。

1. **見出しの先頭番号の振り直し**: 原 ADR の `### 1.` / `### 2.` / `### 5.` を本 ADR では `### 1.` / `### 2.` / `### 3.` とした。番号は原 ADR 内での決定の並び順を示すものであり、後継では自身の決定集合における位置へ振り直す。見出しタイトルと決定本文は変更していない。

### 決定本文に残る原 ADR 内の決定番号（読み替え）

逐語 restate の不変条件により決定本文は改変していないため、本文中の決定番号は原 ADR での番号のままである。本 ADR の決定2 が引く「決定3（多決定 ADR の部分 core 反転（ADR分割））」と決定3 が引く「決定4（Amend 機構の廃止）」はいずれも原 ADR の決定であり、分割後は ADR-20260726-02 の決定1 および決定2 が担う。

## Decision

### 1. Status を承認軸と有効性軸の2軸に分離する

1 つの `Status` 欄に混在していた 2 軸を、別フィールドに分離する。値は日本語のユビキタス言語で確定する。

- **承認軸（不変・承認の歴史記録）**: `提案中` / `承認済み` / `却下`
    - `提案中`: 起案され、承認者の判断を待つ
    - `承認済み`: 承認された履歴事実。以後不変
    - `却下`: 提案が承認に至らず終了。一度も運用されない終端
- **有効性軸（可変・現在の効力）**: `有効` / `上書き済み` / `廃止済み`
    - `有効`: 現在運用中
    - `上書き済み`: 後継 ADR に置き換えられた（後継識別子を保持）
    - `廃止済み`: 後継なしで放棄された

`却下`（承認軸: 一度も承認されなかった終端）と `上書き済み` / `廃止済み`（有効性軸: 承認後に効力を失った状態）を別語とし、2 軸が語彙レベルで衝突しないようにする。これは ADR-20260511 のライフサイクル状態（`Proposed / Accepted / Deprecated / Superseded` の英文4状態）と、`docs/development/event-storming.md` の「状態名を英文表記で確定」という決定の両方を置き換える。

### 2. front-matter を唯一の権威とし、有効 ADR index は導出ビューとする

状態系は各 ADR ファイル冒頭の front-matter に置く。キーは英語（構造的フィールド名）、値は上記の日本語ユビキタス言語とする。

```yaml
---
status: 承認済み          # 承認軸・不変（提案中 / 承認済み / 却下）
validity: 有効            # 有効性軸・可変（有効 / 上書き済み / 廃止済み）
superseded-by: ADR-...   # validity=上書き済み のとき必須（分割時はリスト値）
---
```

front-matter を単一の権威とし、有効 ADR index（`docs/adr/index.md`）はそこから機械生成する純粋な導出ビューとする。index は `validity: 有効` の ADR のみを列挙し、ファイル全体が生成物（build artifact）であって人手編集しない。これにより「本文を読めば確実（確実性）」と「一覧で探せる（検索性）」を drift させずに両立する。

front-matter スキーマの必須ルール（drift-lint が強制する）:

| 遷移 | status | validity | superseded-by |
|---|---|---|---|
| 起票 | 提案中 | （無し） | （無し） |
| 承認 | 承認済み | 有効 | （無し） |
| 上書き | 承認済み（不変） | 上書き済み | 必須 |
| 廃止 | 承認済み（不変） | 廃止済み | （無し） |
| 却下 | 却下 | （無し） | （無し） |

`superseded-by` は単一後継を既定とするが、1本の ADR が複数の後継へ分割される場合（決定3「多決定 ADR の部分 core 反転（ADR分割）」）はリスト値を取りうる。この 1→N のケースでは、`validity: 上書き済み` の原 ADR が全後継を列挙し、各後継が本文 `## 関連ADR` に逆参照（`Supersedes:`）を持つ（drift-lint レイヤ3 が N 対 1 で双方向性を検査する）。

キーを英語としたのは、キーが状態概念そのものではなく構造的なフィールド名であり、英語キーでも概念の二重管理による drift を生まないためである（ユビキタス言語の本体は値側にある）。冒頭で `status` と `validity` が隣接することで「承認済み」を「有効」と誤読する罠も防ぐ。生成入力を本文見出しの正規表現抽出ではなく front-matter の key-value 解析としたのは、後者のほうが堅牢なためである。

### 3. drift-lint（3レイヤ）と合流先

有効性の同期は、CI 不在下でも「index を再生成して一致するか」を検査する drift-lint で担保する。検査契約は3レイヤ:

- **レイヤ1（front-matter スキーマ検証）**: 上記スキーマ必須ルールを満たすこと。
- **レイヤ2（index 同期）**: `docs/adr/index.md` を再生成し、コミット済みと差分ゼロであること。
- **レイヤ3（相互参照双方向性）**: 「`A.superseded-by` が B を列挙する」⟺「B 本文 `## 関連ADR` に `Supersedes: A` が存在する」の双方向を検査すること（分割による 1→N では A が複数の後継を列挙し、各後継が A を逆参照する N 対 1 を含む）。前方向（A の列挙に対する B の逆参照欠落）だけでなく、逆方向——B が `Supersedes: A` を宣言するのに A の `superseded-by` に B が無い——の検出も要件に含む。corpus に残存する `Amends:` / `Amended by:` 関係は検査対象外とする（決定4 により生存語彙へ移行のうえ corpus から除去されるため、移行完了後は該当関係が存在しない）。

合流先は独立プラグイン `adr` 同梱の `lint-adr.sh`（`plugins/adr/scripts/lint-adr.sh`）として実体化し、同プラグインの PreToolUse フック（`git commit` 前ゲート。導入先に `docs/adr` がある場合のみ発火し、無い場合は no-op）から呼ぶ。本リポでは `.claude/settings.json` の `enabledPlugins` へ `adr` を登録して常時発火させる。人間も手動実行できる二面構成とする。CI 設定ファイル（`.github`）は基盤不在のため作らない。

## Consequences

**得られる利益**:

- 記憶を持たないエージェントが「今どれが有効な ADR か」を単一の導出ビュー（`docs/adr/index.md`）から安価に判別でき、承認の歴史記録（承認軸）が不変に保たれる。
- 有効性の同期を drift-lint で機械的に担保できるため、CI 不在の制約が本質的問題でなくなる。

**受容したトレードオフ**:

- front-matter への移行が完了するまで、既存 ADR の `## Status` 見出し形式と新スキーマが混在する過渡状態を受容した（本 ADR 自身では解消せず移行フェーズ3へ委ねた）。この過渡状態は、フェーズ3の front-matter 一括移行（#476）と `## Status` 節の遡及除去（#489→#514）の完了により corpus 全体で解消済み。

**将来の留保事項（本 ADR のスコープ外＝ downstream）**:

- 機構の実装（`scripts/lint-adr.sh` と PreToolUse フック合流、`docs/adr/index.md` 生成、`docs/adr/README.md` 廃止手順・`template.md` の改訂、ライフサイクル操作スキル）は実装 Issue に委ねる。この機構は実装済み。drift-lint はその後 ADR 運用機構のプラグイン抽出（#492/#493）で独立プラグイン `adr` 同梱の `plugins/adr/scripts/lint-adr.sh`＋同プラグインの PreToolUse ゲートへ移った（現配置は決定5 本文と 2026-07-21 変更履歴を参照。ここでの `scripts/lint-adr.sh` は起票当時に想定した合流先を指す）。
- 移行（全 ADR への front-matter 付与、`ADR-20260531-2` の Superseded 実例の validity 移設、既存 `Amends:` / `Amended by:` 関係の生存語彙への移行（live は `Supersedes:` / `Superseded by:` / `Related:` / `## 変更履歴` へ移し、retired は後継の supersede 連鎖へ吸収して Amend 語彙を corpus から除去する。凍結して grandfather 固定はしない。取りこぼしを防ぐため移行対象はファイル数でなくエッジ単位で列挙し、1ファイルが複数の `Amends:` を宣言するケースを含める）、英語状態名から日本語ユビキタス言語への移行、`docs/development/event-storming.md`「技術的意思決定」集約の状態機械の作り替え〔英文4状態→2軸・`却下` 終端追加〕、index 初期生成）は Issue #463 フェーズ3に委ねる。
- 本 ADR および ADR-20260511 の front-matter 化もフェーズ3の一括移行に含めた（起票時点では両 ADR とも `## Status` 形式だった）。両 ADR とも #476 で front-matter 化済み。
