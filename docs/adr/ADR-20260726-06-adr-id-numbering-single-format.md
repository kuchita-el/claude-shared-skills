# ADR-20260726-06: ADR の採番方式を日付＋2桁ゼロ埋め連番＋slug の単一形式へ統一する

## Context

本 ADR は ADR-20260711-3-adr-two-axis-status-validity-model（以下、原 ADR）の分割により生じた後継のひとつである。ただし他の5本と異なり、原 ADR の生存決定を逐語 restate したものではなく、**原 ADR の決定8「採番方式・配置（ADR-20260511 から不変で引き継ぐ）」のうち採番方式項を反転する新しい決定**である。原 ADR の決定8 は採番方式と配置の2項からなり、配置項は ADR-20260726-05 へ生存 re-home された。

### 反転する対象

原 ADR が ADR-20260511 から不変で引き継いでいた採番方式は、同日1件目には連番を付けず、2件目以降に `-2` から付与する形式だった。これは同一の起票日に対して連番あり・連番なしの2つのファイル名形式を許すため、識別子の形が1つに定まらない。参照側は2形式を解釈し分ける必要があり、ファイル名から起票順を読む処理も形式ごとに分岐する。#550 はこの二形式併存を単一形式へ統一する判断であり、本 ADR はその根拠を正典として記録する。

### 2桁ゼロ埋めとする理由

連番をゼロ埋めするのは、**ファイル名の `LC_ALL=C sort` による辞書順整列だけで起票順が再現される**ようにするためである。ゼロ埋めしないと同日10件目で `-10` が `-2` より前に照合され、2桁に到達した時点でこのゴールが破れる。ソート側を数値ソートへ変える案は採らない。それで直るのは生成物である index の中だけであり、GitHub のファイル一覧・`ls`・エディタのファイルツリーでは逆転が残るためである。

### #550 の分割方針における位置づけ

#550（ID 形式の単一化）は3段に分割された。1段目（#566）が adr プラグインの規約文書を新形式へ確定させ、2段目（#570）が本 ADR を含む正典 ADR 側の記録をそれに追従させ、3段目（#567）が `docs/adr/` 配下の既存ファイルの遡及リネームと参照の書き替えを担う。本 ADR の承認時点では、規約文書と正典 ADR は新形式・既存ファイル名は旧形式という過渡状態が残る。

## Decision

### 1. ADR のファイル名・識別子は単一形式とする

ADR のファイル名規則を次の単一形式に定める。

```
ADR-YYYYMMDD-NN-<slug>.md
```

- `YYYYMMDD`: ADR の起票日。採番日＝起票日とする
- `-NN`: 同日内の連番。`01` 始まりの2桁ゼロ埋めとし、**同日1件目にも `-01` を付与する**。同日99件を上限とする
- `<slug>`: 内容を表す短い英数字ハイフン区切りの文字列

**識別子**は番号部（`ADR-YYYYMMDD-NN`）を指し、**full slug**（ファイル名から `.md` を除いた文字列＝`ADR-YYYYMMDD-NN-<slug>`）とは区別する。両者は別の値であり、相互参照が保持するのは full slug の方である。

**採番衝突時の解消手順**: 同日に既存の ADR がある場合（並行して起票する場合を含む）は、対象日のファイルを配置ディレクトリから列挙し、既存ファイルの連番部から最大番号を特定して、最大番号 + 1 を2桁ゼロ埋めで発番する。

## Consequences

**得られる利益**:

- ファイル名の辞書順整列だけで起票順が再現される。index のような生成物に限らず、GitHub のファイル一覧・`ls`・エディタのファイルツリーという素の一覧でも同じ順序が得られる。
- 同一の起票日に対してファイル名の形が1つに定まる。参照側・照合側が連番あり／なしの2形式を解釈し分ける必要がなくなり、識別子を機械処理する箇所の分岐が消える。

**受容したトレードオフ**:

- 本 ADR の承認時点では、`docs/adr/` 配下の既存 ADR のファイル名が旧形式のまま残るため、新形式と旧形式が corpus 内で混在する過渡状態を受容する。この窓で起票される新規 ADR は新形式になるため、放置すると混在は増える。

**将来の留保事項（本 ADR のスコープ外＝ downstream）**:

- 既存 ADR の遡及リネームと、それに伴う full slug 参照・識別子形式参照・H1 見出しの書き替えは #567 に委ねる。上記の過渡状態はその完了により解消する。
