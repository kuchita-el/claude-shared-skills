# ADR-202608280911-01: ADR 化要否判定の品質は条文の質だけで支え、判定を機械実行する検証装置を持たない

## Context

ADR 化要否の判定は、判定手続きを述べる運用文書だけでなく、判定を機械実行して結果を検証する装置一式を伴って運用されてきた。装置は固定題材集合とその期待値、判定結果を受け取る直列化契約、点数の閾値を持つ設定ファイル、題材ごとの走行記録を残す開発専用台帳、およびそれらを走らせる実行支援スクリプトとテストからなる。

2026-08-27 時点の棚卸しで、この装置一式が約 6,400 行を占め、ADR corpus の不変条件を守る中核機構（drift-lint・有効性 index 生成・識別子発番・commit 前ゲートとそれらのテスト、約 1,840 行）の約 3.5 倍に達していることが分かった。装置は配布プラグインのどのスキルからも commit ゲートからも呼ばれず、判定手続き文書を改訂する担い手が手で起動する開発支援ツールであり、配布物として利用者へ届く価値の本体ではない。

装置を持ち続けるか手放すかは、判定のぶれをどう抑えるかという品質の担保手段の選択であり、判定手続きの中身（何項目で何を数え、境界を何点に置くか）とは別の問いである。後者の実体は ADR-202608011651-01 決定2 により運用文書へ委ねられており、本 ADR の対象ではない。前者を決めた記録は corpus に存在しない。

## Decision

**ADR 化要否判定の品質は、判定手続きを述べる条文の質だけで支える。判定を機械実行し、その結果を固定題材集合の期待値と突き合わせて検証する装置を、リポジトリに持たない。**

- 判定は、条文を読む判定主体が散文で結論と根拠を返す形のみを採る。判定結果を機械可読な形式で直列化する契約を置かない
- 判定手続きの改訂に対する退行検出を、固定題材集合と期待値の突き合わせによって行わない
- 判定に用いる閾値・値域の定義は、判定手続きを述べる条文が単独で保持する。条文の外にある設定ファイルや契約仕様へ外出ししない

**射程の限定**: 本決定が対象とするのは ADR 化要否の判定の品質担保手段である。ADR corpus の不変条件を守る機構（front-matter スキーマ・index 同期・相互参照の双方向性・参照先の生存性・ファイル名規約の各検査と、それを commit 時に走らせるゲート）の要否は本決定の対象外であり、いずれも維持する。判定手続きが何項目で構成され境界が何点であるかも、ADR-202608011651-01 決定2 のとおり運用文書の側の事項であって本決定の対象ではない。

**再導入の条件**: 判定のぶれが実害として再観測された場合、その時点の実障害を根拠に必要最小の検証を設計し直す。旧装置の復活を既定の選択肢にしない。

## Consequences

**得られた利益**:

- 配布プラグインの規模が、配布価値の本体である機構の側へ寄る。利用者へ届かない開発支援装置が配布物と開発資産の双方から外れる
- 判定手続きの条文を改訂するたびに、固定題材集合の再導出・期待値の更新・走行記録の追記という付随作業が発生しなくなる
- 判定の実体が条文 1 本に集約され、判定主体が条文だけを読んで判定を完了できるようになる。装置が持っていた値域定義を読むために別ファイルを辿る必要がなくなる

**却下した代替案**:

| 却下した案 | 却下理由 |
|---|---|
| 装置の廃止にあわせて点数化そのものを撤去し、判定を定性判断へ転換する | 判定の枠組み（項目数・閾値・合計点）の変更は、装置を持つか否かとは独立の決定であり、一体で反転しない。同じ ADR へ束ねれば、片方だけを反転したいときに全体の退役と後継への救出を要求する。枠組みの改訂は運用文書の側で別途行えば足りる |
| 装置を削除せず、実行を止めて凍結資産として残す | 動かさない検査資産は、参照台帳・期待テスト一覧・配布物移植性検査といった既存の常設ゲートへの追随義務だけを残し、検証の便益を生まない。復元の必要が生じた場合は git 履歴から取り出せる |
| 装置の削除を先行させ、判定の実体を条文へ取り込む作業は後続の工程へ回す | 条文は判定の実体を装置側のファイルへ外出ししているため、装置を先に消すと条文が指示先を失う期間が生じる。その期間に判定を求められた主体は、値域も閾値も参照できない条文だけを渡されることになる |
| 判定のぶれを抑える代替として、条文の改訂時に再導出の要らない軽量な検査を新設する | 廃止と同時に別の検査機構を立てれば、廃止の根拠（配布価値の本体でない装置を持たないこと）が新設分へそのまま跳ね返る。ぶれが実害として観測されてから、その実障害を根拠に設計する順序を採る |

**受容したコスト**:

- 判定手続きの条文を改訂したとき、改訂が過去の判定結果を変えてしまう退行を機械的に検出する手段が無くなる。改訂の影響は条文を読んで評価するほかない
- 判定者間で結論が割れたかどうかを、独立試行の突き合わせによって観測する経路が無くなる。ぶれは実害として現れるまで可視化されない
- 判定の実体を条文が単独で保持するため、条文は判定手続きだけでなく値域の定義も抱える。単一ファイルの分量は増える
