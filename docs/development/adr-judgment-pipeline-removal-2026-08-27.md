## §1: 本簡素化の設計判断に対する ADR 化要否の判定（AC7）

### 判定対象の決定

ADR 化要否の判定を機械実行する一式（固定題材集合の実行支援スクリプト・その期待値と fixtures・判定結果の直列化契約・点数の閾値設定・開発専用台帳・退行検出のテスト）を、配布価値の本体でないと見て削除し、判定の実体（閾値の数値と値域の定義）を存続する条文 `adr-scoping.md` へ内製化する。

### 必要条件: 却下代替が在ること

**成立**。採らなかった選択肢とその却下理由が、対として特定できる。

| 採らなかった選択肢 | 却下理由 | 出所 |
|---|---|---|
| 点数化ごと撤去し、判定を定性判断へ転換する | 判定の枠組み（4 項目・閾値・合計点）の変更は本簡素化の射程を超える。装置を持つか否かとは独立に反転する決定である | 設計 spec 節1「存続対象」（`docs/superpowers/specs/2026-08-27-adr-plugin-simplification-design.md`）が「4項目・閾値・合計点という判定の枠組み自体は現状維持とし、点数化の撤去は行わない」と明記 |
| 参照除去を後続工程（スキル再設計）まで遅らせ、削除だけを先に行う | 条文が判定の実体を削除対象へ外出ししているため、条文が指示先を失う期間が生じる | 同 spec 節2 が「PR2 まで参照除去を遅らせる代替案を棄却した帰結としての二段作業」と記録 |
| 削除ではなく退避・縮退（凍結資産としての保存）に留める | 動かさない検査資産は常設ゲートへの追随義務だけを残し、検証の便益を生まない。復元は git 履歴で足りる | 同 spec「決定事項」1「退避・縮退ではなく削除（git履歴には残る）」 |

代替案の名指しだけでも、トレードオフの記述だけでもなく、名指しと却下理由が対になっている。成立するか迷う余地は無い。

### 粒度判定基準（4 項目）

発見型の短絡は適用しない。本件は未記録の規範の発見ではなく、意図的に下した設計判断であり、短絡の前提（保持先が実装・テスト資産・操作手順であり、違反が現に検出・阻止されている）にも当たらないためである。したがって 4 項目すべてを判定した。

| 項目 | 点数 | 根拠 |
|---|---|---|
| 1. 後戻りコストが高い | **1** | 「配布済み成果物への利用者影響」に該当する。配布プラグイン `plugins/adr` から実行支援スクリプト 1 本とスキル参照ファイル 2 本が消え、版が `0.5.0` → `0.6.0` へ上がる。利用者から見れば提供物の削除である。あわせて反転時に直す追跡下ファイル（追加だけでは矛盾が解けないもの）も、条文 `adr-scoping.md`・スキル定義 `SKILL.md`・2 つの plugin manifest で閾値 3 件に達する |
| 2. 複数の適用先に波及する | **0** | 本決定の規範（判定を機械実行する装置を持たない）が適用される最小単位を、判定を実行する `manage-adr` スキル 1 単位と読むか、装置が跨っていた実行可能単位・成果物種別 4 単位と読むかで結論が割れる。項目単位の同点処理に従い 0 点へ倒した |
| 3. 採用理由が時間経過で揮発しやすい | **1** | 保持先が値域内に無い。(A) 本決定を強制する実装・テスト資産・操作手順は、装置の削除後に存在しない。(B) 条文 `adr-scoping.md` は `references/` 配下の共有規約ファイルとして値域に入るが、本決定の採用理由は同ファイル本文に書かれず（規範本文の責務は何が正しいかを述べることであり、廃止の経緯は書かない）、契約仕様の「(B)でも採用理由がなければ対象外」に当たる。保持先が無いため条件 1〜3 を評価し、条件1（却下理由が採用理由とは別に必要である）に該当した。採用理由（配布価値の本体でないこと・規模比 3.5 倍）からは、なぜ点数化ごと撤去しなかったか・なぜ後続工程へ遅らせなかったかは導けない |
| 4. ツールで自動強制できない | **1** | 阻止の状態は `検査なし`。本決定への違反（判定を機械実行する装置の再導入、判定の実体の条文外への再外出し）を検出・阻止する検査はリポジトリに無い。削除対象の bats が持っていた「条文が契約仕様と閾値設定を名指していること」を要求するアサーションは旧規範の側を強制するものであり、本決定の規範を守らない。Issue #783 の制約により代替ガードも新設しない |

**合計 3 点**（閾値: スコア境界 3 点以上で ADR 化を推奨）。

### 結論

**ADR 化する。行き先は新規 ADR。**

行き先の振り分けは、既存 ADR が扱っていない枠組みを立てるかどうかで決めた。

- `ADR-202608011651-01`（`validity: 有効`）決定2 は、粒度判定基準の項目名とスコア境界を ADR の決定内容から外し、実体を運用文書へ委ねている。したがって「閾値と値域の定義を条文へ内製化する」側は同 ADR の枠組みの中の事項であり、運用文書の改訂として行えば足りる（同 ADR :50「項目の追加・削除・改名、および境界の点数の変更は、運用文書の改訂として行い、本 ADR の反転を要さない」）。この面は新規 ADR の決定内容に含めない
- 一方「判定の品質担保を機械検査に置かず、条文の質だけで支える」側は、判定手続きの中身ではなく品質担保手段の選択であり、これを決めた記録は corpus に存在しない。`ADR-202607230648-01` も抽出時点の配置対象を定めたもので、抽出後に何を持ち続けるかは扱っていない。既存 ADR が扱っていない枠組みにあたるため、新規 ADR の側へ振り分けた

束ねの制約に照らし、新規 ADR の core は「判定の品質担保を機械検査に置かない」1 つに絞った。閾値の内製化はこれと独立に反転しうるうえ、上記のとおり ADR の決定内容に含めない事項であるため、束ねていない。
