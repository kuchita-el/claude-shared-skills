# コーディングエージェント向けプラグインの共通設計原則

## 用語

- プラグインは、コーディングエージェントへ能力を追加する配布単位である。
- skillは、目的、手順、入出力、停止条件、許可ツールを定めた能力の契約である。
- agentは、独立した文脈と役割で委譲された作業を実行する主体である。
- hookは、ホスト上のイベントを契機に自動実行される接続点である。
- scriptは、決定的な処理や検査を実行するプログラムである。
- referenceは、skillなどが必要時に読む補助規範または仕様である。
- manifestは、プラグインの名前、版、能力、接続面を機械可読に宣言するファイルである。
- hostは、Claude CodeやCodexなど、プラグインを動かす実行環境である。
- adapterは、共通の意味をhost固有のツール、権限、呼び出し方法へ接続する層である。
- MCP/app adapterは、外部サービスやアプリケーションとの接続をhost上で実現するadapterである。
- workflowは、複数の能力を順序や分岐で結ぶ作業経路である。
- profileは、独立能力を既定の経路として組み合わせた推奨設定である。
- inquiryは、根の問いへ答えるために、複数の問いを統治する調査単位である。
- pivotは、結論によってほかの問いを決めうる中核の問いである。
- 枝刈りは、pivotの結論により、別の問いを直接解かず明示的に決着させることである。
- dogfoodは、配布物を作者自身の実作業へ適用して効果と副作用を観測することである。
- contextは、エージェントが判断時に参照できる入力情報の集合である。
- degradedは、本来の機構を使えず、明示した制限付きの代替経路で動く状態である。
- 正本は、同じ意味を管理する権威ある情報源である。
- 未決は、調査の問いがまだ決着しておらず、完了を阻む状態である。
- SoTはSingle Source of Truthの略で、同じ意味を管理する単一の正本を指す。
- ADRはArchitecture Decision Recordの略で、設計判断と却下代替を残す記録である。
- ACはAcceptance Criteriaの略で、成果を受け入れられるかを判定する条件である。
- lintは、定めた形式や規則への違反を機械的に検出する検査である。

## 根拠採用基準

根拠の権威性は、主張の種類と資料の射程を組み合わせて判定する。
上位の資料であっても、明示された射程外の主張には使わない。

| 優先 | 権威性 | 採用方法 |
|---|---|---|
| 1 | 現行の規範・正本 | 現在の規則や用語の定義に使う。単一出典の宣言と射程を優先する |
| 2 | `承認済み` かつ `有効` な ADR | 決定の骨子、却下代替、射程の根拠に使う。可変な現行手順の代用にはしない |
| 3 | 実行可能契約・機械可読宣言・実装 | 現在の挙動、権限、停止条件、host 差分の観測に使う。規範の存在は推定しない |
| 4 | Issue と実装計画 | 要求、仮説、調査範囲の出典に使う。既存挙動の証明には使わない |
| 5 | 時点固定の設計・観測記録 | 既存事例、測定、調査手法の参考に使う。現在の規範へ自動昇格させない |
| 6 | `上書き済み` または廃止済みの ADR | 歴史的経緯だけに使う。現行規範は有効な後継または運用上の正本で確認する |

同じ主張が競合する場合は、現行の正本を優先する。
ADR は自身が保持する決定の骨子に限って優先し、運用詳細は現在の実行可能契約で確認する。
観測記録には観測時点と限界を残す。根拠から導けない一般化は、仮説または仮対応と明記する。
