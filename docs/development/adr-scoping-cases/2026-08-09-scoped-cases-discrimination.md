# 4題材の追加・改訂が狙った条項へ効いているかの判別

## 結論

CASE-30・CASE-32・CASE-09・CASE-11について、題材の修正後に独立した判定を各2試行記録した。数値の期待帰結は8試行すべて一致した。CASE-30は項目3の条件2を経由して0点、CASE-32は項目4の阻止により0点、CASE-09/11は条件3の第1連言が不成立となり項目3が0点になった。

CASE-30の修正前1試行は、正本の必要条件（却下した選択肢と却下理由の対）が題材文に無かったため不成立となった。この試行は有効な2試行へ混ぜず、[raw-returns.md](runs/2026-08-09-raw-returns.md) の該当節に破棄理由を残した。CASE-11/32にも必要条件修正前の試行があり、同じ扱いとした。

## 読んだ根拠

一次資料は [2026-08-09-raw-returns.md](runs/2026-08-09-raw-returns.md) であり、judgments.tsvの根拠列は索引としてのみ使った。

- CASE-30: raw-returns.md:74–91。両試行が共有規約ファイルを値域(B)として扱ったため、期待した「段2・条件2のみ」の観測にはならなかった。項目3は0点で一致したが、狙った条件2の到達は観測できない。これは題材の採用理由が共有規約ファイル本文にあることによる。
- CASE-32: raw-returns.md:164–179および修正後trial 1の該当節。両試行が「違反を検出しコミットを阻止する」を項目4の0点根拠に挙げ、値域(A)による項目3の短絡も説明した。期待帰結と一致した。
- CASE-09/11: raw-returns.md:16–33、raw-returns.md:128–161。両題材とも、項目3の第1連言について、題材文が名指しした共有規約ファイル1つでは規範が分かれざるを得ないとは言えないと述べた。題材文に無い保持先を補っていない。期待帰結と一致した。
- 全8試行: judgments.tsvの根拠_項目2列を確認し、決定を知らない作業者の人数・選択箇所を項目2の点数根拠にしていないことを確認した。題材文の適用単位を数えている。

## 期待帰結との突き合わせ

次のコマンドで、8データ行、15列、対象文書commit・題材集合commitの実値を確認した。

```bash
awk -F '\t' -v expected=8 '
  /^#/ {next} $1=="題材ID" {next} NF==0 {next}
  { n++
    if (NF != 15) { printf "列数が15でない: %s 試行%s (%d列)\n", $1, $2, NF; bad=1 }
    if ($14 !~ /^[0-9a-f]{7,40}$/) { printf "対象文書commit が短縮ハッシュでない: %s 試行%s = %s\n", $1, $2, $14; bad=1 }
    if ($15 !~ /^[0-9a-f]{7,40}$/) { printf "題材集合commit が短縮ハッシュでない: %s 試行%s = %s\n", $1, $2, $15; bad=1 }
  }
  END { printf "データ行数: %d\n", n; if (n != expected+0) { print "データ行数が期待と違う"; bad=1 }; exit bad }
' docs/development/adr-scoping-cases/runs/2026-08-09-judgments.tsv
```

差分は無かった。なおCASE-30の「段2・条件2のみ」は狙った観測にならず、CASE-32の狙いとCASE-09/11の第1連言は根拠欄に現れた。この結果は題材文の記述密度と保持先の設計に帰属する観測であり、規範側の一意性欠陥とは判定しない。

## 担保する範囲／担保しない範囲

担保する範囲は、返却全文の根拠欄に狙った条項が現れた場合、その条項へ判定が到達した正の証拠として読めることである。担保しない範囲は、(1)非言及が不使用の証拠になること（1行制限による省略と不使用を区別できない）、(2)条項を削ったときに帰結が動くかという退行検出力、(3)自己申告と内部処理の一致である。これは観察であり介入ではないため、変異実測の代替としてこれらを保証しない。

## 残る限界
