## 測定の限界

- **標本が小さい。** 題材24件・試行2回であり、κ も生の一致率も単独では読めない。項目4 のように1点率が 95.8% へ偏った項目では偶然一致率が 0.920 に達し、κ の分解能がほとんど無い。
- **担い手が1系統である。** 本実行の判定はすべて同一系統のモデルによる汎用サブエージェントが担った。したがって測れているのは同一の担い手における再現性であり、判定者間信頼性ではない。担い手を変えた試行は本実行の2試行には含めていない。
- **試行間の完全一致は「判定手続きが一意である」ことを意味しない。** 項目1〜4 の一致が完全であっても、それは同一の担い手が同一の入力に対して同じ読みを再現したことを示すにすぎない。CASE-18 は修正前に両試行が一致していたが、題材文から結論の言い換えを落とすと割れた。一致は、題材文が結論を先に与えていないことを前提にして初めて意味を持つ。
- **記録の大半が人手の再符号化であり、独立に追検証できない。** 数値4列（項目1〜4）以外の列——根拠4列（9〜12列目）・行き先列・参照ファイル一覧列——は、判定側の散文の返却を記録者が圧縮・写像した派生物である。根拠列は初回の通し・1巡目では24題材すべてで試行1 と試行2 が byte 単位で同一になっており、これは自由文の返却が2回の独立実行で完全一致した結果ではなく、符号化の産物と読むのが自然である。符号化者は試行1 の値と期待値を知った状態で試行2 を符号化しうるため、この経路は返却全文が残っていない限り閉じない。**再実行3巡目の42行のみ `runs/2026-07-29-raw-returns.md` に返却全文を保持しており、符号化の妥当性を原文へ突き合わせて確かめられる。残る6行（CASE-01・CASE-02・CASE-17）についてはできない。**
- **参照ファイル一覧が正規化ラベルである。** 13列目は実パスではなく「プロンプトファイル,adr-scoping.md」という2語のラベルへ畳んでいる（再実行3巡目の42行は自動注入分を追記している）。記録だけからは第三者が実パスを追検証できない。

## 入力の限定に関する限界

判定側は組み立て済みプロンプトファイルと対象文書のみを読む建て付けだが、**実行基盤の水準でこれが守られていない。**

再実行3巡目の42試行の多くが、参照ファイル欄でリポジトリルートの `CLAUDE.md` を挙げ、「自分で開いたのではなく実行基盤がセッション開始時に自動注入した」と申告している。ユーザースコープの `CLAUDE.md` やメモリ index を併せて挙げた試行もある。Claude Code はサブエージェント起動時にこれらを自動でコンテキストへ載せるため、判定側の操作では避けられない。したがって**試行の破棄・再実行では解消しない**（`README.md` §7.1）。

申告が現れなかった試行について、注入が無かったことを意味しない。判定側は返却形式に沿って自分が読んだと認識したものを挙げているにすぎず、注入の有無を観測する手段を持たないためである。

初回の通しと再実行1〜2巡目の記録（現在まで残る6行を含む）についても、同じ実行基盤を使っている以上、**自動注入が起きていなかったことの証拠にはならない。** 当時は返却全文を保持しておらず、申告の有無を原文で確かめる手段も無い。したがって「入力の限定は守られている」という初回時点の記述は取り下げ、上記のとおり改める。

混入した `CLAUDE.md` が判定へ効きうるかは別に評価する必要がある。本リポジトリの `CLAUDE.md` は ADR の粒度判定基準の**実体を持たず**、`manage-adr` スキルの `references/adr-scoping.md`（＝対象文書そのもの）を指すポインタに留まる。したがって判定の入力として新たな規定を与えてはいない。ただし ADR 運用の存在自体は伝わるため、行き先の分岐（既存 ADR が扱っていない枠組みか）に対する事前分布を動かした可能性は否定できない。**この可能性を排除した測定は本実行では行えていない。**
