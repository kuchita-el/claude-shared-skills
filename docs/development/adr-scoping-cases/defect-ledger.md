# 条文欠陥台帳

固定題材集合が検出した対象文書（`plugins/adr/skills/manage-adr/references/adr-scoping.md`）側の欠陥を、題材・欠陥・追跡の対応として一箇所に集める。

## 1. この台帳の責務

`expectations.tsv` の備考列は、期待値の導出が割れた原因を行ごとに記録している（README §2.3 が定める扱い）。同じ欠陥が複数の題材に跨るため、備考列だけを読んでも「いま条文に何件の欠陥が在庫として残っているか」「どれが追跡されているか」が分からない。本台帳はその在庫を持つ。

**持つもの**

- 対象文書の側に帰属する欠陥と、それを検出している題材の対応
- 各欠陥の現行本文での所在と、暫定で採った読み・反対に読んだ場合の帰結
- 追跡している Issue、または追跡が無いこと

**持たないもの**

- 題材集合の側の検出力の穴（条文は一意だが題材が当たっていない範囲）。README §11「現時点で検出力が及ばない範囲（既知の穴）」が持つ。本台帳は重複して表を持たず、§6 から参照する
- 期待値そのものと、その再導出。`expectations.tsv` が持つ
- 条文をどう直すかの判断。本台帳は在庫を示すだけであり、改訂の是非は決めない

本台帳の作成は判定の再走行を伴わない。既存の記録（`expectations.tsv` の備考列、README §11、`sources.md` §7・§8）と対象文書の現行本文を突き合わせて作る。

### B-01: 新設された必要条件が既存題材の期待値へ織り込まれていない

必要条件は粒度判定基準の前段に置かれ、不成立なら点数を数えないと定める。24題材の期待値はこの条件の新設前に導出されており、条件の成否は期待値へ織り込まれていない。題材文が必須要素 (e)（却下した選択肢・受け入れた不利益の有無とその中身）として書いている事実は、次の3群に分かれる。

| 題材文の記述 | 題材 | 件数 |
|---|---|---|
| 却下した選択肢とその却下理由を具体的に述べている | CASE-02 / 03 / 04 / 08 / 09 / 11 / 15 / 16 / 21 / 22 / 23 / 26 | 12 |
| 「却下した選択肢は無く、受け入れた不利益・犠牲も無い」 | CASE-01 / 05 / 06 / 07 / 10 / 14 / 24 / 25 / 27 / 28 / 29 | 11 |
| 「却下した選択肢があったのか…いずれも内容を知りようがない」 | CASE-12 / 13 / 17 / 18 / 19 / 20 | 6 |

上表は題材文の記述の分類であり、必要条件の成否の判定ではない。判定は独立2試行の手順に乗せて行うものであり、本台帳では行わない。ただし後2群（17題材）は必要条件が求める「却下した選択肢の名指しと却下理由の対」を題材文が持たない側であり、CASE-11は #624 でこの対を題材文へ追加したため前1群へ移した。`期待_行き先` が `ADR化する` の8題材のうち6題材（CASE-12 / 13 / 18 / 19 / 20 / 28）がこの側に入る。**期待値が現行本文と食い違っている可能性が高い。**

あわせて、返却形式は必要条件の成否を既に返しており点数フィールドも持たない。残る欠陥は、必要条件不成立時の2行形式を `cmd_crosscheck` と期待値層が受け取っていない点である。

#### B-01 の PR2 判定

題材文の必須要素 (e) を再導出し、成立11件・不成立18件とした。必要条件は却下選択肢の名指しと却下理由の対で判定し、受け入れた不利益や採用理由の有無を追加要件にはしない。不成立行は点数を不問化し、`adr-scoping.md` の一般則に従う3分岐を期待値へ記録した。`ADR化する` は CASE-04 / CASE-26 の2件へ縮退し、CASE-04 ↔ CASE-12 と CASE-09 ↔ CASE-11 は必要条件の成否を跨いだため、対の測定喪失を README §11 へ記録した。縮退は受け入れ、題材の追加・改訂を #747 として追跡する。

**追記（2026-08-25、#761 第2ラウンドによる）**: 不成立行の点数の一括不問化は、対の測定喪失に加えて**項目1 の陽性側（1）と項目2 の陰性側（0）の測定点も退役させた**。当時これらの極性を担っていた題材が本判定で不成立側へ移り、点数欄が全 `-` となったためである。この極性の回復も #747 が追跡する（既存の CASE-04 ↔ CASE-12 の対の回復に並置する射程として #747 本文へ追加した）。退役した題材の名と現在の測定点の計数は README §11 の項目1 行・項目2 行が持ち、本台帳では重複して持たない。

## 8. 台帳の更新手順
