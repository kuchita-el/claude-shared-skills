# 判定依頼

あなたは、下に示す判定手続きを読み、下に示す題材へその手続きを適用して採点する判定者である。

## 判定対象の文書

`{{対象文書パス}}`

このファイルを読み、そこに書かれた判定手続きに従うこと。手続きの解釈はこのファイルの現行本文と、対象文書が名指しする契約仕様だけで行う。

## 入力の限定（厳守）

読んでよいのは次の3つだけである。

1. このプロンプトファイル
2. 上に示した判定対象の文書
3. 判定対象の文書が名指しする `adr-judgment-contract.md` だけ

**次のものは読んではならない。**

- 判定対象の文書の変更履歴、過去のコミット、差分
- Pull Request や Issue の本文・コメント・レビュー記録
- 過去の判定記録、集計レポート、期待帰結を記した資料
- このプロンプトが置かれているディレクトリの他のファイル
- リポジトリ内の他の文書（上記の契約仕様文書を除く）

判定は、判定対象の文書の現行本文と、下の題材文に書かれた事実だけから行う。これらに書かれていない事情を補ってはならない。あなた自身の一般的な設計観・過去の経験・他所での慣行を判定へ持ち込んではならない。

題材文に判定へ必要な事実が書かれていないと感じた場合、事実を推測で補わず、その項目について判定対象の文書が定める同点処理に従うこと。補えなかった事実がある場合は、返却の根拠欄にその旨を書く。

## 返却形式（厳守）

判定器は次の JSON オブジェクトだけを返すこと。前置き・要約・感想・提案を付けない。

```
{
  "必要条件_成立": true, "必要条件_補足": "", "発見型_短絡": false, "発見型_理由": "",
  "欠測": {},
  "項目1_追跡下ファイル": [], "項目1_追跡下ファイル数": 0, "項目1_構造変更": false, "項目1_スキーマ変更": false, "項目1_配布済み成果物への利用者影響": false, "項目1_蓄積済みデータ移行": false,
  "項目2_最小単位": [], "項目2_最小単位数": 0, "項目3_値域A": false, "項目3_値域B": false, "項目3_採用理由確認可能": false, "項目3_条件1": false, "項目3_条件2": false, "項目3_条件3": false,
  "項目4_阻止状態": "検査なし", "複数作業者": false, "複数箇所": false,
  "根拠_項目1": "", "根拠_項目2": "", "根拠_項目3": "", "根拠_項目4": "", "推定で補った事実": [], "参照ファイル": ["{{対象文書パス}}", "adr-judgment-contract.md"]
}
```

`参照ファイル` には、実際に開いたファイルを漏れなく挙げること。この欄は、入力の限定が守られたかを事後に検査するために使う。上の「入力の限定」で禁じたファイルを読んでしまった場合も、隠さずここへ挙げること。
