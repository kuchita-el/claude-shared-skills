# CASE-31 項目4境界題材の判別記録

## 結論

CASE-31は `期待_必要条件=成立` かつ `期待_項目4=0` の測定行として成立した。2試行とも `必要条件_成立=true`、`発見型_短絡=false`、`項目4_阻止状態=現に阻止` であり、`derive` は項目4=0を返した。短絡を経ずに通常の4項目判定へ入ったことも、両試行の場の値で確認できる。

## 一次資料との突き合わせ

一次資料は `runs/2026-08-16-case31-raw-returns.md` と `runs/2026-08-16-case31-returns/CASE-31-{1,2}.json` である。

| 試行 | 必要条件 | 短絡 | 項目4阻止 | 値域A | 値域B | 理由確認 | 根拠の要旨 |
|---:|---|---|---|---|---|---|---|
| 1 | true | false | 現に阻止 | false | true | true | 共有規約ファイル本文に規範と採用理由があり、受け入れ側設定が違反コミットを拒否する |
| 2 | true | false | 現に阻止 | true | true | true | リポジトリ外側の受け入れ側設定を規範を強制する資産として値域Aへ数えたが、規範と理由は共有規約ファイル本文にある |

場の値と根拠原文は、必要条件・阻止状態について両試行で一致している。項目3は試行間で保持先の読みが割れた。試行1は、題材文が値域Aの資産種別を個別に否定し、阻止の担い手をリポジトリ外側に置いた構成を値域A=falseと読んだ。試行2は、値域Aの列挙が所在を限定しないため受け入れ側設定を値域Aへ含めた。D5が承知した残余リスクが現れたものである。`derive` は値域A=trueでも項目3を0へ導出し、両試行の測定行は成立した。

## CASE-01との対比

CASE-01の旧来の項目4=0は、必要条件不成立により項目1〜4が不問化され、現在は測定対象ではない。CASE-01は保持先が実装・テスト資産・操作手順で短絡側へ読まれうる題材であり、CASE-31は共有規約ファイル本文に規範と理由を置き、阻止の担い手を受け入れ側設定として分離した題材である。

## 担保する範囲

- 現行対象文書の項目4が「現に阻止」を0点側として導出する測定行を得た。
- 同一入力2試行で、必要条件・短絡・阻止状態・導出結果を固定した。
- 期待帰結との差は無く、crosscheckは照合件数2・スキップ件数0だった。

## 担保しない範囲と限界

非言及が不使用の証拠になること、条項を削った際に帰結が動くこと、他の担い手や文脈で同じ読みになることは担保しない。標本は2試行、担い手は1系統であり、実行基盤による `CLAUDE.md` の自動注入も既知の限界として残る。`derive` は `発見型_短絡` を読まないため、短絡の有無は点数へ効かない。

1点率・偶然一致率の更新はフル再実行を要するため、本PRでは行わない。
