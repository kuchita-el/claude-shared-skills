# 相互参照の規約の ADR 化要否判定（2026-08-06）

`plugins/adr/skills/manage-adr/references/cross-references.md` として成文化した内容が ADR 級かを、`plugins/adr/skills/manage-adr/references/adr-scoping.md` の手続きに沿って判定した記録。#561 AC7 の証跡である。

## 判定対象

`Related:` の書式規約（判定単位・書式不問・full slug 完全一致・複数列挙の非検査・散文中識別子の非対象・同一 stem の dedup）と、機械検査の範囲（source 限定・違反種別・双方向非強制・fail-open・是正手段）。

## 手続きの適用

### 類型の同定: 発見型

本件は「既に運用されているが、どの ADR にも記録されていない規範を発見した」類型に当たる。規約の実体は `lint-adr.sh` のレイヤ4 実装として既に稼働しており、本 PR はそれを人が読める規約として書き起こしたものである。

`adr-scoping.md`「発見型: 未記録の規範を見つけたとき」に従い、判定へ入る前に**保持先**を同定する。

- **保持先**: 実装・テスト資産・操作手順（`plugins/adr/scripts/lint-adr.sh` のレイヤ4 検査、`scripts/fixtures/lint-adr/` の fixture、`scripts/tests/lint-adr-layers.bats` の回帰、および同梱の PreToolUse commit ゲート）
- **違反が現に検出・阻止されているか**: されている。`Related:` の参照先退役・dangling は lint が違反として報告し（exit 1）、commit ゲートが `git commit` を exit 2 でブロックする

### 発見型短絡の適用

保持先が実装・テスト資産・操作手順であり、かつ違反が当該資産によって現に検出・阻止されている。したがって `adr-scoping.md` の規定どおり、**項目3（採用理由が時間経過で揮発しやすい）と項目4（ツールで自動強制できない）はいずれも該当しない**。強制をツールが担っており、採用理由の保持先も当該資産だからである。

この時点で残る項目1（後戻りコストが高い）と項目2（複数の適用先に波及する）の合計は最大2点であり、ADR 化の境界である3点へ届かない。よって**両項目を評価するまでもなく判定は確定する**。

### 必要条件（却下代替が在ること）について

発見型短絡が先に結論を確定させるため、必要条件の成否は判定を左右しない。参考として付言すると、本件の規約は検査器の実装挙動を書き起こしたものであり、採らなかった選択肢とその却下理由の対を持たない（書式不問・先頭 stem のみといった仕様は、誤検出回避という理由付けは持つが、却下した代替案の名指しを伴わない）。必要条件の側から見ても成立しない。

## 結論

**ADR 化しない。**

該当点数: 発見型短絡により項目3・項目4 は非該当。残り最大2点で境界（3点）未達のため、項目1・項目2 は評価を要さない。

## 行き先

`adr-scoping.md`「ADR 化しない（2点以下）の行き先」の第1分岐（ツールで自動強制される規範 → 実装・テスト資産・操作手順に置く）に当たる。

本 PR での置き場所は `plugins/adr/skills/manage-adr/references/cross-references.md`（`manage-adr` スキルの操作手順の一部）であり、同分岐と整合する。採用理由と既知の限界は当該ファイルへ併記して自己完結させた（複数列挙の2件目以降が検査されないこと、双方向を強制しない理由、fail-open の範囲）。
