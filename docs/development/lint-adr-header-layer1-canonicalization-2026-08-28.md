## 3. 再混入ガード（面⑦）

### 3.1 設計

**ブロックの切り出しは行番号によらない。** レイヤ宣言行（`# レイヤ1` の宣言行から `# レイヤ2` の宣言行の直前まで）で範囲を決める。行番号で固定すると、ヘッダへ1行足すだけで検査が別の範囲を見る（#787 と同型）。

**表の検査は2段で持つ。** レイヤ1 ブロックには markdown 表を一切置かせない。決定2 により、当ブロックに現れうる表は値組の再定義しかないためである。加えてヘッダ全域では、状態の語彙値（`提案中` / `承認済み` / `却下` / `有効` / `上書き済み` / `廃止済み`）を含む表の行を落とす。ブロックの中だけを見る作りにすると、写しの置き場所を1つ隣へずらすだけでガードが空振りする。レイヤ2〜5 が値の語彙を含まない表を持つことは妨げない。

**fail-closed を4点持つ。** 「無いこと」を確かめる検査は、走査対象が空になった瞬間に何も照合しないまま緑になる。抽出の非空・抽出の下端（`set -euo pipefail` で閉じていること）・上端（`# レイヤ2` 宣言の存在）・ブロックの非空をそれぞれ落とす。下端を見るのは、終端の目印が変わると `sed` が一致せず本文末尾まで出し、ヘッダを見ているつもりで実装本体まで見ることになるためである（範囲が無言で広がる形の空振り）。

**正の錨を2点持つ。** ブロックが違反種別の列挙を持つこと（決定2 の「持つ」側）と、正本ポインタを持つこと（決定1 の置換先）を確かめる。抽出が別の範囲へずれた場合はここでも落ちる。

多バイト文字の照合は bash のリテラル部分文字列操作だけで行い、awk の文字クラスを使わない（mawk はバイト単位に分解して誤判定する）。
