# ADR 化する側の2分岐を退行検出の網へ入れるか（Issue #621 調査メモ）

- 調査日: 2026-08-23
- 追跡: Issue #621
- 対象: `plugins/adr/skills/manage-adr/references/adr-scoping.md`「判定結果の行き先」節の「ADR 化する」側の2分岐（同ファイル 105・106 行）
- 位置づけ: 固定題材集合（`docs/development/adr-scoping-cases/`）の README §11 が「現状はこの分岐を射程外として扱う」と暫定的に記していた扱いを確定させる

## 対象の2分岐

対象文書は「ADR 化する」と判定した後の行き先を次の2つへ分けている（`adr-scoping.md:105-106`、原文引用）。

- 既存 ADR が扱っていない枠組みを立てる場合、または既存 ADR の結論・方向・前提を反転・置換する場合 → **新規 ADR** の側へ振り分ける
- `validity: 有効` な既存 ADR が定める枠組みの中に収まり、その枠組みを保ったまま別の面（適用範囲・条件・パラメータ値・理由付け）を追加するだけの場合 → 当該 ADR への**非core 改訂**の側へ振り分ける

分岐の入力は「既存 ADR が当該の枠組みを扱っているか」であり、これは当該決定単体の属性ではなく、当該決定と既存 ADR 群との**関係**である。

## 結論

**測らない。** この2分岐を固定題材集合の退行検出の網へ入れない。射程外であることを確定した扱いとして README §11 に記録する。案A（必須要素への追加）・案B（既存 ADR の一覧を追加入力）・案D（下流の判定を別の被テスト対象として立てる）はいずれも採らない。

骨子は4点。

1. **現行の測定機構では、行き先を判定器が返さない。** 返却契約は「ペイロードは点数・合計・行き先を持たない」と定め（`adr-judgment-contract.md`「直列化形式」）、README §5 手順4 も「点数・合計・行き先は判定器に申告させず、`derive` が閾値設定から導出する」と定める。`derive` の成立側は `dest="ADR化する"` の単一値で下位分岐を持たない（`adr-scoping-cases.sh` の `cmd_derive`）。したがって題材文の必須要素へ (k) を足す案A を採っても、返却契約と `derive` を同時に作り替えるまでは帰結が1件も動かない（問い1・問い3）。
2. 案B は判定側の入力を増やすため、README §5・§7 と `prompt-template.md` の二重の入力制限を同時に改訂したうえ、時点によって変わる入力を持ち込むことになり、§6 が測ると宣言している「同一入力に対する再現性」という測定の性格そのものを壊す（問い2）。
3. 案A は §2.2 の契約とは両立しうるが、分岐の述語（枠組みの中に収まるか）の一意性を**対象文書の側が保証していない**（`edit-decision.md:32` が機械検査の不在を既知の限界として明記している）。一意でない述語に期待値を置いても、割れは規範側の欠陥として台帳へ積まれるだけで退行検出の網にならない（問い3）。
4. **実害の大きさは誤りの型で分かれる。** `adr-scoping.md:105` の第2選言型（既存 ADR の結論・方向・前提を反転・置換する決定を非core 改訂の側へ振る誤り）は、下流の必須の人間ゲートが同一の述語を問い直すため吸収される。第1選言型（既存 ADR が扱っていない枠組みを立てる決定を、枠内に収まると読んで非core 改訂の側へ振る誤り）に対応する問いは下流に無く、ゲートを素通りする。したがって「実害は小さい」は2分岐の全体には言えず、第2選言型に限る（問い5）。第1選言型を含めても結論が動かないのは、骨子1〜3 が pivot と独立に立つためである。

### 枝刈りの記録

問いは pivot（問い5）から当たった。問い5 が第2選言型について「実害は小さい」を返し、かつ問い1・問い3 の途上で「現行機構では行き先を判定器が返さない」ことが分かった時点で、**どの経路を採るかの比較は決している**。それでも問い1〜3 を「前提消滅」とせず解いたのは、AC2 が却下した選択肢の理由の記録を求めるためであり、案A・案B を却下する理由が立つ深さまでは答えを出す必要があったからである。

一方、**深さは打ち切った**。案A の新記号 (k) の具体的な文言、案B のスクリプト改修の設計、案D の題材集合の設計には降りていない。これは省略ではなく、採否の決定に不要な深さとして意図的に止めた範囲である。

**採る側へ翻す場合の再開点は題材文の書き方ではない。** 骨子1 のとおり、行き先は判定器の返却に含まれず `derive` が導出する。再開はまず「返却契約と `derive` に行き先の下位分岐を持たせるか」から始まり、それが動かない限り題材を足しても帰結は1件も動かない。

## 問い5: 分岐を誤ったときの実害（pivot）

### 答え

**誤りの型で分かれる。** 第2選言型（結論・方向・前提の反転・置換）の誤りは、単独で不可逆な結果へ到達する経路が無く実害が小さい。第1選言型（既存 ADR が扱っていない枠組みの新設）の誤りは、下流の人間ゲートに対応する問いが無いため素通りする。「実害は小さい」は前者に限る。

### 根拠1: 2分岐は「提示」であり確定ではない

対象文書自身がそう宣言している（`adr-scoping.md:108`）。

> いずれも振り分け先の提示であって、分類（core／非core／些末）の確定ではない。分類基準の実体、確定の手続き（利用者へ問うこと）、安全則（迷えば core 寄り＝新規 ADR に倒す）、および選んだ操作の手順と変更履歴の残し方は、すべて `edit-decision.md` に従う。

スキル本体も同じ経路を記している（`SKILL.md:79`）。

> 要否の判定は起票操作の前段であり、ADR 化すると判断した場合のみ起票（5遷移）へ進む。ただしその行き先は新規 ADR とは限らず、既存 ADR への非core 改訂の側もある（分類の確定は粒度判定ではなく前掲の編集判定フローに従う）。

つまり2分岐は、点数がそのまま帰結を決める4項目とは性格が違う。4項目はスコア境界という機械的な閾値へ入力され、点数が ADR 化の可否を決める。2分岐は何も確定しない。

### 根拠2: 第2選言型の誤りは下流の必須ゲートが同一述語で再導出する

**本根拠の射程は `adr-scoping.md:105` の第2選言（既存 ADR の結論・方向・前提を反転・置換する場合）に限る。** 同じ行の第1選言（既存 ADR が扱っていない枠組みを立てる場合）は根拠2b で別に評価する。

重い方向とは「本来は新規 ADR（core）であるべき決定を、非core 改訂の側へ振り分けてしまう」誤りである。対象文書自身が可逆性の非対称を認めている（`edit-decision.md:34`）。

> core を非core と誤判定すると、再承認イベントを飛ばして core 変更を権威記録に焼き込む不可逆な不整合が残る。逆に非core を core と誤って新規 ADR にしても過剰なだけで可逆（後で統合できる）。

ところがこの重い方向へ振り分けた場合、処理は `edit-decision.md` の判定フローへ入る。そこには次の3つが揃っている。

- **人間ゲートが必須**: 「分類（core／非core／些末）は**必ず利用者へ問う**。スキルが本文の変更内容から自動で core/非core を決めない」（`edit-decision.md:9`。`SKILL.md:67,73` も同じ）
- **問いの第1問が2分岐と同一の述語**: 「その編集で『決定の結論・方向・前提』が変わるか？ YES → core」（`edit-decision.md:15`）。これは `adr-scoping.md:105` の「既存 ADR の結論・方向・前提を反転・置換する場合 → 新規 ADR」と同じ述語である
- **既定が安全側**: `AskUserQuestion` の既定選択肢は core（`edit-decision.md:9`、`SKILL.md:67`）

したがって、第2選言型で重い方向を誤っても、その誤りが権威記録へ焼き込まれるには、利用者が既定の core を退けて明示的に非core を選ぶ必要がある。2分岐の出力単独では到達しない。

### 根拠2b: 第1選言型の誤りは下流ゲートを素通りする

第1選言型の誤りとは「実際にはどの既存 ADR も扱っていない枠組みを立てる決定を、既存 ADR の枠内に収まると読んで非core 改訂の側へ振り分けてしまう」ものである。この型は下流の人間ゲートで捕まらない。

- **第1問が別の対象を問うている**: `edit-decision.md:15` の「その編集で『決定の結論・方向・前提』が変わるか」は**既存 ADR の結論**について問う。扱われていない面を足すだけなら答えは NO であり、これは誤読ではなく同ファイルの基準に照らして正しい答えである。第2問へ進んで非core となり、直接編集・`validity` 不変・再承認なしで確定する
- **本来この型に対応する規定は、2分岐が誤ったときにちょうど無効化される**: `edit-decision.md:20`「先行 ADR が決めていない facet を後継が決める場合」がその規定だが、同 `:26` が「既存 ADR の枠組みの中へ別の面を追加する経路を選んだ場合は…本規定の対象外」と定めている。どちらの経路を採るかは本フローの手前＝2分岐で決まるため、2分岐が枠内と読み違えた時点でこの規定は掛からない
- **安全則は掛からない**: `adr-scoping.md:108` が指す安全則（迷えば core 寄り）と `AskUserQuestion` の既定 core は、「迷った場合」の確率的な緩和であって構造としての捕捉ではない

帰結は「本来は独立の ADR として記録されるべき決定が、既存 ADR への面の追加として埋まる」ことである。是正経路が皆無ではない——`transitions.md`「分割（多決定 ADR の部分上書き）」の衛生的分割が対応する——が、分割は**既定では行わない任意の例外**であり（`SKILL.md:54,57`）、原 ADR の退役と後継の起票を伴う。したがってこの型について「実害は小さい」とは言えない。

それでも結論（測らない）が動かないのは、測る側の案が pivot と独立の障害を持つためである。とくに案A は、現行の測定機構が行き先を判定器から受け取らない以上（骨子1）、題材文へ (k) を足しても第1選言型を捕捉しない。案D（下流の `edit-decision.md` を被テスト対象として立てる）も、第1選言型に対応する問いが下流に無い以上そのままでは捕捉せず、先に**規範の改訂**（`edit-decision.md` の側へ「既存 ADR が当該の枠組みを扱っているか」を問う段を足す）が要る。この捕捉漏れは `adr-scoping.md` を被テスト対象とする本Issueの射程外にあり、塞ぐには規範の側の改訂が要る。追跡は Issue #774 へ切り出した（#773 と同型の扱い——同じ配布物で見つかり、本Issueの射程外で、規範の改訂を要する）。

### 根拠3: 軽い方向は未承認段階で終端できる

軽い方向とは「本来は非core 改訂であるべき決定を、新規 ADR の側へ振り分けてしまう」誤りである。この経路は `edit-decision.md` の人間ゲートを通らない（`edit-decision.md:26` が「どちらの経路を採るかは本フローの手前で決まる」と述べるとおり、経路選択そのものは下流の対象外）。ただし帰結は次のとおり限定されている。

- 起票は `status: 提案中`・`validity` 空で始まり、承認は別の遷移である（`transitions.md:48,56`）
- index 生成器は front-matter の `validity: 有効` を持つ ADR だけを載せる（`gen-adr-index.sh:112`）。実測では ADR ファイル69本に対し index のエントリは49件
- 未承認のまま終端させる遷移がある。「却下（却下）— 一度も承認に至らず終了する終端」（`transitions.md:147-149`）

つまり誤って起票された ADR は、承認されるまで有効 ADR index に載らず、その間は却下で低コストに取り消せる。

**ただし承認後の是正手順は無い。** `edit-decision.md:34` は「後で統合できる」と述べるが、`統合` を語として持つ箇所を `plugins/adr/skills/manage-adr/` 配下で走査すると、当該の一文と `adr-demotion.md:98`（無関係の条件2内訳表）の2件だけであり、統合に対応する遷移手順は定義されていない。承認まで進んだ場合の是正は `adr-demotion.md` の格下げ判定を経由するほかなく、同ファイルの安全側（迷ったら残す）の下では容易には成立しない。したがって軽い方向の誤りも無害ではなく、「承認前に気づけば安い」という条件付きの評価である。

この欠陥は配布物（`edit-decision.md` の安全則が依拠する可逆性の根拠と、`transitions.md` の遷移集合との不整合）の側にあり、本Issueの射程外である。追跡は Issue #773 へ切り出した。

### 根拠4: 機械検査は分類の当否を見ない

`edit-decision.md:32` が自ら述べている。

> **既知の限界**: 結論の有無の判定はテキストの解釈に委ねられ、機械検査は存在しない。

つまり誤分岐を後段で捕まえる自動検査は無い。この事実は「だから測るべきだ」の側の論拠になりうる。第2選言型については根拠2・3 と合わせて読むと逆になり——機械検査を置かない設計判断は既に下されていて、その代わりに人間ゲートと安全則が置かれている——固定題材集合の設計を曲げてまで「提示」の当否を測る価値は無い。第1選言型については人間ゲートも掛からないため（根拠2b）、この打ち消しは働かない。それでも測らないのは、測る側の案が骨子1〜3 の障害を越えられないからであって、実害が無いからではない。

### 根拠5: 2分岐は測定網の中で孤立した末端である

2分岐は点数計算へ入力されず、点数からも影響を受けない。`expectations.tsv` の `期待_行き先` は `agreement.dest` として独立に集計される（README §9 の `--stats` キー契約）。したがってこの2行を改訂しても、項目1〜4 の測定点へは波及しない。網の穴が他の測定点を汚染する経路が無いということであり、穴を放置するコストが局所に留まる。

## 問い3: 案A は §2.2 の契約と両立するか

### 答え

**書き方を選べば両立する。ただし両立しても測定として成立しない。**

### 両立する側の根拠

§2.2 の契約は「対象文書が判定の入力として名指しする**事実**であり、対象文書が結論として述べる述語（値域を満たす／段1で確定する／条件Nに当たる／○点、およびその言い換え）は書かない」である。

行き先の分岐専用の入力事実を必須要素へ置く先例は既にある。(i)「その規範に従う作業者が単独か複数か」がそれで、§2.2 は「(i) は判定結果の行き先の分岐が入力として名指しする事実であり、これを欠くと行き先の期待値が一意に決まらない。(i) は行き先だけに効く」と述べている。構造的には案A は (i) の対称形（ADR 化しない側の行き先分岐に対する (i) の、ADR 化する側の行き先分岐に対する版）にあたる。

書き分けは可能である。

- **契約と両立する書き方**: 既存 ADR の決定内容と本決定の内容を並べて事実として述べる（「ADR-X は〜と定めており `validity` は有効である。本決定は〜である」）。判定側は両者の関係を自分で導出する
- **契約に反する書き方**: 「本決定は既存 ADR の枠組みの中に収まり、別の面を追加するだけである」。これは `adr-scoping.md:106` の分岐条件の逐語であり、結論述語の言い換えにあたる

後者を避ける規律は既に働いた実績がある。PR #616 は CASE-13・CASE-18・CASE-20 の題材文から「書くとすれば」を落としている（対象文書の条件3の判定枠組みを名指しする語であったため。README §2.4）。

### それでも成立しない理由

両立性とは別に、4つの障害がある。第1の障害は他の3つより前段にあり、単独で案A を成立させない。

1. **現行の測定機構では、行き先を判定器が返さない。** 返却契約は「ペイロードは点数・合計・行き先を持たない」と定め（`adr-judgment-contract.md`「直列化形式」）、フィールド表にも枠組み該当性に相当する欄が無い。README §5 手順4 も「点数・合計・行き先は判定器に申告させず、`derive` が閾値設定から導出する」と定める。`derive` の成立側は `dest="ADR化する"` の単一値で下位分岐を持たない（`adr-scoping-cases.sh` の `cmd_derive`）。したがって題材文へ (k) を足しても、判定器はその事実を用いた行き先を返す口を持たず、`derive` はその事実を受け取らない。**案A 単独では帰結が1件も動かない。** 案A を成立させるには、返却契約へフィールドを足し、`derive` へ下位分岐を足し、`expectations.tsv` の値域と `crosscheck` の照合を同時に改める必要がある（測定機構そのものの改訂であり、題材の追加ではない）。
2. **述語の一意性が対象文書の側で保証されていない。** 「枠組みの中に収まるか」の判定について、`edit-decision.md:32` は「結論の有無の判定はテキストの解釈に委ねられ、機械検査は存在しない」と既知の限界として明記している。README §2.3 は、題材文が (a)〜(j) を備えているのに規範本文の読みが分かれて割れる場合を「規範側の欠陥」として `defect-ledger.md` へ積む扱いと定めている。一意でない述語に期待値を置けば、割れはこの経路へ流れるだけで、退行検出の網としては機能しない。
3. **必須要素の性格が1段変わる。** (a)〜(j) はいずれも当該決定**単体**の属性である。案A の (k) だけが、他の記録済み決定の内容を題材文へ持ち込むことを要求する。題材文が架空の既存 ADR 群を抱えることになり、契約の性格が変わる。
4. **題材追加が不可避である。** 既存題材への遡及はしない扱い（#624 が定め、Issue #621 の制約も継承している）により、(k) を持つ新規題材だけが2分岐を測る。案A は「題材を足さずに塞げる案」ではない。

## 問い2: 案B が実験条件へ与える影響

### 答え

**影響は大きい。** 測定の性格そのものが変わる。

### 実測した事実

- **index だけでは分岐を決められない。** `docs/adr/index.md` は52行・49エントリで、列は「識別子（stem リンク）＋ H1 見出しの `: ` 以降」の2列のみである。エントリは結論の要約文であり、適用範囲・条件・却下代替を含まない。「既存 ADR が枠組み X を扱っているか」を判定するには ADR 本文まで読む必要がある。実際に渡すのは ADR 本文69本ということになる
- **入力制限が二重に置かれている。** README §5「判定側が読んでよいのは次の3つだけである」と `prompt-template.md:13-25`「入力の限定（厳守）… 次のものは読んではならない」が同一の3件限定と禁止5項目を持つ。両方の改訂が要る
- **事後検査の許容集合も変わる。** README §7 は「対象文書とプロンプトファイル以外のパスが挙がっていないこと」を照合する。実データでも `参照ファイル` 欄は対象文書と契約仕様の2件に留まっている（`runs/2026-08-16-case624-raw-returns.md`）。index を正当な入力にすれば、この照合基準の定義も同時に改訂が要る
- **入力が時点で変わる。** `docs/adr/index.md` は直近17コミット（2026-07-14〜2026-08-07）で変更されている。ADR が増減するたびに変わる。判定記録は「対象文書 commit」列で対象文書を固定管理しているが、index の commit を記録する列は無い

### 測定の性格への影響

README §6 は「この設計で測っているのは、同一入力に対する判定の再現性である」と宣言している。index を入力へ加えると、同じ題材でも実行時点が違えば入力が変わり、過去の走行記録との比較が成立しなくなる。列を足して index の commit も固定すれば形式上は救えるが、その場合は「対象文書の改訂で帰結が動いたのか、index の変化で動いたのか」という交絡が新たに入る。

さらに §5 が入力を絞る理由そのものと衝突する。

> これらを読めば、判定者は対象文書の現行本文が導く帰結ではなく、過去にそう判定された結果を再生できてしまい、対象文書を改訂しても帰結が動かなくなる。

ADR 群は、まさに `adr-scoping.md` の過去の判定結果の集積である。ADR 本文を読ませることは、判定側へ「この主題は過去に ADR 化された」という事実を与えることであり、§5 が塞ごうとしたリークと同型になる。

## 問い4: 測らないと決めた場合の記録先

### 題材集合側

`docs/development/adr-scoping-cases/README.md` §11 に記録する。具体的には次を行う。

- §11 の表の「ADR 化する側の2分岐が潰れている」行について、帰結欄を暫定記述から確定した扱いへ置き換え、追跡欄を「#621（決定済み）」とする
- 同じく「必要条件の織り込みで `ADR化する` 側が縮退した」行の帰結欄から、#747 が2分岐を担うという記述を外す
- 表の後段の「**ADR 化する側の2分岐が潰れている** は題材を足すだけでは塞がらない」の段落を、確定した扱いと本メモへの参照を持つ記述へ改める

### 対象文書側

**注記は不要と判定した。** 後続Issueも起票しない。理由は3つ。

1. 「この2行が固定題材集合の退行検出の網に入っていない」は**題材集合の側の属性**であって、`adr-scoping.md` の規範としての属性ではない。対象文書の読者（`manage-adr` スキルの利用者）にとって、その2行が測られているかどうかは判定の手順を変えない
2. `adr-scoping.md` は配布物（プラグイン）である。リポジトリ内部の実験装置の事情を配布物へ書くのは、プラグイン／利用者側の境界を越える
3. 記録の目的は「なぜ測っていないのかを次の担い手へ渡すこと」であり、その読者は題材集合を触る担い手である。README §11 と本メモで届く

## 統合

**測らない（案C）。** 案A は、現行の測定機構が行き先を判定器から受け取らないため、題材を足すだけでは帰結が1件も動かない（測定機構そのものの改訂が要る）。加えて §2.2 とは両立するものの、述語の一意性が対象文書側で保証されておらず測定として成立しない。案B は測定の性格そのものを変える。案D は本Issueの射程外である。実害の側は型で分かれ、第2選言型は小さいが第1選言型は下流ゲートを素通りする（根拠2b）。それでも測らないのは、測る側の案がいずれも上記の障害を越えられないためである。

## ADR 化要否の判定（AC6）

### 粒度判定基準

### 行き先

`adr-scoping.md`「ADR 化しない」の一般則のうち、「ツールでは強制できないが、複数の作業者・複数の箇所へ効かせたい規範 → 共有規約文書」に当たる。単一の変更に閉じる判断ではない（今後この題材集合を触る担い手すべてに効き続け、「なぜ測っていないのか」が再び問われる）。題材集合における当該の文書は README であり、採用理由は本メモへ併記する。

自動強制の側へ寄せる余地は現時点では無い。運用形（成立側の `期待_行き先` を単一値に留める）を語の一致で検査しても、`期待_行き先` の値域が型として定まっていない以上、検査として意味を持たないためである。値域の型付けと `crosscheck` の成立側照合の有効化は保留とし、README §11 に保留の事実を残した。
