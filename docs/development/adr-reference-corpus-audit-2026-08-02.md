# ADR corpus 全数監査: 記録の参照原則の遡及適用（#658）

## この記録の位置づけ

`ADR-202608011355-01` 決定1（記録の参照原則）が宣言する適用範囲「既存 corpus にも及ぶ」を、`docs/adr/README.md` 以外の可変文書についても満たすため、corpus 内の全 ADR を母集合として再走査し、判定テストを適用した記録である。走査結果・判定・型分類・変更種別一覧・型外事例・申し送り事項を単一のファイルへ収める。

### 本Issue限りの規範の上書き（明示）

`plugins/adr/skills/manage-adr/references/edit-decision.md` は退役 ADR を判定フローの対象外と定め、「決定内容に触れる編集は退役 ADR に加えてはならない」と明示する。本Issueは利用者承認済みの特例としてこれを外し、退役 ADR の全節（`## Decision` を含む）を是正の射程へ含める。

ただし**原則 ADR（`ADR-202608011355-01`）の適用限界の条文自体は変更しない**。射程の改訂は本Issueの OUT であり、本Issueが行うのは条文を据え置いたままの一回限りの特例適用である。

## 走査条件（再実行可能な形で記録する）

- **走査根**: `docs/adr/`（リポジトリルート起点の再帰 grep は使わない）

走査根を `docs/adr/` へ固定する理由: 作業ツリー内の `.claude/worktrees/` 配下に複数の worktree があり、いずれも `docs/adr/` の複製を持つ。これらは `.gitignore` 対象だが grep の走査対象からは外れないため、ルート起点の走査は同一箇所を多重に拾い、候補件数も後続の0件確認も偽になる。本監査の作業 worktree 自身は入れ子の `.claude/worktrees/` を持たないことを確認済み（`ls -d .claude/worktrees` が不在を返す）。

### 走査コマンド

```sh
# (A) コロン形式: path.md:478 / path.md:166-186
grep -rnE '\.(md|sh|json|ya?ml|bats|ts|js|py|txt):[0-9]+' docs/adr/

# (B) L<数字> 形式・列挙形を含む全 L 表記（除外規定の適用は目視で振り分ける）
grep -rnE '(^|[^A-Za-z0-9_])L[0-9]+' docs/adr/

# (C) 可変文書への言及一般（バッククォート付きのパス・ファイル名）
grep -oE '`[^`]*`' <ADRファイル> \
  | grep -vE '^`ADR-[0-9]{12}-[0-9]{2}' \
  | grep -E '\.(md|sh|json|ya?ml|bats|ts|js|py|txt|toml)|/' \
  | grep -vE '^`docs/adr/ADR-'
```

条件 (C) はあくまで機械的な当たりであり、判定の母集合は**各 ADR の本文全文**である。バッククォートを伴わない素のファイル名・スキル名・パスによる言及も拾うため、全 65 件を1件ずつ全文読み込んだうえで箇所を確定した。

### 「可変文書」の定義（本監査で用いた線引き）

ADR ファイル（`docs/adr/ADR-*.md`）以外の、後から書き換わりうる文書・スクリプト・ソースコード。

- 該当する: `docs/` 配下の設計文書・開発文書、`plugins/` 配下の SKILL.md・エージェント定義・`references/` 配下・スクリプト、`CLAUDE.md`、各種 `README.md`（`docs/adr/README.md`・`docs/adr/index.md` を含む）、設定ファイル
- 該当しない: ADR ファイル自身、ADR 識別子、Issue 番号、PR 番号、コミットハッシュ（いずれも不変の識別子）

## 判定テストと分類

適用した判定テストは `ADR-202608011355-01` `## Consequences`「適用有無の判定基準」が定める次の形である。

> **基準**: その記述の真偽が、参照先の現在の内容に依存して決まるかどうか。依存するなら時点固定または自己完結化を要し、依存しないなら記録として既に閉じている。
> 判定に迷う場合は、参照先を空にした状態でその記述を読み直し、偽になるなら適用対象、真のままなら対象外として振り分ける。

分類は次の四分類とする。

1. **適用対象**（＋型＋処理: 自己完結化／時点固定）
2. **対象外・AC2 書式抵触あり**（処理: `書式是正のみ`）— 判定テストは通るが行番号を伴い、除外規定にも該当しない箇所。行番号のみを落とし、内容・時制・語順・パス表記には手を入れない
3. **対象外・書式抵触なし**（＋根拠）— 是正しない
4. **除外規定該当** — AC2 の除外2種（パスを伴わない `L<数字>`、ADR を指す行番号参照）に当たる箇所

### AC2 の書式要求は適用対象判定の superset である

判定テストは「参照先を空にすると偽になるか」を問うのに対し、AC2 は「可変文書のパス表記へ隣接して行番号を伴う記述が無い」という無条件の書式要求である。したがって**判定テストでは対象外だが行番号を伴い、除外規定にも該当しない箇所**が存在する。これを分類 2「書式是正のみ」で受ける。この処理は原則本文が持つ2処理（自己完結化／時点固定）のいずれでもない第三の処理であるため、件数と対象箇所を後掲の「型外」節へも計上する。

### 規模が見積りを超えた理由

プラン作成時の見積りは「可変文書パスへ言及する ADR 51 件のうち、判定テストで適用対象へ絞られるのは 20〜30 件」という想定に立っていた。実測がこれを超えたのは、判定テストが**パス表記を伴わない現在形の内容主張**も適用対象に取るためである。原則 ADR 自身が示す判定基準（`ADR-202608011355-01` `## Consequences`）は「README が現にその規定を保持していることを現在形で主張しており、README を導線へ縮退させれば主張が偽になる」箇所を適用対象としており、この形は corpus 全域に分布する。パス言及の有無を母集合の代理指標に使った見積りが、この分布を捉えられていなかった。

なお、この読みの妥当性は次の実例で確認した。7 件の ADR の `## 変更履歴` が共有する同一文「有効 ADR が退役 ADR を `Related:` で指す状態が lint-adr レイヤ4 の違反になる」は、日付付きエントリの内部にありながら検査器の現在の挙動を現在形で主張する。原則 ADR は同種の形（日付付き `## 変更履歴` 内の現在形主張）を実際に是正対象として扱い「当時の」を補う処理を採っているため、これらは適用対象である。
