## この記録の位置づけ

### 走査コマンド

```sh
# (A) コロン形式: path.md:478 / path.md:166-186
grep -rnE '\.(md|sh|json|ya?ml|bats|ts|js|py|txt):[0-9]+' docs/adr/

# (B) L<数字> 形式・列挙形を含む全 L 表記（除外規定の適用は目視で振り分ける）
grep -rnE '(^|[^A-Za-z0-9_])L[0-9]+' docs/adr/

# (C) 可変文書への言及一般（バッククォート付きのパス・ファイル名）
grep -oE '`[^`]*`' <ADRファイル> \
  | grep -vE '^`ADR-[0-9]{12}-[0-9]{2}' \
  | grep -E '\.(md|sh|json|ya?ml|bats|ts|js|py|txt|toml)|/' \
  | grep -vE '^`docs/adr/ADR-'
```

条件 (C) はあくまで機械的な当たりであり、判定の母集合は**各 ADR の本文全文**である。バッククォートを伴わない素のファイル名・スキル名・パスによる言及も拾うため、全 65 件を1件ずつ全文読み込んだうえで箇所を確定した。

### 「可変文書」の定義（本監査で用いた線引き）

ADR ファイル（`docs/adr/ADR-*.md`）以外の、後から書き換わりうる文書・スクリプト・ソースコード。**線引きの軸は所在ではなく可変性である**。原則 ADR の条文は「後から書き換わりうる」としか述べておらず、リポジトリ内という限定を置いていない。

- 該当する（リポジトリ内）: `docs/` 配下の設計文書・開発文書、`plugins/` 配下の SKILL.md・エージェント定義・`references/` 配下・スクリプト、`CLAUDE.md`、各種 `README.md`（`docs/adr/README.md`・`docs/adr/index.md` を含む）、設定ファイル
- 該当する（リポジトリ外）: 外部プラグインのスキル定義（`superpowers` 配下の各スキル）、CLI 同梱の組み込みエージェント・workflow（`Explore`・`Plan`・`deep-research`）、Claude Code ハーネスの仕様・挙動（フックの発火条件、`Agent` tool の引数、プラグイン更新機構）、ベンダの移行ガイド等の外部文書
- 該当しない: ADR ファイル自身、ADR 識別子、Issue 番号、PR 番号、コミットハッシュ（いずれも不変の識別子）

#### 外部文書に対する処理規律（2026-08-02、利用者判断）

外部文書は射程に含めるが、**参照そのものを落とさない**。処理は「当時の記載を転記したうえで、参照リンクを併記する」形を採る。

根拠は変更ライフサイクルの差である。リポジトリ内の文書は本リポジトリの開発の中で頻繁に書き換わるため、記録が現在形で指すと短期に変質する。外部文書は変質の速度も様態も異なり、かつこちらの制御下にない。原則が塞ごうとしているのは「指し先の変化で記録の意味が変質する経路」であって、外部資料への到達可能性そのものではない。主張を時点固定または自己完結化すれば変質の経路は塞がるため、ポインタまで落とす必要はない。

したがって外部文書を指す箇所の是正後の形は次のとおり。

- 現在形の主張部分は「当時の」を補う（時点固定）か、当時の記載の実質を書き下ろす（自己完結化）
- 参照リンク・名称は参考として残す。落とすのは行番号のみ（AC2 の書式要求は外部文書にも等しく掛かる）

リポジトリ内資産にはこの併記規律を適用しない。内部資産の是正は従来どおり具体（パス・行番号・実装手段）を落とす。

## 判定テストと分類

適用した判定テストは `ADR-202608011355-01` `## Consequences`「適用有無の判定基準」が定める次の形である。

> **基準**: その記述の真偽が、参照先の現在の内容に依存して決まるかどうか。依存するなら時点固定または自己完結化を要し、依存しないなら記録として既に閉じている。
> 判定に迷う場合は、参照先を空にした状態でその記述を読み直し、偽になるなら適用対象、真のままなら対象外として振り分ける。

分類は次の四分類とする。

1. **適用対象**（＋型＋処理: 自己完結化／時点固定）
2. **対象外・AC2 書式抵触あり**（処理: `書式是正のみ`）— 判定テストは通るが行番号を伴い、除外規定にも該当しない箇所。行番号のみを落とし、内容・時制・語順・パス表記には手を入れない
3. **対象外・書式抵触なし**（＋根拠）— 是正しない
4. **除外規定該当** — AC2 の除外2種（パスを伴わない `L<数字>`、ADR を指す行番号参照）に当たる箇所

### AC2 の書式要求は適用対象判定の superset である

判定テストは「参照先を空にすると偽になるか」を問うのに対し、AC2 は「可変文書のパス表記へ隣接して行番号を伴う記述が無い」という無条件の書式要求である。したがって**判定テストでは対象外だが行番号を伴い、除外規定にも該当しない箇所**が存在する。これを分類 2「書式是正のみ」で受ける。この処理は原則本文が持つ2処理（自己完結化／時点固定）のいずれでもない第三の処理であるため、件数と対象箇所を後掲の「型外」節へも計上する。

### 規模が見積りを超えた理由

プラン作成時の見積りは「可変文書パスへ言及する ADR 51 件のうち、判定テストで適用対象へ絞られるのは 20〜30 件」という想定に立っていた。実測がこれを超えたのは、判定テストが**パス表記を伴わない現在形の内容主張**も適用対象に取るためである。原則 ADR 自身が示す判定基準（`ADR-202608011355-01` `## Consequences`）は「README が現にその規定を保持していることを現在形で主張しており、README を導線へ縮退させれば主張が偽になる」箇所を適用対象としており、この形は corpus 全域に分布する。パス言及の有無を母集合の代理指標に使った見積りが、この分布を捉えられていなかった。

なお、この読みの妥当性は次の実例で確認した。7 件の ADR の `## 変更履歴` が共有する同一文「有効 ADR が退役 ADR を `Related:` で指す状態が lint-adr レイヤ4 の違反になる」は、日付付きエントリの内部にありながら検査器の現在の挙動を現在形で主張する。原則 ADR は同種の形（日付付き `## 変更履歴` 内の現在形主張）を実際に是正対象として扱い「当時の」を補う処理を採っているため、これらは適用対象である。

### 処理の割り当てについての明確化

レビューの過程で、`自己完結化` を「参照先の内容を書き下ろす」と一律に読むと決定と衝突する例が挙がった（`ADR-202606270040-01` は `## Decision` で「規約本文を二重化しない」と定め、`ADR-202608011651-01` は「判定項目・境界を本 ADR が保持しない」と定めている）。

| 型 | 落とすもの | 書き下ろしの要否 |
|---|---|---|
| SoT 所在宣言型 | 具体パス。**決定の骨子は残す** | 不要（パスを落とすだけ） |
| 行番号名指し型 | 行番号。**指していた内容を述べる** | 要 |
| 実装挙動主張型 | 実装の手段。**事実の性質だけ残す** | 不要（手段を落とすだけ） |
| 現状主張型 | —（「当時の」を補う） | 不要 |

### R5: 否定的存在主張の決着（利用者判断）

「〜が無い」「現行未定義」「空白」「該当なし」型の記述について、原則 ADR は判定手順を二重に置いている。

- **一次基準**: その記述の真偽が、参照先の現在の内容に依存して決まるかどうか
- **タイブレーカー**: 判定に迷う場合は、参照先を空にした状態で読み直し、真のままなら対象外

否定的存在主張はこの2つで逆の結論を出す。何かが追加されれば偽になるため一次基準では適用対象だが、参照先を空にすれば「無い」は真のまま保たれるため空化手順では対象外になる。

**一次基準を採ると決着した**（2026-08-02、利用者判断）。根拠は条文の構造である。タイブレーカーは「判定に迷う場合は」と明示的に従属節へ置かれており、一次基準が答えを出す場面では発火しない。加えて同節は「本基準は本原則の禁止範囲を狭めるものではない。本原則は『可変文書を現在の参照先として指さない』を無条件に課しており、本基準はある記述がその『現在の参照先として指す』に当たるかを個別に見分ける手順にすぎない」と述べており、手順が原則の射程を削る読みを封じている。

ただし**参照先が文書でない場合はこの限りでない**。`ADR-202608011351-01` 行58「優先度が要る場面が現に生じておらず」は運用上の事象についての否定主張であり、可変文書への参照を含まない。一次基準に照らしても依存先が無いため対象外とした。

### R6: 外部文書の射程（利用者判断）

原則 ADR は「可変文書」を**後から書き換わりうる**という性質で定義しており、リポジトリ内という所在の限定を置いていない。一方で本監査が初回に用いた線引きはリポジトリ内資産の列挙であった。この差により、台帳内で外部資産への現在形主張の扱いが割れていた（`superpowers` 系スキルへの言及は無条件に適用対象、ベンダの移行ガイドと `Agent` tool の挙動は判定割れ、プラグインフックの自動マージ挙動は対象外）。

**射程へ含めると決着した**（2026-08-02、利用者判断）。原則の条文に所在による限定が無く、外部文書はこちらの制御下にない分だけ可変性が高いためである。

あわせて**処理規律を1つ加えた**。外部文書を指す箇所は、当時の記載を転記したうえで**参照リンクを併記する**。根拠は変更ライフサイクルの差である。リポジトリ内の文書は本リポジトリの開発の中で頻繁に書き換わるが、外部文書は変質の速度も様態も異なる。原則が塞ごうとしているのは「指し先の変化で記録の意味が変質する経路」であって外部資料への到達可能性そのものではなく、主張を時点固定または自己完結化すれば変質の経路は塞がる。詳細は「『可変文書』の定義」節に置いた。
