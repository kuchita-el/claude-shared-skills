# Claude モデル特性とモデル振り分け指針

スキル・サブエージェント設計時に「どのモデルにどの作業を割り当てるか」を判断するための参照ドキュメント。

- 作成日: 2026-07-22。**節ごとに最終確認の時点が違う。** 2026-09-13 に一次情報で確認し直したのは、§1 のラインナップ・価格・コンテキスト長・既定 effort・拡張思考の形式、§2 の位置付けと fast mode 対応、§3 の fast mode 全段落である。§3 の `model` / `effort` フィールドの仕様と解決順序は 2026-07-22 確認のまま据え置いているが、同節のうち「Haiku 4.5 が `effort` に対応しないこと」だけは 2026-09-13 の確認に由来する（根拠は §1 と同じ公式のモデル一覧であり、Claude Code の sub-agents ドキュメントではない）。§4 の公式 3 区分は 2026-07-22 確認のまま据え置いている。§5 も 2026-07-22 時点のまま更新していない。各節の内部にも時点の断りを置く

## 1. 現行モデルの基本情報

| モデル | モデルID | 位置付け（公式） | 価格 入力/出力（per MTok） | コンテキスト長 | 最大出力 | 既定 effort | 速度 | 信頼できる知識カットオフ |
|---|---|---|---|---|---|---|---|---|
| Claude Fable 5.1 | `claude-fable-5-1` | 要求の厳しい推論と長時間稼働のエージェント作業向け | $10 / $50 | 1M | 128K | `high` | 最も遅い | 2026年6月 |
| Claude Opus 5 | `claude-opus-5` | 複雑なエージェント型コーディングとエンタープライズ業務向け | $5 / $25 | 1M | 128K | `high` | 中程度 | 2026年5月 |
| Claude Sonnet 5 | `claude-sonnet-5` | 速度と知能の最良の組み合わせ | $2 / $10 | 1M | 128K | `high` | 速い | 2026年1月 |
| Claude Haiku 4.5 | `claude-haiku-4-5`（フルID `claude-haiku-4-5-20251001`） | フロンティア級知能に迫る最速モデル | $1 / $5 | 200K | 64K | 非対応 | 最速 | 2025年2月 |

補足（2026-09-13 に公式ドキュメントで確認）:

- 出力単価の相対比は Haiku : Sonnet : Opus : Fable = 1 : 2 : 5 : 10。表の価格は基本料金であり、Batch API は50%引き、プロンプトキャッシュの読み取りは基本入力価格の10%（Fable 5.1 と Mythos 5.1 は2.5%）。
- **Haiku 4.5 は `effort` パラメータに対応しない。** 他の3モデルは既定 `high`。Haiku 4.5 を割り当てた役割では、水準を動かす手段が `model` の側にしか残らない。
- Haiku 4.5 のみコンテキスト長 200K・最大出力 64K と他モデルより狭く、知識カットオフも約1年古い（学習データのカットオフは 2025年7月であり、信頼できる知識のカットオフとは別の値）。
- 拡張思考の形式も Haiku 4.5 だけ異なる。Haiku 4.5 は Extended（`thinking.type: "enabled"` と `budget_tokens` で予算を明示）、他の3モデルは Adaptive で、Fable 5.1 は Adaptive が常時オン。
- 公式の推奨は「大半のワークロードはまず Opus 5。要求の厳しい推論と長時間稼働のエージェント作業、または Opus 5 を高い effort で評価してもなお届かない場合に Fable 5.1」。
- legacy 扱いで引き続き利用できるのは Fable 5 / Opus 4.8 / Opus 4.7 / Opus 4.6 / Opus 4.5 / Sonnet 4.6 / Sonnet 4.5。
- 4.6 世代以降のモデルIDは日付を持たない表記だが、その表記自体が固定スナップショットを指す。
- 1M トークンは現行トークナイザ（Opus 4.7 で導入）でおよそ 555k 語にあたる。

次の2件は 2026-07-22 時点の観測であり、2026-09-13 に確認した一次情報には対応する記述が無い。真偽を判定していないため、観測時点を添えたまま残す。

- Claude Mythos 5 は Fable 5 と同一スペック・同一価格の招待制限定モデル（一般利用は Fable 5）。現行世代の Mythos 5.1 が Fable 5.1 と同じ関係にあるかは未確認。
- Fable 5 は安全性分類器の発火時に Opus へ自動フォールバックする（セッションの5%未満、以降そのセッションは Opus 継続）。Fable 5.1 での挙動は未確認。

## 2. 各モデルの強み・弱み（公式claimの要約）

- **Fable 5.1**: 曖昧な問題（サブトルなバグ、未知のドメイン、アーキテクチャ判断）に強い。公式は要求の厳しい推論と長時間稼働のエージェント作業を用途に挙げ、Opus 5 を高い effort で評価しても届かない場合の受け皿に置く。弱みは速度とコスト。
- **Opus 5**: 複雑なエージェント型コーディングとエンタープライズ業務向けであり、公式が大半のワークロードの第一候補に挙げるモデル。fast mode（品質同一・最大2.5倍高速・高コスト）に対応する2モデルのうちの1つ（もう1つは legacy の Opus 4.8）。
- **Sonnet 5**: 「正確に記述できる編集、機械的な変更、既にコンテキストにあるコードへの質問」に適する（公式ブログ）。日常コーディングの既定モデル。
- **Haiku 4.5**: 「能力要件が控えめな素直な作業」に適する（公式ブログ）。公式ドキュメントは探索系サブエージェントの低コスト化例として `model: haiku` を明示している。

先代 Fable 5 について 2026-07-22 に確認した次の3点は、Fable 5.1 で再確認していない。結果だけを指示すれば経路を自分で計画し検証も自発的に行うこと、大きめのタスクを分割せず渡せること、Claude Code の既定モデルではなく明示選択（`/model fable`）が要ること。

## 3. Claude Code での利用形態

### サブエージェントの model フィールド

`agents/*.md` frontmatter の `model` に指定できる値は `sonnet` / `opus` / `haiku` / `fable` / フルモデルID / `inherit`（未指定時のデフォルトは `inherit` = 親セッションと同一モデル）。

モデル解決の優先順位（高い順）:

1. `CLAUDE_CODE_SUBAGENT_MODEL` 環境変数
2. Agent tool 呼び出し時の `model` パラメータ
3. サブエージェント定義（frontmatter）の `model`
4. メイン会話のモデル

### effort フィールド

frontmatter の `effort`（`low`〜`max`、モデル依存）でそのサブエージェント実行中のみ effort を上書きできる。未指定時はセッション継承のため、検証系エージェントの厳密さが親セッションの設定に依存する点に注意（`effort: high` の明示で固定できる）。

ただし **Haiku 4.5 は `effort` に対応しない**（他の3モデルは既定 `high`）。Haiku 4.5 を指定した役割では、`effort` を書いても水準は動かない。

### fast mode

同じ Claude Opus を速度優先の API 設定で動かすリサーチプレビューであり、別モデルではない。品質と能力は標準の Opus と同一で、最大2.5倍速い。したがってモデル選択や effort の代替にはならない（同一品質・低レイテンシ・高コスト）。対応は Opus 5 と Opus 4.8 の2モデルに限られ、Sonnet・Haiku その他では利用できない。Opus 4.7 の fast mode は 2026-06-25 に非推奨化され 2026-07-24 に削除済みで、Claude Code は Opus 4.7 を非対応モデルとして扱う（切り替えると fast mode はオフになる）。

価格は Opus 5 / Opus 4.8 とも $10 / $50 per MTok で、1M コンテキストの全域に一律で掛かる。会話の途中で最初に有効化すると、その時点の会話コンテキスト全体へ fast mode の非キャッシュ入力価格が掛かる。有効化するならセッション開始時のほうが安い。標準 Opus とは別のレート制限を持ち、上限に当たると自動的に標準速度へフォールバックする。

利用の前提が 2 つある。**Team / Enterprise 組織では既定でオフであり、Owner による有効化が要る**（未有効化のまま `/fast` を叩くと「組織によって無効化されている」と表示される）。また **Batch API とも Priority Tier のコミットメントとも併用できない**。CI・バッチ処理へ持ち込めないため、fast mode は対話的な作業に閉じたレバーである（いずれも 2026-09-13 に公式ドキュメントで確認）。

CLI では `/fast` でトグルし、ユーザー設定ファイルの `"fastMode": true` でも設定できる。既定では対話セッションでの設定がセッションを跨いで持続し、`"fastModePerSessionOptIn": true` を置くと毎セッション off から始まる。Claude Code v2.1.219 以降、fast mode の既定モデルは Opus 5。利用できるのは Anthropic API とサブスクリプションプラン（usage credits 経由）に限られ、Amazon Bedrock / Google Cloud / Microsoft Foundry / Claude Platform on AWS では利用できない。

## 4. 作業種別ごとの振り分け指針

公式に確認できる区分は次の3つである。

| モデル | 公式が挙げる作業 |
|---|---|
| Sonnet 5 | 正確に記述できる編集、機械的な変更、既にコンテキストにあるコードへの質問 |
| Haiku 4.5 | 能力要件が控えめな素直な作業。公式ドキュメントは探索系サブエージェントの低コスト化例として `model: haiku` を明示している |
| Fable 5.1 / Opus 5 | 曖昧な問題（サブトルなバグ、未知のドメイン、アーキテクチャ判断） |

公式ブログ由来でもう1点、コスト効率について確認できる記述がある。単価だけでなく試行錯誤の回数を加味すること——Fable は複雑な多段階問題でステップ数が少なく済むため、タスク総コストでは安くなり得る（2026-07-22 確認。先代 Fable 5 についての記述であり、Fable 5.1 では再確認していない）。

**これ以上の細分は本文書が持たない。** model × effort の組み合わせごとの費用対効果は [`model-effort-cost-guide.md`](model-effort-cost-guide.md)（第三者ベンチマークの実測に基づく model × effort の費用対効果ガイド。新設）が扱う。

本節は以前、作業種別11行の推奨表と「コスト効率の考え方」2項目を持っていた。推論に由来する行が第三者実測と突き合わせられない根拠のまま残っていたため、根拠の性格が揃う「公式が明示している範囲」へ畳んだ。畳む対象は推論に由来する行であり、公式ブログ由来の1項目（上の Fable のステップ数）は本節へ残している。もう1項目（`effort` がモデル選択とは別のレバーであること）は `subagent-execution-parameters.md` が「`model` と `effort` は別々の軸である」として規約の側で持つため、本節では重複させない。

**公式 claim と第三者実測が食い違う箇所**: 旧表は「通常の実装 → Sonnet 5」を公式ブログ由来として挙げていた。一方 DeepSWE v1.1 の実測（2026-09-13 時点、113タスク、pass@1 定義）では、`sonnet-5/low` が pass@1 0.305・1回あたり平均コスト $2.19、`opus-5/low` が 0.581・$1.66 である。後者が成功率とコストの双方で前者を上回る。1回で完遂するまでの期待コスト（1回あたり ÷ pass@1）で見ると $7.17 対 $2.86 となる。**ただしこの割り算は、同じ設定での再試行が独立であることを仮定している。同一ベンチの pass@4 実測はこの仮定を否定しており**（`opus-5/high` は実測 87.6% に対し独立仮定の予測 99.5%）**、$7.17 / $2.86 は上限側へ振れた目安である**（[`model-effort-cost-guide.md`](model-effort-cost-guide.md) が同じ但し書きを持つ）。順序の比較には使えるが、額面を持ち出さない。公式 claim を実測が上書きするという関係ではなく、根拠の性格が違う2つが食い違っている事実として扱う。

## 5. 本リポジトリでの適用状況（2026-07-22 時点）

`plugins/dev-workflow/agents/*.md` の現行 model 設定は Issue #317 の実機並行評価（Opus版/Sonnet版の比較）に基づく:

| エージェント | model | 経験的裏付け |
|---|---|---|
| code-reviewer / test-designer | opus | Sonnet版で実バグ見逃しを実測、降格不可判定（#317） |
| plan-reviewer / test-spec-validator | opus | 「重要」指摘の見落としを実測、降格不可判定（#317） |
| refactorer | sonnet | 3種コーパスで振る舞い不変を実測（#317） |
| plan | opus | #317 評価対象外。裏付けなし（将来の評価候補） |

この表が置く「レビュー・検証系は Opus、機械的変換は Sonnet」という割り当ては、かつて §4 が持っていた推論由来の推奨表と整合していた。その表は 2026-09-13 に廃しているため、現在この割り当ての裏付けは #317 の実機並行評価だけである。model 設定を変更する際は `docs/dogfood/317-evaluation-methodology.md` の手法で再評価すること。**同文書が「2026-07-16 評価で判明した前提の誤り」節に置く単価前提（Opus 対 Sonnet の単価差 1.67 倍、$5/$25 対 $3/$15）は、当時の観測であり現行値ではない。** 現行の Sonnet 5 は $2/$10 で（§1）、同じ論法では 2.5 倍になる。同節の「降格の経済的動機は初回反映時の想定より小さい」という結論は、この単価では成立しない。手法は使え、単価の数値は §1 を見ること。プラグインの版はコミット SHA が担うため、版の繰り上げは要らない（ADR-202609061416-01）。ただし版を繰り上げないことと変更が利用環境へ届くことは別であり、反映には利用側での marketplace の再取得（Claude は `claude plugin update`、Codex は `codex plugin marketplace upgrade`）が要る。
