# 文書の恒久性の規約（`docs/` 配下）

`docs/` 配下へ何を残し、何を残さないかを判断するための単一の出典。リポジトリに過去の記録を保持せず、恒久的価値のある情報は正本へ移してから記録本体を削除する。別ディレクトリへの退避も、注記を足しての据え置きも採らない。退避は区別のコストを別の場所へ移すだけであり、注記は読み手とツールの双方へ但し書きの読み取りを課し続ける。

## 依拠する軸

本規約は新しい軸を立てない。`docs/principles.md`「ストック情報とフロー情報」（ドキュメントをストックとフローに区別し、両者は異なる整理原理に従うと定める節）の既存の区別をそのまま用い、その上に `docs/` 配下の配置規律を載せる。「恒久文書」「過去記録」は同節のストック／フローを `docs/` の配置判断へ言い換えた呼称であり、第2の軸ではない。

## 1. `docs/` はストック情報の置き場である

`docs/` の追跡下に置くのはストック情報だけである。調査記録・作業記録・当時の設計 spec・実験ログは、フロー情報の定義（作業を駆動し、完了後は参照頻度が下がる）に当てはまるフロー情報の成果物であり、フロー情報の成果物を `docs/` へ恒久配置しない。フロー情報の運搬体は Issue・PR・実装プラン（`docs/plans/` に置くが追跡下に入れない）である。

## 2. ストック情報の追随義務

ストック情報は原則として現在真であり続ける義務を負う。実装・運用が記述と食い違った場合は、記述と実装のどちらかを直す。この追随義務は `docs/principles.md` の定義に含まれておらず、本規約が `docs/` 配下の配置判断のために同軸の上へ載せる規定である。軸を増やしてはいないが、原文の引用でもない。

追随義務の免除には、恒久のものと一時のものの2種がある。**恒久の免除**を受けるのは、記録であることを構造的に宣言する形式に限る。本リポジトリでは `docs/adr/` の ADR（専用ディレクトリ・識別子・front-matter の `status` / `validity`）がこれに当たる。ADR は時点の決定でありながら決定の根拠として繰り返し参照されるためストックに属し、`principles.md` もストックの例に ADR を挙げる。ADR 本文は `validity` を問わず時点の事実を述べたものとして扱い、追随の対象から外す。有効な ADR の Decision が現在の規範を述べていても、ADR は時点の決定の記録であって、§2 冒頭の義務を負う規約文書ではないためである。

**一時の免除**を受けるのは、§4 の「区分対象外」として据え置いたファイルのうち第2類（未完了の後続作業が引き継ぎ文書として参照しているもの）に限る。第2類は中身が引き継ぎの時点で凍っていることが据え置きの理由であり、据え置きを認めた以上、記述が現況とずれることもその帰結として認める。据え置かれている限りその内部の記述を追随の対象から外し、据え置きの根拠が消えた時点で再判定して、恒久文書と判定されればその時点から追随義務を負う。

第1類（実行中の機構が入力として消費している資産）は、据え置きの間も追随義務を負ったままとする。第1類の据え置きの理由は削除の可否であって中身が凍っていることではなく、実行中の機構が入力として現に読む以上、記述は現況と一致していなければならない。据え置きが認めるのは削除の先送りだけである。ここで免除を認めると、条文が「追随の対象から外す」と述べる一方で機構は「直さなければ緑にならない」と述べる、真逆の指示が同時に立つ。

恒久の免除のこの原理から、後述の区分は `docs/adr/` の ADR 本体へ適用しない。ADR がその状態を終えるかどうかは、`plugins/adr/skills/manage-adr/references/adr-demotion.md`（ADR の格下げ判定を定める条文）が扱う別軸である。

## 3. 恒久的価値のある事実は、それを要するストック文書の中へ引用する

恒久的価値のある事実（実測値・実験結果・却下理由）は、独立した記録として配置しない。それを必要とするストック文書の中へ、観測の時点と条件を明示した根拠として引用する形で残す。時点と条件を落として結論だけを移すと、移設先は現在真であることを要求される文書であるため、前提が動いた時点で誤った現況記述に変わる。

移す対象は、存続するストック文書の条文が判断を下すために現に必要とする事実に限る。単一の出典であることは移設の十分条件ではない。工程の実施記録を全量移すと、移設先が新たな過去記録になり、この規約が達しようとした状態を移設先で崩す。

## 4. 区分

`docs/` 配下の追跡下の文書（§2 により適用対象外とした `docs/adr/` を除く）は、次のいずれかを取る。

| 区分 | 定義 | 処遇 |
|---|---|---|
| 恒久文書 | ストック情報。蓄積され繰り返し参照され、§2 の追随義務を負う | 存続させ、変更のたびに追随させる |
| 過去記録 | フロー情報の成果物。特定の作業を駆動するために書かれ、記述された時点の観測・判断であり以後を追わない。現在の実装や外部仕様と食い違っていても記述の誤りではない | §3 に沿って恒久的価値のある事実を移してから、記録本体を削除する |
| 区分対象外 | 下記2類。上の基準を適用せず据え置く | 据え置く。§2 の追随義務を一時的に免れるのは第2類だけで、第1類は据え置きの間も負ったまま（削除の先送りのみ）。内部に残る参照は2類とも参照掃きの対象外とする（§6）。据え置きの根拠が消えた時点で再判定する |

区分は本来ストック／フローの2値である。「区分対象外」は第3の値ではなく、2値の適用を一時的に免除する枠であり、免除の根拠が消えた時点で2値のいずれかへ戻る。

恒久部分と過去部分が同一ファイルに混在する場合、ファイル単位では畳めない。区分は節の粒度まで適用し、恒久文書の内部に残る時点固定の節も処理の対象とする。ファイル単位に留めると、現況の出典として指されている文書の内部に但し書き付きの節が残る。

### 区分対象外の2類

- **実行中の機構が入力として消費している資産**。削除が機構側の改修を伴うため、文書側の判断だけでは処遇を決められない
- **未完了の後続作業が引き継ぎ文書として参照しているもの**。当該作業の完了時に再判定する。据え置きの根拠に挙げてよいのは、その時点で未完了である作業に限る

## 5. 恒久文書へ持ち込まないもの

次に当たる記述は、恒久文書へ書かない。混ざったら落とす。

- **一時的な定量値**（各資産の行数、ファイル数、棚卸しの集計）。時点の測定は、測定した時点のフロー情報の運搬体——§1 が挙げる Issue・PR・実装プラン——が持つ
- **個別の Issue / PR 番号と、その処遇表**。在庫の状態は GitHub を単一の出典とする
- **完了した工程の実施記録**（削除対象の一覧、工程分割、実施順序、着手時の実測値）

恒久文書へ書くのは、次の同種の判断でも同じ規範として効くものだけである。

## 6. 参照掃きと追随の除外

過去の時点の観測・判定・移行を記録した文書は、参照先が消えても書き換えない。参照掃きの受入条件を書くときは、これらを除外集合としてパスで明示する。明示しないと「参照が残っている」と判定され、記録を改竄しなければ緑にできない状態に追い込まれる。現在真であることを要求される規約文書の側は逆で、陳腐化した例示への注記を置くならそちらへ置く（置くこと自体は義務ではない）。どちらに当たるかは、その文書が時点の事実を述べているか、現在の規範を述べているかで判別する。

受入条件へパスを名指しする必要が生じるのは、次の2つに限られる。第一に、`docs/adr/` を走査面に含める受入条件——本規約により `docs/` 配下に過去記録は残らないため、恒久の除外集合はこれに尽きる。第二に、§4 の区分対象外として据え置いたファイル——据え置きが解けるまでの一時のものであり、除外ではなく次段に定める固定の形を取る。据え置きが解けた時点で第二は消え、第一だけが残る。

区分対象外として据え置いたファイルの内部に残る参照は、当該ファイルが据え置かれている限り参照掃きの対象外とする。これは §2 の追随義務の免除と射程が異なり、第1類・第2類の双方に掛かる。実行中の機構が入力として消費するのは資産の一部であり、機構が検査しない部分に残る陳腐化した参照まで追随を強いる理由は無いためである。据え置きを認めた以上その帰結も認めるためでもあり、参照は据え置きが解ける時点に一緒に解消される。ただし除外は無条件の免除にしない——当該パスを走査対象から外すのではなく、ヒットの件数と場所を据え置きファイルの当該行に固定し、据え置きファイル以外に残っていないことを検査で示す。
