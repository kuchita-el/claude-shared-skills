## 観測したこと

2026年11月に、Task Memory を1つのタスクで運んだ。実装した文脈が、タスクのブランチの `docs/memory/tasks/` に覚え書きを置き、push した。実装の文脈を持たない別のエージェントが、ブランチからそれを読んで検証し、所見を同じファイルへ追記した。そのエージェントは、申し送りが足りたかも書いた。

足りたものは、次のとおりだった。

- ブランチと親のブランチの関係、環境の覚え書き、済んだ変異と負例、計画から外れた判断と理由、疑ってほしい箇所。
- 読み手は、済んだ変異をやり直さずに、別の変異へ進めた。疑ってほしい箇所は、そのまま検証の入口になった。

足りなかったものは、次のとおりだった。

- 作業の計画が振った記号（コミット・前提・試験に付けた番号）が、追跡していない計画でしか解けなかった。
- 何を確かめれば完了かの一覧と、完了の条件が無かった。
- そのブランチの PR の番号と、CI の状態が無かった。
- 件数が古い時点の値のままだった。進み具合の並びが、コミットの順と違った。

## 言えること

- Task Memory は、別の文脈への申し送りとして働く。済んだ検証と、疑っている箇所を書くと、読み手は同じ確認を繰り返さずに済む。
- 追跡していない文書の記号に頼らずに書く。完了の条件と、PR の番号も書く。

## 当てはまらない場合と、確かめていないこと

- 1回の観測である。確信度を medium にしたのは、このためである。
- 読み手は、同じホストの中で起動した別のエージェントだった。別のセッションと、別のホストでは確かめていない。
- 読み手は、依頼文で計画の場所を教えられ、計画を読めた。計画を読めない読み手がどこで止まるかは、観測していない。
