# #1054 の検討: 実装 Issue の起票案

このファイルは Task Memory である。レビューへ出す前に、起票した Issue へ移して消す。

設計は `docs/development/shared-memory/design.md` の 7節（7.1〜7.4）が正本である。下の起票案は、その節を作るための作業の分け方だけを持つ。設計の理由は写さない。

## 決まったこと（2026-11-23、利用者との対話）

- 方向: 2つの判断を別の場に分ける。送り出しはプロジェクトの PR で承認し、受け入れは Global の選別で後から行う。
- 運ぶ者: 2つのリポジトリが在るセッションの AI か、人間が、明示して運ぶ。候補の提案と昇格の終わりにも運ぶ。プロジェクトの CI は運ばない。
- 運んだ後の `outbox/`: 利用先に任せる。運ぶコマンドが Global の履歴で運び済みを判定するので、残しても消しても2度は運ばない。

AI の判断で決め、設計書に書いたもの（利用者が異を唱えなかったもの）:

- Global の入口: 候補を足すだけのブランチを、Global の CI が確かめて取り込む。
- 別の文脈を作れないホスト: 語の照合は必須にし、読みは未実施と PR に書いて、送り出しを止めない。
- 下書きは、一般化した別の文書にする。propose-records の Global 向きの下書きも `outbox/` を通す。
- 選別の合図は人間が決める。古い候補を自動で捨てない。
- 元の記録との対応は、元の記録の `sent-as` に持つ（項目名は仮）。
- ADR は保留にする。判定の記録は PR の説明に書く。

## 進める順番

A → B → C → D。

- A は、ほかの全ての土台である。
- B より先に C の利用規則を入れると、旧い promote-record が Global の `records/` へ PR を出し、新しい利用規則と食い違う。そのため B を先にする。
- B だけが入った状態でも壊れない。承認済みの下書きが `outbox/` に溜まり、C が入ると運ばれる。

## 起票案 A: 検査器と形式で、送り出しの下書きと選別の前の候補を扱う

ラベル: `shared-memory`、`type:feature`、`size:medium`。親: #1018。

### 目的

設計書 7.2〜7.4節の置き場を、形式と検査器が扱えるようにする。プロジェクトの `outbox/` と Global の `candidates/` である。B〜D の土台になる。

### すること

**形式（`plugins/shared-memory/references/format.md`）**

- 記憶の根の表に、`outbox/` と `candidates/` を足す。
- 下書きと候補の形を定める。記録と同じ形式とし、次を持たない。
  - `Project` の出典
  - `superseded-by`・`moved-to`
  - `type: evolution`
- 記録の項目に `sent-as` を足す（場合によって書く項目）。値は、送り出した下書きの識別子を1件以上とする。
- 索引に、候補の表を足す。記録の表とは分ける。
- 「記録の版」に、候補の版も数えることと、引用で「候補」と添える形を足す。
- 「Task Memory」から、運ぶ途中の提案の例外を外す。
- 「検査器が違反とするもの」の表に、新しい規則を足す。

**検査器（`plugins/shared-memory/scripts/memory.mjs`）**

- `outbox/` と `candidates/` を読み、記録と同じ形式の規則を掛ける。
- 識別子の重複を、`records/`・`outbox/`・`candidates/` を合わせて見る。
- 上の「持たないもの」を、違反にする。
- `sent-as` の値の形を検査する。指す先が `outbox/` に在るかは見ない。運んだ後に消してよいためである。
- 索引に、候補の表を出す。
- `version` が、`candidates/` の記録の版も返す。`records/` と `candidates/` のどちらで見つけたかを、出力で区別する。replace-record が「`records/` に在るか」を判定するためである。
- 下書きを候補へ写すコマンドを足す（名前は仮に `carry`）。
  - 引数は、Project の根、Global の根、Project の起点の ref、Global の起点の ref である。
  - Project の起点の木の `outbox/` から、下書きを読む。作業ツリーは読まない。
  - 起点の照合は、`version` と同じ規則で行う。
  - Global の起点の履歴で、同じ内容のファイルが `candidates/` か `records/` に一度でも在れば、飛ばす。
  - 同じ識別子で内容が違うファイルが Global に在れば、写さずに示す。
  - 残りを、Global の作業ツリーの `candidates/` へ、バイトの単位で同じに書く。
  - 下書きごとに、写した・運び済み・止めた、のどれかを出力する。
  - どちらかの履歴が浅ければ止まる。ネットワークへ出る git のコマンドは呼ばない。
- 使い方の文と終了コードを直す。

**試験（`scripts/tests/shared-memory-check.bats`・`shared-memory-git.bats`）**

- 新しい規則ごとに、正例と負例を置く。
- 運び済みの判定は、次を持つ。
  - 捨てた候補（Global の履歴にだけ在る）
  - `outbox/` に残っている運び済みの下書き
  - 別のプロジェクトとの識別子の衝突
- 変異は、検出の側と免除の側を対で置く。免除の側の例は「同じ内容が履歴に在るのに写す」である。

### 決めていないこと

- 規則の名前と、写すコマンドの名前。
- 写すコマンドが Global の起点に何を受けるか。`version` と同じ規則で足りるか。
- `sent-as` の項目名。

### 完了の条件

- `bash scripts/run-tests.sh` の shared-memory の試験が通る。
- 本リポジトリの `docs/memory` が、新しい検査器の `check` を通る。
- 設計書 9節の検査器の行と、食い違わない。

### 依存

無い。

## 起票案 B: 送り出しを、プロジェクトの PR で承認する形へ移す

ラベル: `shared-memory`、`type:feature`、`size:medium`。親: #1018。

### 目的

設計書 7.1・7.2節。Global へ出す下書きを `outbox/` に書き、機密の確認の結果を、プロジェクトの PR で人間に示す。promote-record から、Global への PR と運ぶ経路を外す。

### すること

**`references/confidentiality.md`**

- 「いつ行うか」: `outbox/` へ書いた後、PR をレビューへ出す前とする。根の外の一時の置き場をやめる。
- 「結果の書き方」: プロジェクトの PR に書く。
  - 元のプロジェクトのリポジトリから得た語は、書いてよい。
  - 利用規則と利用者が挙げた語は、件数だけを書く。
- 「読み」: 別の文脈を作れなければ、未実施と書く。送り出しは止めない。

**promote-record**

- 下書きを、`<Project の根>/outbox/` へ書く。`mktemp -d` の置き場をやめる。
- 出典に `Project` を書かない。元の記録に `sent-as` を書く。
- 手順4（昇格先の出典の検索）を外し、`sent-as` の確認に置き換える。送り直すと明示する引数を足す。
- 元の記録は、同じブランチの上のものでもよい。手順3 の版の取得は、要らなくなるか見直す。
- 次を外す。
  - 手順10（昇格先へ書く）
  - 手順11（Global への PR）
  - 「運ぶ経路」
- 5つの確認の表をやめる。代わりに、PR に添える送り出しの報告の形を定め、`references/pr-body.md` を置き換える。
- Global の根が在れば、既存の記録との突き合わせを行い、報告に添える（任意）。

**propose-records**

- Global 向きの下書きを、`outbox/` へ書く。Global の根へ書く手順と、一時の置き場を外す。
- 層の条件に、Project の根が在ることを足す。
- Global の記録への追記と置き換えの扱いを外す。食い違いか補うものを本文に書いた下書きを、送り出す扱いにする。
- 件数の目安を、置く先の層ごとに数える。

**文書**

- プラグインの README。
- 本リポジトリの `AGENTS.md` の「共有の記憶」の節。`outbox/` の置き場と、送り出しの変更は人間のレビューを経ることを足す。

**eval（`evals/shared-memory/`）**

- `behavior-promote-carry` を外すか、送り出しのケースへ置き換える。
- `behavior-promote-confidential` の採点器を、Global の PR の本文から、送り出しの下書きと報告へ移す。
- `behavior-propose-records` の、Global の下書きの採点器を直す。

### 決めていないこと

- 送り出しの報告の置き場。スキルは PR を作らないので、報告をどこに置けば、承認する人間に届くか。案は、スキルの出力に報告を載せ、PR を作る者が説明へ写す形である。
- 送り直しを明示する引数の名前。

### 完了の条件

- 2つのスキルが Global の根へ書かないことを、eval か試験で確かめている。
- `behavior-promote-confidential` を `--runs 3` で実行している。仕込んだ機密（内部のホスト名・作り物のトークン）が、3回とも下書きと報告に出ない。揺れが残れば、回数を書いている。
- `bash scripts/run-tests.sh` が通る。
- 設計書 7.1・7.2節と食い違わない。

### 依存

- A
- #1046 を吸収する。

## 起票案 C: 承認済みの下書きを運ぶ手順と、Global の取り込み

ラベル: `shared-memory`、`type:feature`、`size:medium`。親: #1018。

### 目的

設計書 7.3節。承認済みの下書きを、手を加えずに Global の `candidates/` へ運び、Global の CI が人間の操作なしで取り込む。

### すること（本リポジトリ）

- `references/carrying.md` を足す。手順は次のとおりである。
  1. 両方のリポジトリで、既定のブランチを取り直す。
  2. 写すコマンドを実行する。
  3. Global の作業用のブランチへ commit・push する。了承は、ホストの許可の確認に任せる。
  4. 報告する。

  push できなければ、運ばずに止まる。
- 運ぶことだけを起動するスキルを足す（名前は仮）。
- promote-record と propose-records の終わりに、`carrying.md` の手順を足す。
- README を直す。

### すること（kuchita-el/shared-memory）

- ワークフローに、取り込みのジョブを足す。
  - 既定のブランチ以外への push で起動する。
  - 差分が `candidates/` の直下への `.md` の追加だけで、検査を通れば、既定のブランチへ取り込む。
  - 取り込んだ後に、索引を作り直してコミットする。
  - それ以外の push では、何もしない。
- `CHECKER_REF` を上げ、索引に候補の表が出るようにする。
- 利用規則を書き換える。
  - 読むとき: 候補の扱いと、引用の形。
  - 書くとき: AI は `records/` を変えず、候補を運ぶ。
  - 運ぶ手順を書く。検査器を入手できないホストのための予備の手順を置くかは、下の「決めていないこと」で決める。
  - 選別の節は、D と合わせて書く。

### 決めていないこと

- 取り込みを、merge のコミットにするか、早送りにするか。
- 並行して運ばれたときに、取り込みを直列にする設定。
- 取り込んだブランチを消すか。
- 検査器を入手できないホストで、git だけで運ぶ予備の手順を、利用規則に置くか。

### 完了の条件

- 設計書 10節の新しい前提を、実機で確かめて、結果を設計書へ書いている。対象は次の2つである。
  - クラウドのセッションからの push と、API を介したコミットで、取り込みが起動する。
  - 既定のトークンで、既定のブランチへ取り込める。
- Global のリポジトリで、次を確かめている。
  - 候補を足すだけのブランチは、取り込まれる。
  - ほかの変更を含むブランチは、取り込まれない。
- 同じ下書きを2度運んでも、候補は1件のままである。捨てた候補を、運び直さない。

### 依存

- A
- B。利用規則の書き換えは、B のスキルが Global へ PR を出さなくなってから入れる。

## 起票案 D: Global の候補を選別する下ごしらえ

ラベル: `shared-memory`、`type:feature`、`size:medium`。親: #1018。

### 目的

設計書 7.4節。AI が選別の案を出し、人間が候補を `records/` へ移して受け入れる。

### すること

- 選別の下ごしらえのスキルを足す（名前は仮）。
  - Global の根で起動する。
  - 候補ごとに、既存の記録とほかの候補を、別の文脈で突き合わせる。`record-crosschecker` を使う。
  - 採る・まとめる・捨てる・置き換えるの案を、根拠つきで出す。
  - 案には、受け入れの4つの観点（検証済みか、他に当てはまるか、適用条件と例外、矛盾）を含める。誰が確かめるかは、利用規則に従う。
  - 頼まれれば、選別の変更をブランチに用意する。既定のブランチへは入れない。
- replace-record: 新しい記録に、`candidates/` から移す候補を受け付ける。A の `version` の区別を使う。
- crosscheck-records: 焦点に、候補を受け付ける。
- 利用規則に、選別の節を足す（C と同じ PR か、その後）。

### 決めていないこと

- 1回の起動で扱う候補の数と、多いときの絞り方。
- 「まとめる」の新しい記録を、誰が書くか。案は、AI が下書きし、人間が選別の変更で承認する形である。
- #1023 の見直しを、このスキルへ入れるか。

### 完了の条件

- 候補を置いた題材で、案が出ることと、スキルが記録を書き換えないことを、eval で確かめている。
- 選別の変更を用意したブランチが、Global の CI に取り込まれないことを確かめている。

### 依存

A、C。
