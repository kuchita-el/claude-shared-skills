## 何をするか

`shared-memory` プラグインへ、次を足す。

- スキル `promote-record`: Project Memory の記録を一般化し、Global Memory への PR にする。5つの確認の結果を PR の本文に書く。
- スキル `crosscheck-records` とサブエージェント `record-crosschecker`: 記録を、書いた文脈とは別の文脈で、既に在る記録と突き合わせる。
- スキル `replace-record` と共有の参照 `replacement.md`: 置き換えの3つをそろえる順序と確かめ方。
- 候補の提案のスキル（`propose-records`）の機密の読みを、別の文脈へ委ねる形に改める。

## 決まっていること

- 未検証（`verification: unverified`）の記録は、既定では昇格を止めない。未検証のまま昇格し、PR の本文に書く。設計の原則が「未検証の区別」へ改まったためである。
- `promote-record` と `crosscheck-records` は、根の既定を決めるために `Bash(git rev-parse*)` を持つ。
- PR の本文の下書きは、別の文脈の読みへ委ねる前に書く。
- モデルを呼ぶ実行は、この作業の全体で1回だけにする。矛盾する1組を突き合わせが報告することを確かめる実行に使う。ほかは未実行として PR の説明に一覧にする。
- 記憶のリポジトリへは、コミットも push もしない。試験の資料も置かない。

## 先行の現物と、計画の前提の食い違い

- `confidentiality.md`「下限の対象」は、1列の表だった。対象の3つの文は変えず、列（含むものの例・判定の入力・段）を足した。3つ目の対象の文が既に持つ例（リポジトリの名前、内部の URL）は、例の列へ重ねて書いていない。
- `confidentiality.md`「結果の書き方」は、「残した語が在ればその根拠」を PR の本文に書くと定めていた。語そのものを書かない定めと両立するよう、「語を残したときは、残した根拠を書く」へ分けた。
- 候補の提案のスキルは、検索の道具が無いホストのために `Bash(grep -i -F *)` を持つ。昇格のスキルの `allowed-tools` は、計画の確定形のままにした（`grep` を足していない）。検索の道具が無いホストでは、語の照合を行えないので止まる、と本文に書いた。足すかどうかは、Codex での確認の時に決める。
- サブエージェントの出力の `class` の値は、試作では「資格情報」だった。`confidentiality.md` の語（認証情報）に合わせた。
- コマンドの書き方の1文は、候補の提案のスキルの文（書いた形のまま、1回に1つずつ）に合わせた。

## 計画・試作から変えた点

- 昇格のスキルの手順5 に、引き継いだ `verified` の扱いを1項目足した。候補の提案のスキルの出所の規則（自分で確かめた観測だけを `verified` にする）と揃えるためである。主張を元の記録が確かめた範囲に収め、広げた範囲は確かめていないこととして分ける。収まらなければ `unverified` とする。PR の本文の書き方にも、1行目の書き方を足した。
