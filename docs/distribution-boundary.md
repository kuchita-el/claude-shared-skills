# 配布物と配布元の境界

プラグインとして配布する資産（以下「配布物」＝ `plugins/` 配下）と、本リポジトリに留める資産（以下「配布元」＝ リポジトリルートの `scripts/` ・ `docs/` 等）の境界を定める。

## 1. この文書が定めること・定めないこと

**定めること**: ある資産を配布物と配布元のどちらへ置くか、およびその根拠。定めるのは資産の配置であって、実行経路の帰属（どのスクリプトがどこから何を起動するか）は定めない。§3 が実行経路に触れるのは現況の置き場所を述べる限りにおいてである。§2 の判断軸を適用した例には、同梱スクリプトのテストと fixture（§3）のほか、配布物内に在った配布元固有の管理表・設計文書をはじめとする文書群を配布元へ移した判断（#652・#657。移設先は `## 関連` が指す）が挙げられる。この列挙は例示であって適用の網羅ではなく、新たな適用のたびに本節へ追記する義務は生じない。配置の根拠はこの文書を単一の出典とし、他の箇所（テストランナーの冒頭コメント・開発ドキュメント・ADR の注記）は本書を指すに留める。

**定めないこと**: 配布物の内部構成（スキル・スクリプト・hook の分割）、レイヤ上書き（プラグイン default とプロジェクト override）の境界、プラグインと利用者側の責務分担の一般原則。これらは本書の射程外であり、それぞれの決定に従う。

## 2. 境界の判断軸

ある資産を配布物へ同梱するかは、次の3点で判断する。

- **配布先の環境で解決できるか**: 配布物のみを自リポジトリへ導入した利用者から見て、その資産が指す参照がすべて解決できるか。解決できない参照を持つ資産は配布物へ置かない。
- **配布元固有のデータを含むか**: 本リポジトリのディレクトリ構成・ファイル名・題材の中身に依存する資産は、配布先にとって意味を持たないため配布元へ残す。
- **手順の実行にその定義が要るか（実行不能性テスト）**: その定義を持たずに読むと、手順のどの行かが評価不能になるものは、配布物へ入れる。射程は動作の判定に限る。落としても手順の判定が成立し続ける由来注記・背景の記述は、この軸では配布物へ引き込まれない。

第1軸（配布先の環境で解決できるか）と第3軸（実行不能性テスト）は修理の向きが逆である。第1軸は解決できない参照を持つ資産を配布物へ置かないという**資産を外へ出す**向きの規範であり、第3軸は手順の実行に定義が要るならその定義を配布物へ入れるという**定義を中へ入れる**向きの規範である。したがって第1軸だけでは検出できない誤配置がある。手順が判定に要る定義を自ら持たず、その定義を抱える文書がたまたま同梱されているために参照は解決できている、という状態がそれにあたる。第1軸はこの状態を通すが、当該文書が他の軸で配布元へ移った時点で手順は評価不能になる。第3軸は文書の配置の決着を待たずに、動作の判定に要る定義を配布物側へ引き込む。

第3軸は §3 が固定する参照方向と同じ向きに働く。配布物内から配布元にある定義を指すことでは解決せず、定義そのものを配布物へ入れることで解決する。

判断軸は資産の種類（実装・テスト・データ・文書）では決まらない。同じ「スクリプト」でも、引数ですべての入力を受け既定値を持たない検査器は配布物へ置き、特定の corpus を前提とするテストランナーは配布元へ残す。

## 3. 適用例: テストと fixture の配置

同梱スクリプトのテストと fixture は、**配布物外（リポジトリルートの `scripts/tests/` および `scripts/fixtures/`）へ置く**。テストを束ねて実行する経路（`scripts/run-tests.sh`）も同じく配布物外に置く。配布物（`plugins/adr/scripts/`）が持つのは検査器のみである。

根拠は2つある。

- **参照方向を一方向に固定する**: 参照を「配布物外のテスト → 配布物内の検査器」の向きだけに保ち、配布物側が fixture のパスを一切知らない状態を維持する。逆向きの参照（配布物内の資産が配布元のパスを名指すこと）を作らないため、配布物のみを導入した利用者から見て解決不能な参照が残らない。この向きは文書やコメントの記述にも及ぶ。配布物内の README・スクリプトヘッダから配布元の文書へリンクを張ると、参照方向を文書側で破ることになるため、本書へのポインタも配布物内には置かない。
- **配布物へ検査用データを同梱しない**: fixture は検査対象の境界事例を符号化した本リポジトリ固有のデータであり、配布先にとって意味を持たない。検査器の振る舞いを固定する責務は配布元が負う。

この配置は `adr-scoping-cases.sh` のテストで先行し（PR #616）、`lint-adr.sh` / `next-adr-id.sh` のテストと fixture も同じ配置へ揃えた。その後、テストは bash スクリプト（`scripts/test-*.sh`）から bats のケース（`scripts/tests/*.bats`）へ載せ替えた（#645）。配置の判断は変わらず、置き場所が `scripts/` 直下から `scripts/tests/` へ下がっただけである。

## 4. 受容した犠牲

テストを配布物外へ出したことで、**配布先リポジトリは同梱スクリプトが自環境（bash の版差・awk 実装差）で動くかを自前で確かめる手段を失う**。配布物は検査器のみを持ち、自己検証手段（smoke チェック等）を同梱しない。

環境差の確認は配布元の責務とする。配布先で不具合が生じた場合、その再現と修正は配布元のテストランナーへ環境条件を持ち込む形で行い、配布物へ検証手段を戻すことでは解決しない。

## 5. ADR-202607230648-01 との射程関係

ADR-202607230648-01（ADR 運用機構のプラグイン抽出）の決定2 は、可搬アーティファクトの集約対象として「テスト / fixtures」を挙げている。この列挙は**抽出時点で `plugins/adr/` へ移す対象**を定めたものであり、以後に追加する同梱スクリプトのテスト・fixture を配布物内へ置くことを定めたものではない。テスト・fixture の配布物内／外の別は同 ADR の射程外である。

**この射程の正本は同 ADR 側にある**（決定2 の射程注記）。本節の記述はその言明を再掲したものに留まり、射程そのものを定めるものではない。射程の解釈に迷う場合は本書ではなく ADR-202607230648-01 を見ること。
