# doc-reviewer の負例・正例と、その確認の記録

`doc-reviewer` が担う判定のうち、機械検査を持たないもの（第1条の全体、第3条、第4条）について、指摘が現に出ることと、欠陥を取り除いた文書では出ないことを確かめる。回帰を検出する手段を人手の記憶に委ねないための最小の手当てである。

## bats に載せない理由

`doc-reviewer` の判定は決定的でない。同じ文書を2回読ませても、指摘の粒度や言い回しは一致しない。合否を機械的に突き合わせる `lint-ja.sh` の fixture と同じ扱いにはできない。したがって本ディレクトリの fixture を実際に読ませる確認は `scripts/run-tests.sh` の実行対象に含めず、この記録を残す形で扱う。

**ただし下表そのものは機械で検査する**。確認が機械化できないことと、確認の台帳が対象を覆っていないことは別の問題である。台帳の更新を忘れると、足した fixture の型は永久に確認されないまま残る。`scripts/tests/doc-reviewer-fixtures.bats` が、下表と実ファイルの一致を双方向に検査する。

## 対応

| 欠陥の型 | 負例 | 正例 |
|---|---|---|
| 第1条 語の接地（漢字の造語） | `negative/01-kanji-coinage.md` | `positive/01-kanji-coinage.md` |
| 第3条 文書の自立 | `negative/02-document-autonomy.md` | `positive/02-document-autonomy.md` |
| 第4条 判断依頼の材料 | `negative/03-decision-request.md` | `positive/03-decision-request.md` |

## 手順

1. fixture を中立な名前（`doc-a.md` のような、内容を示さない名前）で一時ディレクトリへ複製する。**ファイル名が欠陥の型を明かすと、初見の読み手という前提が崩れて確認にならない**
2. `doc-reviewer` を、定義が認める4つの入力（対象・文書種別・読み手・プラグインルートのパス）だけを渡して起動する。素材や起草の経緯にあたる情報は渡さない
3. 負例について、対応する型の指摘が出ることを確かめる。正例について、その型の指摘が出ないことを確かめる
4. 結果を下表へ追記する

正例に対応する型の指摘が出た場合、まず疑うのは正例の側である。ここまでの実施では、正例に出た指摘はいずれも正例そのものの欠陥であり、指摘の側が誤っていた例は無かった。

## 起動の経路について

`writing` プラグインが読み込まれた環境では、`subagent_type` に `writing:doc-reviewer` を指定して起動する。この形でのみ、定義の `model` と `effort` が実効値になる。

下表の実施は、プラグインが未登録のセッションで行った。定義ファイルを読ませたうえで一般のサブエージェントとして起動し、`model` は `opus` を明示的に渡した。`effort` を渡す手段が呼び出し側に無いため、`effort` は親セッションの値を継承している。判定の内容はこの差に依存しないが、`effort` の実効値が定義の値と一致していない点は記録として残す。

## 実施の記録（2026-08-08）

この実施は、第1条に機械検査と許可リストがあった時点の設計に対して行った。その後の改修で第1条の機械検査と許可リストは廃止され、第1条は本エージェントが唯一の執行手段になっている。あわせて本エージェントの定義側も変わった。入力の4つ目が許可リストのパスからプラグインルートのパスへ替わり、第1条の判定項目から許可リストによる免除の記述が消えている。

**したがって下表は取り直しを要する。** 判定の基準そのもの（意味の復元可能性と、第3条との境界）は変えていないため、下表の結果が反転する見込みは低い。それでも、定義を変えた後に一度も確認していない状態で記録だけが残ると、記録が現在の定義に対する保証であるかのように読める。

取り直しが必要な理由は2つある。

- 入力契約と第1条の判定項目が変わったため、下表が対応づく定義の版が現在のものと異なる
- `negative/03-decision-request.md` の本文を1文だけ書き換えた（廃止した機構への言及を落とした）。下表の「初稿のまま指摘が出た」は、書き換える前の本文に対する記録である

取り直しの結果が出るまで、下表は**過去の定義に対する記録**として読むこと。

### 負例

いずれも初稿のまま、対応する型の指摘が出た。

| 負例 | 期待した型 | 結果 |
|---|---|---|
| `negative/01-kanji-coinage.md` | 第1条のうち漢字の造語 | 出た。「目的接地」「値域整合」「題材集合」の3語を、一般に流通する熟語ではない独自の圧縮語として指摘 |
| `negative/02-document-autonomy.md` | 第3条 | 出た。採用した案が名指しされていないこと、決定を左右した制約が本文に無いこと、影響節の配下が参照の指示だけであることの3箇所 |
| `negative/03-decision-request.md` | 第4条 | 出た。前提・判断軸・選択肢・帰結・推奨のいずれも無いこと、および性質の異なる3件を1文に並べていることの2箇所 |

負例はいずれも、期待した型に加えて他の条の指摘も受けた。短い文書に欠陥を1つだけ含ませることは難しく、型の分離は完全ではない。確認の対象は期待した型の指摘の有無であり、他の条の指摘の有無は判定に用いない。

### 正例

| 正例 | 期待 | 結果 |
|---|---|---|
| `positive/01-kanji-coinage.md` | 第1条の指摘が出ない | 出なかった。後述の境界を定義へ足したうえで確認した |
| `positive/02-document-autonomy.md` | 第3条の指摘が出ない | 出なかった。5条すべてで該当なし |
| `positive/03-decision-request.md` | 第4条の指摘が出ない | 出なかった。材料5点が揃い、論点が1件へ絞られていると判定された |

正例が通るまでに要した改稿は、`positive/01` が5稿、`positive/02` が2稿、`positive/03` が3稿である。**各稿で出た指摘はいずれも正例そのものの欠陥であり、指摘の側が誤っていた例は無かった**。初稿の `positive/01` は、造語を別の造語へ言い換えたうえで括弧内に語幹を繰り返しただけで、接地になっていなかった。初稿の `positive/02` は、影響節が参照先へ逃げたままだった。

## 確認から定義へ戻した修正

`positive/01` は5稿を重ねても第1条の指摘が残った。稿ごとに指摘される語は変わり、最後の稿で挙がったのは「直す」と「語を数える」だった。いずれも読み手が意味を取れる一般の語であり、指摘の中身は語の意味ではなく、手順の細部が書かれていないことだった。

第1条が問うのは意味の復元可能性であり、手順が本文で完結しているかは第3条が扱う。両者が混ざると、意味を取れる語まで第1条の指摘に並び、本当に復元できない語が埋もれる。この境界を `doc-reviewer.md` の第1条の判定項目へ書き足した。

境界を足したあと、負例の側で第1条の指摘が消えていないことを確かめた。**判定の語彙を狭めると、その語彙に依存していた負例が黙って無力化する。** `lint-ja.sh` の負例に対して変異検査が担っている確認を、ここでは人手で行った。結果は次のとおり。

| 対象 | 期待 | 結果 |
|---|---|---|
| `negative/01-kanji-coinage.md`（境界を足した後） | 第1条の指摘が出続ける | 出た。「目的接地」「値域整合」を漢字の圧縮語として指摘 |
| `positive/01-kanji-coinage.md`（境界を足した後） | 第1条の指摘が出ない | 出なかった。「直す」について、意味は取れる語であり運用の細部は第3条の側だと明示して判定から外した |

境界を足す前後で、負例は赤のまま、正例は緑へ転じた。境界が正例だけに効いており、負例の赤さを支えている判定は残っている。

## 観測された限界

- **このリポジトリで定着している漢字の造語を指摘する。** 「検査器」は複数の負例・正例で第1条の指摘を受けた。第1条は免除の機構を持たないため、文書ごとに初出で接地するか、指摘を受け入れたうえで人が落とすかのいずれかになる。
- **機械検査との判定が割れる余地は第2条に残る。** 実施の時点では第1条にも機械検査があり、「ゲート」（通過を止める関門）という語を `lint-ja.sh` は候補として挙げたが、本エージェントは直後の文が言い換えを与えているとして指摘しなかった。その後の改修で第1条の機械検査は廃止され、この経路での割れは起きなくなった。第2条については、機械検査が候補の提示までを担い確定判断を本エージェントが行う分担が残っている。
- **判定は決定的でない。** 同じ文書の同じ語について、指摘する回と指摘しない回があった。`positive/03` の「確定」「赤くなる」は、ある実施では指摘されず、文言を一部変えた次の実施では指摘された。この記録は個々の指摘の再現性を保証しない。保証するのは、期待した型の指摘が負例で出て正例で出ないという関係が、実施した時点で成立していたことである。
