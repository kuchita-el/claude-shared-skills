# 振る舞いの不変条件（スキル実行時）

スキル実行中に、生成する出力・成果物の分量と、作業として踏み込む範囲を判断するための単一の出典。各スキルとサブエージェント定義はこの規約を参照し、規約本文を自身へ転記しない。

## 背景

スキルの実行主体には、指示がなくとも自分の作業を検証し、依頼より広い範囲へ踏み込み、応答と成果物が長くなる方向の挙動がある。これはスキル固有の欠陥ではなく実行主体の挙動であり、スキルごとに個別の対処を書き足すと同じ趣旨の文言が分散して drift する。

**記述様式**: モデル名・モデル版を直書きせず、挙動として観測される不変条件の形で記述する。特定の版に紐づく数値・閾値を置かない。

## 他の規約との境界

token と出力に関わる規律は4軸ある。本規約は**実行時の生成・範囲軸**を扱う。

| 軸 | 出典 | 縛る対象 |
|---|---|---|
| 作成時（静的） | CLAUDE.md「スキル設計の token 規律」 | `description` 長・SKILL.md 行数・`allowed-tools`（スキルという成果物の静的サイズ） |
| 実行時（データフロー） | `context-budget.md` | メイン context を通過・滞留するデータ |
| 実行時（生成・範囲） | 本規約 | 出力・成果物の分量と、作業として踏み込む範囲（どれだけ書くか・どこまでやるか） |
| 実行時（表現） | `japanese-writing.md`（`writing` プラグインが定める共通規約） | どう書けば読み手が意味を取れるか（語の接地・参照の自己完結・文書の自立・判断依頼の材料・根拠の同居） |

**表現軸との重なり**: `japanese-writing.md` の第1条（語の接地）と本規約の不変条件1 は、その場で作った略語について重なる。不変条件1 が扱うのは分量を削る手段としての略語であり、第1条が扱うのは読み手が意味を復元できない語一般である。略語は後者の部分集合にあたる。

`context-budget.md` が「メイン context に載せるか」を扱うのに対し、本規約は上表の3行目が示す範囲を扱う。内容を重複させない。

なお、成果物にどの節が存在するかは各出力形式テンプレートの責務であり、本規約は扱わない。本規約が扱うのは節の中身の分量である。

## 不変条件

### 1. 結論を先に置き、選択的に書く

ユーザー向けの応答は結論から書く。分量を減らす手段は**含める内容の取捨選択**であって、文そのものの圧縮ではない。断片化・記号の連鎖・その場で作った略語で短くしない。読み直しや再質問が発生すれば、短縮による利得は失われる。

### 2. 成果物は必要な分量を超えて書かない

ファイルとして書き出す成果物（プラン・精査レポート・ドキュメント）は、扱う内容を満たす分量にとどめる。重複する要約・定型文で嵩を増やさない。

### 3. 依頼された範囲を超えて変更しない

依頼の範囲がそのまま成果物の範囲である。曖昧さは慎重な同僚がするように解釈し、読み方によって成果物が実質的に変わる場合にのみ確認を挟む。依頼そのものに問題を見つけた場合は、指摘を述べたうえで依頼どおりに進める。範囲を黙って狭めない・広げない・作り替えない。

### 4. 自己訂正を語り過ぎない

先の発言を訂正するのは、その誤りがユーザーの判断・コード・結論を変える場合に限る。訂正は簡潔に述べて作業を続ける。謝罪・自己批判・経緯の詳述・過去の誤りの列挙をしない。後続の質問それ自体は誤りの合図ではない。

### 5. 進行の実況を目的化しない

ツール呼び出しの合間に書く文は、発見・方針転換・行き詰まりを伝えるために書く。定型の進捗報告を機械的に挟まない。
