# 全件モード入出力契約

refine-issue スキルの全件モードにおける、サブエージェントの返却形式（入口）と集約後にユーザーへ最終提示する形式（出口）を1ファイルで定義する。

## 入口: サブエージェント返却形式

全件モードのサブエージェント返却形式テンプレート。SKILL.md 手順3 において全件モードのサブエージェントが自身で Read し、refine-prompt.md の {OUTPUT_FORMAT} プレースホルダ位置に適用する形で出力形式として運用する。本節の以下の本文をテンプレートとして遵守すること（本節の外＝出口節・対応表はテンプレートに含めない）。

各Issueについて以下のフィールドを持つ構造化データとして結果を返してください。形式は YAML / JSON など機械的に集約可能な構造であれば任意。ここに定義されていないフィールドは追加しない。

- `number`: Issue番号
- `title`: タイトル
- `size`: Small / Medium / Large（判定不能時は `-`）
- `type`: bug / feature / refactor / spike / chore / docs（判定不能時は `-`）
- `is_ready`: true / false
- `clarification_items`: 確認事項のリスト（なければ空配列）

精査対象Issueが複数の場合、各Issueのオブジェクトを配列で返すこと。

## 出口: 集約後出力形式

スキル側（メイン）は入口節の形式で返されたサブエージェントの結果を集約し、以下の最終形式に変換してユーザーに提示する。SKILL.md 手順4 が本節の形式に従って出力を組み立てる。

ここに定義されていないセクションは追加しない。

```markdown
## Issue精査サマリー

| # | タイトル | サイズ | 種別 | Ready | 確認事項 |
|---|---------|--------|------|-------|---------|
| 1 | 機能追加 | Medium | feature | ❌    | 2件     |
| 3 | バグ修正 | Small  | bug     | ✅    | なし    |
| 5 | -        | -      | -       | -     | error   |

### 統計

- 精査対象: {total}件
- 作業可能（Ready）: {ready}件
- 未充足あり（Not Ready）: {not_ready}件

### 次のアクション

- Not ReadyのIssueは確認事項を解消後、`/refine-issue {number}` で個別に再精査
- ReadyのIssueは作業開始可能（確認事項が付いていても非ブロッカー助言であり、着手を妨げない）
```

## 入口と出口の対応

入口節の各フィールドが、出口節のどこへ反映されるかの対応。

| 入口フィールド | 値域 | 出口サマリー表での反映先 |
|---|---|---|
| `number` | Issue番号 | 「#」列 |
| `title` | 文字列 | 「タイトル」列 |
| `size` | Small / Medium / Large / `-` | 「サイズ」列 |
| `type` | bug / feature / refactor / spike / chore / docs / `-` | 「種別」列 |
| `is_ready` | true / false | 「Ready」列（true→✅、false→❌）と、統計の「作業可能（Ready）」「未充足あり（Not Ready）」の件数 |
| `clarification_items` | リスト（空可） | 「確認事項」列（件数表記。空なら「なし」） |
| （返却なし＝サブエージェント失敗） | — | 「#」列は手順2で保持した Issue 番号リストから埋める。「タイトル」「サイズ」「種別」「Ready」列は `-`（タイトルは入口返却にのみ存在し、メインは Issue JSON を読まないため）。「確認事項」列は `error` とし、エラー詳細を表直後に補足する。統計では `{total}` にのみ数え、`{ready}` / `{not_ready}` のいずれにも数えない |

具体例（出口節のサンプル行と対応する）: 入口 `{number: 1, title: "機能追加", size: "Medium", type: "feature", is_ready: false, clarification_items: [2件]}` は `| 1 | 機能追加 | Medium | feature | ❌ | 2件 |` となる。Issue #5 の結果がサブエージェント失敗により返らない場合は `| 5 | - | - | - | - | error |` となる。

統計の内訳: `{total}` は精査対象の件数であり、`{ready} + {not_ready} + サブエージェント失敗件数` に等しい。

`is_ready: true` と `clarification_items` 非空は併存しうる。全件モードでは非ブロッカー助言（HOW混入助言等。`refine-prompt.md`「実現方法の混入（HOW混入）の指摘」）も `clarification_items` へ入るため、「確認事項」列に件数が入りながら統計では「作業可能（Ready）」に計上される行が正常に生じる。統計の Ready / Not Ready を分けるのは `is_ready` のみであり、確認事項の有無ではない。
