# 遷移リファレンス（transitions.md）

ADR の5遷移（起票・承認・上書き・廃止・却下）と分割の実行手順。front-matter の写入・採番の実行・相互参照の書き込みを、どの順に何へ書くかとして記す。状態の値域、遷移ごとの front-matter 必須ルール、採番方式そのものは SKILL.md が指す状態モデルの規約が実体を持つため、本ファイルではそれらを再定義せず、規約に従う適用手順のみを扱う。

## 目次

- 共通: front-matter の書き方
- 採番規則
- 起票（提案中）
- 承認（承認済み・有効）
- 上書き（上書き済み・双方向相互参照）
- 分割（多決定 ADR の部分上書き）
- 廃止（廃止済み）
- 却下（却下）
- 共通: 退役に伴う inbound `Related:` の点検・付け替え
- 自己検証の対象ディレクトリ
- index の再生成・検証
- 入出力例（上書き遷移）

## 共通: front-matter の書き方

各 ADR ファイル冒頭に `---` で挟んだ front-matter を置く。キーは英語、値は日本語ユビキタス言語。各キーに書ける値と、遷移ごとにどの組み合わせを取るかは SKILL.md が指す状態モデルの規約に従う。

```yaml
---
status: <承認軸の値>
validity: <有効性軸の値 | （空）>
superseded-by: <後継 ADR の full slug | （空）>
---
```

- **値の説明・トレーリングコメントを書かない**。lint パーサ（`${CLAUDE_SKILL_DIR}/../../scripts/lint-adr.sh`）は `key: value` の行全体を値として取り込むため、`# 説明` を付けると値が壊れる。
- 「キー省略」と「キーあり値空」は同じ「空」として扱われる。空にする軸は値を空にする（キー行自体は残してよい）。
- H1 見出しは `# ADR-YYYYMMDDHHMM-NN: <タイトル>` 形式にする（`gen-adr-index.sh` が `: ` 以降をタイトルとして抽出するため）。

各遷移後の `status`/`validity`/`superseded-by` の最終状態は、必ず SKILL.md が指す状態モデルの規約の必須ルール表に一致させること。

**遷移前の状態確認（実行ガード）**: 各遷移は期待する遷移元状態を前提とする — 承認は `status: 提案中` から、上書き・廃止は `承認済み`・`validity: 有効` な ADR に対して、却下は未承認の `status: 提案中` に対して行う。実行前に対象 ADR の現在の `status`/`validity` を確認し、期待と異なれば操作を中断して利用者に確認する。`承認済み` の `status` は不変であり、承認済み ADR へ却下操作を適用しない。lint は最終状態のスキーマ整合のみを検査し遷移元は見ないため、この不変条件は手順側で守る。

## 採番規則

識別子・ファイル名の形式、同一時刻部内の連番の付け方、採番衝突時の発番規則は SKILL.md が指す状態モデルの規約に従う。本節では実行手順としての補足のみを記す。

- 発番は `bash ${CLAUDE_SKILL_DIR}/../../scripts/next-adr-id.sh <対象ディレクトリ>` を実行し、出力された識別子に `-<slug>` を付してファイル名とする。時刻部の取得と同一時刻部内の連番決定はスクリプトが担うため、`Glob` で配置ディレクトリを列挙して番号を組み立てない。対象ディレクトリの解決は SKILL.md が指す配置の規約に従い、本スキルの自己検証も同ディレクトリを対象とする。
- **複数の ADR を続けて起票する場合は1件ずつ発番する**。「発番 → ファイル作成 → 次の発番」の順に進め、発番をまとめて先行させない。スクリプトは配置ディレクトリの既存ファイルから連番を決めるため、ファイルを作る前に続けて呼ぶと同じ識別子が返る。同一分の起票では時刻部も同一になるため、この場合の識別子は完全に重複する。
- 相互参照（`superseded-by`／`Supersedes:`）に書き込む値は、番号部だけの識別子ではなく **full slug**（ファイル名から `.md` を除いた stem）とする。lint は参照先の存在を stem で解決するため、番号部のみを書くと参照先不在の違反になる。

## 起票（提案中）

新規 ADR ファイルを生成する。骨格は SKILL.md が指す雛形の構成（front-matter＋`## Context`／`## Decision`／`## Consequences`／`## 関連ADR` の見出し）に準拠しつつ、**見出し骨格＋空プレースホルダを新規に組み立てる**。決定内容の本文（Context／Decision／Consequences の中身）は上位／人間が埋める前提で、空プレースホルダのまま残す。

- front-matter: `status: 提案中`、`validity:`（空）、`superseded-by:`（空）
- ファイル名を採番規則で決定する。
- **テンプレートの HTML 注釈ブロック（`<!-- ... -->`）を生成物へ残さない**。とりわけ `## 関連ADR` 節のテンプレート注釈には表記例として `- Supersedes: ADR-YYYYMMDDHHMM-NN-<slug>` の行が含まれ、lint-adr の本文走査は HTML コメントを認識せずこの例示行を実データの逆参照として拾い、存在しない後継先を指す相互参照違反（起票直後の自己検証が exit 1）を招く。`## 関連ADR` 節は注釈を除去し、先行・後継・関連が無ければ `該当なし` のプレーンな1行のみを置く。

## 承認（承認済み・有効）

対象 ADR の front-matter を編集する。

- `status: 承認済み`、`validity: 有効`。`superseded-by` は空のまま。
- `status` は以後不変（承認は歴史事実）。

## 上書き（上書き済み・双方向相互参照）

core 変更で新規 ADR（後継）が起票・承認済みであることを前提とする（後継が未作成なら起票を先行させる。上書き操作単体では後継ファイルを新規生成しない）。**旧 ADR と後継 ADR の2ファイルを両方更新する**。

1. **旧 ADR の front-matter**（後継への置換を記録）:
   - `status: 承認済み`（不変）、`validity: 上書き済み`、`superseded-by: <後継の full slug>`
2. **後継 ADR の本文 `## 関連ADR`**（逆参照を追加）:
   - `- Supersedes: <旧の full slug>` の行を1行追加する。
3. **旧 ADR の本文 `## 関連ADR`**（後継の明示）:
   - `- Superseded by: <後継の full slug>` の行を1行追加する。lint の本文走査は `Supersedes:` のみを対象とするため、この記載漏れは exit 0 のまま素通りする（front-matter には残るが、本文だけを見る消費面に後継が現れなくなる）。lint に頼らず、手順として実施したことを確認する。
4. **他 ADR から旧 ADR への `Related:`（inbound 参照）を後継へ付け替える**（手順1〜3 が旧 ADR と後継の2ファイルを扱うのに対し、本手順は**旧 ADR を指している側**を扱う）:
   - 手順の実体は後掲「共通: 退役に伴う inbound `Related:` の点検・付け替え」節にある。上書きは後継がある退役であり、**退役させる ADR を現行の出典として指し続けないことが必須**の側に入る。同節のタイミング制約（退役側の `validity` の書き換えより後にしない）は上書きでは手順1 に掛かる。上書きの締めでは、SKILL.md の自己検証（lint exit 0）に加えて同節の**「締めの確認」**を実施する（3点はいずれも exit 0 に現れないため、lint だけでは付け替えの完了を確認できない）。同節の `Related:` 行の Grep が0件でも締めの確認は省略しない — Grep は `Related:` 行のみを対象とし、`Related:` 行以外（非 ADR ファイル・散文引用）の死角は Grep 件数と無関係に残る（同節「`Related:` 行以外を別途特定する」）。

手順1〜2 の双方向が揃わないと lint-adr レイヤ3（相互参照双方向性）が違反する。lint は次を厳格に要求するため厳守する:

- 後継本文の逆参照は `## 関連ADR` 節内の行で、`- Supersedes: <旧 full slug>`（行頭 `- `＝バレット、full slug 完全一致）。
- `superseded-by` の値と後継ファイル名の stem が一致し、`Supersedes:` の値と旧ファイル名の stem が一致すること（forward・reverse の両方向を検査）。

本節の手順は単一後継（1→1）の上書きを対象とする。原 ADR が複数の決定を束ねていて一部の決定だけが反転する場合（1→N の部分上書き）は、下記「分割（多決定 ADR の部分上書き）」の手順に従う。分割は5遷移の一種ではなく、決定のファイル間再配置という別軸の構造操作であり、5遷移表の外に並置される。

## 分割（多決定 ADR の部分上書き）

複数の決定を束ねた ADR の一部だけが core 反転し、残りの決定が生存する場合に使う。原 ADR 全体をそのまま `上書き済み` にすると生存決定を誤って退役させるため、上書きの前に生存決定を後継へ救出する。

反転を伴わずに、束ね ADR を予防的に分解する場合（衛生的分割）にも同じ手順を用いる。この場合は退役する決定がなく、全決定が生存決定として後継へ移る。

1. 生存決定の後継 ADR を起票する。一体で反転するクラスタごとに1本以上とし、`status: 提案中` で開始して承認後に `status: 承認済み` / `validity: 有効` へ更新する。後継が複数本になる場合は、採番規則のとおり**1本ずつ発番してファイルを作成してから次を発番する**（分割の後継は同一分に起票されるため、識別子を分けるのは連番部だけであり、発番を先行させると重複する）
2. 後継の `## Decision` に生存決定の本文を**逐語**で転記する。トップレベル項目の先頭番号は、後継での単独可読性のため振り直してよい。番号付き決定の前に置くリード文のような非決定文は、逐語の対象ではないため後継の文脈に合わせて書いてよい
3. 後継の残りの節を書く。`## Context` は新規記述とする。`## 関連ADR` は後継が保持する決定集合に照らして書き下ろす（原 ADR の `Related:` を機械的に引き継がない）。`## Consequences` は次の配分規則に従う

   **基本則**: 生存決定に対応する記述を保持し、退役する決定に由来して無効となる記述のみ除く。

   **保持集合の読み方**: 「保持」の対象は**各後継の担当決定に対応する記述**である。担当決定に対応しない項目（他の後継が担う決定の帰結、原 ADR 固有で後継に適用先が無い項目）は最初から保持集合に入らない。「のみ除く」は保持候補の内側に掛かる制約であり、**生存決定に対応する記述を編集的に刈り込むことの禁止**を意味する。1→N の分割では各後継が原 ADR の帰結の一部しか持たないのが正常であって、これを基本則への違反と読まない（そう読むと N≧2 のあらゆる分割が違反になり、規則が適用不能になる）。

   **配分の粒度**: 判定の基準は「その文が単独で1つの決定に帰属するか」であり、バレットという表記単位ではない。決定ごとに分離可能な複数文を含むバレットは文単位で配分してよい。規則1 は1文が複数の決定にまたがって切り分けられない場合の規定である。

   - **規則1（またがる項目は全文を重複掲載）**: 1文が複数の決定にまたがる帰結項目は、文を切らず**該当する全後継へ全文のまま掲載する**。切ると各後継の側で意味が欠ける
   - **規則2（帰結が0件の後継は節を置かない）**: 担当決定に対応する帰結が1項目も無い後継は `## Consequences` 節ごと置かない（空の節も「該当なし」も置かない）。**置かなかった事実を手順4 の開示へ含める**。0件かどうかは**規則1 の重複掲載を適用した後の件数**で数える。担当決定にまたがる項目を規則1 で受け取った後継は0件ではなく、固有の帰結を持たなくても薄い節を持つ（節を持たせるために帰結を新規執筆してはならない。新規執筆は分割中に決定内容を変えないという前提に反する）
   - **規則3（反転された決定への言及は逐語保持）**: 反転された決定に言及する説明句を含む項目は、その説明句ごと**逐語で保持し、注記を足さない**。反転の事実は原 ADR 側と、反転を担う後継の側が記録する（本規則は分割時点で書き下ろす帰結記述に掛かる。他 ADR が現況の出典として指す `Related:` 行の注釈は生きたポインタであり、後掲の共通節の規定に従って反転を反映する。両者は射程が異なる）
   - **規則4（原 ADR 固有の項目は除く）**: 原 ADR に固有で後継に適用先が無い項目（原 ADR 自身の起票判断を記録した項目など）は除く。**除去は手順4 の開示対象**である

   規則の導出根拠は次の3原則である。(a) **帰結は決定に従属する** — どの後継がどの帰結を持つかは担当決定によって決まり、帰結の側で独立に決めない。(b) **記録は単独で読めなければならない** — 他の後継を併読しないと意味が通らない配分にしない（規則1・規則2 の根拠）。(c) **記録は時点固定であり後から直さない** — 分割時点の記述をそのまま運ぶ（規則3 の根拠）
4. 手順2〜3 で原 ADR から改変した箇所（先頭番号の振り直し、リード文等の非決定文の書き換え、`## Consequences` の調整）を、後継の `## Context` に理由とともに記載する。決定件数の言い換えのような機械的な追随も開示に含める（「以下の4点を決定する」→「以下の2点を決定する」の類は、後継だけを読む読者には決定が落ちた痕跡と区別がつかないため）

   **改変しなかったことによる不整合も開示する**: 手順2 の逐語転記は決定本文を一字も変えないため、原 ADR の文脈に依存した参照が後継の内側では解決できなくなる。手順3 の規則3（反転された決定への言及は逐語保持）に該当する `## Consequences` の項目も同様に本文を改めないため、同じ不整合が生じる。改変したことを開示する（上記）のと対をなす扱いとして、**改変せずに指し先を開示する**。対象は次の4類型である。

   - **他の決定の番号への参照**: 決定本文が原 ADR 内の別の決定を番号で指しており、その決定が別の後継へ移った、または反転した場合
   - **原 ADR 自身への自己言及**: 決定本文が「本 ADR」等で原 ADR を指しており、後継では指し先が変わる場合
   - **後継が持たない節への参照**: 決定本文が原 ADR の節を指しており、後継がその節を持たない場合（手順3 の規則2 で `## Consequences` 節を置かなかった後継など）
   - **反転された決定への言及を含む `## Consequences` の項目**（手順3 の規則3 に該当）: 規則3 が本文の改変を禁じるため、反転により指し先または記述内容が偽になっても項目本文は逐語のまま残る場合

   扱いは、**後継の `## Context` 配下に、類型と指し先の対応を開示する**こと。対象の本文（`## Decision` の決定本文、または規則3 該当の `## Consequences` 項目）は改変しない。見出しの文言・見出しレベル（小見出しにするか太字インラインにするか）は固定せず、要件は位置（`## Context` 配下）と記載内容（どの記述がどこを指すか）に限る。例: 決定本文に「決定3 の凍結原則」という記述が残り、その決定3 が別の後継へ移った場合、後継の `## Context` に「決定本文に残る原 ADR 内の決定番号（読み替え）: 『決定3』は本 ADR の決定1 を指す」相当の記載を1行以上置く。

   **射程は `## Decision` に限る。** `## Consequences` に残る同種の参照は、読み替えの開示ではなく**本文を改めたうえで本手順の開示対象に含める**ことで処理する。逐語転記の不変条件が掛かるのは手順2 の `## Decision` であり、`## Consequences` は手順3 の配分規則の裁量下にあって改変できるためである。改変できる対象へ読み替え表を置くと、読者に余計な間接層を強いる。**ただし手順3 の規則3（反転された決定への言及は逐語保持）に該当する項目は例外である。** 反転された決定への言及を含む `## Consequences` の項目は規則3 が改変を禁じているため、本手順でも本文を改めず、読み替えの開示（後継の `## Context`、上記4類型目）側で処理する。この優先関係は規則3 が射程とする「反転」に限られ、反転を伴わない番号参照・自己言及・後継が持たない節への参照には及ばない（それらは引き続き本文改変＋本手順の開示で処理する）。
5. 後継の `## 関連ADR` に `- Supersedes: <原 ADR の full slug>` を記載する
6. 原 ADR の front-matter `validity` を `上書き済み` に書き換え、`superseded-by` に**全後継の full slug をカンマ区切りで列挙**する（例: `superseded-by: <後継1 の full slug>, <後継2 の full slug>`）
7. 原 ADR の `## 関連ADR` に `Superseded by: <後継の full slug>` を全後継について記載する。表記（後継ごとにバレットを立てるか、単一行へ読点区切りで並べるか）はファイル内の既存様式に合わせてよく、要求されるのは全件が挙がっていることのみ。既存の `Related:` 行は退役時点のスナップショットとして残置し、分割の一環としては編集しない（この節は本手順が書き込む対象であり、既存行が巻き込まれうる。分割以外の文脈での編集可否は、退役 ADR 一般の凍結原則の射程に従う）
8. **他 ADR から原 ADR への `Related:`（inbound 参照）を後継へ付け替える**。手順7 までが原 ADR 自身の `## 関連ADR` を扱うのに対し、本手順は**原 ADR を指している側**を扱う。手順の実体は後掲「共通: 退役に伴う inbound `Related:` の点検・付け替え」節にあり、分割は後継がある退役として**退役させる ADR を現行の出典として指し続けないことが必須**の側に入る。同節のタイミング制約（退役側の書き換えより後にしない）は分割では手順6 に掛かる。分割に固有の扱いは次の3点である

   - **後継ごとに参照行を分ける**: 1行が複数の決定を名指ししており、それらが別々の後継へ分かれた場合は、**参照行を後継ごとに分ける**。注釈本文は改変せず、名指しされた要素をそれぞれの行へ分配する。1行に畳んだまま片方の後継だけを指すと、もう一方への参照が失われる。生存 re-home 分と反転分が同じ行に同居する場合も同様に行を分け、**反転側だけ**を共通節の規定に従って書き替える
   - **注釈中の決定番号を後継側へ揃える**: 手順2 で後継の先頭番号を振り直した場合は、**注釈中の決定番号も後継側の番号へ揃える**。番号は指し先の同定情報であり、その更新は注釈本文の改変にあたらない（改変しないのは注釈の論旨・語調・名指しする決定の内容である）
   - **後継の承認前に先行してよい**: 後継が未承認＝`validity` 空のうちはレイヤ4 が fail-open で通過するため、付け替えを後継の承認より先に済ませてもよい。原 ADR の退役だけが先行した状態はコミットできない

締めに次の4点を確認する。

- **網羅性（手順1〜2）**: 原 ADR の `## Decision` のトップレベル決定を全件列挙し、各決定が「手順2 でいずれかの後継へ逐語転記された」か「core 反転中で退役する」かの**いずれか一方**に分類されていること。未分類の決定と、両方に該当する決定（退役対象でありながら後継へ逐語転記されている）が、いずれも0件であること。分割は 1→N で生存決定が複数後継へ分散するため、後継を1本ずつ検査するだけでは全体の網羅を誰も見ないまま終わる。転記し忘れた決定は下記の逐語性検査でも切り出し対象に入らず、差分として現れない。逆に反転中の決定が後継へ紛れ込むと、反転が黙って無効化される（反転中の決定はそれ自身の後継が改訂後の内容として担うのであって、原文の逐語転記先を持たない）
- **逐語性（手順2）**: 後継ごとに、網羅性で「逐語転記された」に分類した決定に対応する箇所のみを原 ADR から切り出し、後継の `## Decision` の**トップレベル決定本文**と突き合わせる（両辺とも決定本文に揃える。原 ADR 側は退役決定を含み、後継側はリード文等の非決定文を含みうるため、節どうしをそのまま比較すると差分が出るのが正常になり検査にならない）。切り出し元を後継の内容ではなく網羅性の分類から定めることで、後継にのみ存在する決定——退役決定の混入や、分割中に書き足された新規の決定——が差分として現れる。トップレベル項目の先頭番号を正規化したうえで差分がないこと。切り出し結果が非空であることと行数が一致することもあわせて確認する（正規化や切り出しの失敗が空入力として差分ゼロに化けるため）
- **開示（手順2〜4）**: 手順4 の開示対象4種それぞれについて、改変が生じていれば後継の `## Context` に対応する記載があることを確認する。(a) 先頭番号の振り直し、(b) リード文等の非決定文の書き換え（決定件数の言い換えを含む）は、原 ADR と後継を突き合わせて改変の有無を判定する。(c) `## Consequences` は原 ADR との差分を列挙する。ただし他の後継が担う決定の帰結（保持集合に最初から入らない項目。上記「保持集合の読み方」参照）は開示すべき改変ではないため、この列挙対象から除く（差分の全件を字義どおり列挙対象にすると、1→N の分割では他の後継が担う帰結の分だけ必ず差分が生じ、「保持集合の読み方」が警告する失敗モード（規則が適用不能になる）が締め側に再発する）。列挙した各差分が**規則2（節不設置）・規則4（除去）による開示**に対応していること。**いずれの開示にも対応しない差分が残る場合、それは開示漏れではなく配分側の誤り**（基本則が禁じる刈り込み、規則1 の重複掲載漏れ、規則3 が禁じる本文改変のいずれか）であり、開示の追加ではなく配分の是正で解消する。(a) は逐語性が正規化で潰し、(b) は逐語性が両辺から外した情報であり、いずれも開示側でしか拾えない。逐語検証は `## Decision` の決定本文にのみ適用し、`## Consequences` には適用しない（意図的な再構成が入るため差分ゼロを要求できない）。(c) の差分列挙には**節ごと置かなかったこと**も含める — 手順3 の規則2 で `## Consequences` を置かなかった後継について、置かなかった事実が開示に現れていることを確認する（節内の項目だけを突き合わせると、節の不在は差分として現れずに漏れる）。あわせて手順4 の「改変しなかったことによる不整合」の開示を確認する。後継の `## Decision` に原 ADR 内の決定番号・原 ADR 自身への自己言及・後継が持たない節への参照が残っていれば、後継の `## Context` に対応する読み替えの開示があること。(d) 後継の `## Consequences` に手順3 の規則3 該当項目（反転された決定への言及を逐語保持した項目）があれば、同じく後継の `## Context` に対応する読み替えの開示があること
- **相互参照（手順5〜8）**: `bash ${CLAUDE_SKILL_DIR}/../../scripts/lint-adr.sh <対象ディレクトリ>` が exit 0 であること。`superseded-by` のリスト値と各後継の `Supersedes:` 宣言が双方向で照合される。加えて、原 ADR 本文の `Superseded by:` に全後継が挙がっていることを確認する。lint の本文走査は `Supersedes:` のみを対象とするため、原 ADR 側の記載漏れは exit 0 のまま素通りする（front-matter には残るが、本文だけを見る消費面に後継が現れなくなる）。あわせて原 ADR の `## 関連ADR` を分割の前後で突き合わせ、分割に由来する変更が `Superseded by:` の追加のみであることを確認する。分割以外を根拠とする変更（例: 廃止された旧運用に由来する相互参照行の除去）が同時に入る場合は、その根拠を示したうえで、`Related:` 等それ以外の既存行が不変であることを確認する（同節は手順7 が書き込む対象であり、既存行が巻き込まれうる）。あわせて「共通: 退役に伴う inbound `Related:` の点検・付け替え」節の**「締めの確認」**を実施する（同節が指示する作業のうち3点は定義上 exit 0 に現れないため、lint とは別に目視で確認する。項目の実体は同節にのみ置く）

分割は編集判定フロー（core／非core／些末）の第4分類ではない。決定のファイル間再配置という構造操作であり、分割中に決定内容は変えない。決定内容の変更が要る場合は、分割とは別に core／非core 編集として分離する。

自己検証は原 ADR と後継を配置した対象ディレクトリに対して行う。分割は `validity` を変える操作であるため、index の再生成も伴う。隔離検証へ退避する場合は、原 ADR と**全後継**を同一の隔離ディレクトリへ含める（下記「自己検証の対象ディレクトリ」の原則どおり、相互参照で指す相手を漏らさない）。

## 廃止（廃止済み）

後継 ADR なしで ADR としての効力を終える。対象 ADR の front-matter と本文を編集する。

1. front-matter: `status: 承認済み`（不変）、`validity: 廃止済み`。**`superseded-by` は付与しない**（空のまま）。
2. `## Consequences` 末尾など本文に廃止日時と退役理由を追記する。退役理由には (a) 放棄か移管かのいずれであるかを明示し、(b) 移管の場合は移送先を**時点固定の過去形**で記す（`edit-decision.md`「記録の参照原則」の適用。同原則は凍結済みの退役 ADR 本文を射程外とするため、退役と同時に本文へ参照を書く本遷移では本手順が担う）。
3. 後継 ADR は存在しないため対象 ADR 自身の `## 関連ADR` の変更は不要。
4. **他 ADR から対象 ADR への `Related:`（inbound 参照）を点検する**（手順1〜3 が対象 ADR 自身を扱うのに対し、本手順は**対象 ADR を指している側**を扱う）:
   - 手順の実体は後掲「共通: 退役に伴う inbound `Related:` の点検・付け替え」節にある。廃止は後継なしの退役であり、同節のうち**点検のみを行い、是正は任意**の側に入る。廃止の締めでは、SKILL.md の自己検証（lint exit 0）に加えて同節の**「締めの確認」**を実施する（廃止では inbound `Related:` に対する機械検査が一切発火しないため、点検を行ったこと自体を確認する受け皿はここにしかない。`validity` を変える操作である以上、index 同期の検査自体は他の遷移と同じく発火し、lint exit 0 は求められる）。

## 却下（却下）

一度も承認に至らず終了する終端。対象 ADR の front-matter と本文を編集する。

1. front-matter: `status: 却下`。**`validity`・`superseded-by` は付与しない**（空のまま）。
2. 却下理由を本文に追記する。

- 廃止（`validity: 廃止済み`）と異なり `validity` を空に保つ。`status: 却下`＋`validity` 空はレイヤ1で合法（`status=承認済み` のときのみ `validity` 必須のため、`却下` では違反にならない）。

## 共通: 退役に伴う inbound `Related:` の点検・付け替え

ADR を退役させるとき（上書き・分割・廃止）、**退役させる ADR を指している側**の `Related:` を点検する。各遷移の手順が退役させる ADR 自身の `## 関連ADR` を扱うのに対し、本節はそれを外から指している参照を扱う。上書き・分割・廃止の3節はいずれも本節を参照し、**手順の実体は本節にのみ置く**。

`Related:` の書式規約と検査範囲（判定単位・書式不問・source は `有効` な ADR のみ・違反種別・是正手段）は `cross-references.md` が定める。本節はそれを前提に、退役に伴う点検・付け替えの実務を述べる。

**是正の強度は後継の有無で非対称である。**

- **後継がある退役（上書き・分割）— 退役させる ADR を現行の出典として指し続けないことが必須**: 対象は `Related:` 行と、非 `Related:` の現況参照（後掲「`Related:` 行以外を別途特定する」が扱う非 ADR ファイル・散文引用）の双方である。**担保の手段は両者で異なる。** `Related:` 行側は、放置すると参照先の `validity` が `上書き済み` になるため lint-adr レイヤ4（参照先退役）が違反し、各操作の締めに要求される自己検証が exit 0 に到達しないことで機械的に担保される。非 `Related:` 側は lint が発火しないため、締めの目視確認（後掲「締めの確認」）でのみ担保される——機械検査の不在は義務の不在を意味しない。**是正の選択（後継への差し替え／事実を述べる記録の行への改稿／参照行の除去）は `cross-references.md`「是正手段」に従う**。関係の意味論・経緯が失われる場合は差し替えを強制せず、記録の行への改稿を選んでよい
- **後継なしの廃止 — 点検のみを行い、是正は任意**: 差し替え先が存在しないため機械検査は違反を出さない（レイヤ4 が違反とするのは参照先 `上書き済み` のみ）。それでも点検するのは、参照先が効力を失ったことで「現行の出典として指している」という参照の記述が陳腐化しうるためである。陳腐化している場合に限り、事実を述べる記録の行へ改めてよい。**改めないまま残すことも許される**

**タイミング**: 退役側の `validity` の書き換えより後にしない。同一コミットに含めてもよいし、先行するコミットで済ませてもよい。退役だけが先行した状態はコミットできない。

- **対象の特定**: `Grep` で `<対象ディレクトリ>` 配下を走査し、退役させる ADR を指す `Related:` 行を洗い出す。パターンは `^[[:space:]]*(-[[:space:]]*)?Related:.*<退役させる ADR の full slug>`。バレットを任意とするのは規約どおりであり、バレット必須のパターンで絞ると `Related:` 直書きの行を取りこぼす。`Related:` 直後に slug が隣接する前提も置かない。直後固定のパターンは、規約が許す markdown リンク書式（`Related: [ADR-x](./ADR-x.md)`）を取りこぼす。ヒットのうち**参照元自身が `有効` の行だけ**を対象とし、参照元が `上書き済み` / `廃止済み` の行は凍結原則により編集しない。1行に複数 ADR を列挙した行もこのパターンでヒットしうるが、2件目以降の生存性判定は後述「2件目以降の列挙は人手で確認する」に従う
- **付け替え先の決定**（後継がある退役）: 各行の注釈が名指ししている決定を引き継いだ後継へ差し替える。後継が1本の上書きでも判定は同じ形を取る。**注釈本文は改変しない**（改変しないのは注釈の論旨・語調・名指しする決定の内容である）。差し替えにより関係の意味論・経緯が失われる場合は、`cross-references.md`「是正手段」に従い `Related:` ラベルを外し事実を述べる記録の行へ改めてもよい
- **名指しされた決定が反転された場合**: 上記の「注釈本文は改変しない」は、決定が生存 re-home された参照に対する規定である。**反転された決定を指す参照は注釈本文が偽になるため、反転の事実を注釈へ反映する**（例: 旧注釈が「…として不変のまま引き継がれた」と述べていれば、反転により何へ置き換わったかを述べる記述に改める）
- **`Related:` 行以外を別途特定する**: 機械検査の対象は `Related:` 行に限られるため、(i) `README.md` 等の非 ADR ファイル（走査対象は `<対象ディレクトリ>` 配下の `ADR-*.md` に限られる）と、(ii) **`有効` な ADR 本文の `## Context` / `## Consequences` にある `<退役させる ADR> 決定N` 形式の散文引用**は、いずれも同じ死角に入る。退役させる ADR の識別子でリポジトリ全体を横断検索し、上記と同じ判定（現況参照／記録）を1件ずつ適用する。**現行の規則・構造の出典として現在形で名指ししている**箇所は、後継がある退役では付け替える。後継なしの廃止では記録の行へ改める側のみが選べるが、是正の要否は「是正の強度は後継の有無で非対称である」に従い**任意**である（改めないまま残すことも許される）。歴史的経緯として過去の事実を述べる散文は記録として据え置く（付け替えると史実が偽になるため）。判定に迷う場合は識別子を後継へ置き換えて読み直し、**偽になるなら記録・真のままなら現況参照**とする。**このタイブレークは後継がある退役（上書き・分割）でのみ成立する。** 廃止には後継が存在しないため、識別子を置き換えて読み直す操作自体が実行できない——廃止の判定は前段（現在形の規則言明か、過去の事実を述べる散文か）だけで振り分ける。後継がある退役のうちでも、**このタイブレークは反転を伴う分割には効かない**。反転された決定は後継へ置き換えれば必ず偽になるため、現在形の規則言明まで一律に記録側へ倒れる。名指しされた決定が反転している場合はタイブレークへ進まず、前段の判定（現在形の規則言明か、過去の事実を述べる散文か）だけで振り分ける
- **2件目以降の列挙は人手で確認する**: 1行に複数の ADR を列挙した参照行の2件目以降に退役させる ADR が現れる場合、判定単位が先頭 stem だけであるため付け替え漏れが検査を素通りする
- **編集分類と `## 変更履歴`**: 本節が触るのは `validity: 有効` な ADR であり、3段構えの編集分類が適用される。**識別子・決定番号のみの付け替え**（参照先の規則は同一で置き場所だけが変わる）は**些末**であり `## 変更履歴` を追記しない。**記述内容に踏み込む場合**（現在形の記述の時点固定、陳腐化した記述の書き替え、注釈への反転の事実の反映）は**非core** であり、対象 ADR の `## 変更履歴` に1行追記する。節が無い ADR で新設する場合の配置は SKILL.md が指す雛形の配置規約に従う。分類そのものは SKILL.md が指す編集判定の規約に従い利用者へ問う

**締めの確認（上書き・分割・廃止に共通）**: 本節が指示する作業のうち次の3点は、いずれも lint の exit code に現れない。3操作それぞれの締めで**目視により確認する**。

- **`Related:` 行以外への付け替え** — 機械検査の走査対象は `<対象ディレクトリ>` 配下の `ADR-*.md` の `Related:` 行に限られるため、非 ADR ファイルと `有効` ADR 本文の散文引用は定義上 exit 0 に現れない。確認する内容は是正の強度の非対称に従う。後継がある退役（上書き・分割）では、退役させる ADR を現行の出典として指し続けている非 `Related:` の記述が残っていないこと（差し替え・記録の行への改稿・除去のいずれかで解消していること。手段の選択は `cross-references.md`「是正手段」に従う）。後継なしの廃止では点検を行ったことのみを確認し、是正の有無は問わない
- **1行に複数 ADR を列挙した参照行の2件目以降** — 判定単位が先頭 stem だけであるため、2件目以降の付け替え漏れは素通りする。確認する内容は上記と同じ強度の非対称に従う（後継がある退役では `Related:` 行として上書き済みを指し続けていないこと、後継なしの廃止では点検を行ったこと）
- **非core と判定した編集の `## 変更履歴` への追記漏れ** — 追記の有無は exit code を変えない。確認する内容は、本節「編集分類と `## 変更履歴`」に従い非core と判定した対象 ADR に `## 変更履歴` の1行が追記されていることである

この3点を回収する受け皿を持たない操作があると、共通節へ到達はするが確認されないまま終わる。3操作いずれの締めでも本項を実施する。

## 自己検証の対象ディレクトリ

SKILL.md の「各操作後の自己検証」は対象ディレクトリを直接 lint する。対象ディレクトリの解決は SKILL.md が指す配置の規約に従う。採番・index 再生成・lint の `<対象ディレクトリ>` には、いずれも同一の解決結果を渡す。

**フォールバック（baseline red 時）**: 操作前から対象ディレクトリが exit 1 で、本操作と無関係な違反が exit 0 到達を妨げる場合に限り、一時ディレクトリへ隔離コピーして検証してよい。この場合に**含めるファイルの規則**は下記。漏らすとレイヤ3 相互参照が false negative（正しい操作でも exit 1）になる。

**原則**: **変更/生成した ADR と、それが相互参照で指す相手をすべて含める** — forward（front-matter `superseded-by` が指す後継）と reverse（本文 `## 関連ADR` の `Supersedes:` が指す先行）の両方向。

- 上書きは**旧 ADR ＋後継 ADR の2ファイル**を必ず含める。旧単体だと旧の `superseded-by` が指す後継が不在となり forward が発火する（実測 exit 1）。旧＋後継で双方向が揃い exit 0 になる。
- 承認・上書き（旧 ADR）・廃止・却下の対象が過去に別 ADR を上書きしていて本文に `Supersedes: <先行>` を持つ場合、対象単体だと reverse（本文起点）が先行不在で発火する（実測 exit 1）。先行 ADR も含めれば exit 0 になる（廃止が現実的なケース）。
- 起票は通常は相互参照を持たないため、生成した ADR のみでよい。

コピー後、`validity` を変える操作（承認・上書き・分割・廃止）では隔離ディレクトリで `index.md` を再生成してから lint する（起票・却下は index 再生成不要）。

## index の再生成・検証

`index.md` は導出ビュー（生成物）であり人手編集しない。手編集しない扱いの根拠は SKILL.md が指す状態モデルの規約に置く。本節は再生成と検証の実行手順のみを記す。

- 生成: `bash ${CLAUDE_SKILL_DIR}/../../scripts/gen-adr-index.sh <対象ディレクトリ>` の出力で `<対象ディレクトリ>/index.md` を再生成する
- 検証: `bash ${CLAUDE_SKILL_DIR}/../../scripts/lint-adr.sh <対象ディレクトリ>` を実行する（ADR corpus が満たすべき機械検査可能な不変条件を検査し、違反0件で exit 0）

`validity` を変える遷移（承認・上書き・分割・廃止）の後は、検証の前に必ず生成を実行する。生成を飛ばすと index 同期レイヤが drift として発火する。自己検証では `<対象ディレクトリ>` に前掲「自己検証の対象ディレクトリ」の解決結果を用いる（baseline red で隔離検証へ退避する場合のみ隔離ディレクトリを対象とする）。

## 入出力例（上書き遷移）

- **入力**: 旧 `ADR-203104091530-01-foo.md`（`status: 承認済み`／`validity: 有効`）、後継 `ADR-203104151045-02-bar`（起票・承認済みで full slug が確定している）
- **出力（旧側 front-matter）**: `status: 承認済み`（不変）／`validity: 上書き済み`／`superseded-by: ADR-203104151045-02-bar`
- **出力（後継側 `## 関連ADR`）**: `- Supersedes: ADR-203104091530-01-foo` を1行追加
