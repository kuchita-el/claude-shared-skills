# 遷移リファレンス（transitions.md）

ADR の5遷移（起票・承認・上書き・廃止・却下）と分割、誤った退役の取り消しの実行手順を記す。何をどの順に、どのファイルへ書くかを扱う。

次の事項は `adr-model.md` が持ち、本ファイルでは再定義しない。

- 各操作の遷移前の状態・遷移後の構成子・ガード、`validity` を変える操作の集合: 「遷移の表」
- front-matter の形と書き方: 「front-matter（状態の唯一の権威）」
- 識別子の発番と、ファイル名の形式: 「採番方式」
- 識別子・full slug・逐語転記・凍結などの語の意味: 「用語集」

各操作の後の自己検証は、`SKILL.md`「各操作後の自己検証（必須）」に従う。5遷移の節名の括弧内は、遷移後の状態を既定値の綴りで示したものである。

## 目次

- 共通: 遷移前の状態の確認
- 起票（提案中）
- 承認（承認済み・有効）
- 上書き（上書き済み・双方向相互参照）
- 分割（多決定 ADR の部分上書き）
- 廃止（廃止済み）
- 却下（却下）
- 取り消し（誤った退役の訂正）
- 共通: 退役に伴う inbound `Related:` の点検・付け替え
- 隔離検証（baseline red のときのフォールバック）

## 共通: 遷移前の状態の確認

各操作の前に、対象 ADR の現在の `status`／`validity` を、`adr-model.md`「遷移の表」の「遷移前の状態」と「ガード」に照らして確かめる。照合には `SKILL.md`「書き込む値の取得」で得た値を使う。期待と異なれば、操作を中断して利用者に確かめる。

lint は最終状態のスキーマ整合だけを検査し、遷移元を見ない。そのため、この確認は手順の側で守る。承認済みは不変であり、承認後の ADR へ却下を適用しない。

## 起票（提案中）

新規 ADR ファイルを生成する。雛形（`template.md`）の構成に準拠しつつ、見出し骨格と空のプレースホルダを新たに組み立てる。構成は、front-matter と、`## Context`／`## Decision`／`## Consequences`／`## <xref-heading>` の見出しである。決定内容の本文（Context／Decision／Consequences の中身）は上位か人間が埋める前提で、空のプレースホルダのまま残す。

- front-matter: `status: <status-proposed>`、`validity:`（空）、`superseded-by:`（空）
- 雛形から写すのは、見出しの構成と並びだけである。雛形の front-matter の値と相互参照の節の見出しは既定値の綴りなので、写さない。書く値は `SKILL.md`「書き込む値の取得」で得る。
- 識別子は `adr-model.md`「採番衝突時の解消手順」に従って発番し、ファイル名を決める。
- **雛形の HTML 注釈ブロック（`<!-- ... -->`）を生成物へ残さない。** `## <xref-heading>` 節の注釈は、表記例として `- Supersedes: ADR-YYYYMMDDHHMM-NN-<slug>` の行を含む。lint-adr の本文走査は HTML コメントを認識せず、この例示行を実データの逆参照として拾う。その結果、存在しない後継を指す相互参照違反になり、起票直後の自己検証が exit 1 になる。
- 先行・後継・関連が無ければ、`## <xref-heading>` の見出しだけを置き、節の本文を空にする。相互参照が無いことを表す語（既定の言語では「該当なし」など）を書かない。その語は導入先の言語に依存するのに、設定の語の群に無いためである。lint は、本文が空の節を違反にしない。節そのものは省かない。上書きや関連の追記が、後からこの節へ行を足すためである。

## 承認（承認済み・有効）

対象 ADR の front-matter を `status: <status-approved>`、`validity: <validity-active>` にする。`superseded-by` は空のままである。

## 上書き（上書き済み・双方向相互参照）

ガード（後継が承認されていること）は `adr-model.md`「遷移の表」が持つ。後継が未作成なら起票を先に行う。上書きの操作だけでは後継ファイルを生成しない。旧 ADR と後継 ADR の2ファイルを両方更新する。

1. 旧 ADR の front-matter: `validity: <validity-superseded>`、`superseded-by: <後継の full slug>` にする。`status` は変えない。
2. 後継 ADR の `## <xref-heading>`: `- Supersedes: <旧の full slug>` の行を1行足す。
3. 旧 ADR の `## <xref-heading>`: `- Superseded by: <後継の full slug>` の行を足し、全後継を書く。lint（レイヤ3 forward）が検出するのは、この行を書いたのに後継の一部しか挙げていない部分記載だけである。行を1行も書かない場合は検出しない。これは移行の判断であり、この行を書く手順より前に退役した導入先の原 ADR を、一斉に赤にしないためである。
4. 他の ADR から旧 ADR を指す参照を、後掲「共通: 退役に伴う inbound `Related:` の点検・付け替え」に従って点検し、付け替える。上書きは、後継がある退役である。上書きの手順1〜3 が旧 ADR と後継を扱うのに対し、この手順は旧 ADR を指している側を扱う。締めに、同節の「締めの確認」を行う。

lint-adr のレイヤ3（相互参照双方向性）は、上書きの手順1・2 の双方向について次を要求する。

- 後継の逆参照は、`## <xref-heading>` 節の中の行で、行頭が `- ` のバレットで始まる `- Supersedes: <旧の full slug>` である。full slug は完全一致で照合する。
- `superseded-by` の値が後継ファイルの full slug と一致し、`Supersedes:` の値が旧ファイルの full slug と一致すること。forward と reverse の両方向を検査する。

**是正手段（レイヤ3 違反の報告を受けたとき）**: forward（front-matter 起点）と reverse（本文起点）のどちらで報告されたかによらず、旧側の `superseded-by` と後継側の `Supersedes:` のどちらが誤っているかを決めてから直す。判断は、どちらの決定が実際に置き換わったかで行う。報告された側を機械的に消さない。

- 後継側に `Supersedes:` の行が無い → 上書きの手順2 の漏れである。後継の `## <xref-heading>` へ `- Supersedes: <旧の full slug>` を足す。
- 旧側の `superseded-by` が空、または誤った full slug を指す → 上書きの手順1 の漏れか誤記である。旧側の front-matter を正しい後継の full slug へ直す。
- 旧側の `superseded-by` が値を持つが、有効な参照先の full slug を1件も含まない（区切り文字や空白だけの値。`adr-model.md`「型の制約と機械検査の対応」の制約5 の経路） → 実際の後継の full slug へ直す。
- 双方が値を持つが、互いを指していない → 実際に置き換えた関係のほうを残し、他方をその値へ揃える。
- 置き換えの事実そのものが誤りだった → 後掲「取り消し（誤った退役の訂正）」の判定基準と手順に従う。分割は同節の射程外であり、後継に対する通常の遷移で訂正する。

本節の是正手段は、分割が書き込む双方向相互参照にも適用する。分割はリスト値の `superseded-by` と後継ごとの `Supersedes:` を書き込むため、同じレイヤ3 違反を生みうる。

本節の手順は、単一後継（1→1）の上書きを対象とする。原 ADR が複数の決定を束ねていて一部の決定だけが反転する場合（1→N）は、後掲「分割（多決定 ADR の部分上書き）」に従う。

## 分割（多決定 ADR の部分上書き）

複数の決定を束ねた ADR を、決定ごとに後継 ADR へ再配置する。原 ADR 全体をそのまま `validity-superseded` にすると、生存決定まで退役させてしまう。そのため、生存決定を後継へ逐語転記してから原 ADR を退役させる。

### 適用条件

既定は分割しない。既存の多決定 ADR を遡って分割せず、次のどちらかのトリガが立ったときだけ駆動する。

- **反転駆動**: 束ねた決定の一部だけが反転し（部分反転）、残りの決定が生存する場合。部分反転が実際に当たったときに駆動し、要求される。
- **衛生的分割**: 反転を伴わずに、束ねた ADR を予防的に分解する場合。既定に対する任意の例外であり、要求されない。退役する決定が無く、全ての決定が生存決定になる。

分割は、編集判定（core／非core／些末）の第4の分類ではない。決定のファイル間の再配置という構造操作であり、分割中に決定内容を変えない。決定内容の変更が要る場合は、分割とは別に core または非core の編集として分ける。新規の ADR が独立に反転しうる決定を束ねないための制約は、`adr-splitting.md` が持つ。

### 決定の振り分け

分割の手順1 の前に、原 ADR の `## Decision` のトップレベル決定を全件列挙する。各決定を、次の3つの行き先のいずれか1つへ振り分ける。

- **後継へ逐語転記する**: 生存決定の既定の行き先である。
- **反転中で退役する**: 反転中の決定である。原文の逐語転記先を持たず、改訂後の内容はそれ自身の後継が担う。
- **後継を立てず原 ADR の記録に残す**: 生存決定のうち、次の2条件をともに満たすものに限る。
  - 原 ADR の本文のどの節にも、その決定の却下代替が無い。何を却下代替と数えるかは、`adr-scoping.md`「必要条件: 却下代替が在ること」の成立の要件に従う。ただし同節の「迷う場合は不成立」の向きは採らず、下の「迷えば後継を立てる」に従う。
  - その決定の規範本文を、ADR の外の資産が現に担っている。判定は `adr-demotion.md`「条件2: 規範本文が ADR の外に在る」の (a) に従う。

3つ目の行き先を設けるのは、却下代替を持たない生存決定を後継へ移すと、後継が生まれた時点で却下代替を欠くためである。ADR の固有価値は却下代替にある（`adr-demotion.md`「ADR の固有価値」）。規範本文が ADR の外に在るなら、後継を立てなくても規範は失われず、決定の記録も原 ADR に残る。

**迷えば後継を立てる。** 2条件のどちらかが成り立つか迷う場合は、後継へ逐語転記する側へ倒す。規範本文が ADR にしか無い決定を原 ADR に残すと、退役とともに規範が効力を失う。全ての決定が原 ADR に残す側に入る場合は、後継が1本も生まれず、分割にならない。この場合は ADR 単位の格下げ判定（`adr-demotion.md`）へ回す。

この振り分けは、`adr-demotion.md` の格下げ判定とは別の判定である。

- 格下げ判定は、`validity-active` の ADR を単位に、ADR ごと廃止するかを決める。この振り分けは、既に駆動した分割の内側で、決定を単位に後継を起こすかを決める。
- 原 ADR の退役は分割そのもの（分割の手順6）が決める。この振り分けは退役の可否を判定しない。
- したがって、格下げ判定の条件1 の値域（トレードオフの記述まで無いこと）を、この振り分けの条件へ流用しない。逆に、この振り分けを分割の外で使って、`validity-active` の ADR の決定を退役させない。

### 手順

分割の手順1〜5 は、後継へ逐語転記すると振り分けた決定を扱う。分割の手順6〜8 は、振り分けによらず、原 ADR 全体と全ての後継に掛かる。

1. 生存決定の後継 ADR を起票する。一体で反転する決定のまとまりごとに1本以上とする。後継は起票（`status-proposed`）から始め、承認で `validity-active` へ移す。後継が複数本になる場合も、`adr-model.md`「採番衝突時の解消手順」のとおり1本ずつ発番する。
2. 後継の `## Decision` に、生存決定の本文を逐語で転記する。トップレベル項目の先頭番号は、後継での単独可読性のため振り直してよい。番号付き決定の前に置くリード文のような非決定文は、逐語の対象ではないため、後継の文脈に合わせて書いてよい。
3. 後継の残りの節を書く。
   - `## Context` は新規に記述し、担当決定の却下代替を後掲「却下代替の持ち越し」に従って含める。
   - `## <xref-heading>` は、後継が保持する決定の集合に照らして書き下ろす。原 ADR の `Related:` を機械的に引き継がない。
   - `## Consequences` は、後掲「`## Consequences` の配分」に従う。
4. 分割の手順2・3 で原 ADR から改変した箇所と、改変しなかったことで生じる不整合を、後掲「開示」に従って後継の `## Context` に記載する。
5. 後継の `## <xref-heading>` に `- Supersedes: <原 ADR の full slug>` を書く。
6. 原 ADR の front-matter を `validity: <validity-superseded>` にする。`superseded-by` には、全後継の full slug をカンマ区切りで列挙する（例: `superseded-by: <後継1 の full slug>, <後継2 の full slug>`）。
7. 原 ADR の `## <xref-heading>` に、全後継について `Superseded by: <後継の full slug>` を書く。後継ごとにバレットを立てるか、1行へ読点区切りで並べるかは、ファイル内の既存の様式に合わせてよい。要求するのは、全件が挙がっていることだけである。
   - 既存の `Related:` 行は退役時点のスナップショットとして残し、分割の一環としては編集しない。この節は分割の手順7 が書き込む対象であり、既存の行が巻き込まれうるためである。分割以外の文脈での編集の可否は、凍結の射程に従う。
8. 他の ADR から原 ADR を指す参照を、後掲「共通: 退役に伴う inbound `Related:` の点検・付け替え」に従って点検し、付け替える。分割は、後継がある退役である。分割に固有の扱いは後掲「inbound 参照の付け替えに固有の扱い」が持つ。

### `## Consequences` の配分

**基本則**: 生存決定に対応する記述を保持し、退役する決定に由来して無効となる記述だけを除く。

保持の対象は、各後継の担当決定に対応する記述である。担当決定に対応しない項目は、最初から保持の対象に入らない。他の後継が担う決定の帰結や、原 ADR に固有で後継に適用先が無い項目がこれに当たる。

「だけを除く」は保持の候補の内側に掛かる制約であり、生存決定に対応する記述を編集で刈り込むことを禁じる。

1→N の分割で各後継が原 ADR の帰結の一部しか持たないのは正常であり、基本則への違反と読まない。そう読むと、後継が2本以上のあらゆる分割が違反になり、規則が適用できなくなる。

配分の判定の基準は、その文が単独で1つの決定に帰属するかである。バレットという表記の単位ではない。決定ごとに分けられる複数の文を含むバレットは、文の単位で配分してよい。

- **規則1（またがる項目は全文を重複掲載する）**: 1文が複数の決定にまたがって切り分けられない帰結項目は、文を切らず、該当する全ての後継へ全文のまま掲載する。切ると、各後継の側で意味が欠ける。
- **規則2（帰結が0件の後継は節を置かない）**: 担当決定に対応する帰結が1項目も無い後継は、`## Consequences` 節ごと置かない。空の節も「該当なし」も置かない。0件かどうかは、規則1 の重複掲載を適用した後の件数で数える。規則1 でまたがる項目を受け取った後継は0件ではなく、固有の帰結を持たなくても薄い節を持つ。節を持たせるために帰結を新たに書いてはならない。分割中に決定内容を変えないという前提に反するためである。
- **規則3（反転された決定への言及は逐語で保持する）**: 反転された決定に言及する説明句を含む項目は、その説明句ごと逐語で保持し、注記を足さない。反転の事実は、原 ADR の側と、反転を担う後継の側が記録する。この規則は、分割の時点で書き下ろす帰結の記述に掛かる。他の ADR が現況の出典として指す `Related:` 行の注釈は生きたポインタであり、後掲「共通: 退役に伴う inbound `Related:` の点検・付け替え」に従って反転を反映する。
- **規則4（原 ADR に固有の項目は除く）**: 原 ADR に固有で、後継に適用先が無い項目（原 ADR 自身の起票の判断を記録した項目など）は除く。

規則の導出根拠は、次の3原則である。

- (a) 帰結は決定に従属する。どの後継がどの帰結を持つかは担当決定で決まり、帰結の側で独立に決めない。
- (b) 記録は単独で読めなければならない。他の後継を併せて読まないと意味が通らない配分にしない（規則1・規則2 の根拠）。
- (c) 記録は時点を固定し、後から直さない。分割の時点の記述をそのまま運ぶ（規則3 の根拠）。

### 却下代替の持ち越し

後継は、担当決定の却下代替を保持して生まれる。却下代替とは、その決定について採らなかった選択肢と、その却下理由の対である。何を数えるかは、前掲「決定の振り分け」と同じく `adr-scoping.md` の成立の要件に従う。原 ADR のどの節に在ったかは問わない。後継の格下げ判定は、後継の本文だけを見て原 ADR を辿らない（`adr-demotion.md`「条件1: 却下代替が本文に無い」）。運ばなかった却下代替は、後継の側では無いものとして扱われる。

原 ADR 上の在り処ごとの扱いは、次のとおりである。

- `## Decision` の決定本文に在る: 分割の手順2 の逐語転記で運ばれる。追加の作業は要らない。
- `## Context` に在る: 後継の `## Context` を新規に記述するという手順はそのままとし、その中へ担当決定の却下代替を運ぶ。選択肢と却下理由は、原 ADR の記述を引用するか、対の中身を変えずに書き直す。却下理由を補強・追加・削除しない。
- `## Consequences` に在る: 担当決定に対応する記述として、基本則の保持の対象に入る。後継の `## Consequences` に保持し、刈り込まない。1文が複数の決定にまたがる場合は規則1 に従う。
- 複数の後継の担当決定にまたがる: 該当する全ての後継へ運ぶ。理由は規則1 と同じである。
- 退役する決定だけに掛かる: 運ばない。反転を担う後継が、改訂後の内容とあわせて扱う。

この要求は決定内容の変更ではなく、分割で保存する対象の拡張である。原 ADR に無い却下代替を書き足すことは、この要求に含まれず、許されない。原 ADR が担当決定の却下代替を持たない場合、後継は却下代替を持たずに生まれる。その決定を後継へ移すか原 ADR に残すかは、前掲「決定の振り分け」で決める。

### 開示

分割の手順4 は、次の2つを後継の `## Context` に記載する。見出しの文言と見出しのレベル（小見出しにするか、太字のインラインにするか）は固定しない。要件は、位置（`## Context` の配下）と、記載内容だけである。

**改変の開示**: 分割の手順2・3 で原 ADR から改変した箇所を、理由とともに記載する。対象は次のとおりである。

- (a) 先頭番号の振り直し
- (b) リード文などの非決定文の書き換え。決定件数の言い換えのような機械的な追随も含める。「以下の4点を決定する」を「以下の2点を決定する」と改めた類は、後継だけを読む読者には、決定が落ちた痕跡と区別がつかないためである。
- (c) `## Consequences` の調整。規則2 で節を置かなかったこと、規則4 で項目を除いたこと、後掲の射程の規定に従って本文を改めたことが、これに当たる。

**改変しなかったことによる不整合の開示**: 逐語転記は決定本文を一字も変えないため、原 ADR の文脈に依存した参照が、後継の中では解決できなくなる。規則3 に当たる `## Consequences` の項目も、本文を改めないため同じ不整合が生じる。これらは本文を改変せず、どの記述がどこを指すかを開示する。対象は次の4類型である（以下、不整合の4類型）。

1. 他の決定の番号への参照: 決定本文が原 ADR の中の別の決定を番号で指しており、その決定が別の後継へ移った、または反転した場合
2. 原 ADR 自身への自己言及: 決定本文が「本 ADR」などで原 ADR を指しており、後継では指し先が変わる場合
3. 後継が持たない節への参照: 決定本文が原 ADR の節を指しており、後継がその節を持たない場合
4. 規則3 に当たる `## Consequences` の項目: 反転によって、指し先または記述内容が偽になった場合

例: 決定本文に「決定3 の凍結原則」という記述が残り、その決定3 が別の後継へ移った場合は、後継の `## Context` に「決定本文に残る原 ADR 内の決定番号（読み替え）: 『決定3』は本 ADR の決定1 を指す」に相当する記載を1行以上置く。

**読み替えの開示の射程は `## Decision` に限る。** `## Consequences` に残る同種の参照は、本文を改めたうえで、改変の開示 (c) に含める。逐語の不変条件が掛かるのは `## Decision` だけであり、`## Consequences` は配分の規則の裁量の下にあって改変できるためである。改変できる対象へ読み替えの表を置くと、読者に余計な間接層を強いる。

例外は規則3 に当たる項目であり、規則3 が改変を禁じるため、本文を改めずに不整合の4類型の4 として開示する。この例外は反転された決定への言及に限る。反転を伴わない番号参照・自己言及・後継が持たない節への参照には及ばない。

### inbound 参照の付け替えに固有の扱い

分割の手順8 では、「共通: 退役に伴う inbound `Related:` の点検・付け替え」に加えて、次の4点を扱う。

- **後継ごとに参照行を分ける**: 1行が複数の決定を名指ししており、それらが別々の後継へ分かれた場合は、参照行を後継ごとに分ける。注釈本文は改変せず、名指しされた要素をそれぞれの行へ分配する。1行に畳んだまま片方の後継だけを指すと、もう一方への参照が失われる。後継へ逐語転記された決定と反転した決定が同じ行に同居する場合も、同様に行を分け、反転した側だけを共通の節の規定に従って書き替える。
- **注釈の中の決定番号を後継の番号へ揃える**: 分割の手順2 で後継の先頭番号を振り直した場合は、注釈の中の決定番号も後継の番号へ揃える。番号は指し先を同定する情報であり、その更新は注釈本文の改変に当たらない。改変しないのは、注釈の論旨・語調・名指しする決定の内容である。
- **後継の承認前に済ませてよい**: 後継が未承認で `validity` が空のうちは、レイヤ4 が fail-open で通る。そのため、付け替えを後継の承認より先に済ませてもよい。
- **原 ADR に残した決定を名指す参照**: 前掲「決定の振り分け」で原 ADR に残した決定には、付け替え先の後継が無い。その決定だけを名指す `Related:` 行は、原 ADR の退役でレイヤ4 の違反になる。是正は、`cross-references.md`「是正手段」のうち、事実を述べる記録の行への改稿か、参照行の除去から選ぶ。
  - 記録の行へ改める場合は `adr-reference-principle.md` に従う。規範本文を担う資産を、現在の参照先として現在形で指さない。
  - `Related:` 行以外の散文の引用も同じ扱いとする。
  - 原 ADR に残した決定と後継へ移った決定を1行が併せて名指す場合は、行を分け、残した決定の側だけを改める。

### 締めの検査

締めに、次の5点を確かめる。

- **網羅性（振り分けと分割の手順1・2）**: 原 ADR のトップレベル決定が、前掲「決定の振り分け」の3つの行き先のいずれか1つに分類されていること。未分類の決定と、2つ以上に分類された決定は、いずれも0件であること。退役する決定と原 ADR に残す決定は、後継へ逐語転記されていないこと。
  - 分割は生存決定を複数の後継へ散らすため、後継を1本ずつ検査するだけでは、全体の網羅を誰も見ないまま終わる。
  - 転記し忘れた決定は、逐語性の検査の切り出しにも入らず、差分として現れない。
  - 反転中の決定が後継へ紛れ込むと、反転が黙って無効になる。原 ADR に残す決定が紛れ込むと、却下代替を持たない後継が生まれる。
- **逐語性（分割の手順2）**: 後継ごとに、網羅性で「後継へ逐語転記する」に分類した決定だけを原 ADR から切り出し、後継の `## Decision` のトップレベル決定本文と突き合わせる。トップレベル項目の先頭番号を正規化したうえで、差分が無いこと。
  - 両辺を決定本文に揃えるのは、節どうしを比べると差分が出るのが正常になり、検査にならないためである。原 ADR の側は退役する決定を含み、後継の側はリード文などの非決定文を含みうる。
  - 切り出し元を、後継の内容ではなく網羅性の分類から定める。そのため、後継にだけ在る決定（退役する決定の混入や、分割中に書き足された決定）が差分として現れる。
  - 切り出した結果が両辺とも空でないことと、行数が一致することも確かめる。正規化や切り出しの失敗が、空の入力として差分ゼロに化けるためである。
- **却下代替（分割の手順3）**: 後継ごとに、担当決定の却下代替を、原 ADR の全ての節（`## Context`・`## Decision`・`## Consequences`）から列挙する。列挙した各却下代替が、後継の本文のいずれかの節に在ること。原 ADR に無い却下代替が、後継に現れていないこと。
  - 逐語性の検査は `## Decision` だけを見るため、`## Context` から運ぶ却下代替の欠落は、ほかのどの検査にも差分として現れない。
  - 担当決定のどれも原 ADR に却下代替を持たない後継は、原 ADR に残す側へ入れなかった理由（規範本文が ADR にしか無い、または判定に迷った）を確かめる。
- **開示（分割の手順2〜4）**: 前掲「開示」の2つを確かめる。
  - 改変の開示の (a)・(b) は、原 ADR と後継を突き合わせて改変の有無を判定する。(a) は逐語性の検査が正規化で潰し、(b) は逐語性の検査が両辺から外した情報であるため、開示の側でしか拾えない。
  - (c) は、`## Consequences` の原 ADR との差分を列挙する。他の後継が担う決定の帰結は、保持の対象に最初から入らないため、列挙から除く。除かないと、1→N の分割では必ず差分が生じ、配分の規則が適用できないという失敗が締めの側で再び起きる。節ごと置かなかったことも列挙に含める。節の中の項目だけを突き合わせると、節の不在は差分として現れない。
  - 列挙した各差分が、(c) のいずれかの開示に対応していること。どの開示にも対応しない差分が残る場合、それは開示の漏れではなく配分の誤りである。基本則が禁じる刈り込み、規則1 の重複掲載の漏れ、規則3 が禁じる本文の改変のいずれかであり、開示を足すのではなく配分を直して解消する。
  - 逐語の検証は `## Decision` の決定本文にだけ適用し、`## Consequences` には適用しない。意図した再構成が入るため、差分ゼロを要求できない。
  - 不整合の4類型について、後継の `## Decision` に該当する参照が残っていれば、また後継の `## Consequences` に規則3 に当たる項目があれば、後継の `## Context` に対応する読み替えの開示があること。
- **相互参照（分割の手順5〜8）**: 自己検証の lint が exit 0 であること。exit 0 に達しない場合は、前掲「上書き（上書き済み・双方向相互参照）」の是正手段に従う。
  - lint は、`superseded-by` のリスト値と各後継の `Supersedes:` を双方向に照合する。原 ADR 本文の `Superseded by:` が後継の一部しか挙げていない部分記載も検出する。行を1行も書かない場合は検出しないため、全ての後継が挙がっていることを目視で確かめる。
  - 原 ADR の `## <xref-heading>` を分割の前後で突き合わせ、分割に由来する変更が `Superseded by:` の追加だけであることを確かめる。分割以外を根拠とする変更が同時に入る場合は、その根拠を示す（例: 廃止された旧運用に由来する相互参照行の除去）。そのうえで、`Related:` などそれ以外の既存の行が変わっていないことを確かめる。
  - あわせて、「共通: 退役に伴う inbound `Related:` の点検・付け替え」の「締めの確認」を行う。

### 照合スクリプト

網羅性と逐語性は、同梱の照合スクリプト（`verify-split-verbatim.sh`）で確かめる。実行形は、`SKILL.md`「分割（多決定 ADR の部分上書き。5遷移とは別軸の構造操作）」が示す。入力は、原 ADR と対応表の2つである。対応表は一時ファイルに書き、分割の成果物に含めない。対応表には、原 ADR のトップレベル決定を、1行に1件ずつ次のいずれかの形で書く。

- 後継へ逐語転記する決定: `<原決定番号> <後継 ADR のファイル名> <後継決定番号>`
- 反転中で退役する決定: `<原決定番号> retire`
- 後継を立てず原 ADR に残す決定: `<原決定番号> keep`

後継 ADR は原 ADR と同じディレクトリに在るものとし、ファイル名で書く（`.md` は省いてよい）。

exit 0 が合格である。exit 1 は網羅性か逐語性の不成立であり、出力の `NG:` 行と差分が箇所を示す。exit 2 は入力の誤り（引数・ファイルの不在・対応表の行の書式）である。

スクリプトが決定として読むのは、`### <番号>.` の見出しか、行頭の `<番号>. ` の項目で書いたトップレベル決定である。原 ADR がどちらでもない形で決定を書いている場合は、切り出し結果が空になって exit 1 になる。その場合は、網羅性と逐語性の条件を目視で確かめる。

## 廃止（廃止済み）

後継 ADR なしで、ADR としての効力を終える。対象 ADR の front-matter と本文を編集する。

1. front-matter: `validity: <validity-abandoned>` にする。`status` は変えず、`superseded-by` は付けない（空のまま）。
2. `## Consequences` の末尾など本文に、廃止の日時と退役の理由を追記する。退役の理由には、(a) 放棄か移管かのいずれであるかを明示し、(b) 移管の場合は移送先を時点を固定した過去形で書く。これは `adr-reference-principle.md` の適用である。同原則は退役 ADR の決定本文を射程外とするため、退役と同時に本文へ参照を書くこの遷移では、本手順が担う。
3. 後継が無いため、対象 ADR 自身の `## <xref-heading>` は変えない。
4. 他の ADR から対象 ADR を指す参照を、後掲「共通: 退役に伴う inbound `Related:` の点検・付け替え」に従って点検する。廃止は、後継の無い退役である。廃止では inbound の参照に機械検査が発火しないため、点検したことを確かめる場所は、同節の「締めの確認」しかない。

## 却下（却下）

一度も承認に至らず終わる終端である。対象 ADR の front-matter と本文を編集する。

1. front-matter: `status: <status-rejected>` にする。`validity`・`superseded-by` は付けない（空のまま）。廃止と違い、`validity` を空に保つ。
2. 却下の理由を本文に追記する。

## 取り消し（誤った退役の訂正）

誤って行った退役（上書き・廃止）を取り消し、対象 ADR を `validity-active` へ戻す。取り消しは遷移ではなく、退役の記録の訂正である。状態の型との関係は、`adr-model.md`「状態の型」と「遷移の表」が持つ。

分割の取り消しは、本手続きの射程外である。分割の後継は生存決定を逐語転記しているため、原 ADR を `validity-active` へ戻すと、同じ決定が2本の `validity-active` の ADR に並ぶ。分割の誤りは、後継に対する通常の遷移で訂正する。

取り消しの判定は、退役済みの ADR 1本ずつに対して行う。判定が問うのは、退役を決めた判定が、その時点の入力に照らして正しかったかである。退役の後に起きた変化は、取り消しの理由にならない。

起動の主体と時期は限らない。格下げ判定は随時の起動を退けている（`adr-demotion.md`「判定の起動」）。それは、判定者のぶれが廃止の側、つまり記録を失う側へ結論を動かすためである。

取り消しの判定でぶれが動かす先は、廃止では `validity-active` へ戻す側、上書きでは後継から辿れる状態を保つ側であり、いずれも記録を失わない。廃止の取り消しで起きうるのは index に残る ADR が増えることであり、これは格下げ判定の安全側（迷ったら残す）が受け入れている誤りと同じ側にある。

### 判定基準

誤りかどうかは、その退役を決めたときの基準を再適用して判定する。起票の判定基準（`adr-scoping.md`）は、いずれの取り消しの判定にも用いない。

- **廃止の取り消し**: `adr-demotion.md` の格下げ判定の基準を対象 ADR へ再適用し、条件が1つでも不成立であれば、その退役は誤りとする。同基準の安全側の向きも、そのまま掛かる。判定の入力は次に固定する。
  - 条件1 の走査対象は、対象 ADR の本文から、廃止の手順2 が追記した廃止の日時と退役の理由を除いた部分とする。退役の後は決定内容が凍結されるため、条件1 の入力は退役の前と変わらない。
  - 条件2 は、廃止の手順1 で `validity: <validity-abandoned>` を書き込んだ変更の時点の資産で判定する。同基準の時制の規定（判定時点の状態を見る）は、取り消しの判定では退役の時点に読み替える。
  - 退役の後に担い手が失われた場合（移送先の削除など）は、退役の誤りではない。失われた規範を改めて記録するかは、新たな決定として起票の判定に掛ける。
- **上書きの取り消し**: 旧 ADR の `## Decision` が結論を与えた事項を列挙する。後継の `## Decision` がそのどれについても結論・方向・前提を変えていないとき、その上書きは誤りとする。
  - 事項ごとの判定は、`edit-decision.md` の判定基準の第1問に従う。旧 ADR が結論を与えていない事項を後継が決めた場合の扱いも、同ファイルに従う。
  - 後継の `## Decision` が旧 ADR の決定を写している場合（字句どおりに写した場合も、同じ結論を書き直した場合も含む）は、射程外とする。取り消すと同じ決定が2本の `validity-active` の ADR に並ぶためであり、分割を射程外とする理由と同じである。この場合は、後継に対する通常の遷移で訂正する。
  - **判定に迷う場合は誤りとしない（上書きを維持する）。** `validity-superseded` の ADR は `superseded-by` から辿れ、記録が失われないためである。`edit-decision.md` の安全則（迷ったら core）と同じ向きである。

### 実行手順

実行前に、前掲「共通: 遷移前の状態の確認」を行う。`validity` が、取り消す退役に応じた値（`validity-abandoned` または `validity-superseded`）であることを確かめる。上書きの取り消しでは、後継が `validity-active` であることも確かめる。後継が既に退役している場合は、後継の本文が凍結の下にあり、上書きの取り消しの手順3 を行えないため、中断して利用者へ確かめる。

**廃止の取り消し**

1. front-matter を `validity: <validity-active>` へ戻す。`status` と `superseded-by`（空）は変えない。
2. 廃止の手順2 が本文へ追記した廃止の日時と退役の理由は消さない。退役が行われた事実の記録だからである。
3. 後掲「記録要件」に従い、対象 ADR の `## 変更履歴` へ1行を追記する。

**上書きの取り消し**

1. 旧 ADR の front-matter を `validity: <validity-active>` へ戻し、`superseded-by` を空にする。
2. 旧 ADR の `## <xref-heading>` から `Superseded by: <後継>` の行を除く。front-matter の状態を本文へ写した表示であり、除いても決定の記録は変わらない。
3. 後継 ADR の `## <xref-heading>` から `Supersedes: <旧>` の行を除く。後継は `validity-active` のまま残る。両者の関連を残す場合は、同じ位置へ `- Related: <旧の full slug>` を置く。
4. 後継を指す `Related:` 行のうち、注釈が旧 ADR の決定を名指ししている行を、旧 ADR へ戻す。上書きの手順4 で付け替えた行がこれに当たる。`Related:` 行以外の記述も、同じ判定で点検する。
5. 後掲「記録要件」に従い、旧 ADR の `## 変更履歴` へ1行を追記する。

上書きの取り消しの手順3・4 は、`validity-active` の ADR への編集であり、分類は `edit-decision.md` に従う。上書きの取り消しの手順1・3 の一方だけを行うと、lint-adr のレイヤ1（front-matter スキーマ）またはレイヤ3（相互参照双方向性）が違反として報告する。上書きの取り消しの手順2・4 と記録要件の実施は lint の exit code に現れないため、締めに目視で確かめる。

### 記録要件

対象 ADR（上書きの取り消しでは旧 ADR）の `## 変更履歴` へ、次の3点を含む1行を追記する。

- 取り消した退役の種類（廃止／上書き）。上書きでは後継の full slug を添える。
- 取り消した日付
- 誤りと判定した根拠。廃止では、不成立とした条件と、その判定を下した決定を書く。不成立が迷いによる場合（安全側の向きによる不成立）は、その旨も書く。上書きでは、結論が変わっていないと判定した事項を書く。

記録を対象 ADR 自身に置くのは、ADR ファイルがあらゆる消費面に対して自己完結するという原則（`edit-decision.md`）による。取り消しは決定内容の編集ではないため、core／非core／些末の分類には掛けない。節を持たない ADR で `## 変更履歴` を新設する場合の配置は、`template.md` の配置規約に従う。

### 規範本文を移送していた場合

廃止の際に規範本文や採用理由を移送先へ併記していた場合、取り消しても移送先の記述を削除しない。取り消しの後は、規範本文が対象 ADR と移送先の2か所に在る状態になる。

- 規範本文（何が正しいか）の正本は、移送先とする。対象 ADR は、決定とその却下代替の記録として index へ戻る（`adr-demotion.md`「ADR の固有価値」）。
- 二重に在ること自体は、格下げ判定のどの条件の成否も変えない。移送先は条件2 の担い手に数え、ADR の本文に同じ規範が残ることは (c) の根拠にしない。
- 取り消しの根拠になった条件が不成立のままである限り、二重に在ることを理由に再び廃止しない（後掲「取り消し後の再判定」）。

### 取り消し後の再判定

取り消した ADR を後に格下げ判定へ掛けるときは、取り消しの記録が不成立とした条件を次のとおり扱う。その条件を成立と判定するには、取り消しの後にその条件の入力が変わったことを、判定の記録に示す。条件1 では本文の改訂、条件2 では担い手の変化がこれに当たる。入力が変わっていないまま、同じ条件の判定を覆さない。判定者のぶれによって、取り消しと再度の廃止が往復するのを防ぐためである。

## 共通: 退役に伴う inbound `Related:` の点検・付け替え

ADR を退役させるとき（上書き・分割・廃止）、退役させる ADR を指している側の参照を点検する。各操作の手順が退役させる ADR 自身の `## <xref-heading>` を扱うのに対し、本節はそれを外から指している参照を扱う。上書き・分割・廃止の3節は、いずれも本節を参照する。

`Related:` の書式規約・機械検査の範囲・是正手段は、`cross-references.md` が定める。本節はそれを前提に、退役に伴う点検と付け替えの実務を述べる。

### 是正の強度

是正の強度は、後継の有無で非対称である。

- **後継がある退役（上書き・分割）**: 退役させる ADR を、現行の出典として指し続けない。対象は、`Related:` 行と、`Related:` 行以外の現況参照（後掲「`Related:` 行以外を別途特定する」）の双方である。
  - `Related:` 行は、放置すると参照先の `validity` が `validity-superseded` になり、lint-adr のレイヤ4（参照先退役）が違反する。自己検証が exit 0 に達しないことで、機械的に担保される。
  - `Related:` 行以外は lint が発火しないため、後掲「締めの確認」の目視でだけ担保される。**機械検査が無いことは、義務が無いことを意味しない。**
- **後継の無い廃止**: 点検だけを行い、是正は任意である。検査が違反を出さない理由と、是正してよい場合は、`cross-references.md`「是正手段」が定める。

どちらの場合も、是正の手段（後継への差し替え、事実を述べる記録の行への改稿、参照行の除去）は `cross-references.md`「是正手段」に従って選ぶ。

**タイミング**: 退役させる側の `validity` の書き換えより後にしない。同じコミットに含めてもよいし、先行するコミットで済ませてもよい。退役だけが先行した状態はコミットできない。

### 対象の特定

`Grep` で `<対象ディレクトリ>` の配下を走査し、退役させる ADR を指す `Related:` 行を洗い出す。パターンは `^[[:space:]]*(-[[:space:]]*)?Related:.*<退役させる ADR の full slug>` である。

- バレットを任意とするのは規約どおりである。バレット必須のパターンで絞ると、`Related:` を直に書いた行を取りこぼす。
- `Related:` の直後に full slug が隣接する前提も置かない。直後に固定したパターンは、規約が許す markdown リンクの書式（`Related: [ADR-x](./ADR-x.md)`）を取りこぼす。
- ヒットのうち、参照元自身が `validity-active` の行だけを対象とする。参照元が退役 ADR の行は、凍結の下にあるため編集しない。
- 1行に複数の ADR を列挙した行も、このパターンでヒットしうる。2件目以降の扱いは後掲「2件目以降の列挙は人手で確かめる」に従う。

### 付け替え先の決定

後継がある退役では、各行の注釈が名指ししている決定を引き継いだ後継へ差し替える。後継が1本の上書きでも、判定は同じ形を取る。注釈本文は改変しない。改変しないのは、注釈の論旨・語調・名指しする決定の内容である。差し替えで関係の意味や経緯が失われる場合は、`cross-references.md`「是正手段」に従い、`Related:` のラベルを外して事実を述べる記録の行へ改めてもよい。

名指しされた決定が反転した場合は、注釈本文を改変しないという規定が掛からない。この規定は、後継へ逐語転記された決定を指す参照に対するものである。反転された決定を指す参照は注釈本文が偽になるため、反転の事実を注釈へ反映する。例えば、旧い注釈が「…として不変のまま引き継がれた」と述べていれば、反転によって何へ置き換わったかを述べる記述に改める。

### `Related:` 行以外を別途特定する

機械検査の対象は `Related:` 行に限られる。そのため、次の2つは同じ死角に入る。

- (i) `README.md` などの非 ADR ファイル。lint の走査対象は、`<対象ディレクトリ>` の配下の `ADR-*.md` に限られる。
- (ii) `validity-active` の ADR 本文の `## Context`／`## Consequences` にある散文の引用。引用の形は `<退役させる ADR> 決定N` などである。

退役させる ADR の識別子でリポジトリ全体を横断検索し、1件ずつ、現況参照か記録かを判定する。

- 現行の規則や構造の出典として、現在形で名指ししている箇所は、現況参照である。後継がある退役では是正する。後継の無い廃止では、是正は任意である（前掲「是正の強度」）。是正する場合の手段は、どちらも `cross-references.md`「是正手段」に従って選ぶ。
- 歴史的な経緯として過去の事実を述べる散文は、記録として据え置く。付け替えると史実が偽になるためである。
- 判定に迷う場合は、識別子を後継へ置き換えて読み直す。偽になるなら記録、真のままなら現況参照とする。
  - この読み直しは、後継がある退役でだけ成り立つ。廃止には後継が無く、置き換える操作自体ができない。
  - 後継がある退役でも、名指しされた決定が反転している場合は効かない。反転された決定は後継へ置き換えれば必ず偽になり、現在形の規則の言明まで一律に記録の側へ倒れるためである。
  - 読み直しが使えない場合は、現在形の規則の言明か、過去の事実を述べる散文かという前段の判定だけで振り分ける。

### 2件目以降の列挙は人手で確かめる

1行に複数の ADR を列挙した参照行で、2件目以降に退役させる ADR が現れる場合がある。判定の単位が先頭の full slug だけであるため、付け替えの漏れが検査を素通りする。

### 編集分類と `## 変更履歴`

本節が触るのは `validity-active` の ADR であり、編集の分類が掛かる。分類は `edit-decision.md` に従う。参照の付け替えが些末と非core のどちらに当たるかの判別例も、同ファイルが持つ。非core と判定した編集は、対象 ADR の `## 変更履歴` に1行を追記する。節が無い ADR で新設する場合の配置は、`template.md` の配置規約に従う。

### 締めの確認

本節の作業のうち次の3点は、lint の exit code に現れない。上書き・分割・廃止のそれぞれの締めで、目視で確かめる。前掲「対象の特定」の `Grep` が0件でも、締めの確認は省かない。`Grep` は `Related:` 行だけを対象とし、`Related:` 行以外の死角は件数と関係なく残るためである。確かめる内容は、前掲「是正の強度」の非対称に従う。

- **`Related:` 行以外への付け替え**: 後継がある退役では、退役させる ADR を現行の出典として指し続けている記述が残っていないこと。差し替え・記録の行への改稿・除去のいずれかで解消していればよい。後継の無い廃止では、点検を行ったことだけを確かめ、是正の有無は問わない。
- **1行に複数の ADR を列挙した参照行の2件目以降**: 後継がある退役では、`Related:` 行として `validity-superseded` の ADR を指し続けていないこと。後継の無い廃止では、点検を行ったこと。
- **非core と判定した編集の `## 変更履歴` への追記**: 前掲「編集分類と `## 変更履歴`」で非core と判定した ADR に、`## 変更履歴` の1行が追記されていること。

## 隔離検証（baseline red のときのフォールバック）

自己検証は、対象ディレクトリを直接 lint する。操作の前から対象ディレクトリが exit 1 で、本操作と無関係な違反が exit 0 への到達を妨げる場合に限り、一時ディレクトリへ隔離してコピーし、そこで検証してよい。

**含めるファイルの原則**: 変更・生成した ADR と、それが相互参照で指す相手を全て含める。forward と reverse の両方向である。forward は front-matter の `superseded-by` が指す後継、reverse は `## <xref-heading>` の `Supersedes:` が指す先行である。漏らすと、レイヤ3 が false negative（正しい操作でも exit 1）になる。

- 上書きは、旧 ADR と後継 ADR の2ファイルを含める。旧 ADR だけだと、旧 ADR の `superseded-by` が指す後継が無いため、forward が発火する（実測で exit 1）。旧 ADR と後継が揃えば、exit 0 になる。
- 分割は、原 ADR と全ての後継を含める。
- 承認・上書き（旧 ADR）・廃止・却下の対象が過去に別の ADR を上書きしていて、本文に `Supersedes: <先行>` を持つ場合は、先行 ADR も含める。対象だけだと、reverse が先行の不在で発火する（実測で exit 1）。廃止で現実に起きるケースである。
- 上書きの取り消しも、旧 ADR と後継 ADR の2ファイルを含める。後継に消し忘れた `Supersedes:` を、reverse が検出できるようにするためである。
- 起票は、通常は相互参照を持たないため、生成した ADR だけでよい。

コピーの後、`adr-model.md`「遷移の表」で `validity` を変える操作では、隔離ディレクトリで `index.md` を再生成してから lint する。
