# 相互参照の規約（cross-references.md）

ADR 本文 `## 関連ADR` に書く関係の語彙と、`Related:` の書式規約・機械検査の範囲を定める。

**本ファイルは `Related:` の書式規約と機械検査の範囲の単一出典である。** drift-lint の実装と本規約が食い違う場合は本規約を正とし、実装側を是正する。`Supersedes:` / `Superseded by:` の側は上書き・分割の実行手順が持つ（下記「関係語彙」）。

## 関係語彙

`## 関連ADR` に書ける関係は次の3種である。

| 語彙 | 意味 |
|---|---|
| `Supersedes:` | 本 ADR が旧 ADR を上書きする。旧 ADR 側の front-matter `superseded-by` が本 ADR を指す |
| `Superseded by:` | 本 ADR が後継に上書きされた。本 ADR 自身の `superseded-by` にも後継の full slug を書く |
| `Related:` | 直接の上書き関係はない関連 |

`Supersedes:` / `Superseded by:` の書式要件（行頭バレット必須・双方向の厳格な一致）と写入手順は、上書き・分割の実行手順を持つ `transitions.md` が定める。本ファイルは `Related:` を扱う。

関連 Issue を併記してよい（書式: `関連Issue: #<番号>`、複数件はカンマ区切り）。Issue 参照は機械検査の対象外である。

## `Related:` の書式規約

1. **判定単位は `Related:` 以降で最初に現れる ADR stem** である。1行が指す参照先は1件と解釈される
2. **書式は不問**である。行頭バレット（`- `）の有無、markdown リンク（`[stem](./stem.md)`）の有無、リンクラベルが stem か説明文かを問わない。`- Related: [詳細](./ADR-X.md)` も `ADR-X` を指すものとして扱う
3. **参照先は full slug 完全一致で解決する**。識別子部だけの略記（`ADR-YYYYMMDDHHMM-NN`）では解決されず、参照先不在として dangling 参照違反になる
4. **1行に複数の ADR を列挙すると、2件目以降は検査されない**。判定単位が先頭 stem だけであるため、2件目以降の参照先が退役・不在になっても機械検査は素通りする。禁止はしないが、**検査を効かせたい参照は1行1件で書く**こと。複数列挙する場合、2件目以降の生存性は人手で担保する
5. **先頭 stem より後に現れる識別子は拾われない**。注釈で他の ADR に言及しても参照とは見なされない（誤検出を避けるための仕様）。逆に、**注釈を先頭 stem の前に置くと注釈中の識別子が参照先になる**（`- Related: （X の後継である）Y` は X を指す）。注釈は参照先の後ろに置くこと
6. **同一ファイル内で同じ stem を複数行から指しても、違反の報告は1件へ集約される**。同じ参照先を plain 行と markdown リンク行の双方で指した場合も報告は1回である

## 機械検査の範囲

`Related:` の参照は、参照先の**生存性**（後継へ置き換えられていないか）と**実在性**（ファイルがあるか）が機械検査される。範囲には次の非対称がある。知らないと過剰な作業か見落としのどちらかになる。

### 検査される側（source）

**`validity: 有効` な ADR の `Related:` だけが検査対象**である。退役（`上書き済み` / `廃止済み`）した ADR は凍結原則の下にあり編集できないため、そこに残る参照は検査しない。編集できない対象へ修復不能な違反を課さないためである。提案中・却下の ADR も、まだ確定した決定の一部でないため対象外とする。

### 違反となる状態

- **参照先退役**: 参照先が実在し、その `validity` が `上書き済み` である。**後継を持たない退役（`廃止済み`）は違反にしない** — 参照先が上書きされている場合は「その決定を引き継いだ後継へ差し替える」という一意の是正があるが、後継が無い場合は差し替え先が存在せず、参照行の除去か `Related:` ラベルの剥がししか選べない。検査が是正ではなく回避を生産するため、建設的な是正が定まる場合へ限定する
- **dangling 参照**: 参照先の `<full slug>.md` が対象ディレクトリに実在しない

### 検査されないこと

- **双方向性は強制しない。一方向の `Related:` は合法**である。`Supersedes:` が双方向の厳格な一致を要求するのと対照的である。双方向を強制すると、後継が `Related:` を書くたび参照先へさかのぼって追記する必要が生じ、退役 ADR では実行できない。双方向は慣用（推奨）に留める
- **参照先が旧形式（front-matter を持たない）または `validity` 空（提案中・却下）の場合は違反にしない**（fail-open）。退役とも dangling とも判定しない
- Issue 番号参照（`#<番号>`）の実在。検査はオフライン実行を前提とし、外部照会を行わない

### 是正手段

違反が出たときの直し方は参照先の状態で決まる。

- **参照先が上書き済みである** → その決定を引き継いだ**後継へ差し替える**。参照先が複数の後継へ分割されている場合は、注釈が名指ししている決定を引き継いだ後継を選ぶ
- **参照先が実在しない（dangling）** → 識別子の誤りなら正しい full slug へ直す。指すべき対象が corpus に存在しないなら、**参照行そのものを除去する**

差し替えでも除去でも失われる情報がある場合（関係の意味論・経緯）は、行を消さずに**事実を述べる記録の行へ改める**。検査対象となるのは行頭（バレットは任意）が `Related:` で始まる行に限られるため、`Related:` ラベルを外して経緯を述べる散文へ改めた行は検査に掛からない。関係の意味論を残したまま違反を解消できる。

**後継を持たない退役（後継なしの廃止）を指す参照は、そもそも違反にならない。** したがって是正は不要であり、上記2分岐のどちらも適用されない。ただし機械検査を通ることと、参照の記述が現況と合っていることは別である。退役によって「現行の出典として指している」という記述が陳腐化する場合に限り、記録の行へ改めてよい（任意。除去も改稿も義務ではない）。

本節の是正は `validity: 有効` な ADR への編集であり、core／非core／些末の分類と `## 変更履歴` の扱いが伴う。分類の判定と履歴の残し方は、SKILL.md 本体が指す編集判定の規約および遷移手順に従う。
