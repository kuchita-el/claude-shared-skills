# 判定結果の行き先と命名規約の振り分け（adr-destination.md）

ADR 化要否の判定を終えた対象を、どこへ置くかを定める。判定そのもの（必要条件・粒度判定基準・判定する入力の値域と定義・閾値とスコア境界の定義）は `adr-scoping.md` が実体を持ち、本ファイルでは再定義しない。本ファイルの分岐ラベルに現れる閾値と値域語は、`adr-scoping.md` が定義した判定結果を指すためのものである。

命名規約を ADR の対象に含めるかの振り分けも、一般則を命名規約へ当てはめた特化として本ファイルが持つ。

## 判定結果の行き先

粒度判定基準の結論ごとに、対象の置き場所を次のとおりとする。ADR に記録が無いことは、その規範が無効であることも、置き場所が無いことも意味しない。合計3点以上の決定のうち、起票の時点の判定が掛かるものは、起票の時点に達した場合だけ次の「ADR 化する」の2分岐へ進む。判定が掛かる射程は `adr-scoping.md`「起票のタイミングとエスカレーション」が定める。達していないものの行き先は後掲「起票の時点に達していない決定の行き先」による。

**ADR 化する（合計3点以上）の行き先**

- 既存 ADR が扱っていない枠組みを立てる場合、または既存 ADR の結論・方向・前提を反転・置換する場合 → **新規 ADR** の側へ振り分ける
- `validity-active` の既存 ADR が定める枠組みに収まり、**その枠組みを保ったまま別の面を追加するだけ**の場合 → **非core 改訂**の側へ振り分ける。新規 ADR を起こさず当該 ADR を改訂するのは、同じ主題を複数の ADR へ分散させないためである。別の面とは、適用範囲・条件・パラメータ値・理由付けである

いずれも振り分け先の提示であって、分類（core／非core／些末）の確定ではない。分類基準の実体、確定の手続き（利用者へ問うこと）、安全則（迷えば core 寄り＝新規 ADR に倒す）、選んだ操作の手順と変更履歴の残し方は、すべて `edit-decision.md` に従う。本節でこれらを再定義しない。非core 改訂の側へ振り分けた対象も、当該 ADR の枠組みの中に収まるかを同ファイルが分類の前に問い直し、収まらなければ新規 ADR の側へ戻す。退役（`validity-superseded`・`validity-abandoned`）した ADR は同ファイルの凍結原則により決定内容の改訂を受けないため、上の2分岐は掛からない。

**ADR 化しない（合計3点未満）の行き先**

次の3分岐を上から順に当てはめ、最初に当たった分岐へ置く。第3分岐は第1・第2分岐のどちらにも当たらないものを受けるため、どの対象もちょうど1つの分岐へ置かれる。必要条件が成り立たず点数を数えなかった決定にも、同じ3分岐を掛ける。

- **第1分岐: 規範を担う保持先が値域(A)に在る** → その資産である**実装・テスト資産・操作手順**に置く。値域(A)は `adr-scoping.md`「判定する入力の値域と定義」の項目3の保持先の値域を指す。採用理由と既知の限界は当該資産のコメント等に併記して自己完結させる
- **第2分岐: 第1分岐に当たらず、次の2条件の少なくとも一方に当たる規範** → **共有規約文書**（規約ファイル・プロジェクト指示）に置く。2条件は選言であり、一方に当たれば足りる。採用理由と既知の限界は当該文書へ併記して自己完結させる。併記の未了が項目3の点数を動かすのは、同居判定の1点条件に当たる決定に限る（併記により値域(B) が成立し0点へ移る）。当たらない決定では点数は動かないが、併記を欠いたまま放置すれば理由は次の判定者へ渡らずに失われる
  - **後続の変更を拘束する**: 規範の本文が、判定対象の変更より後に行われる変更へ、何をする・しないを指示している
  - **適用先が2単位以上ある**: 項目2で数えた適用先が2単位以上である。何を1単位と数え、何を除外するかは `adr-scoping.md`「判定する入力の値域と定義」の項目2の定めが正本であり、本分岐は独自に数え直さない。必要条件が成り立たず点数を数えなかった決定でも、本条件のために同じ定めで適用先を数える
- **第3分岐: 第1・第2分岐のいずれにも当たらない判断** → **その変更の説明**に書く。変更の説明とは、その変更が PR を経る場合は PR 説明、経ない場合はコミットメッセージをいう。後続の変更を拘束せず、適用先も1単位以下であるため、単一の変更に閉じる判断である。この記録は、`adr-scoping.md`「起票のタイミングとエスカレーション」の条件1が数える保留中の記録に当たらない。他の箇所で同じ問いが再出したときは、改めて4項目から判定する

**第1分岐の入口と置き場所の区別**: 入口を決めるのは、規範を担う保持先が値域(A)に在るかどうかだけである。第1分岐の入口と、項目3が値域(A)として0点に数える保持先は、同じ集合を指す。値域(A)が散文だけの記述を含まないことも、`adr-scoping.md` の同じ節が定めるとおりである。「実装・テスト資産・操作手順」は入口に当たった規範の置き場所の呼び名であり、入口の条件ではない。値域(A)の保持先が在るかは、判定対象の変更を適用した後の状態で見る。同じ変更で実装や検査を足して規範を担わせる場合は、第1分岐に当たる。行き先は、判定対象の変更が規範をどこへ置くかを決めるものだからである。したがって、実装ファイル・テスト・手順書の中に書かれていても、規範を担わない散文だけの記述しか持たない規範は第1分岐に当たらない。

違反を検査する仕組みの状態（項目4 の `現に阻止`／`警告どまり`／`検査なし`）は、第1分岐の入口を左右しない。値域(A)の保持先が在れば、検査が警告どまりで阻止しない場合も、検査が皆無の場合も第1分岐に置く。阻止まで動かすか、検査を足すかは当該資産の実装の課題であり、置き場所を変えない。値域(A)の保持先が無い規範は、検査の状態を問わず第1分岐に当たらない。値域(A)に当たるか迷う場合は、第1分岐に当たらないものとして第2分岐の判定へ進む。

**「後続の変更を拘束する」の判定**: 入力は規範の本文だけであり、作業者の人数や将来の見込みは入力にしない。判定対象の変更で何を採ったかだけを述べ、以後の変更への指示を含まない判断は当たらない。当たるか迷う場合は当たるものとする。共有規約文書へ置いた規範は不要になれば外せるが、変更の説明にだけ置いた規範は後続の変更から読まれないためである。

ただし既に記録済みの決定そのものへ触れる編集は、粒度判定の点数ではなく `edit-decision.md` の分類が入口となる。スコア境界未満であることは、既存 ADR への改訂を妨げない。

この一般則が最も効くのは、ADR 運用そのものや開発の進め方を主題とする規範である。この層は規範が実装・テスト資産・操作手順の側で既に強制されていることが多く、そのぶん記録の不在が欠落と誤読されやすい。

**起票の時点に達していない決定の行き先**

合計3点以上と判定しても、`adr-scoping.md`「起票のタイミングとエスカレーション」が定める起票の時点に達していない決定は、前掲「ADR 化する」の2分岐へ進めず保留する。保留中の決定は次のとおり置く。

- **判定の記録** → **その変更の説明**（前掲の第3分岐の定義による）に書く。記録には次の4点を含める。第1に決定の内容、第2に必要条件で特定した却下代替（採った選択肢・却下した選択肢・却下理由）である。第3に4項目の点数と `adr-scoping.md`「判定に添える申告」が求める申告（適用先の列挙を含む）、第4に起票の時点に達していないため保留した旨である。後の判定が起票の時点を判定するとき、この記録の選択肢と適用先の列挙が照合の入力になる
- **決定の本文** → 前掲「ADR 化しない」の3分岐が決める置き場所に置く。第3分岐に当たる場合は、判定の記録と同じ変更の説明に置くことになる。第1・第2分岐に当たる場合、変更の説明に書いた判定の記録は本文の置き場所の代わりにならない

## 命名規約の ADR 化基準

### 本節の射程

本節が対象とするのは、**識別子——変数・関数・型・ファイル・ディレクトリ等、コードや成果物の中で対象を指し示す名前——に、どの名前を与えるか、およびその名前をどう綴るか**を定める規範に限る。次の3つは名前そのものを定めていないため、本節の射程外とする。

- **記述の並び順とレイアウト**（import 順、宣言の並び、空白・改行・字下げ）。並べ方・空け方は名前ではない
- **成果物メタデータの値の形式**（front-matter の値、設定値、コミットメッセージの書式や言語）。名前ではない値に掛かる形式である
- **識別子の採番形式**（連番・日付・ハッシュ等の採り方と、その桁数、および採番部分の内部にある区切り記号の形式）。どの名前を与えるかではなく、値の生成規則である。識別子が採番部分と綴り部分を併せ持つ場合、射程外となるのは採番部分だけであり、綴り部分は射程内として扱う。**区切り記号は、両側とも採番部分であるものだけが採番部分に属し、それ以外はすべて綴り部分に属する**（片側でも綴り部分に接するものに加え、識別子の端にあって片側に何も接しないものも綴り部分とする）。例として `ADR-YYYYMMDDHHMM-NN` では、日付部と連番部を隔てるハイフンは両側とも採番部分であるため射程外、`ADR` と日付部を隔てるハイフンは綴り部分に接するため射程内である

**この3類型は個別の列挙であり、識別子の一部を成すかどうかにかかわらず射程外である。** 「識別子の一部を成すか」を3類型の判別基準として読んではならない——第3類型が挙げる採番部分は識別子の一部を成すが、どの名前を与えるかではなく値の生成規則であるため射程外に置いている。

一方、**成果物をツリー上のどのディレクトリへ置くかを定めるファイル配置規約は、本節の射程内とする。** ツリー上の所在は、その成果物を指し示す完全なパスという識別子の一部を与えるためである。第1類型（記述の並び順とレイアウト）が射程外である理由は「成果物の内部での並べ方が識別子のいずれの部分にもならないため」であり、ツリー上の配置が射程内・成果物内部の配置が射程外という非対称はこの2つの対比に限った説明である（前段のとおり、3類型全体を貫く基準ではない）。これに対し、どの内容をどの成果物へ入れるかを定める分割の規範は、名前を与えても綴りを定めてもいないため射程外とする。

射程外の規範には本節の表も末尾の例外も掛からない。行き先は前掲「判定結果の行き先」の一般則3分岐が決める。

### 振り分け

射程内の命名規約のうち ADR 化対象とするかどうかは、構造的か書式的かで振り分ける。

| 種別 | 特徴 | 例 | 配置 |
|---|---|---|---|
| 構造的命名規約 | 横断・後戻りコスト高 | ファイル配置規約、集約名、ドメイン用語統一 | ADR 化（`docs/adr/`） |
| 書式的命名規約 | 表記に閉じる・原理的にツール強制可能 | 変数命名、識別子の大文字小文字と区切り記号の使い分け、接頭辞・接尾辞の綴り | Linter／フォーマッタ規約として配置（ADR 外） |

本表は前掲「判定結果の行き先」の一般則を命名規約へ当てはめたものであり、強制が現に動いている場合は一般則の典型例として対応する（強制が未実装の場合の扱いは本節末尾の例外による）。構造的命名規約の行（ADR 化）は、一般則の「ADR 化する（合計3点以上）の行き先」に対応する。書式的命名規約の行（Linter／フォーマッタ規約として配置＝ADR 外）は、「ADR 化しない（合計3点未満）の行き先」の第1分岐に対応する。同分岐は規範を担う保持先が値域(A)に在るものを実装・テスト資産・操作手順に置き、Linter／フォーマッタ本体とその設定がここでの値域(A)の保持先にあたる。表の軸（構造的／書式的）と一般則の軸（値域(A)の保持先の有無）は直交するため、対応は一対一ではない。構造的命名規約であってもツールで現に強制されている場合は、次の指示どおり項目4に照らして振り分ける。

ツールで自動強制できる規約は ADR 外とする。判断に迷う場合は、粒度判定基準の項目4（ツールで自動強制できない）に照らして振り分ける。

本節の「ツールで自動強制できる」は項目4と同じ現在時制で読む（違反が現に検査され、作業が阻止されている状態）。ただし前段のタイブレーカーは対象が構造的か書式的かを決めるためのものであり、**原理的に**強制できるかを問う。これは項目4の点数を決める問いとは別であり、強制が未実装でも原理的に強制できる規約は書式的の側へ振り分ける。

**書式的命名規約は、強制がまだ実装されていない場合も ADR 外とする。** 行き先は強制の実装（Linter／フォーマッタ規約とその設定）であり、採用理由は当該設定へ併記する。強制が未実装であることは、記録すべき設計判断ではなく実装の欠落だからである。強制が未実装の場合に限り、本表は一般則の特化ではなく**例外**として働く。粒度判定基準の合計が3点へ届く場合も、振り分けは表が決める。**本例外が掛かるのは、必要条件が成立し、かつ対象が本節の射程内である場合に限る**（次項「適用順」）。

### 適用順

必要条件・射程・本表の順に掛ける。

1. **必要条件（却下代替が在ること）は本節にも前置する。** 不成立なら点数を数えず、本表も末尾の例外も掛からない。行き先は一般則3分岐が決める。必要条件より先に本節を掛けないのは、掛ければ却下代替を持たない決定について本節だけが独自の行き先を持つことになり、`adr-scoping.md`「必要条件: 却下代替が在ること」節が定める「不成立なら行き先は一般則に従う」と衝突するためである
2. 必要条件が成立し、対象が**射程内**であれば、本表と末尾の例外が掛かる。このうち一般則3分岐に**優先するのは末尾の例外だけ**であり、優先が働くのは書式的命名規約について強制が未実装の場合に限る。構造的命名規約の行は一般則の「ADR 化する（合計3点以上）の行き先」に対応する写像であって優越ではないため、粒度判定の合計がスコア境界未満であれば ADR 化せず、行き先は一般則3分岐が決める
3. 必要条件が成立していても、対象が**射程外**であれば、本表も末尾の例外も掛からず、一般則3分岐が決める
