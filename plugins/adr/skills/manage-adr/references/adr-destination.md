# 判定結果の行き先と命名規約の振り分け（adr-destination.md）

ADR 化要否の判定を終えた対象を、どこへ置くかを定める。判定そのもの（必要条件・粒度判定基準・判定する入力の値域と定義・閾値とスコア境界の定義）は `adr-scoping.md` が実体を持ち、本ファイルでは再定義しない。本ファイルの分岐ラベルに現れる閾値と値域語は、`adr-scoping.md` が定義した判定結果を指すためのものである。

命名規約を ADR の対象に含めるかの振り分けも、一般則を命名規約へ当てはめた特化として本ファイルが持つ。

## 判定結果の行き先

粒度判定基準の結論ごとに、対象の置き場所を次のとおりとする。ADR に記録が無いことは、その規範が無効であることも、置き場所が無いことも意味しない。

**ADR 化する（合計3点以上）の行き先**

- 既存 ADR が扱っていない枠組みを立てる場合、または既存 ADR の結論・方向・前提を反転・置換する場合 → **新規 ADR** の側へ振り分ける
- `validity: 有効` な既存 ADR が定める枠組みの中に収まり、**その枠組みを保ったまま別の面（適用範囲・条件・パラメータ値・理由付け）を追加するだけ**の場合 → 新規 ADR を起こさず、当該 ADR への**非core 改訂**の側へ振り分ける。同じ主題を複数の ADR へ分散させないためである

いずれも振り分け先の提示であって、分類（core／非core／些末）の確定ではない。分類基準の実体、確定の手続き（利用者へ問うこと）、安全則（迷えば core 寄り＝新規 ADR に倒す）、および選んだ操作の手順と変更履歴の残し方は、すべて `edit-decision.md` に従う。本節でこれらを再定義しない。退役（上書き済み・廃止済み）した ADR は同ファイルの凍結原則により決定内容の改訂を受けないため、上の2分岐は掛からない。

**ADR 化しない（合計3点未満）の行き先**

- **ツールで自動強制される規範** → **実装・テスト資産・操作手順**に置く。強制するコード本体・その fixture／テスト・実行を組み込む手順が置き場所であり、採用理由と既知の限界は当該資産のコメント等に併記して自己完結させる
- **ツールでは強制できないが、複数の作業者・複数の箇所へ効かせたい規範** → **共有規約文書**（規約ファイル・プロジェクト指示）に置く。採用理由と既知の限界は当該文書へ併記して自己完結させる。併記の未了が項目3の点数を動かすのは、同居判定の1点条件に当たる決定に限る（併記により値域(B) が成立し0点へ移る）。当たらない決定では点数は動かないが、併記を欠いたまま放置すれば理由は次の判定者へ渡らずに失われる
- **単一の変更に閉じる判断** → **その変更の PR 説明**に書く。`adr-scoping.md`「起票のタイミングとエスカレーション」の昇格フローの前段にあたり、他の箇所で同じ問いが再出した時点で改めて判定へ掛ける

強制する資産はあるが検査が警告どまりで阻止しない規範は、第1分岐（実装・テスト資産・操作手順）に置く。阻止まで動かすかは当該資産の実装の課題であり、置き場所を変えない。

ただし既に記録済みの決定そのものへ触れる編集は、粒度判定の点数ではなく `edit-decision.md` の分類が入口となる。スコア境界未満であることは、既存 ADR への改訂を妨げない。

この一般則が最も効くのは、ADR 運用そのものや開発の進め方を主題とする規範である。この層は規範が実装・テスト資産・操作手順の側で既に強制されていることが多く、そのぶん記録の不在が欠落と誤読されやすい。

## 命名規約の ADR 化基準

### 本節の射程

本節が対象とするのは、**識別子——変数・関数・型・ファイル・ディレクトリ等、コードや成果物の中で対象を指し示す名前——に、どの名前を与えるか、およびその名前をどう綴るか**を定める規範に限る。次の3つは名前そのものを定めていないため、本節の射程外とする。

- **記述の並び順とレイアウト**（import 順、宣言の並び、空白・改行・字下げ）。並べ方・空け方は名前ではない
- **成果物メタデータの値の形式**（front-matter の値、設定値、コミットメッセージの書式や言語）。名前ではない値に掛かる形式である
- **識別子の採番形式**（連番・日付・ハッシュ等の採り方と、その桁数、および採番部分の内部にある区切り記号の形式）。どの名前を与えるかではなく、値の生成規則である。識別子が採番部分と綴り部分を併せ持つ場合、射程外となるのは採番部分だけであり、綴り部分は射程内として扱う。**区切り記号は、両側とも採番部分であるものだけが採番部分に属し、それ以外はすべて綴り部分に属する**（片側でも綴り部分に接するものに加え、識別子の端にあって片側に何も接しないものも綴り部分とする）。例として `ADR-YYYYMMDDHHMM-NN` では、日付部と連番部を隔てるハイフンは両側とも採番部分であるため射程外、`ADR` と日付部を隔てるハイフンは綴り部分に接するため射程内である

**この3類型は個別の列挙であり、識別子の一部を成すかどうかにかかわらず射程外である。** 「識別子の一部を成すか」を3類型の判別基準として読んではならない——第3類型が挙げる採番部分は識別子の一部を成すが、どの名前を与えるかではなく値の生成規則であるため射程外に置いている。

一方、**成果物をツリー上のどのディレクトリへ置くかを定めるファイル配置規約は、本節の射程内とする。** ツリー上の所在は、その成果物を指し示す完全なパスという識別子の一部を与えるためである。第1類型（記述の並び順とレイアウト）が射程外である理由は「成果物の内部での並べ方が識別子のいずれの部分にもならないため」であり、ツリー上の配置が射程内・成果物内部の配置が射程外という非対称はこの2つの対比に限った説明である（前段のとおり、3類型全体を貫く基準ではない）。これに対し、どの内容をどの成果物へ入れるかを定める分割の規範は、名前を与えても綴りを定めてもいないため射程外とする。

射程外の規範には本節の表も末尾の例外も掛からない。行き先は前掲「判定結果の行き先」の一般則3分岐が決める。

### 振り分け

射程内の命名規約のうち ADR 化対象とするかどうかは、構造的か書式的かで振り分ける。

| 種別 | 特徴 | 例 | 配置 |
|---|---|---|---|
| 構造的命名規約 | 横断・後戻りコスト高 | ファイル配置規約、集約名、ドメイン用語統一 | ADR 化（`docs/adr/`） |
| 書式的命名規約 | 表記に閉じる・原理的にツール強制可能 | 変数命名、識別子の大文字小文字と区切り記号の使い分け、接頭辞・接尾辞の綴り | Linter／フォーマッタ規約として配置（ADR 外） |

本表は前掲「判定結果の行き先」の一般則を命名規約へ当てはめたものであり、強制が現に動いている場合は一般則の典型例として対応する（強制が未実装の場合の扱いは本節末尾の例外による）。構造的命名規約の行（ADR 化）は一般則の「ADR 化する（合計3点以上）の行き先」に対応し、書式的命名規約の行（Linter／フォーマッタ規約として配置＝ADR 外）は「ADR 化しない（合計3点未満）の行き先」のうち「ツールで自動強制される規範 → 実装・テスト資産・操作手順に置く」分岐に対応する（Linter／フォーマッタ本体とその設定がここでの実装資産にあたる）。表の軸（構造的／書式的）と一般則の軸（ツール強制の可否）は直交するため、対応は一対一ではない。構造的命名規約であってもツールで現に強制されている場合は、次の指示どおり項目4に照らして振り分ける。

ツールで自動強制できる規約は ADR 外とする。判断に迷う場合は、粒度判定基準の項目4（ツールで自動強制できない）に照らして振り分ける。

本節の「ツールで自動強制できる」は項目4と同じ現在時制で読む（違反が現に検査され、作業が阻止されている状態）。ただし前段のタイブレーカーは対象が構造的か書式的かを決めるためのものであり、**原理的に**強制できるかを問う。これは項目4の点数を決める問いとは別であり、強制が未実装でも原理的に強制できる規約は書式的の側へ振り分ける。

**書式的命名規約は、強制がまだ実装されていない場合も ADR 外とする。** 行き先は強制の実装（Linter／フォーマッタ規約とその設定）であり、採用理由は当該設定へ併記する。強制が未実装であることは、記録すべき設計判断ではなく実装の欠落だからである。強制が未実装の場合に限り、本表は一般則の特化ではなく**例外**として働く。粒度判定基準の合計が3点へ届く場合も、振り分けは表が決める。**本例外が掛かるのは、必要条件が成立し、かつ対象が本節の射程内である場合に限る**（次項「適用順」）。

### 適用順

必要条件・射程・本表の順に掛ける。

1. **必要条件（却下代替が在ること）は本節にも前置する。** 不成立なら点数を数えず、本表も末尾の例外も掛からない。行き先は一般則3分岐が決める。必要条件より先に本節を掛けないのは、掛ければ却下代替を持たない決定について本節だけが独自の行き先を持つことになり、`adr-scoping.md`「必要条件: 却下代替が在ること」節が定める「不成立なら行き先は一般則に従う」と衝突するためである
2. 必要条件が成立し、対象が**射程内**であれば、本表と末尾の例外が掛かる。このうち一般則3分岐に**優先するのは末尾の例外だけ**であり、優先が働くのは書式的命名規約について強制が未実装の場合に限る。構造的命名規約の行は一般則の「ADR 化する（合計3点以上）の行き先」に対応する写像であって優越ではないため、粒度判定の合計がスコア境界未満であれば ADR 化せず、行き先は一般則3分岐が決める
3. 必要条件が成立していても、対象が**射程外**であれば、本表も末尾の例外も掛からず、一般則3分岐が決める
