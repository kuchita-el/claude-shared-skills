# ADR の格下げ判断基準（adr-demotion.md）

既に記録された ADR を退役させるか、`validity-active` のまま存置するかを判定する基準を定める。退役は `validity: <validity-abandoned>` へ移して index から外すことである。本ファイルがこの判定の実体であり、判定条件・判定形式・安全側の向きをここ以外で独自に再定義しない。

本ファイルは判定の**内容**に加えて、判定を誰がいつ何へ回すか（起動主体・起動タイミング・入力範囲）を定める。後者は後掲「判定の起動」が持つ。

## 位置づけ: 起票判定との関係

| | 起票判定（`adr-scoping.md`） | 格下げ判定（本ファイル） |
|---|---|---|
| 問い | この決定を ADR として書くか | この ADR を index から外すか |
| 対象 | まだ記録されていない決定 | `validity: <validity-active>` の既存 ADR |
| 判定形式 | チェックリストのスコアと境界値 | 必要条件の連言（全条件成立で退役） |
| 安全側 | 迷ったら ADR 化しない | 迷ったら残す |

**起票判定を遡及適用して格下げを決めない。** 両者は次の点で非対称であり、同じ項目・同じ境界・同じ安全側を共有できない。

- **コストの所在**: 起票では書くコストを今から払うかが問われる。格下げでは書くコストは既に埋没しており、検索性の負荷と参照価値が問われる
- **使える入力**: 起票では決定の性質のみを見る。格下げでは運用実績が観測できる
- **不可逆性の向き**: 起票しない判断は可逆であり、後から必要性が判明した時点で遡及して ADR 化できる。退役は index から外し、本文を凍結原則の下へ置く。`validity-active` の ADR からの `Related:` 参照は、後継を持つ退役（`validity-superseded`）に限り drift 検査が是正を求める。本ファイルが扱う後継を持たない退役（`validity-abandoned`）を指す参照は検査対象外であり、是正は任意の点検にとどまる（`cross-references.md`「是正手段」）。`validity-abandoned` から `validity-active` への状態遷移は規約に存在しない。誤った退役を取り消す手続き（`transitions.md`「取り消し（誤った退役の訂正）」）は在るが、それは退役の時点の入力へ本基準を再適用し、条件の不成立が判明した退役に限られる。正しく退役した ADR を戻す経路にはならない

両基準が共有するのは、ADR の固有価値をどこに置くかという定義だけである（次節）。項目・境界・安全側は共有しない。

## ADR の固有価値

ADR が living doc（共有規約文書・spec・実装・スキーマ等、現在の正しさを保持し続ける資産）と区別される点は、**採らなかった選択肢とその却下理由**（なぜ他ではないか）を保持することにある。規範本文（何が正しいか）は living doc の責務である。

したがって却下代替を持たない ADR は living doc の写しであり、index に置く固有の価値を持たない。これが条件1 の根拠である。

同じ定義は起票の側でも条件として働く。`adr-scoping.md`「必要条件: 却下代替が在ること」が、粒度判定基準へ進む前の必要条件として同じものを課す。共有するのはこの定義だけであり、判定項目・境界・安全側は前節のとおり共有しない。

## 判定形式

**全条件が成立した場合に限り退役させる。1つでも不成立なら存置する**（必要条件の連言）。条件ごとの点数を合計しない。

スコア式（起票判定と同形の N 項目・境界値）を採らない。項目間の相殺が起きるためである。不可逆側へ倒す判定において、ある項目の高さが別の項目の不成立を埋め合わせる形は適さない。加えて、二値の少数項目によるスコアは同種の文書群に対して縮退しやすく、大半が同一の並びへ張り付いて解像度を失う。

段階式（必要条件のゲート＋通過分のスコアによる優先度付け）も採らない。優先度が要る場面（大量の一括棚卸し）が現に生じておらず、第2段が空転する。

## 安全側の向き

**迷ったら残す。** 各条件は退役側へ倒すときのみ成立とし、成立するか迷う条件は不成立とする。1つでも不成立なら存置であるから、迷いは必ず存置へ落ちる。

起票判定の「判断に迷ったら ADR 化しない」と各項目の同点処理（迷ったら0点）は、起票しない判断が可逆であることに支えられている。退役にはその支えがない。したがって向きを逆に取る。

判定形式に連言を採ることで、この向きは全条件で一様になる。項目ごとに符号が異なるスコア式では、同点処理の向きが項目ごとに反転して誤りやすい。

## 各条件の判定手続き

本基準は点数を持たないため、**数える対象を持たない**。条件ごとに定めるのは走査対象・列挙する対象・値域・時制の4つである。

### 条件1: 却下代替が本文に無い

当該 ADR の本文に、自分の決定について採らなかった選択肢とその却下理由が書かれていないこと。

- **走査対象**: 当該 ADR の本文のみ。他の ADR・規約文書・Issue・PR・コミットメッセージは見ない。節見出しの有無は問わず、`Context` / `Decision` / `Consequences` のいずれの本文中に書かれていてもよい
- **列挙する対象**: `## Decision` のトップレベル決定を全件列挙し、決定ごとに「却下した選択肢」と「その却下理由」の対が本文に在るかを見る
- **値域**: 決定ごとに次の3値を取る。**全決定が「記載なし」であるときに限り条件1 は成立**する
  - **記載あり** — 却下した選択肢と、それを却下した理由の対が特定できる
  - **部分的** — 却下代替の痕跡はあるが、対として特定できない。下記の型がこれにあたる
  - **記載なし** — 却下した選択肢の名指しも、却下理由の記述も、受け入れた不利益・トレードオフの記述も、本文に一つも無い
- **時制**: 判定時点の本文のみを見る。過去に別の場所へ書かれていたか、これから書き足せるかは入力にしない

**「部分的」の型**（いずれも条件1 は不成立＝存置へ倒す）

- 代替案が名指しされているが、却下理由が本文に無い
- 代替案と却下理由の対応を一対一に特定できない
- 却下理由が他の ADR や規約文書の基準の援用にとどまり、当該決定に固有の理由が本文に無い
- トレードオフや受け入れたコストの記述はあるが、対応する代替案を特定できない

意図的に決めなかった面の記述（本 ADR では決めないと述べた射程外の論点）は却下代替ではない。その存在は「記載あり」にも「部分的」にも数えない。

**分割後継の扱い**: 分割によって生じた後継 ADR も、当該後継の本文だけで判定し原 ADR を辿らない。後継に却下代替が無ければ「記載なし」として扱う。担当決定の却下代替を後継へ持ち越すことと、生存決定に後継を立てず原 ADR に残す振り分けは、分割手順（`transitions.md`「分割（多決定 ADR の部分上書き）」節）が定める。振り分けの条件と安全側の向きも同節に従う。本判定は、結果として後継の本文に在るものだけを見る。分割手順の振り分けは決定を単位に後継を起こすかを決めるものであり、本判定と責務を分ける（同節「格下げ判定との責務の違い」）。

### 条件2: 規範本文が ADR の外に在る

規範本文（何が正しいか）が living doc 側に在る、または決定が現に効力を失っていること。

- **走査対象**: 当該 ADR の各決定が定める規範について、それを現に担っている資産。ADR 本文の外を走査する点で条件1 と異なる
- **列挙する対象**: 決定ごとに、規範を現に担っている資産を同定して列挙する
- **値域**: 決定ごとに次の3値を取る。**全決定が (a) または (b) であるときに限り条件2 は成立**する
  - **(a) 正本が ADR の外に在る** — 共有規約文書・spec・型定義／スキーマ／テンプレート・規範を強制する実装／テスト／フック／CI のいずれかが規範本文を担っている。**強制機構が引き取っている場合も (a) に含める**
  - **(b) 決定が現に効力を失っている** — 規範そのものが放棄された、または前提が消滅して適用先が無い
  - **(c) いずれでもない** — 規範本文が当該 ADR の本文にしか無い
- **時制**: 判定時点の状態のみを見る。移送の予定・計画は入力にしない。「これから living doc へ出す」は (a) に当たらず、出し終えてから判定する
- 担っている資産を同定できない場合、その資産が規範本文を担っていると言えるか迷う場合は **(c)** として扱う（安全側）
- **決定が定める規範のうち、担い手を同定できない部分が在るなら (c) とする。** 決定全体として主たる部分が担われていることを (a) の根拠にしない。規範をどう分解するかの単位は定めない。担い手の無い部分がどこかに残るかだけを見る。退役させれば、担われていない部分の規範は失われるためである

条件1 が主、条件2 が従である。却下代替を持たない ADR であっても、規範本文の正本がまだ ADR にしか無いなら、退役させれば規範そのものが失われる。条件2 はその取りこぼしを塞ぐ。規範本文を living doc へ移す作業は、条件2 を満たすための前作業にあたる。

## 格下げ固有の入力の採否

格下げ判定は起票判定と違って運用実績を観測できる。観測しうる入力のうち、基準へ採ったものと採らなかったものを次のとおり定める。

| 入力 | 採否 |
|---|---|
| 被参照の実績 | 採らない |
| 強制機構が規範を引き取った実績 | 条件2 の (a) に含める |
| 正本が ADR 外へ移った実績 | 条件2 の (a) そのもの |
| 問いが再燃した実績 | 採らない |

**被参照の実績を採らない理由**: 被参照は決定の性質ではなく記録の消費面の状態である。退役は記録の削除ではなく index からの除去である。`validity-active` の ADR からの `Related:` 参照に drift 検査が是正を求めるのは、後継を持つ退役（`validity-superseded`）に限る。その参照は、参照側の付け替えで解消される。本ファイルが扱う `validity-abandoned` への退役はこの検査の対象外である。参照の是正は任意の点検にとどまる（`cross-references.md`「是正手段」）。参照されていること自体は、その ADR が却下代替を持つことも、規範本文の正本であることも意味しない。

**再燃の実績を採らない理由**: 2つある。

第一に、走査面が閉じていない。条件1・条件2 は「無いこと」の判定でありながら実行可能だが、それは走査面が閉じているためである（ADR は full slug という識別子を持ち、追跡下ファイルへの走査が対象集合に対して網羅的になる）。再燃には対応する識別子が無く、「同じ問い」の同一性は主題の一致判断であって照合ではない。走査面も Issue・PR コメント・クローズ済みの議論へ散り、追跡下に閉じない。

第二に、安全側の向きと構造的に両立しない。連言では「再燃の不在」が退役の成立要件になる。安全側（迷えば不成立）を当てると、再燃していないと確信できるかを毎回問うことになるが、否定的存在命題であるため通常は確信できない。結果としてこの条件はほぼ常に不成立となり、全 ADR が存置へ倒れる。発火しない条件は条件として働かない。逆に「再燃の記録が現に在る場合に限り存置」と書けば発火するが、それは迷いを退役側へ倒すことであり安全側の向きと矛盾する。

起票判定の昇格フロー（他の機能でも同じ問いが出てきた時点で ADR へ昇格させる）で再燃が機能するのは、判定者が2回目の場面に居合わせて直接観測するためである。過去へ遡って再構成する格下げとは条件が異なる。

## 判定結果の行き先

- **退役**（全条件成立）→ `transitions.md`「廃止（廃止済み）」の手順へ進む。同手順が求める退役理由には、条件2 で同定した移送先を時点固定の過去形で記す
- **存置**（1つでも不成立）→ 状態を変えない。条件2 が (c) で不成立となった決定は、規範本文の移送が未了であることを示す。移送は本判定の外の作業であり、移送の未了を理由に退役させない

退役させた ADR は凍結原則の下に入り、決定内容の編集を受けない。凍結原則の射程は `edit-decision.md` に従う。

退役が誤っていたと判明した場合は、`transitions.md`「取り消し（誤った退役の訂正）」に従って取り消す。

## 判定の起動

格下げ判定は、次に定める事象が起きたときに、その事象に関わる `validity-active` の ADR だけへ回す。定期の棚卸しや判定者の思い立ちでは回さない。

### 起動の根拠

判定形式が連言であるため、ある ADR の結論が存置から退役へ変わるのは、いずれかの条件の入力が変わったときに限られる。入力が変わっていない ADR へ判定を繰り返しても、結論を動かしうるのは判定者のぶれだけである。

条件1 の入力は当該 ADR の本文であり、編集判定フローを経た改訂でしか変わらない。条件2 の入力は ADR の外の資産の状態であり、ADR に触れない変更で変わる。そこで起動を、条件2 の入力を変える事象と、利用者による廃止の求めに結び付ける。

起動を逃した ADR は存置のまま残る。これは安全側の向き（迷ったら残す）と同じ側の誤りであり、起動事象を網羅的にしなくてよい根拠になる。

### 起動タイミング・起動主体・入力範囲

次のいずれかの事象が起きたときに判定する。

| 事象 | 起動主体 | 入力範囲 |
|---|---|---|
| 1. ADR ファイル（`ADR-*.md`）と `index.md` 以外のファイルへ、`validity-active` の ADR の識別子を含む行を追加した | その変更を行う者 | 追加した行が識別子を含む `validity-active` の ADR |
| 2. ファイルを削除または改名した | その変更を行う者 | 削除・改名前のパス（リポジトリルートからの相対パス）を本文に含む `validity-active` の ADR |
| 3. 利用者が、特定の `validity-active` の ADR の廃止を求めた | 求めを受けて判定を行う者 | 求めが名指しした ADR |

- 事象1 は、規範本文を living doc へ書き出したこと、または規範を強制する実装・テスト・フック・CI を足したことの痕跡である。条件2 の (a) を成立させうる
- 事象1 から ADR ファイルと `index.md` を除くのは、ADR 間の相互参照と index の再生成が規範の移送ではないためである
- 事象2 は、ADR が規範を及ぼす先の消滅（適用先の消滅）である。条件2 の (b) を成立させうる
- 事象1・2 の判定は、その事象を生じた変更の中で行う。PR を経る変更では当該 PR の中で行う
- 判定の結果（ADR ごとの退役／存置と、決定ごとの条件1・条件2 の値）は、その変更の説明に残す。変更の説明の定義は `adr-destination.md`「判定結果の行き先」に従う。この記録は保留した旨を持たないため、起票の時点の判定が数える保留中の記録に当たらない
- 入力範囲は当該 ADR 単体に限る。ADR 群の全数へは回さない。`validity-active` 以外の ADR は対象外である
- 退役済みの ADR に対する取り消しの判定は本節の対象外であり、`transitions.md`「取り消し（誤った退役の訂正）」が起動を定める
- 退役と判定した後の手順は、前掲「判定結果の行き先」に従う

### 検討した起動形態と採否

| 起動形態 | 採否 | 理由 |
|---|---|---|
| 定期の監査として全数へ回す | 採らない | 入力の変わっていない ADR へ判定を繰り返すことになる。結論を動かしうるのは判定者のぶれだけであり、同じ ADR 群でも試行ごとに結論が割れる |
| ADR の編集・上書きのたびに当該 ADR へ回す | 採らない | 条件2 の入力を変える事象は ADR の外で起き、ADR の編集とは同時に起きない。core の改訂は上書きへ進むため、格下げの対象にならない |
| 規範本文が ADR 外へ移ったとき・強制機構が規範を引き取ったときに回す | 採る（事象1） | 条件2 の (a) の入力を変える事象である。識別子の追加は差分から機械的に観測できる |
| 適用先が消滅したときに回す | 採る（事象2） | 条件2 の (b) の入力を変える事象である。適用先はファイルパスという識別子を持ち、追跡下ファイルへの閉じた走査で検知できる |
| 被参照0件が続いたときに回す | 採らない | 被参照は判定の入力に採っていない（前掲「格下げ固有の入力の採否」）。入力でない量の変化で起動しても、条件の入力は変わらない |
| 疑義を持った者が随時回す | 採らない | 起動が判定者の思い立ちに依存し、入力の変わらない ADR へ判定を繰り返す経路を残す。利用者が特定の ADR の廃止を明示して求めた場合だけを事象3 として採る |

適用先の消滅は、判定の条件へ足さず起動の事象に置く。条件へ足しても連言の項が増えて退役が難しくなるだけで、消滅という事象を検知する働きを持たないためである。

### 起票のタイミングとの使い分け

まだ記録されていない決定について起票判定へ入る時点は、`adr-scoping.md`「起票のタイミングとエスカレーション」が定める。本節が定めるのは、既に `validity-active` の ADR について格下げ判定へ入る時点である。1つの変更が両方の起動点に当たる場合は、それぞれ独立に判定する。
