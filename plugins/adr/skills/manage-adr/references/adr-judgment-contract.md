# ADR 判定器の契約仕様

この文書は、判定器が返す実測事実の値域・直列化形式・判定ごとの必須ルールの実体である。4項目の名称、閾値、スコア境界、迷った場合の向きは `adr-scoping.md` が定め、閾値とスコア境界の数値は `adr-scoring-thresholds.json` が唯一の実体として定める。

## 実測事実の値域と定義

判定器は点数を算出せず、次の事実だけを観測する。件数は列挙した配列の長さと一致させ、事実が題材文から確定できない場合は推測せず明示値で申告する。

| 項目 | 捕捉する実測事実 |
|---|---|
| 項目1 | 反転時に直す追跡下ファイルの列挙と件数、構造変更・スキーマ変更・配布済み成果物への利用者影響・蓄積済みデータ移行の各成否 |
| 項目2 | 規範が適用される最小単位（モジュール、実行可能単位、成果物種別）の列挙と件数 |
| 項目3 | 値域(A)(B)の各成否、採用理由を確かめられるか、条件1〜3の各成否 |
| 項目4 | 判定時点の阻止の状態（`現に阻止` / `警告どまり` / `検査なし`）。`未実装` は `検査なし` として記録する |

項目1では再生成で追随する成果物、追加だけで矛盾しないファイル、決定を記録するだけの ADR（本体・`index.md`・相互参照）および追跡用 Issue を数えない。規範の適用先として直す ADR は数える。禁止規範の反転でも、記述の追加だけなら数えず、禁止を述べる既存記述が矛盾する場合は数える。項目2は入れ子を最小単位へ分解し、同じプラグイン内の別スキル・別スクリプト・別成果物種別は別単位とする。決定を記録する ADR と追跡用 Issue は除外するが、規範の適用先である ADR は含める。作業者の人数や形容による規模は入力にしない。構造変更・スキーマ変更・配布済み成果物への利用者影響・蓄積済みデータ移行は、ファイル数とは独立に評価する。

原文が件数だけを示し、個々の名前を列挙していない場合、配列の長さを件数に合わせるために `原文列挙_N`（`N` は1始まりの通し番号）を用いる。この値は実体名の推測ではなく、原文に列挙が無いことを表す構造化上のプレースホルダであり、実体を監査できる名前として扱わない。

項目3の保持先は次の閉じた値域で判定する。(A) は規範を強制する実装本体、その fixture／テスト、型定義・テンプレート・スキーマ、フック・CI・実行手順。(B) は共有規約ファイル（`references/` を含む）とプロジェクト指示ファイル。散文だけの記述は(A)ではなく、(B)でも採用理由がなければ対象外である。ADRへの識別子・表題・リンクだけの参照、PR説明、Issue、レビューコメント、記憶は値域外とする。値域に当たるか迷う場合も0点とする。(A) は理由の記載や強制の稼働を問わず0点とし、(B) は当該決定の採用理由が本文に現に書かれている場合だけ0点とする。保持先が無い場合だけ、(1) 却下理由が採用理由とは別に必要である、(2) 受け入れた不利益・犠牲の説明が採用理由とは別に必要である、(3) 規範が複数のファイルへ分かれざるを得ず、1つの資産の傍らへ理由を置けない（現状の配置ではなく、これから書く場合の形で判定する）、を評価する。理由が確かめられない場合、条件1・2は不成立とし、条件3は理由によらず判定する。

## 直列化形式

判定器から保存者へ渡す機械可読境界では、1判定を1つの JSON Pretty ファイルへ保存する。ファイル名 `<題材ID>-<試行番号>.json` が同定を担い、ペイロードは点数・合計・行き先を持たない。利用者向けのスキル出力はこの機械可読契約の対象外で散文とする。

| フィールド名 | 値域 | 必須性 | 記入者 |
|---|---|---|---|
| 必要条件_成立 | 真偽、`当時未施行`、`原文に記述なし` | 必須 | 判定器 |
| 必要条件_補足 | 文字列 | 必須 | 判定器 |
| 発見型_短絡 | 真偽 | 必須 | 判定器 |
| 発見型_理由 | 文字列 | 必須 | 判定器 |
| 項目1_追跡下ファイル | 文字列配列 | 必須 | 判定器 |
| 項目1_追跡下ファイル数 | 0以上の整数 | 必須 | 判定器 |
| 項目1_構造変更 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目1_スキーマ変更 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目1_配布済み成果物への利用者影響 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目1_蓄積済みデータ移行 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目2_最小単位 | 文字列配列 | 必須 | 判定器 |
| 項目2_最小単位数 | 0以上の整数 | 必須 | 判定器 |
| 項目3_値域A | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目3_値域B | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目3_採用理由確認可能 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目3_条件1 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目3_条件2 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目3_条件3 | 真偽、明示欠測値 | 必須 | 判定器 |
| 項目4_阻止状態 | `現に阻止` / `警告どまり` / `検査なし`（未実装は検査なし） | 必須 | 判定器 |
| 複数作業者 | 真偽 | 必須 | 判定器 |
| 複数箇所 | 真偽 | 必須 | 判定器 |
| 根拠_項目1 | 空でない文字列 | 必須 | 判定器 |
| 根拠_項目2 | 空でない文字列 | 必須 | 判定器 |
| 根拠_項目3 | 空でない文字列 | 必須 | 判定器 |
| 根拠_項目4 | 空でない文字列 | 必須 | 判定器 |
| 推定で補った事実 | 文字列配列 | 必須 | 判定器 |
| 参照ファイル | 文字列配列 | 必須 | 判定器 |
| 対象文書commit | 7文字以上40文字以下の16進ハッシュ | 必須 | 記録者 |

点数を模したフィールドは保持しない。必要条件_成立が `当時未施行` の場合は、当時その規定が無かったため、必要条件を点数算出の入力にしない。必要条件が偽なら点数を数えず ADR 化しない。項目1〜4の算出に使うフィールドが `当時未施行` または `原文に記述なし` の場合は0や偽へ読み替えず算出不能とする。JSON を採るのは散文を含む返却を安全に構造化するためであり、台帳 TSV は既存記録との互換性のため据え置く。台帳の点数列との二重保持は `crosscheck` で一致検査する。

## 判定ごとの必須ルール

- 必要条件の成否を必ず申告し、偽なら項目の点数を算出せず ADR 化しない。`当時未施行` は旧条文に必要条件が無かったことを示すため、項目1〜4の算出は続ける。
- 発見型短絡の適用と理由、省略した項目を申告する。
- `adr-scoping.md` の同点処理に従い、迷った項目は0点へ倒す。
- 題材に無い事実を推定で補わず、補えなかった事実を申告する。
- 条文に無かった項目1〜4の算出フィールドは `当時未施行`、条文は在ったが返却に無い事実は `原文に記述なし` とする。いずれも0や偽で補わず算出対象外とする。必要条件の `当時未施行` だけは算出に使わない欠測として許容する。

(a) 実測事実の定義と (c) 必須ルールは、判定主体を問わず適用する。(b) JSON 直列化は判定器から保存者など機械が読む境界だけに適用する。
