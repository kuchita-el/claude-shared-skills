# ADR の状態モデルと識別子規約（adr-model.md）

ADR の状態（承認軸・有効性軸）の値域と各値の定義、遷移ごとの front-matter 必須ルール、ファイルの配置と採番方式を定める。本ファイルがこれらの規約の実体であり、状態語彙・採番規則をここ以外で独自に再定義しない。

## 状態の2軸

状態は**承認軸**と**有効性軸**に分離して管理する。1つの状態欄に混在させると、「承認された歴史事実」と「現在効力を持つか」という性質の異なる2つの情報が互いを上書きしてしまうためである。値は日本語のユビキタス言語で確定する。

### 承認軸（`status`・不変の履歴事実）

| 値 | 定義 |
|---|---|
| `提案中` | 起案され、承認者の判断を待っている状態 |
| `承認済み` | 承認された履歴事実。以後不変 |
| `却下` | 提案が承認に至らず終了。一度も運用されない終端 |

### 有効性軸（`validity`・可変の現在の効力）

| 値 | 定義 |
|---|---|
| `有効` | 現在運用中 |
| `上書き済み` | 後継 ADR に置き換えられた（`superseded-by` に後継の full slug を保持） |
| `廃止済み` | 後継なしで放棄された |

### 軸の関係

- `却下`（承認軸・一度も承認されなかった終端）と `上書き済み` / `廃止済み`（有効性軸・承認後に効力を失った状態）は別語である。2軸が語彙レベルで衝突しないよう、両者を混同して扱わない
- `提案中` をスキップして直接 `承認済み` に到達する経路は持たない。即承認のケースは「提案 → 承認」を連続実行として扱う

## front-matter（状態の唯一の権威）

状態系は各 ADR ファイル冒頭の front-matter に置く。キーは英語（構造的フィールド名）、値は上記の日本語ユビキタス言語とする。

```yaml
---
status: <提案中 | 承認済み | 却下>
validity: <有効 | 上書き済み | 廃止済み | （空）>
superseded-by: <後継ADRの full slug | （空）>
---
```

- front-matter が状態の唯一の権威である。**本文に `## Status` 節を置かない**。新規起票時も、承認・上書き・廃止・却下のいずれの遷移時も同様である。本文へ状態を書き足すことは重複を生むだけで、以後の遷移で取り残される drift 源になる
- 「キー省略」と「キーあり値空」は同じ「空」として扱う。空にする軸は値を空にする（キー行自体は残してよい）
- 有効 ADR の一覧（index）は front-matter から機械生成する導出ビューであり、人手編集しない。これにより「本文を読めば確実（確実性）」と「一覧で探せる（検索性）」を drift させずに両立する

## 遷移ごとの必須ルール

各遷移後の `status` / `validity` / `superseded-by` は必ず次の組み合わせに一致させる。

| 遷移 | status | validity | superseded-by |
|---|---|---|---|
| 起票 | 提案中 | （無し） | （無し） |
| 承認 | 承認済み | 有効 | （無し） |
| 上書き | 承認済み（不変） | 上書き済み | 必須 |
| 廃止 | 承認済み（不変） | 廃止済み | （無し） |
| 却下 | 却下 | （無し） | （無し） |

- 上書き・廃止では `status` を変更しない（承認は歴史事実であり不変）
- `superseded-by` は単一後継を既定とするが、1本の ADR が複数の後継へ分割される場合はリスト値（カンマ区切り）を取りうる。この 1→N のケースでは、`上書き済み` の原 ADR が全後継を列挙し、各後継が本文の関連 ADR 節に逆参照を持つ（双方向で照合される）
- 後継 ADR は full slug の参照のみで保持し、実体への直接参照は持たない（自己参照・循環参照の構造的不整合を防ぐ）

## 配置

- `docs/adr/` 配下にフラット構造で配置する。サブディレクトリは作らない

## 採番方式

ファイル名規則: `ADR-YYYYMMDDHHMM-NN-<slug>.md`

- `YYYYMMDDHHMM`: ADR の起票時刻（採番時刻＝起票時刻）を分粒度で表す。**作業者のローカル時刻**を用い、UTC 等へ変換しない（日付部の意味を起票日からずらさないため）
- `-NN`: 同一時刻部内の連番。`01` 始まりの2桁ゼロ埋めとし、同一時刻部1件目にも `-01` を付与する。ゼロ埋めするのは、ファイル名の `LC_ALL=C sort` による辞書順整列だけで起票順が再現されるようにするため（ゼロ埋めしないと10件目で `-10` が `-2` より前に照合される）。同一時刻部99件を上限とする
- `<slug>`: 内容を表す短い英数字ハイフン区切りの文字列

時刻部・連番部の双方を常に必須とし、いずれかを省略した形は作らない。**時刻部が並行ブランチ間の一意性を担い、連番部が同一分内に起票されるバースト（多決定 ADR の分割で後継を同時に起票する場合など）の順序を担う**。バースト内の順序は決定クラスタ順であって時間順ではないため、時刻部だけでは順序づけられない。

**識別子**は番号部（`ADR-YYYYMMDDHHMM-NN`）を指し、**full slug**（ファイル名から `.md` を除いた文字列＝`ADR-YYYYMMDDHHMM-NN-<slug>`）とは区別する。両者は別の値であり、相互参照が保持するのは full slug の方である。

**時刻の取得**: 実行時コンテキストは日付までしか持たず分粒度の時刻を含まないため、時刻部は同梱の発番スクリプト `${CLAUDE_SKILL_DIR}/../../scripts/next-adr-id.sh` から取得する。スキル側で `date` 等の外部コマンドを直接実行しない（許可するコマンドを同梱スクリプトに限る）。

同一時刻部の採番例:

| 同一時刻部の件数 | ファイル名 |
|---|---|
| 1件目 | `ADR-YYYYMMDDHHMM-01-<slug>.md` |
| 2件目 | `ADR-YYYYMMDDHHMM-02-<slug>.md` |
| 3件目 | `ADR-YYYYMMDDHHMM-03-<slug>.md` |

### 採番衝突時の解消手順

発番は同梱スクリプトが担い、列挙の対象を**同一時刻部を持つ既存ファイルに限る**。

1. `bash ${CLAUDE_SKILL_DIR}/../../scripts/next-adr-id.sh <対象ディレクトリ>` を実行する
2. スクリプトはローカル時刻から時刻部を決め、`ADR-<時刻部>-*.md` に一致する既存ファイルの連番部から最大番号を特定して、最大番号 + 1 を2桁ゼロ埋めで発番する（同一時刻部の既存が無ければ `01`）
3. 出力された識別子に `-<slug>` を付してファイル名とする

**配置ディレクトリ全体・同日全体を列挙して最大番号 + 1 を取らない**。日単位で最大 + 1 を取る手順は、配置ディレクトリについて単一の直列化されたビューが存在することを前提とするため、並行するブランチがそれぞれ自分の base に対して正しく実行しても同一識別子を発番する。時刻部が異なれば連番は互いに独立し、ブランチ間の調整なしに一意性が保たれる。

過去時刻での発番（遡及移行など）は、環境変数 `ADR_TIMESTAMP`（`YYYYMMDDHHMM` の12桁）で時刻部を上書きする。

**入出力例**

- 入力: 起票時刻が 2031-04-09 15:30（ローカル）。同一時刻部の既存 ADR が2件あり、それぞれ `-01`（`ADR-203104091530-01-<slug>.md`）と `-02`（`ADR-203104091530-02-<slug>.md`）。同日の別時刻に起票された ADR は何件あっても連番に影響しない
- 手順2: 同一時刻部の既存の最大番号は `2`
- 期待結果: 最大番号 + 1 を2桁ゼロ埋めした `-03` を発番し、ファイル名は `ADR-203104091530-03-<slug>.md` とする
- exit code: `0`＝発番成功（識別子を stdout へ出力）／`1`＝同一時刻部が99件に達している、または `ADR_TIMESTAMP` の形式が不正／`2`＝対象ディレクトリ不在
