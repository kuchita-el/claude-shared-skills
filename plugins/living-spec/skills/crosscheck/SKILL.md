# 規則間の矛盾の突き合わせ

機械検査を通った正本に、意味の突き合わせを掛ける。直さずに報告する。直すのは `structure` か利用者。基準の空白（C9）の問いを未決の印として記録するのも `structure` か利用者で、このスキルは記録しない。

## 引数

焦点（UC・条件・状態モデルの名前、または変更したファイル）。無ければ全体。

`--base` が無いときに起点にするのは、焦点に挙がったファイルの最初の1つだけである。2つ目以降の焦点が別の根にあっても、注記は出ない。焦点が複数の根にまたがるときは、根ごとに分けて起動する。このスキルは焦点どうしのパスを比べない。

基準の版（任意）。`--base <版>` の形でだけ受け、渡されたときは基準の版から変わった要素の一覧を焦点にする。焦点の位置に置いた名前は、版として読まない。`main` という名前の UC と区別できなくなるためである。

既定の版は持たない。`--base` が無ければ版を問わず、今のまま動く。引数なしの起動を版を問う報告へ変えると、今の利用者の手順が変わるためである。対話の道具の無いホストでも、同じに動かすためでもある。

`--base` と併せて受けるのは、起点にするパス1つだけである。`--base` のときに限り、`--base` とその値を除いた引数のうち、`/` を含むものをパス、含まないものを名前と見なす。`origin/main` のように `/` を含む版の値は数えない。`/` を含む名前はパスと見なされ、その名のファイルが無ければ手順1 の `check` が止まる。名前か2つ目のパスがあれば、突き合わせずに終え、起動し直し方として次の2点を伝える。

- `--base`（とパス1つ）だけか、名前だけで起動し直すこと
- 根の直下のディレクトリやファイルは、`./<ディレクトリ>` のように `/` を含む形で渡すこと

## 手順

起点の渡し方・根の取り方・注記の伝え方は `${CLAUDE_PLUGIN_ROOT}/references/starting-point.md` に従い、基準の版は同書の「基準の版の渡し方」に従う。根を決める規則の正本は `${CLAUDE_PLUGIN_ROOT}/references/format.md` の「置き場の設定」。このスキルでは次のとおりとする。

- 扱っているファイルとは、`--base` が無いときは焦点に挙がったファイルの最初の1つである。焦点が名前だけか、焦点が無ければ、引数を付けない
- `--base` のときの扱っているファイルとは、併せて渡したパス（引数の節でパスと見なした引数）である。無ければ引数を付けない
- `--base` を受けたら、手順1 より前に引数の形を確かめる。名前か2つ目のパスがあれば、`check` を実行せずに、起動し直し方（引数の節の2点）を伝えて終える
- 注記を伝えたら、答えを待たずに終える（手順1）。利用者の答えを受けて起動し直す

1. `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" check [起点]` を実行する。次を上から順に当てはめ、最初に当たったもので扱う。
   - 終了コード 2 なら、標準エラーを示して止まる
   - 注記が出たら、違反の有無によらず手順2 以降へ進まない（`rule-crosschecker` を起動しない）。注記と扱いの問いを報告して終える
   - 違反があれば、正本が崩れたままでは意味の突き合わせが空振りするため、違反を示して止まる
2. 手順1 の `check` の1行目から根を取る。置き場を `<根>/.living-spec.json` から読む（無ければ既定）
3. `--base` を受けたときだけ、`node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" diff --base <版> [起点]` を実行する。起点は手順1 と同じとし、版は「基準の版の渡し方」に従って渡す。次を上から順に当てはめ、最初に当たったもので扱う。
   - 終了コード 0 以外なら、標準エラーを示して止まる。終了コード 2 の理由は `${CLAUDE_PLUGIN_ROOT}/references/format.md` の「基準の版から変わった要素の一覧（`diff`）」の終了コードが定める。想定外の例外の 1 も、差分0件と取り違えないよう同じく止まる
   - 終了コード 0 で標準出力が空なら、「差分なし」と渡した基準の版を報告して終える（`rule-crosschecker` を起動しない）。利用者は変わった所だけを確かめるつもりでいるため、全体の突き合わせへ広げない
   - それ以外は、標準出力の行の並びを焦点とする。`外された` の行だけでも、0件として扱わない
4. `rule-crosschecker` エージェントへ、根の絶対パス（手順2 の根）・置き場・焦点と、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）を渡す。起草の経緯・作り手の意図は渡さない
   - `--base` のときは、手順3 の行をそのまま焦点として渡し、行の読み方を1文添える。行は種類・区分・同一性の値をタブで区切った並びで、`外された` の要素は作業ツリーに無い
   - 差分の本文（各版の中身・変わった欄の値）は渡さない。`外された` の要素も焦点から外さない
5. 返った指摘から最大3件を抜き取り、根拠を確かめる。
   - 抜き取る件数は、blocker と warning を合わせて最大3件とする。
   - blocker を出力の並びの先頭から取る。3件に足りなければ、warning を同じ並びの先頭から足す。
   - 出力の並びは、エージェントが返した文面での出現順を指す。id の番号順に並べ替えない。
   - 抜き取った指摘ごとに、根拠の path:行 を自分で読んで、指摘どおりの記述があるかを確かめる。
   - 抜き取った指摘が C9 なら、evidence の表の側のレコードの `未決` に、同じ欄を挙げた項目が無いことも確かめる。あれば、印の付いた箇所を再指摘したものとして食い違いとする。
   - 指摘が0件なら、出力の並びの先頭の pass の行から当てはめる。pass の行が無ければ食い違いとする。
   - 取った行の見た範囲を場所ごとに分けて揃え、エージェントへ渡した置き場と根からの相対で照らす。続けて次の (i)〜(iv) を順に当てはめ、最初に当たったもので扱う。
     - 揃え方は次のとおりとする。絶対パスで書かれていれば、根の絶対パスを除く。path:行 の形は、行を除いたファイルとして扱う。`*` を含む形（例 `docs/rdra/*.yaml`）は、`*` より前の部分が属する置き場のディレクトリとして扱う。どの置き場にも属さない場所は、置き場の外とする。
     - (i) 置き場の配下のファイルが挙がっていれば、見た範囲に書かれた順で先頭の1つを自分で読む。読めなければ食い違いとする。
     - (ii) 表の置き場のディレクトリを指していれば、確かめたとし、読まない。検査（`run.mjs check`）が通った時点で、表の置き場は実在するためである。
     - (iii) 置き場を指す場所が要求票・例の置き場のディレクトリだけなら、その行では確かめられない（置き場の外の場所は数えない）。path を含まない文だけの行（例「全ての表」）も同じとする。次の pass の行へ進み、その行の見た範囲を同じく揃えて、(i) から当てはめる。全ての pass の行で確かめられなければ、確かめられなかったとする。
     - (iv) どれにも当たらなければ（見た範囲が空、または置き場の外だけを指す）、食い違いとする。
     - (i)・(ii)・(iv) に当たった行で止まり、次の pass の行へ進まない。
   - 食い違えばその旨を報告に付す。食い違いには、根拠の記述が指摘と違う場合と、指摘0件の当てはめで食い違いとした場合を含む。確かめられなかった場合は、食い違いと別の語のまま報告に付す。

## 出力

| id | 重さ | 根拠（両側） | なぜ両立しないか | 直し方の案（C9 は問い） |
|---|---|---|---|---|

表の後に、blocker・warning・pass の件数と、blocker・warning のうちの C9 の件数と、抜き取りで確かめた指摘の id（blocker・warning を含む）を書く。指摘が0件でも、見た範囲を書く。指摘が0件のときは、確かめた pass の id と、確かめた内容（読んだファイル、表の置き場を指していたこと、または食い違いの中身）を書く。全ての pass の行で確かめられなかったときは、その旨を書く。食い違いと確かめられなかったは、別の語のまま書く。

「差分なし」で終えたときは、表を出さない。

焦点も `--base` も無く、手順5 まで通って全体を突き合わせたときは、報告の末尾に、`--base <版>` を渡せば変わった要素に絞れることを書く。

`--base` で手順3 を通ったときは、「差分なし」でも、報告の末尾に1文を添える。アーキテクチャ特性の変更は一覧に出ないので、特性の表を変えたときは `--base` を付けずに、特性の名前か特性の表のファイルを焦点にして起動するよう述べる。
