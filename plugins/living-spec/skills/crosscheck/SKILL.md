# 規則間の矛盾の突き合わせ

機械検査を通った正本に、意味の突き合わせを掛ける。直さずに報告する。直すのは `structure` か利用者。

## 引数

焦点（UC・条件・状態モデルの名前、または変更したファイル）。無ければ全体。

起点にするのは、焦点に挙がったファイルの最初の1つだけである。2つ目以降の焦点が別の根にあっても、注記は出ない。焦点が複数の根にまたがるときは、根ごとに分けて起動する。このスキルは焦点どうしのパスを比べない。

## 手順

根は検査器が起点から決める。規則の正本は `${CLAUDE_PLUGIN_ROOT}/references/format.md` の「置き場の設定」。`.living-spec.json` や `docs/rdra` を自分で探さない。パスも比べない。

- 起点の渡し方: 扱っているファイルがあれば、それを `check`・`render` の引数に渡す。無ければ引数を付けない。扱っているファイルとは、焦点に挙がったファイルの最初の1つである。焦点が名前だけか、焦点が無ければ、引数を付けない
- 1回の実行の中では、2回目以降の `check`・`render` に最初と同じ起点を渡す
- 起点を替えるのは次の3つの場合だけである。替えた後は、以後の `check`・`render` にその起点を渡す
  - 範囲外の注記に答えて、対象を根の置き場へ移したとき（移した先）
  - 対象の領域を独立した正本にしたとき（その根）
  - 正本の無い場所で新しく根を作ったとき（その根）
- 根の取り方: `check` の標準出力の1行目が `根: ` で始まれば、その後ろを根の絶対パスとする
- 注記の伝え方: 標準エラーに注記が出たら、そのまま利用者へ伝え、扱い（対象を根の置き場へ移す／その領域を独立した正本にする）を尋ねる。答えを得るまで、注記の対象を根の正本として扱わない。このスキルは答えを待たずに終える（手順1）。利用者の答えを受けて起動し直す

1. `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" check [起点]` を実行する。
   - 終了コード 2 なら、標準エラーを示して止まる
   - 注記が出たら、違反の有無によらず手順2 以降へ進まない（`rule-crosschecker` を起動しない）。注記と扱いの問いを報告して終える
   - 違反があれば、正本が崩れたままでは意味の突き合わせが空振りするため、違反を示して止まる
2. 手順1 の `check` の1行目から根を取る。置き場を `<根>/.living-spec.json` から読む（無ければ既定）
3. `rule-crosschecker` エージェントへ、根の絶対パス（手順2 の根）・置き場・焦点と、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）を渡す。起草の経緯・作り手の意図は渡さない
4. 返った指摘から最大3件を抜き取り、根拠を確かめる。
   - 抜き取る件数は、blocker と warning を合わせて最大3件とする。
   - blocker を出力の並びの先頭から取る。3件に足りなければ、warning を同じ並びの先頭から足す。
   - 出力の並びは、エージェントが返した文面での出現順を指す。id の番号順に並べ替えない。
   - 抜き取った指摘ごとに、根拠の path:行 を自分で読んで、指摘どおりの記述があるかを確かめる。
   - 指摘が0件なら、出力の並びの先頭の pass の行から当てはめる。pass の行が無ければ食い違いとする。
   - 取った行の見た範囲を場所ごとに分けて揃え、エージェントへ渡した置き場と根からの相対で照らす。続けて次の (i)〜(iv) を順に当てはめ、最初に当たったもので扱う。
     - 揃え方は次のとおりとする。絶対パスで書かれていれば、根の絶対パスを除く。path:行 の形は、行を除いたファイルとして扱う。`*` を含む形（例 `docs/rdra/*.yaml`）は、`*` より前の部分が属する置き場のディレクトリとして扱う。どの置き場にも属さない場所は、置き場の外とする。
     - (i) 置き場の配下のファイルが挙がっていれば、見た範囲に書かれた順で先頭の1つを自分で読む。読めなければ食い違いとする。
     - (ii) 表の置き場のディレクトリを指していれば、確かめたとし、読まない。検査（`run.mjs check`）が通った時点で、表の置き場は実在するためである。
     - (iii) 置き場を指す場所が要求票・例の置き場のディレクトリだけなら、その行では確かめられない（置き場の外の場所は数えない）。path を含まない文だけの行（例「全ての表」）も同じとする。次の pass の行へ進み、その行の見た範囲を同じく揃えて、(i) から当てはめる。全ての pass の行で確かめられなければ、確かめられなかったとする。
     - (iv) どれにも当たらなければ（見た範囲が空、または置き場の外だけを指す）、食い違いとする。
     - (i)・(ii)・(iv) に当たった行で止まり、次の pass の行へ進まない。
   - 食い違えばその旨を報告に付す。食い違いには、根拠の記述が指摘と違う場合と、指摘0件の当てはめで食い違いとした場合を含む。確かめられなかった場合は、食い違いと別の語のまま報告に付す。

## 出力

| id | 重さ | 根拠（両側） | なぜ両立しないか | 直し方の案 |
|---|---|---|---|---|

表の後に、blocker・warning・pass の件数と、抜き取りで確かめた指摘の id（blocker・warning を含む）を書く。指摘が0件でも、見た範囲を書く。指摘が0件のときは、確かめた pass の id と、確かめた内容（読んだファイル、表の置き場を指していたこと、または食い違いの中身）を書く。全ての pass の行で確かめられなかったときは、その旨を書く。食い違いと確かめられなかったは、別の語のまま書く。
