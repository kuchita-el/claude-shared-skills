# 要求の可視化

## 引数

描く正本のファイルかディレクトリ（任意）。無ければ作業ディレクトリから根を決める。

## 手順

根は検査器が起点から決める。規則の正本は `${CLAUDE_PLUGIN_ROOT}/references/format.md` の「置き場の設定」。`.living-spec.json` や `docs/rdra` を自分で探さない。パスも比べない。

- 起点の渡し方: 扱っているファイルがあれば、それを `check`・`render` の引数に渡す。無ければ引数を付けない。扱っているファイルとは、引数に示された描く正本のファイルかディレクトリである
- 1回の実行の中では、2回目以降の `check`・`render` に最初と同じ起点を渡す
- 起点を替えるのは次の3つの場合だけである。替えた後は、以後の `check`・`render` にその起点を渡す
  - 範囲外の注記に答えて、対象を根の置き場へ移したとき（移した先）
  - 対象の領域を独立した正本にしたとき（その根）
  - 正本の無い場所で新しく根を作ったとき（その根）
- 根の取り方: `check` の標準出力の1行目が `根: ` で始まれば、その後ろを根の絶対パスとする
- 注記の伝え方: 標準エラーに注記が出たら、そのまま利用者へ伝え、扱い（対象を根の置き場へ移す／その領域を独立した正本にする）を尋ねる。答えを得るまで、注記の対象を根の正本として扱わない。このスキルは答えを待たずに終える（手順4）

1. `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" render [起点]` を実行する。書き出した場所（既定 `<根>/.cache/living-spec/index.html`、`.living-spec.json` の `output` で変わる）が標準出力に出る
2. 終了コード 2 なら、起点が見つからない・正本が見つからない・設定の誤り・根の探索で読めない・根に表の置き場が無い、のいずれか。設定の誤りは、`.living-spec.json` を読めないか、根に属さない置き場があるときである。標準エラーの内容を示して止まる
3. 書き出した場所と開き方を示す。開くのは利用者に任せ、ブラウザを自動で起動しない
   - macOS: `open <path>` ／ Linux: `xdg-open <path>` ／ WSL: `explorer.exe "$(wslpath -w <path>)"`（WSL 内のブラウザは日本語のフォントが無いことがある）
   - 描き直した後に古い図が出たら、ブラウザのキャッシュを飛ばして読み直す（Ctrl+Shift+R）
4. 手順3 を済ませたうえで注記が出ていたら、書き出した場所と開き方に続けて、注記と扱いの問いを示して終える。描いた図は根のものである。描画は済んでいるので止めない

## 描くもの

- 先頭に生成時刻と根のパス（古い図を見ていないかの見分け）
- 開いた直後に見えるのは全体像で、状態モデルごとの状態遷移図（辺の名札は遷移 UC、仮説の遷移は破線）と遷移の表、UC の一覧（アクター・仮説・要求票と例の有無）、どの UC にも結び付かない要求票と例（ある場合）
- UC ごとの縦串は UC 名の見出しだけを並べて本文を閉じておく。UC の一覧や遷移の表で UC 名を選ぶ、見出しを押す、縦串へのページ内リンクやアンカー付きのアドレスで到達する、のいずれかで開く。縦串の中身: 説明・アクター・外部システム、その UC が動かす遷移を強調した図、情報、条件、要求票の行（RDRA 欄が指す要素の中身を行の直下に畳んで出す）と同名ルールの例、票に結び付かない例
- 表に無い名前は印を付けて出す。検査の違反があっても描く

図は Mermaid を jsdelivr から読むため、表示にはネットワークが要る。表の部分と縦串の開閉は、ネットワークが無くても読める（動く）。

PostToolUse フックが入っていれば、表・票・例の編集のたびに描き直される。
