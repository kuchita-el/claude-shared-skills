# 要求の可視化

## 引数

描く正本のファイルかディレクトリ（任意）。無ければ作業ディレクトリから根を決める。

基準の版（任意）。利用者が `main` やコミット等で指定したときだけ使い、その版と作業ツリーの今の中身を描き分ける。

## 手順

起点は `${CLAUDE_PLUGIN_ROOT}/references/starting-point.md` の「探さない」「起点の渡し方」、注記は同書の「注記の伝え方」に従う。このスキルでは次のとおりとする。

- 扱っているファイルとは、引数に示された描く正本のファイルかディレクトリである
- 実行するのは `render` の1回だけである。`check` は実行しない
- 注記を伝えたら、答えを待たずに終える（手順4）

1. `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" render [--base <版>] [起点]` を実行する。基準の版の指定があれば、その版をそのまま `--base` に渡す（git を呼ばず、版を確かめない）。版は `--base '<版>'` のように単引用符で囲んで渡す（git の参照名は、シェルが読み替える `;`・`&`・`$`・`|` を含められる）。書き出した場所（既定 `<根>/.cache/living-spec/index.html`、`.living-spec.json` の `output` で変わる）が標準出力に出る。基準の版を指定したときは別のファイル（既定 `<根>/.cache/living-spec/index-diff.html`）へ書く
2. 終了コード 2 なら、標準エラーの内容を示して止まる。終了コード 2 の理由は `${CLAUDE_PLUGIN_ROOT}/references/format.md` の「検査の規則」の終了コードが定め、基準の版を指定したときは同書の「基準の版との描き分け」の「止まる場合」も当たる
3. 書き出した場所と開き方を示す。開くのは利用者に任せ、ブラウザを自動で起動しない
   - macOS: `open <path>` ／ Linux: `xdg-open <path>` ／ WSL: `explorer.exe "$(wslpath -w <path>)"`（WSL 内のブラウザは日本語のフォントが無いことがある）
   - 描き直した後に古い図が出たら、ブラウザのキャッシュを飛ばして読み直す（Ctrl+Shift+R）
4. 手順3 を済ませたうえで注記が出ていたら、書き出した場所と開き方に続けて、注記と扱いの問いを示して終える。描いた図は根のものである。描画は済んでいるので止めない

## 描くもの

- 先頭に生成時刻と根のパス（古い図を見ていないかの見分け）
- 開いた直後に見えるのは全体像で、状態モデルごとの状態遷移図（辺の名札は遷移 UC、仮説の遷移は破線）と遷移の表、UC の一覧（アクター・仮説・要求票と例の有無）、どの UC にも結び付かない要求票と例（ある場合）
- UC ごとの縦串は UC 名の見出しだけを並べて本文を閉じておく。UC の一覧や遷移の表で UC 名を選ぶ、見出しを押す、縦串へのページ内リンクやアンカー付きのアドレスで到達する、のいずれかで開く。縦串の中身: 説明・アクター・外部システム、その UC が動かす遷移を強調した図、情報、条件、要求票の行（RDRA 欄が指す要素の中身を行の直下に畳んで出す）と同名ルールの例、票に結び付かない例
- 表に無い名前は印を付けて出す。検査の違反があっても描く
- 基準の版を指定すると、足された・変わった・外された要素に印が付き、外された要素も残して描く。比べ方と印の付く位置は `${CLAUDE_PLUGIN_ROOT}/references/format.md` の「基準の版との描き分け」が定める

図は Mermaid を jsdelivr から読むため、表示にはネットワークが要る。表の部分と縦串の開閉は、ネットワークが無くても読める（動く）。

PostToolUse フックが入っていれば、表・票・例の編集のたびに描き直される。描き分けの HTML はフックが描き直さないので、編集の後に描き分けを見るときは、基準の版を指定してもう一度描く。
