# 起点と根の手順

検査器の `check`・`render` を実行するスキルが従う手順である。根を決める規則の正本は `references/format.md` の「置き場の設定」で、ここには写さない。

扱っているファイルが何か、注記を伝えた後にどう続けるかは、各スキルが定める。

## 探さない

根は検査器が起点から決める。`.living-spec.json` や `docs/rdra` を自分で探さない。パスも比べない。

## 起点の渡し方

- 扱っているファイルがあれば、それを `check`・`render` の引数に渡す。無ければ引数を付けない
- 1回の実行の中で `check`・`render` を2回以上呼ぶときは、2回目以降に最初と同じ起点を渡す
- 起点を替えるのは次の3つの場合だけである。替えた後は、以後の `check`・`render` にその起点を渡す
  - 範囲外の注記に答えて、対象を根の置き場へ移したとき（移した先）
  - 対象の領域を独立した正本にしたとき（その根）
  - 正本の無い場所で新しく根を作ったとき（その根）

## 根の取り方

`check` を実行するスキルは、`check` の標準出力の1行目から根を取る。1行目が `根: ` で始まれば、その後ろを根の絶対パスとする。`render` の標準出力は書き出した場所だけで、根を出さない。

## 注記の伝え方

標準エラーに注記が出たら、そのまま利用者へ伝え、扱い（対象を根の置き場へ移す／その領域を独立した正本にする）を利用者に問う。答えを得るまで、注記の対象を根の正本として扱わない。
