# 昇格の PR の本文

昇格の PR の本文は、次の形で書く。見出しと表の行を、省かず、並べ替えない。

```markdown
## 昇格する記録

- 新しい記録: records/<識別子>-<名前>.md
- 出典: Project <元の識別子>@<版>

## 昇格の確認

| 確認 | 結果 | 確かめた者 | 根拠 |
|---|---|---|---|
| 元の経験は検証済みか | … | … | 元の記録の verification の値と、出典の種類 |
| 他のプロジェクトにも当てはまるか | … | … | 主張が依る前提と、それを applies-when へ書いた箇所 |
| 適用条件と例外は何か | … | … | applies-when の文と、本文の「当てはまらない場合」の箇所 |
| 機密の情報を含まないか | … | … | 照合した語の件数と一致の件数、別の文脈の読みの指摘の件数 |
| 既存の記録と矛盾しないか | … | … | 見た範囲（索引の行数、本文を読んだ記録の識別子） |

## 突き合わせの報告

| 関係 | 相手の記録（層と識別子） | 根拠 | 理由 |
|---|---|---|---|

## 人間が決めること

- （食い違いの裁定、置き換えるかどうか、一般化の範囲の当否）
```

## 書き方

- **5つの行**: いつも全て書く。確かめなかった確認も、行を残して結果に理由を書く。
- **1行目（元の経験は検証済みか）**: 結果に、元の記録の `verification` の値を書く。この文脈が観測を確かめ直していなければ、確かめたのは元の記録の値と出典であることを書く。`unverified` のまま昇格するときは、未検証であることを書く。
- **結果**: 次の3つの形に限る。
  - `確かめた: <中身>`
  - `省いた: 利用規則の定め`
  - `未実施: <理由>`
- **確かめた者**: `AI（このスキル）`、`別の文脈（record-crosschecker）`、`人間に委ねる` のどれかを書く。利用規則が人間の確認と定めた行は、結果を `未実施: 人間が確かめる` とし、確かめた者を `人間に委ねる` とする。
- **機密の行**: 結果に書けるのは `確かめた` だけである。ほかの結果になるなら、この本文を昇格先への PR に使わない。根拠には件数だけを書く。照合した語と、指摘された文字列は書かない。書くと、確認そのものが混入の経路になる。
- **突き合わせの報告**: 「食い違う」と「重なる」の行だけを載せる。「関わる」は、表の後に件数だけを書く。表の後に、関係ごとの件数、見た範囲、根拠を確かめた行、根拠の食い違いの有無、突き合わせの文脈（別の文脈か、未実施か）を書く。0件でも、見た範囲を書く。機密の指摘は載せない。
- **元の記録と種類を変えたとき**: 「昇格する記録」に、変えた種類と理由を1行で足す。
- **利用規則の読み取りに迷ったとき**: 「人間が決めること」に、迷った箇所と、既定（AI が確かめる）で扱ったことを書く。
- **固有名**: 元のプロジェクトの名前を書かない。出典は、層の名前・識別子・版だけで指す。

## 運ぶ経路で使うとき

PR を出せず、記録とこの本文をファイルとして運ぶときは、末尾に次の節を足す。

```markdown
## 運ぶ者へ

- 済んでいない確認: （上の表で `未実施` とした行）
- 昇格先で行うこと: 記録を records/ へ置く。形式を検査する。未実施の確認を行う。この本文で PR を出す。
- 運び終えたら、プロジェクト側の2つのファイルを消す。
```
