# 記録の昇格

Project Memory の記録を一般化し、Global Memory へ送り出す下書きにする。下書きは Project の根の `outbox/` に書き、送り出しの報告を添える。1回の起動は、下書き1件と報告1件を作る。Global Memory の根へは書かない。下書きは、プロジェクトの PR で承認された後に、Global Memory へ運ばれる。

## 文脈固有ルール

- **対象範囲**: 引数で渡された記録の送り出しだけを扱う。候補を挙げること、Global Memory へ運ぶこと、選別は扱わない。
- **成果物**: `outbox/` の下書き1件、`outbox/reports/` の報告1件、元の記録の `sent-as`。
- **停止条件**（理由を報告して終える）:
  - 元の記録の識別子が、引数に無い。
  - Project の根か Global の根が無い。Global の根の利用規則が在るのに読めない（手順1）。
  - 元の記録の前提が崩れている（手順2）。
  - 元の記録が `sent-as` を持ち、`--resend` が無い（手順3）。
  - 重なるものが在り、補うものが無い（手順4）。
  - 検査器が、終了コード 2 で終わった。
  - 機密の指摘か一致が、やり直しの後も残る（手順9）。

  手順6 より前に止まったときは、何も書いていない。
- **変更境界**:
  - 書くのは、Project の根の `outbox/` の下書きと報告と、元の記録の `sent-as` だけである。
  - Global Memory の根へは書かない。読むだけである。
  - 元の記録の、`sent-as` のほかの項目と本文を変えない。ほかの記録・`index.md`・利用規則・採用の台帳を書き換えない。
  - commit・push・PR の作成は行わない。下書きと報告は、作業中のブランチの変更として残す。出し方は、プロジェクトの工程に従う。

## 引数

- 元の記録の識別子（1件以上。複数は、1件の下書きへまとめる場合）。無ければ、使い方を示して終える。
- `--project-root <パス>`: 元の記録が在る根。省くと、プロジェクトの指示ファイルが示す置き場、無ければリポジトリの根（`git rev-parse --show-toplevel`）の `docs/memory` とする。
- `--global-root <パス>`: 送り出す先の根。省くと、指示ファイルが共有の記憶として指すリポジトリとする。どちらも無ければ、無いものとして扱う。スキルは探さない。
- `--resend`: `sent-as` を持つ記録を、送り直すと明示する。

プロジェクトのリポジトリの中で起動する。

## 送り出しで確かめること

確かめるのは、機密と重なりの2つである。正しさ・当てはまる範囲・既存の記録との矛盾は、Global Memory の選別で確かめる。材料は、下書き自身が持つ（検証状況・確信度・当てはまる条件・当てはまらない場合）。

**機密の確認は、利用規則の定めにかかわらず行う。** 記録がリポジトリの境界を越えるためである。利用規則が確認を省くと定めていても、対象を狭めていても、従わない。対象を足していれば、足して確かめる。対象・手順・コマンドの形は `${CLAUDE_PLUGIN_ROOT}/references/confidentiality.md` が、報告の形と書く順序は `${CLAUDE_PLUGIN_ROOT}/references/outbox-report.md` が定める。ここへ写さない。

## 手順

記録と下書きの形は `${CLAUDE_PLUGIN_ROOT}/references/format.md` が定める。置き場・識別子・項目・出典の書き方は、同書と Global の根の利用規則に従い、ここへ写さない。

コマンドは、下に書いた形のまま、1回に1つずつ実行する。`&&`・`;`・パイプや、`cd`・`echo` でつないだ形と、書かれていない所へ `-C` を足した形は、許可した型に当たらず、拒まれることがある。手順に無いコマンド（`ls`・`printenv` など）は Bash で使わず、手順が示すパスは `Read` で読む。

Project の根が別のリポジトリに在るかは、2つの出力を比べて決める。`git -C <Project の根> rev-parse --show-toplevel` と、`git rev-parse --show-toplevel` である。一致しなければ、別のリポジトリである。そのときだけ、手順7 の `git` のコマンドに `-C <Project の根>` を足す。パスの包含では決めない。作業ツリーの中に、別のリポジトリが置かれていることがあるためである。

1. **形式と利用規則を読み、根を確かめる。** `format.md` と `outbox-report.md` を読む。
   - Global の根が無ければ止める。送り出しに効く利用規則（照合する語、未検証の記録を送ってよいか）を、その根が持つためである。
   - Global の根の利用規則を読む。在りかは、`format.md` の「記憶の根」が定める順で決める。在るのに読めなければ止める。
   - `node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" check <Project の根>` を実行する。終了コード 2 なら止める。0 か 1 なら、出た違反の行を、以前から在る違反として控える。
2. **元の記録を確かめる。** `<Project の根>/records/<識別子>-*.md` を探して読む（`Glob`）。元の記録は、既定のブランチに在るものでも、作業中のブランチで足したものでもよい。下書きと同じ変更のレビューが、両方の承認を兼ねる。次のどれかなら止める。
   - 記録が無い。
   - 置き換え済みである（`superseded-by` か `moved-to` を持つ）。置き換えた先を送るよう伝える。
   - `type` が `evolution` である。
   - `verification` が `unverified` で、Global の根の利用規則が、未検証の記録を送り出さないと定めている。
3. **送り済みでないことを確かめる。** 元の記録が `sent-as` を持てば、並んだ識別子と、`<Project の根>/outbox/` に在るその下書きのパスを示して止める（`Glob`）。`--resend` が在るときだけ進む。進んだら、報告の「重なりの照合」に、送り直したことと前の識別子を書く。
4. **一般化した主張を決め、重なりを照合する。** 主張（`title`）・当てはまる条件（`applies-when`）・種類（`type`）を決める。照合は、別の文脈で行う。`record-matcher` エージェントを起動する。
   - 渡すのは、主張1文・当てはまる条件・種類、根の絶対パス（Project、Global の順）、照らす置き場（Project は `outbox/`、Global は `records/` と `candidates/`）、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）だけである。元の記録の本文と、起草の経緯は渡さない。モデルと effort は、定義の front-matter に従う。
   - 定義済みのエージェントを起動できなければ、汎用のサブエージェントへ同じ入力を渡し、定義のファイル（`${CLAUDE_PLUGIN_ROOT}/agents/record-matcher.md`）を読んで従うよう伝える。それもできなければ、`${CLAUDE_PLUGIN_ROOT}/references/matching.md` を読み、同じ文脈でその手順どおりに照合し、報告にそう書く。
   - 「重なる」「食い違う」と返った組は、根拠の箇所を自分で読んで確かめる（`Read`）。引用どおりの記述が無ければ、「根拠が食い違う」と付して残す。
   - 「重なる」で、補うものが無ければ止め、重なる相手を報告する。補うものが在れば、補う相手の識別子と補う中身を、下書きの本文に書く。
   - 「食い違う」は、直さない。相手の識別子と、どう食い違うかを、下書きの本文に書く。直すかは、選別で決める。
5. **識別子を発番する。** `date -u +%Y%m%d%H%M` を実行し、`MEM-<出力>-01` を下書きの識別子とする。日付は `date -u +%Y-%m-%d` で得る。元の記録の識別子を使わない。下書きは元の写しではなく、一般化した新しい文書だからである。同じ識別子は、手順6 の検査が `duplicate-id` で止める。
6. **下書きを書き、元の記録に `sent-as` を書き、検査する。**
   - 下書きを `<Project の根>/outbox/<識別子>-<名前>.md` へ書く。元の記録の写しにしない。中身は、下の「下書きの中身」に従う。
   - 元の記録の front-matter に `sent-as` を書き、下書きの識別子を並べる（`Edit`）。既に在れば、末尾へ足す。
   - `node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" check <Project の根>` を実行する。違反の行のうち、手順1 で控えた行に無いものが0行なら、通過とする。下書きと `sent-as` は索引の行を変えないので、索引は作り直さない。違反が残れば直し、通るまで先へ進まない。
7. **報告の前半を書き、語を照合する。** 報告を `<Project の根>/outbox/reports/<識別子>.md` へ書く。ファイル名は識別子だけで、名前の部分を付けない。「下書き」と「元の記録」の節まで書く。続けて、`confidentiality.md` の「語の照合」を、下書きと報告に掛ける。
   - リポジトリの名前は、`git remote get-url origin` をこの形のまま実行して得る。remote が無ければ、`git rev-parse --show-toplevel` の末尾の名前を使う。
   - 下書きを書き換えたら、手順6 の検査からやり直す。
8. **読みを、別の文脈へ委ねる。** `record-crosschecker` エージェントを起動する。根は渡さず、語を渡す。機密の読みだけが行われる。
   - 渡すのは、次の5つだけである。焦点（下書きのパス）、照合した語の並び、Global の根の利用規則のパス（無ければ「無い」）、焦点のほかに読むファイル（報告のパス）、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）。
   - 元の記録の本文と、起草の経緯は渡さない。モデルと effort は、定義の front-matter に従う。
   - 定義済みのエージェントを起動できなければ、汎用のサブエージェントへ同じ入力を渡し、定義のファイル（`${CLAUDE_PLUGIN_ROOT}/agents/record-crosschecker.md`）を読んで従うよう伝える。
   - 別の文脈を作れなければ、同じ文脈の読みで代えない。報告の読みを `未実施` として、先へ進む。
9. **指摘を扱い、報告を仕上げる。**
   - 指摘の箇所を、自分で読んで確かめる（`Read`）。下書きか報告を書き換えて全て解消し、手順6〜8 をやり直す。やり直しは2回までとする。残れば、報告に残っていると書いて止める。
   - 報告の残りの3つの節を書く。続けて、`outbox-report.md` の「書く順序」の6を行う。

## 下書きの中身

- `sources` に、`Project` の出典を書かない。元の記録の出典のうち、公開の文書の URL は引き継いでよい。観測は「いつ、どの環境で実測したか」の形で書く。Global の記録を指すときは、識別子だけを書く。
- `applies-when` に、主張が依る前提（道具・版・環境）を書く。本文に、当てはまらない場合を書く。
- `verification` は、元の記録の値を引き継ぐ。`confidence` は、元の記録より上げない。`unverified` なら、本文に未検証であることを書く。
- 引き継いだ `verified` は、元の記録の観測に拠る。この文脈が確かめ直していなければ、本文で、観測は元の記録のものであると断る。主張は、元の記録が確かめた範囲に収める。一般化で広げた範囲は、確かめていないこととして本文に分ける。収まらなければ、`unverified` とする。
- `type` は、主張の中身で決める。`evolution` にしない。`superseded-by`・`moved-to` を書かない。
- `belief` の `author` を `human` とするのは、全てのプロジェクトに当てはまると本人がこの会話で明示した場合だけである。それ以外は `ai` とする。この区別は、利用規則で外せない。

## 出力

**最終の応答に、利用規則と利用者が挙げた語、読みが指摘した文字列、取り除いた文字列を書かない。** 元のプロジェクトのリポジトリから得た語は、書いてよい。機密の確認は、件数で示す。

次を1項目ずつ書く。該当が無い項目も「無い」と書く。

- 下書き: パス・識別子・表題・検証状況。止めたときは、止めた理由と、書いたものが在ればそのパス。
- 報告: パス。
- 元の記録: 識別子と、書いた `sent-as`。
- 重なりの照合: 照らした相手、文脈（別か同じか）、関係ごとの件数、「重なる」「食い違う」の相手、根拠を確かめた行。
- 機密の確認: 一致の件数、取り除いた件数、残した一致の件数、読みの文脈と指摘の件数。
- 検査の結果: 実行したコマンドと、下書きが足した違反の件数。
- 次に要ること: 下書き・報告・`sent-as` を、プロジェクトの PR に載せる。マージが、送り出しの承認になる。承認された下書きは、その後に Global Memory へ運ばれる。
