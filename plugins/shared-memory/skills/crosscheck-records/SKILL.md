# 記録の突き合わせ

焦点の記録を、既に在る記録と、書いた文脈とは別の文脈で突き合わせる。直さずに報告する。直すかどうかは、人間が決める。

## 文脈固有ルール

- **対象範囲**: 焦点に挙がった記録だけを扱う。根の全体の突き合わせ、機密の情報の確認、置き換えは扱わない。
- **成果物**: 報告だけである。
- **停止条件**: 焦点が無い。識別子の焦点が、1つのファイルに決まらない（手順1）。焦点の根が、1つに決まらない（手順1）。突き合わせる根を検査できない、または検査が索引の行のほかに違反を出した（手順2）。別の文脈を作れない（手順3）。
- **変更境界**: 何も書かない。記録も索引も書き換えない。

## 引数

- 焦点: 記録の識別子か、記録のファイルのパス。1件以上。無ければ、使い方を示して終える。根の全体を対象にする起動は持たない。
- `--project-root <パス>`、`--global-root <パス>`: 突き合わせる根。

根は、次のとおり決める。指示ファイルは、セッションに読み込まれているものを使う。探しに行かない。

- **Project Memory の根**: `--project-root`。省くと、プロジェクトの指示ファイルが示す置き場とする。それも無ければ、リポジトリの根（`git rev-parse --show-toplevel`）の `docs/memory` とする。焦点が全てファイルのパスで渡されたときは、この既定を求めない。
- **Global Memory の根**: `--global-root`。省くと、指示ファイルが共有の記憶として指すリポジトリとする。どちらも無ければ、無いものとして扱う。スキルは探さない。
- **焦点の根**: 焦点がファイルのパスなら、そのファイルが在る `records/` の親である。焦点が識別子なら、手順1 で決める。焦点が複数在るときは、全ての焦点が同じ根に在ることを求める。
- **突き合わせる根**: 焦点の根が Global Memory の根と同じディレクトリなら、その根だけである。それ以外は、焦点の根と、Global Memory の根（在れば）である。同じディレクトリかは、2つを絶対パスにして比べる。

決めた場所が記憶の根かどうかは、手順2 の検査器の結果で確かめる。

## 手順

コマンドは、下に書いた形のまま、1回に1つずつ実行する。`&&`・`;`・パイプや、`cd`・`echo` でつないだ形と、`-C` を足した形は、許可した型に当たらず、拒まれることがある。手順に無いコマンド（`ls`・`printenv` など）は使わず、ファイルの在りかは `Glob` で、中身は `Read` で見る。

1. **焦点を解決する。** 識別子で渡された焦点ごとに、上の2つの根の `records/` の直下を、`<識別子>-*.md` で探す（`Glob`）。
   - 見つかったファイルが、2つの根を合わせて1件なら、そのファイルを焦点にする。在った根が、焦点の根である。
   - 0件か、2件以上なら、探した根と、見つけたパスを示して止まる。ファイルのパスで渡し直すよう伝える。推測で1つを選ばない。
   - 探す根は、「引数」の定めで決めた Project Memory の根と Global Memory の根である。無い層は探さない。
   - パスで渡された焦点も含めて、焦点の根が2つ以上に分かれたら、根ごとの焦点を示して止まる。根ごとに分けて起動し直すよう伝える。
2. **根を検査する。** 突き合わせる根ごとに、`node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" check <根>` を実行する。次を上から順に当て、最初に当たったもので扱う。
   - 終了コード 2 で、標準エラーが、`records/` が無いか、ディレクトリでないと述べる。引数を省いて決めた根なら、その層は無いものとして扱う。引数か、焦点のパスで決まった根なら、標準エラーを示して止まる。
   - そのほかの終了コード 2 なら、標準エラーを示して止まる。
   - 違反の行（`パス:規則: 説明`）に、`index.md:index:` で始まらない行が在れば、違反を示して止まる。正本が崩れたままでは、突き合わせが空振りするためである。
   - `index.md:index:` の行だけなら進む。索引が記録と一致していなかったことを、報告に付す。索引は作り直さない。
3. **別の文脈へ委ねる。** `record-crosschecker` エージェントを起動する。行わせるのは、照合だけである。語を渡さないので、機密の読みは行われない。
   - 渡すのは、突き合わせる根の絶対パス（Project、Global の順。無い層は「無い」）、焦点のファイルの絶対パス、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）だけである。記録を書いた経緯と、書き手の意図は渡さない。
   - モデルと effort は定義の front-matter に従い、呼び出す側では指定しない。
   - 定義済みのエージェントを起動できないホストでは、汎用のサブエージェントへ同じ入力を渡す。あわせて、定義のファイル（`${CLAUDE_PLUGIN_ROOT}/agents/record-crosschecker.md`）を読んで従うよう伝える。
   - 別の文脈を作れなければ、突き合わせない。同じ文脈の照合で代えない。「未実施」と報告し、別のセッションで行うための入力（定義のファイルのパスと、上の渡す値）を示して終える。
4. **根拠を確かめる。** 「重なる」「食い違う」と返った組ごとに、根拠に挙がった記録の箇所を、自分で読む（`Read`。シェルのコマンドで読まない）。引用どおりの記述が無ければ、「根拠が食い違う」と付して残す。「関わる」「関係なし」は確かめ直さない。
5. **報告する。** 下の形で報告する。直さない。置き換えも行わない。

## 出力

| 関係 | 相手の記録（層と識別子） | 根拠 | 理由 |
|---|---|---|---|

載せるのは、「食い違う」と「重なる」の行である。表の後に、次を1項目ずつ書く。0件でも省かない。

- 関係ごとの件数（重なる・食い違う・関わる・関係なし）。
- 見た範囲: 根ごとのパス、読んだ索引の行数、本文を読んだ記録。
- 根拠を確かめた行と、根拠の食い違いの有無。
- 突き合わせの文脈: 別の文脈か、未実施か。
- 索引が記録と一致していなかった根（在れば）。

エージェントの報告の全文は載せない。
