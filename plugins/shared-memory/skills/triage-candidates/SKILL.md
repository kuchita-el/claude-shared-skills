# 候補の選別の下ごしらえ

Global Memory の根の `candidates/` に在る候補を、既存の記録とほかの候補と突き合わせ、5つの結果のどれにするかの案を出す。受け入れるかを決めるのは、人間である。

## 文脈固有ルール

- **対象範囲**: 選んだ候補の案だけを扱う。見直し（受け入れた記録を古びていないか確かめること）、送り出しの確認、機密の読みは扱わない。
- **成果物**: 案の表。頼まれたときだけ、選別の変更を載せたブランチ（手順7）。
- **停止条件**: Global Memory の根を決められない。ブランチを用意するとき、branch.md の前提が崩れている。根を検査できない、または検査が索引の行のほかに違反を出した（手順2）。識別子の候補が、1つのファイルに決まらない（手順3）。別の文脈を作れない（手順4）。
- **変更境界**:
  - 頼まれない限り、何も書かない。記録・候補・索引を書き換えない。
  - 書いてよいのは、選別の変更を用意するよう頼まれたときの、新しく切ったブランチの上だけである。既定のブランチと、起動したときのブランチへは書かない。例外は、ホストが、セッションの現在のブランチへしか push できないと定める場合である。このときだけ、HEAD が既定のブランチの先端と同じ（branch.md）なら、現在のブランチへ切り替えずに書く。
  - commit・push・PR の作成は行わない。

## 引数

- 候補の識別子: 任意。1件以上。名指したときは、その候補だけを扱う。無ければ、識別子の古い順に10件を扱う。
- `--global-root <パス>`: Global Memory の根。省くと、指示ファイルが共有の記憶として指すリポジトリとする。それも無ければ、現在のディレクトリとする。指示ファイルは、セッションに読み込まれているものを使う。探しに行かない。
- `--prepare-branch`: 選別の変更をブランチに用意する。頼まれたときだけ付ける。

## 手順

コマンドは、下に書いた形のまま、1回に1つずつ実行する。`&&`・`;`・パイプ・`2>&1` や、`cd`・`echo` でつないだ形は、許可した型に当たらず、拒まれる。終了コードは、足した `echo` ではなく、結果から読む。手順に無いコマンド（`ls`・`pwd`・`printenv` など）は Bash で使わず、手順が示すパスは `Read` で読む。根は、引数のパスのまま `check` へ渡す。

1. **読む。** `${CLAUDE_PLUGIN_ROOT}/references/format.md` の「送り出しの下書きと候補」「記録の形」を読む。根の利用規則が在れば読み、受け入れの4観点を誰が確かめると定めているかを控える。
2. **根を検査する。** `node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" check <根>` を実行する。
   - 終了コード 2 なら、標準エラーを示して止まる。
   - 違反の行（`パス:規則: 説明`）に、`index.md:index:` で始まらない行が在れば、違反を示して止まる。正本が崩れたままでは、突き合わせが空振りするためである。
   - `index.md:index:` の行だけなら進む。報告に付す。索引は作り直さない。
3. **候補を選ぶ。** `<根>/candidates/*.md` を `Glob` で集め、ファイル名の昇順に並べる。
   - 識別子で渡されたら、その識別子で始まるファイルを選ぶ。0件か2件以上なら、探した場所を示して止まる。
   - 渡されなければ、先頭の10件を選ぶ。残りの件数を控える。
   - 候補が0件なら、0件と報告して終える。
4. **別の文脈へ委ねる。** 選んだ候補を5件ずつの組に分け、組ごとに `record-crosschecker` エージェントを起動する。複数の組は並列に起動する。行わせるのは、照合だけである。
   - 渡すのは、根の絶対パス（Project は「無い」、Global は根）、焦点の候補のファイルの絶対パス、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）だけである。候補を書いた経緯は渡さない。
   - モデルと effort は定義の front-matter に従い、呼び出す側では指定しない。
   - 定義済みのエージェントを起動できないホストでは、汎用のサブエージェントへ同じ入力を渡す。あわせて、定義のファイル（`${CLAUDE_PLUGIN_ROOT}/agents/record-crosschecker.md`）を読んで従うよう伝える。
   - 別の文脈を作れなければ、案を出さない。同じ文脈の照合で代えない。「未実施」と報告し、別のセッションで行うための入力（定義のファイルのパスと、上の渡す値）を示して終える。
5. **根拠を確かめる。** 「重なる」「食い違う」と返った組ごとに、根拠に挙がった箇所を `Read` で読む。引用どおりの記述が無ければ、「根拠が食い違う」と付す。
6. **案を決める。** 候補ごとに、次の規則を上から当て、最初に当たったもので決める。案は1つだけ付ける。
   1. 既存の記録と食い違う: 候補の根拠（出典・当てはまる条件）が既存の記録より強ければ「置き換える」、そうでなければ「捨てる」。どちらが正しいかは決めず、根拠の強さを並べ、人間が決めることへ載せる。
   2. ほかの候補と食い違う: 規則1と同じに根拠（出典・当てはまる条件）を比べる。根拠が弱い側を「捨てる」。強い側は、次の規則へ進む。どちらも明らかに強くなければ、両方を「捨てる」。どちらが正しいかは決めず、食い違いを人間が決めることへ載せる。
   3. 既存の記録と重なる: 補うものが在れば「補う」、無ければ「捨てる」。同じ記録と重なるほかの候補が在れば、相手に並べる。
   4. ほかの候補と重なる: 互いに補うなら「まとめる」。一方が他方を含むなら、含まれる側を「捨てる」。含む側は、次の規則へ進む。どちらでもなければ、次の規則へ進む。
   5. 記述が欠けていて直せない: 「捨てる」。欠けは記述の欠落に限る。本文に当てはまらない場合が無い、主張と本文が対応しない、出典が観測を辿れない、のどれかである。直せる欠けなら「採る」とし、直し方を人間が決めることへ載せる。
   6. AI が確かめる観点で、ほかのプロジェクトに当てはまらない（プロジェクトに固有）と判断した: 「捨てる」。
   7. 上のどれにも当たらない: 「採る」。

   `verification: unverified` と `confidence` は、案を決めない。人間が決めることへ載せる。利用規則が人間に割り当てた観点は、判断に入れず、「人間が確かめる」と示す。
7. **用意する（`--prepare-branch` のときだけ）。** `${CLAUDE_SKILL_DIR}/references/branch.md` と `${CLAUDE_PLUGIN_ROOT}/references/replacement.md` を読み、そのとおりに行う。前提（branch.md「前提」）が崩れていれば、何も書かずに止まる。付いていなければ、何も書かない。
8. **報告する。** 下の形で報告する。

## 出力

案の表。候補1件につき1行。「案」は、採る・まとめる・捨てる・補う・置き換えるの1つである。

| 候補 | 案 | 相手（層と識別子。無ければ `-`） | 根拠 |
|---|---|---|---|

受け入れの4観点の表。候補1件につき1行。

| 候補 | 検証済みか | 他に当てはまるか | 適用条件と例外 | 矛盾 | 確かめた者 |
|---|---|---|---|---|---|

- 検証済みか: 候補の `verification` と、出典の有無。
- 他に当てはまるか: ほかのプロジェクトにも当てはまるか。「当てはまる」「当てはまらない」「不明」のどれかと、理由1文を書く。不明は案を決めない。
- 適用条件と例外: `applies-when` と、当てはまらない場合の記述が在るか。
- 矛盾: 手順4 の結果。「なし」か、「食い違う: <相手>」。
- 確かめた者: 利用規則が人間に割り当てた観点は、材料だけを示し、「人間が確かめる」と書く。定めが無い観点は、AI が確かめ、人間が裁定する。

表の後に、次を1項目ずつ書く。0件でも省かない。

- 「まとめる」の下書き: まとめる組ごとに、新しい記録の表題と主張だけを書く。`--prepare-branch` のときは、手順7 が書いた記録のパスを示す。
- 人間が決めること: 食い違いの裁定、確かめていない観点、直せる欠けの直し方。
- 件数: 扱った候補の件数と、残りの件数。
- 見た範囲: 根のパス、読んだ索引の行数、本文を読んだ記録と候補。
- 突き合わせの文脈: 別の文脈か、未実施か。
- 索引が記録と一致していなかったときは、その旨。
- 用意したブランチ（在れば）: ブランチの名前と、変えたファイル。

エージェントの報告の全文は載せない。
