# 選別の変更の用意

案の表を、ブランチの上の変更にする。頼まれたときだけ行う。受け入れるかを決めるのは、人間である。変更を既定のブランチへ入れるのも、人間のマージか直接の編集である。

## 前提

次のどれかに当たれば、何も書かずに止めて、理由を報告する。

- 手順4 が「未実施」だった。案が無い。
- `git status --porcelain` に当たるものが在る。作業ツリーが汚れている。

## 手順

1. **ブランチを切る。** `date -u +%Y%m%d%H%M` で時刻を得て、`git switch -c triage-<時刻>` を実行する。起動したときのブランチへは書かない。
2. **案ごとに変える。** 識別子は、新しい記録だけ `date -u +%Y%m%d%H%M` で発番する。同じ分に複数作るときは、連番を増やす。

   | 案 | すること |
   |---|---|
   | 採る | `git mv <根>/candidates/<ファイル> <根>/records/<ファイル>`。言い回しを直すときだけ、移した記録を書き換える |
   | まとめる | 新しい記録を `records/` へ書く。`verification` は `unverified`、`author` は `ai`、`sources` に、まとめた候補と記録の識別子を書く。まとめた候補を `git rm` で除く。下書きの承認は、人間のマージである |
   | 捨てる | `git rm <根>/candidates/<ファイル>` |
   | 補う | 既存の記録へ、主張を変えずに候補の中身を足し、`updated` を改め、`sources` へ候補の識別子を足す。候補を `git rm` で除く |
   | 置き換える | `replacement.md` の手順に従う。新しい記録は、採った候補を移したものか、まとめた記録である。候補は `git mv` で `records/` へ移し、まとめた候補は `git rm` で除く |

3. **検査する。** 索引を変更に含める根では、`index <根> --write` の後に `check <根>` を実行する。含めないと規則が定める根では、`index.md` を書かず、`check <根>` の違反の行から `index.md:index:` で始まる行を除く。残りが0行なら通過とする。違反が残れば、説明に従って直し、検査し直す。終了コード 2 は、標準エラーを示して止まる。
4. **報告する。** ブランチの名前と、変えたファイルを示す。commit していないことと、既定のブランチへ入れていないことを書く。

## 守ること

- 変えるのは、案の表に在る候補と、その相手の記録だけである。
- 案を人間が直していたら、直した案に従う。
- 既定のブランチへ入れない。ブランチを切れなかったときは、止める。
