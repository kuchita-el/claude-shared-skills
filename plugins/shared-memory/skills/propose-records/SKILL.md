# 学びの候補を記録として提案する

タスクの材料から学びの候補を挙げ、既に在る記録と照らして、足す・直す・捨てるに分ける。足すものと直すものは、Project の記録か、Global Memory へ送り出す下書きにして検査する。捨てた候補と、見送った候補も、理由つきで示す。送り出しの下書きは、Project の根の `outbox/` に書き、送り出しの報告を添える。Global Memory の根へは書かない。終わりに、既に承認された下書きを運ぶ。

## 文脈固有ルール

- **対象範囲**: 渡された材料と、このタスクの差分から挙げた候補だけを扱う。Project の記録を Global へ上げること（昇格）は扱わない。
- **成果物**: 全ての候補の表と、足す・直すと決めた候補の下書き。送り出しの下書きには、送り出しの報告。
- **停止条件**: 次のどれかなら、下書きを作らずに終える。表は出す。
  - Project の根が無い。Project の記録の置き場も、送り出しの下書きの置き場も無いためである。
  - 関門と照合を通った候補が0件である。
- **変更境界**:
  - 書くのは、Project の根の `records/` と `outbox/` の下と、索引を変更に含めるときの `index.md` だけである。索引は検査器で作り直し、手で書かない。
  - Global Memory の根へは、手順8 で運ぶ候補のほかは書かない。Global の記録への追記と置き換えも行わない（手順4）。
  - `inbox/`・利用規則・採用の台帳・指示ファイル・決定の記録を書き換えない。記録を消さない。
  - Task Memory は読むだけである。書き換えず、消さない。消すのは、タスクを進めている持ち主である。
  - commit・push・PR の作成を、このスキルは事前に許可しない（手順8）。Global へ commit・push するのは、手順8 で運ぶときだけである。

## 引数

| 引数 | 意味 |
|---|---|
| 材料（自由文か、ファイルのパス。複数可） | 会話に無い材料を足す。作業メモを渡せる |
| `--base <版>` | 差分の基準。渡されたら `<版>..HEAD` を材料にする |
| `--project-root <パス>` | Project Memory の根を指す |
| `--global-root <パス>` | Global Memory の根を指す |

どれも任意である。根は、次の順で決める。

- Project: 引数、指示ファイルが示す置き場、リポジトリの根の `docs/memory` の順に当てる。決めた場所が記憶の根でなければ、Project Memory は無いものとして扱う（確かめ方は手順1）。ほかの場所を探さない。
- Global: 引数、指示ファイルが共有の記憶として指すリポジトリの順に当てる。どちらも無ければ、無いものとして扱う。このスキルは探さない。

## 手順

記録の形は `${CLAUDE_PLUGIN_ROOT}/references/format.md` が定める。識別子・項目・置き換え・出典と版の書き方は同書に従い、ここへ写さない。

コマンドは、下に書いた形のまま、1回に1つずつ実行する。`cd` や `echo` をつないだ形と、書かれていない所へ `-C` を足した形は、許可した型に当たらず、拒まれることがある。手順に無いコマンド（`ls`・`printenv` など）は Bash で使わず、手順が示すパスは `Read` で読む。

Project の根が別のリポジトリに在るかは、2つの出力を比べて決める。`git -C <Project の根> rev-parse --show-toplevel` と、`git rev-parse --show-toplevel` である。一致しなければ、別のリポジトリである。そのときだけ、手順7 でリポジトリの名前を得る `git` のコマンドに `-C <Project の根>` を足す。パスの包含では決めない。作業ツリーの中に、別のリポジトリが置かれていることがあるためである。

1. **根を決める。** 上の順で決める。リポジトリの根は `git rev-parse --show-toplevel` で得る。
   - 決めた場所が記憶の根かどうかは、`node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" check <場所>` で確かめる。終了コード 2 で、標準エラーが `records/` が無いか、ディレクトリでないと述べるなら、その層は無いものとして扱う。
   - 終了コード 0 か 1 なら、記憶の根である。出た違反の行を、その根に以前から在る違反として控える。手順6 の判定に使う。
   - 在る根ごとに、その根への書き方の規則（利用規則）を確かめる。在りかは、`format.md` の「記憶の根」が定める順で決める。セッションの指示として読み込まれていなければ、読む。Global の根の利用規則が在るのに読めなければ、送り出しの下書きを書かない（手順4 の層の条件）。
2. **材料を集め、候補を挙げる。**
   - 材料は、会話、引数で渡されたもの、差分、自分のタスクの Task Memory の4つである。
   - 差分は、概要（`git status`、`git log --oneline`、`git diff --stat`）で当たりを付け、観測の裏づけに要る箇所だけを読む。`--base` が無ければ、未コミットの変更と、会話が言及するコミットだけを見る。既定のブランチを推測しない。
   - Task Memory は、Project の根が在れば、自分のタスクのファイルを読む。置き場とファイル名は、`format.md` の「Task Memory」が定める。ブランチの名前は `git rev-parse --abbrev-ref HEAD` で得る。結果が `HEAD` か、ファイルが無ければ、飛ばす。`tasks/` のほかのファイルは、引数で渡されたものだけを読む。ほかのタスクの覚え書きが置かれるためである。
   - 1候補は、1つの主張（`title` になる1文）とする。同じ条件で同じ行動の変化を言うものは、1つに畳む。
   - 同じ1回の試行や、同じ対象から出た複数の観測は、それぞれが別々に次の行動を変えるときだけ分ける。そうでなければ、1つの主張にまとめ、観測を本文に並べる。
   - 次の関門を上から当て、最初に当たったもので捨てる。別の出口へ送る候補は、行き先を表に書くだけにする。

   | 関門 | 表に書く理由 |
   |---|---|
   | このタスクの中で観測した事実が無い（一般論、タスクの外からの伝聞） | 観測が無い |
   | 次の作業で行動が変わらない | 行動が変わらない |
   | 機械で強制できる | lint・テスト・型へ移す |
   | 毎回守る規範である | 指示ファイルへ移す |
   | プロジェクトの決定であり、指示ファイルが決定の正本を別に定めている | 決定の記録へ送る |

3. **照合する。** 関門を通った候補を、候補を書いた文脈とは別の文脈で、既存の記録と照らす。
   - `record-matcher` エージェントを起動できるなら、起動する。
   - 定義済みのエージェントは起動できないが、汎用のサブエージェントを起動できるなら、そちらへ同じ入力を渡す。あわせて、定義のファイル（`${CLAUDE_PLUGIN_ROOT}/agents/record-matcher.md`）を読んで従うよう伝える。
   - どちらもできなければ、`${CLAUDE_PLUGIN_ROOT}/references/matching.md` を読み、同じ文脈で、その手順どおりに照合する。出力に「同じ文脈で照合した」と書く。
   - 渡すのは、候補ごとの番号・主張1文・当てはまる条件・種類と、根の絶対パス（Project、Global の順。無い層は「無い」）と、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）だけである。照らす置き場は渡さない。Global の候補と、Project の `outbox/` の下書きも、相手に入る。会話、材料の本文、候補を挙げた経緯は渡さない。
   - モデルと effort は、定義の front-matter に従う。呼び出す側では指定しない。
4. **層と扱いを決める。**
   - 層: 次の4つを全て満たす候補だけを、Global へ送り出す下書きにする。1つでも満たさなければ、Project へ置く。迷えば Project へ置く。3つ目を満たすが、ほかを満たさない候補は、表の層に「Project（Global 向き）」と書く。
     - Project の根が在る。下書きの置き場が、その根の `outbox/` だからである。
     - Global の根が在り、その利用規則が在れば読めている。照合する語と、送り出しの定めを、その根が持つためである。
     - 主張と当てはまる条件が、このプロジェクトのコード・構成・規約・決定を条件に含まない。
     - 機密の情報を含めずに書ける。対象は `${CLAUDE_PLUGIN_ROOT}/references/confidentiality.md` が定める。
   - 検証状況は、層を分ける条件にしない。確かめていない候補も、`verification: unverified` と書いて、決まった層へ置く。Global の根の利用規則が、未検証の記録を送り出さないと定めていれば、その候補は Project へ置く。
   - 扱い: 「重なる」「食い違う」と返った候補は、根拠に挙がったものの本文を読んで確かめてから決める。「関係なし」は確かめ直さない。次を上から当て、最初に当たったものを採る。下の「Global 側」は、Global の記録・候補と、Project の `outbox/` の下書きをいう。

   | 照合の結果 | 扱い | 表に書く理由 |
   |---|---|---|
   | 重なるか、食い違う記録が `moved-to` を持つ | 捨てる | `<識別子>` は記憶の外（`<移した先>`）へ移してある。食い違いは、移した先で直す |
   | 食い違う記録が `belief` かつ `author: human` で、本人の明示の発言が材料に無い | 捨てる | 人間の判断基準 `<識別子>` と食い違う |
   | 食い違う記録が在り、候補が未検証 | 足す（置き換えない） | `<識別子>` と食い違う、未検証の仮説 |
   | 食い違う相手が Global 側に在り、候補が検証済み | 足す（Project なら例外として、送り出しなら食い違いを本文に書く） | `<識別子>` と食い違う |
   | 食い違う記録が Project に在り、候補が検証済み | 直す（置き換え） | `<識別子>` を置き換える |
   | 重なる記録が Project に在り、候補が補うものが在る | 直す（追記） | `<識別子>` に足す |
   | 重なる相手が Global 側に在り、候補が補うものが在る | 足す（補う相手と中身を本文に書く） | `<識別子>` を補う |
   | 重なるものが在り、補うものが無い | 捨てる | `<識別子>` と重なる |
   | 関わる記録だけが在る。または、関係なし | 足す | 新しい主張 |

   - 食い違いは、どの扱いでも、中身を表に示す。
   - Global 側の記録・候補・下書きは、直さない。直すかは、Global の選別で決める。
   - 置き換えは、Project の根の中でそろえる。別の根の記録は、置き換えの項目で指せない。
   - 件数: 下書きにする候補（足す・直す）が、置く先ごとに5件を超えるときは、次の行動の変化が大きい順に並べ、上位の5件だけを下書きにする。置く先は、Project の記録と、送り出しの下書きの2つである。残りは、扱いを「見送り」とし、理由を表に書く。下書きにしない。
     - 並べる基準は、上から順に次の3つである。従わないと、誤りに気づけないもの。当てはまる条件が広いもの。この文脈が自分で確かめたもの。
     - 5件は上限ではない。超えるときに絞る手順の起点である。起動した人が名指した候補は、見送らない。その根の規則が別の数を定めていれば、それに従う。送り出しの下書きの数は、Global の根の規則に従う。
5. **下書きを作る。** `${CLAUDE_SKILL_DIR}/references/drafting.md` を読み、その書き方で、足す・直すと決めた候補の下書きを書く。下書きにする候補が無ければ、読まない。置き換える下書きが在るときは、`${CLAUDE_PLUGIN_ROOT}/references/replacement.md` も読む。
   - Project の下書きは、Project の根の `records/` へ書く。
   - 送り出しの下書きは、Project の根の `outbox/` へ書く。形は、`format.md` の「送り出しの下書きと候補」が定める。
   - 記録の版は、`node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" version <根> <識別子> --ref <起点>` で得る。起点の決め方と、`--ref` を省く場合と、版を得られないときの扱いは、`drafting.md` の「出典と版」が定める。版を得る前に、このスキルは履歴を取り直さない（取り直すのは、手順8 で運ぶときだけである）。取り直していない起点は、検査器が終了コード 2 で拒む。別のコマンドで版を数えない。
   - 確かめていないことは `verification: unverified` とする。AI の提案や推測を `verified` にしない。別の文脈が観測し、この文脈が確かめていないものも、`unverified` とする。何を自分で確かめたとするかは、`drafting.md` が定める。
   - `belief` を `author: human` にするのは、本人の明示の発言が材料に在るときだけである。
6. **検査する。** Project の根に行う。下書きが足した違反が無くなるまで、先へ進まない。送り出しの下書きは索引に載らないが、形式と識別子の重複は、ここで検査器が見る。
   - 判定の入力は、`check <根>` の違反の行（`パス:規則: 説明`）のうち、手順1 で控えた行に無いものだけである。0行なら、通過とする。
   - 手順1 で控えた行と同じ違反は、以前から在るものである。直さず、件数を「検査の結果」に書く。下書きでない記録を、検査を通すために書き換えない。
   - 索引を変更に含める根: 先に `node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" index <根> --write` を実行する。続けて `node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" check <根>` を実行する。その根の規則が含めないと定めていなければ、こちらである。
   - 索引を変更に含めないと規則が定める根: `index.md` を書かない。`check <根>` の違反の行から、`index.md:index:` で始まる行を除いて判定する。
   - 終了コード 2（検査できない入力）なら、標準エラーを示して止まる。
   - 下書きが足した違反が残れば、下書きを直して、検査し直す。
7. **機密を確かめ、送り出しの報告を書く。** 送り出しの下書きが在るときだけ行う。利用規則の定めにかかわらず行う。手順は `confidentiality.md` が、報告の形と書く順序は `${CLAUDE_PLUGIN_ROOT}/references/outbox-report.md` が定める。ここへ写さない。
   - 報告は、下書きごとに `<Project の根>/outbox/reports/<下書きの識別子>.md` へ書く。ファイル名は識別子だけで、名前の部分を付けない。元の記録は「無い」とする。重なりの照合の節は、手順3 の結果で書く。
   - 語の照合: 対象は、送り出しの下書きと報告の全てである。リポジトリの名前を得るコマンドは、同書の形のまま実行する。Project の根が別のリポジトリに在るとき（判定は「手順」の冒頭）だけ、`git -C <Project の根>` で始まる形にする。
   - 読み: `record-crosschecker` エージェントへ委ねる。根は渡さず、語を渡す。機密の読みだけが行われる。渡すのは、次の5つだけである。焦点（送り出しの下書きのパス）、照合した語の並び、Global の根の利用規則のパス（無ければ「無い」）、焦点のほかに読むファイル（報告のパス）、plugin root path（`${CLAUDE_PLUGIN_ROOT}`）。会話と、候補を挙げた経緯は渡さない。モデルと effort は、定義の front-matter に従う。
   - 定義済みのエージェントを起動できなければ、汎用のサブエージェントへ同じ入力を渡し、定義のファイル（`${CLAUDE_PLUGIN_ROOT}/agents/record-crosschecker.md`）を読んで従うよう伝える。別の文脈を作れなければ、同じ文脈の読みで代えない。報告の読みを `未実施` とし、先へ進む。
   - 指摘が返ったら、箇所を読んで確かめ（`Read`）、下書きか報告を書き換えて、手順6 の検査からやり直す。やり直しは2回までとする。残れば、報告に残っていると書き、表にもそう書く。
8. **出し方。** 記録・送り出しの下書き・報告・作り直した索引を、作業中のブランチの変更として残して終える。commit・push・PR の作成は、プロジェクトの工程に従う。送り出しの下書きは、プロジェクトの PR で承認された後に、Global Memory へ運ばれる。PR は出さない。
   - Global の根が在れば、続けて `${CLAUDE_PLUGIN_ROOT}/references/carrying.md` を読み、その手順で、Project の既定のブランチの `outbox/` に在り、まだ運んでいない下書きを運ぶ。検査器は `node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs"` の形で実行する。この起動で書いた下書きは、まだ承認されていないので運ばれない。

## 出力

**最終の応答に、利用規則と利用者が挙げた語、読みが指摘した文字列、取り除いた文字列を書かない。** 元のプロジェクトのリポジトリから得た語は、書いてよい。機密の確認は、件数で示す。

全ての候補を、次の表で示す。捨てた候補と、見送った候補も省かない。

| # | 候補（主張） | 種類 | 層 | 検証 | 扱い | 理由 | 照合の根拠 | 下書き |
|---|---|---|---|---|---|---|---|---|

- 層は、`Project`・`Global（送り出し）`・`Project（Global 向き）` のどれかである。
- 扱いは、足す・直す・捨てる・見送りの4値である。
- 理由は、手順2 の関門の語か、手順4 の語で書く。
- 照合の根拠は、層と識別子と、根拠にした1文である。候補か送り出しの下書きなら、そう添える。無ければ `-` とする。
- 下書きは、ファイルのパスである。無ければ `-` とする。機密の指摘か一致が残った送り出しの下書きは、「機密の確認を通っていない。直すか取り下げるまでレビューへ出さない」と添える。

表の後に、次を1項目ずつ書く。該当が無い項目も、「無い」と書く。

- **照合の見た範囲**: 根ごとのパスと先頭のコミット、読んだ索引の行数、本文を読んだ記録、索引に載っていない記録と下書きを見たか。先頭のコミットは、同じリポジトリの根なら `git log -1 --format=%h`、別のリポジトリの根なら `git -C <根> log -1 --format=%h` で得る。
- **照合の文脈**: 別の文脈か、同じ文脈か。
- **無かった根**: 例は「Global Memory は付いていないので、照合していない」である。
- **読んだ Task Memory**: パス。このスキルは消していないこと。
- **検査の結果**: 実行したコマンドと、下書きが足した違反の件数と、以前から在った違反の件数。
- **記録の版**: 版を得た記録と、渡した起点。版を得られなかった記録と、検査器が示した理由。版を得る前に、このスキルは取り直していないこと。
- **送り出し**（送り出しの下書きが在るとき）: 報告のパス、一致の件数、取り除いた件数、残した一致の件数、読みの文脈と指摘の件数。
- **出し方**: 作業中のブランチに残した変更。送り出しの下書きは、プロジェクトの PR で承認された後に運ばれること。
- **運んだ結果**（Global の根が在るとき）: `carrying.md` の「報告」の項目。
