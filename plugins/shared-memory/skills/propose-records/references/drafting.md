# 下書きの書き方

足す・直すと決めた候補を、記録の下書きにする書き方を定める。記録の形（項目・識別子・ファイル名・front-matter の書き方）は、`format.md` が定める。本書は写さない。

## 足す

- 新しい記録を、決めた根の `records/` へ書く。Global の根へ置く下書きは、呼び出したスキルの手順が定める置き場を経る。
- 識別子の時刻は、`date -u +%Y%m%d%H%M` で得る。1回の起動で複数の記録を作るときは、連番を増やす。
- `created` と `updated` は、`date -u +%Y-%m-%d` で得る。
- 本文は、「観測したこと」「言えること」「当てはまらない場合と、確かめていないこと」に分ける。観測した事実と、その解釈を混ぜない。
- 観測には、時点と環境（道具の版など）を添える。
- 照合で「関わる」と返った記録は、出典か本文で触れる。
- 食い違う記録が在る、未検証の候補は、置き換えにしない。どの記録とどう食い違うかと、何を確かめれば決まるかを、「当てはまらない場合と、確かめていないこと」に書く。

## 直す（主張を変えない）

`title` を変えずに済む追記は、記録をその場で直し、`updated` を改める。出典の追加、検証の更新、当てはまらない場合の追加が、これに当たる。

## 直す（主張を変える）

`title` を変える必要が在るなら、置き換える。`format.md` の「置き換え」が定める3つを、同じ変更でそろえる。3つとも、旧い記録と同じ根に置く。

## 検証と出所

- `verification` を `verified` にできるのは、この文脈が自分で確かめた観測だけである。確かめていない解釈は、`unverified` にするか、本文の「確かめていないこと」に分けて書く。
- 自分で確かめたとは、この文脈の道具の呼び出しの結果に、観測そのものが現れていることをいう。コマンドを実行して出力を見た場合と、観測の出力そのもの（ログ、結果のファイル、対象のファイル）を読んだ場合が、これに当たる。
- 作業メモや Task Memory の地の文だけが根拠の観測は、別の文脈の観測である。この文脈で同じことを確かめられるなら、確かめる。確かめられなければ、次のとおり書く。
  - `verification` は `unverified` とする。
  - `sources` に、誰が、いつ、どの環境で観測したかを書く。書いた側は確かめていないことも書く。
  - 本文の「観測したこと」を、観測した側の報告であるという断りから始める。
- 一部だけを自分で確かめたときは、本文で、確かめたことと、報告だけに拠ることを分ける。主張（`title`）を確かめた範囲に収めれば、`verified` にできる。
- `confidence` は、観測の回数と条件の広さで決める。1回の観測なら、`high` にしない。
- `author` は、AI が書いた下書きでは `ai` とする。`belief` を `human` にするときは、本人の発言を本文に引く。

## 出典と版

- 出典は、「いつ、どの環境で、何を実行して観測したか」の形で書く。
- 別の層の記録を出典に挙げるときは、検査器の `version` で版を得て、`format.md` の「記録の版」の書き方で添える。
  - 起点は、`--ref` で渡す。渡すのは、その記録が在る根の利用規則が既定のブランチとして名指す枝の、remote 追跡の ref である。利用規則が `origin` の `main` を名指すなら、`refs/remotes/origin/main` を渡す。
  - 利用規則が無いか、枝を名指していなければ、`--ref` を省く。`format.md` の「記録の版」が定める既定の起点になる。
  - 利用規則が、取り直した直後の `FETCH_HEAD` を起点に定めていても、`FETCH_HEAD` は渡さない。規則どおりに取り直した後なら、remote 追跡の ref も同じコミットへ進む。取り直していなければ、`FETCH_HEAD` は別の枝を指しうる。
  - 履歴を取り直すのは、スキルを起動する側である。スキルは、git の通信の許可を持たないので、取り直さない。利用規則が取り直しを定めているときは、取り直していないことを、スキルの出力の「記録の版」に書く。
  - 終了コード 1（起点で、その識別子の記録が1件に決まらない。無いか、複数在る）は、標準エラーで分ける。無いなら、版の代わりに「未マージ」と書く。複数在るなら、版を添えず、理由を「記録の版」に書く。
  - 終了コード 2（履歴が浅い、起点を解決できない、git を使えない）なら、版を作らない。別のコマンドで数えず、別の起点で試し直さない。出典には版を添えず、識別子と標準エラーの理由を「記録の版」に書く。
- 同じ根の記録を挙げるときの書き方は、`format.md` の `sources` の定めに従う。同じ根かどうかは、下書きを置く根から見て決める。Global の根へ置く下書きが Global の記録を挙げるときは、同じ根である。

## 置き場と索引

- `index.md` を手で書かない。作り直すのは、検査の段である。
- `inbox/` と `tasks/` へ書かない。
