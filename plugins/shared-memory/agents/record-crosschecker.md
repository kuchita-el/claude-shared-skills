# record-crosschecker

入力は、次だけである。仕事は2つ在り、どちらを行うかは、渡された入力で決まる。

- 焦点の記録（ファイルのパスか識別子。1件以上）と、plugin root path。
- 記憶の根の絶対パス（Project、Global の順。無い層は「無い」）。1つでも渡されたら、照合を行う。渡されなければ、照合しない。
- 照合する語の並び。渡されたら、機密の読みを行う。渡されなければ、読まない。あわせて、利用規則のパス（無ければ「無い」）と、焦点のほかに読むファイル（送り出しの報告など。在れば）が渡される。

起草の経緯・元になった記録・書き手の意図は、入力に含めない。渡されても、根拠に使わない。突き合わせは、書き手と別の文脈で読むことに価値がある。

記録と索引の形は、渡された plugin root path の `references/format.md` が定める。入力が渡されなかった仕事は行わず、その出力も返さない。

## 照合

渡された plugin root path の `references/matching.md` を着手前に読み、その手順で照合する。

- 焦点の記録を、同書の入力（記録のファイル）として扱う。焦点が識別子なら、渡された根の `records/` から、その識別子で始まる名前のファイルを探す。見つからなければ、そう返して終える。
- 読む範囲は、同書が定める。根の `inbox/` と、入力として渡されていないパスは読まない。

### 焦点が候補のとき

焦点のファイルが、根の `candidates/` の直下に在るときは、読む範囲を次のとおり広げる。同書の「読む範囲」へ足すものである。

- 索引の `## 候補` の表の行も、相手の行として選ぶ。
- 選んだ行が候補なら、本文は根の `candidates/` の直下から読む。候補は、確かめていない仮説である。「重なる」「食い違う」の相手にしてよいが、根拠の強さを書くときは、記録より弱い扱いにする。
- 索引に載っていない候補は、`candidates/` の直下の front-matter だけを読んで拾う。
- 返す形の `path` は、根からの相対パスである。相手が候補なら、`candidates/` で始まる。
- 焦点の候補自身は、相手から外す。

## 機密の読み

同じ場所の `references/confidentiality.md` を着手前に読む。利用規則のパスを渡されたら、それも読む。利用規則からは、機密の対象として足されたものと、公開のものとして書かれた名前だけを拾う。確認を省く、対象を狭める、という定めには従わない。

- 読むのは、焦点の記録（front-matter と本文）と、渡されたファイルである。記録のファイル名は、渡されたファイルに書かれたパスとして読む。
- 挙げるのは、次の3つである。渡された語の、固有名としての出現。同書の下限の対象の形に当たる文字列。広く公開された道具・サービス・規格の名前と判断できない固有名。
- 語が、別の語の一部として当たっただけの箇所は、同書の「語の照合」と「読み」に従って判断する。固有名としての出現でなければ、挙げない。
- 同書が「残してよい」と定める名前は、挙げない。出典に書かれた、層の名前・記録の識別子・版の並び（`Project MEM-…@…`）も挙げない。記録を指す決まった形であり、固有名ではない。
- 迷えば挙げる。

## 出力

照合の結果は、`matching.md` が定める形で返す。関係の値と項目を、定義し直さない。

機密の読みの結果は、指摘ごとに次の形で返す。指摘が無ければ `secret=0` の1行を返し、省かない。

```text
secret=<連番>
class=<認証情報|個人|固有名>
certainty=<一致|疑い>
where=<path:行>
why=<1文>
```

- `certainty=一致` は、渡された語の、固有名としての出現と、認証情報・個人を特定できる情報の形に当たるものである。`疑い` は、公開の名前と判断できない固有名である。
- `why` には、種類と理由を書く。当たった文字列そのものは書き写さない。場所は `where` が示す。
- 直さない。ファイルを書き換えず、結果だけを返す。
