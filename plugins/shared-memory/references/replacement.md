# 置き換えの手順

記録を別の記録で置き換えると決まった後に、そろえる順序と確かめ方を定める。何をそろえるか（置き換えの3つと、その中身）は、`format.md` の「置き換え」が定める。ここへ写さない。

置き換えるかどうかは、この手順では決めない。決めるのは、人間か、この手順を呼び出したスキルである。

## 前提

次のどれかに当たれば、何も書かずに止めて、理由を報告する。

- 旧い記録が、その根の `records/` に無い。
- 旧い記録が、既に置き換え済みである（`superseded-by` か `moved-to` を持つ）。置き換えられるのは、いま有効な記録だけである。`superseded-by` を辿った先に在る、いま有効な記録を、報告に示す。
- 旧い記録と新しい記録が、別の根に在る。置き換えの項目は、同じ根の記録しか指せない。
- 新しい記録として渡された記録が、既に既定のブランチに在る。3つを同じ変更で行えないためである。決め方は、「新しい記録を識別子で受け取るとき」が定める。

## 手順

`format.md` の「置き換え」の3つを、次の順でそろえる。

1. **新しい記録。** `format.md` と、その根の規則に従って書く。識別子で渡された記録を使えるのは、同じブランチの上に在り、まだ既定のブランチに入っていない場合だけである。
2. **旧い記録。** 同書が定める置き換えの項目を足し、`updated` を改める。本文とほかの項目は変えない。
3. **`evolution` の記録。** 置き換えを表す項目と本文は、同書が定める。ほかの項目は、次のとおり書く。
   - `title` は、何が何へ変わったかを1文で書く。
   - `applies-when` は、旧い記録の当てはまる条件を引く。旧い記録を根拠にした判断を見直す場面で、索引から見つかるようにするためである。
   - `author`・`verification`・`confidence` は、変わった理由について決める。理由を述べた者が `author` である。確かめていない理由は `unverified` と書く。
   - `sources` は、変わる根拠になった作業の記録か、新しい記録の出典を書く。
   - 新しい記録と同じ分に識別子を作るときは、連番を増やす。
4. **確かめる。** 呼び出したスキルが定める実行形で、検査器の `check` をその根に掛ける。違反が残れば、違反の行の説明に従って直し、検査し直す。置き換えの形の誤りは、`replacement`・`dangling`・`evolution` の規則が落とす。

## 新しい記録を識別子で受け取るとき

新しい記録を、この手順で書かずに、既に在る記録の識別子で受け取ることが在る。昇格の PR で足した記録で、同じ根の既存の記録を置き換える場合が、これに当たる。この手順で書いた記録には、下の確かめは要らない。

判定の入力は、検査器の `version` を、その根と新しい記録の識別子に掛けた結果である。起点には、既定のブランチを指す ref を渡す。渡し方と、省いたときの既定は、`format.md` の「記録の版」が定める。実行形は、呼び出したスキルが定める。次を上から当て、最初に当たったもので扱う。

| `version` の結果 | 扱い |
|---|---|
| 終了コード 1 で、標準エラーが、起点にその記録が無いと述べる | 既定のブランチに入っていない。作業ツリーの `records/` に、その識別子の記録が1件在れば、使う。そうでなければ止める |
| 終了コード 0（版が出た） | 既定のブランチに入っている。止める |
| そのほか（終了コード 1 で、複数在ると述べる。終了コード 2） | 決められない。標準エラーを示して止める。標準エラーが示す直し方（取り直す、起点を渡す）の後に、起動し直すよう伝える |

- 判定は、起動した側が最後に取り直した結果の時点のものである。取り直していない起点は、検査器が終了コード 2 で拒む。検査器は履歴を取り直さない。取り直すのは、起動する側である。
- 作業中の HEAD を、起点に渡さない。足したばかりの記録が、既定のブランチに在ると判定される。
- 止めるときは、何も書かない。

## 複数の記録を置き換えるとき

- **複数の旧い記録を、1つで置き換える**: 旧い記録のそれぞれに、同じ `superseded-by` を書く。`evolution` は1件にし、`from` に全てを並べる。
- **1つの旧い記録を、複数で置き換える**: `superseded-by` は1件しか書けない。主たる1件を書き、`evolution` の `to` に全てを並べる。`superseded-by` に書いた記録は、`to` に含める。

## コミットに分けるとき

3つを同じ変更で行うことは、`format.md` が定める。変更を複数のコミットに分けるときは、次を守る。

- 旧い記録への変更と、`evolution` の記録は、同じコミットに入れる。片方だけが入った状態は、検査が `replacement` で落とす。
- 新しい記録は、それより前か、同じコミットに入れる。
- どのコミットも、同じブランチの上の、既定のブランチへ入る前の変更に入れる。既定のブランチに入った記録を、後の変更で新しい記録にしない。

## 扱わないもの

- 記憶の外へ移す場合（`moved-to`）。扱いは `format.md` が定める。
- 層をまたぐ置き換え。上の層へ昇格した記録は、元の記録を置き換えない。
- どちらも既に既定のブランチに在る、2つの記録の間の置き換え。新しい記録を足す変更にならず、`format.md` の「置き換え」の形を取れない。食い違いの扱いは、人間が決める。
