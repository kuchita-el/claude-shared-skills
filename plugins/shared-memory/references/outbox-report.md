# 送り出しの報告

送り出しの下書きに添える報告の形と、書く順序を定める。報告は、プロジェクトの PR で送り出しを承認する人間が、判断に使う材料である。置き場は、`format.md` の「送り出しの下書きと候補」が定める（`outbox/reports/<下書きの識別子>.md`）。ファイル名は識別子だけであり、下書きのファイル名の名前の部分を付けない（例: `outbox/reports/MEM-202611230706-01.md`）。

## 形

下書き1件につき1ファイルを、次の形で書く。5つの節を、省かず、並べ替えない。

```markdown
# 送り出しの報告: <下書きの識別子>

## 下書き

- 識別子: <下書きの識別子>
- パス: outbox/<下書きのファイル名>
- 表題: <下書きの title>
- 検証: <verified か unverified>

## 元の記録

- <元の記録の識別子>

## 語の照合

| 語 | 出所 | 一致 | 取り除いた | 位置 |
|---|---|---|---|---|

## 読み

- 文脈: <別の文脈（record-crosschecker）か、未実施>
- 指摘: <件数>
- 位置: <指摘ごとの、下書きの中の位置>

## 重なりの照合

- 相手: <照らした相手>
- 文脈: <別の文脈か、同じ文脈>
- 結果: <関係ごとの件数>
- 補う相手: <識別子>
```

## 書き方

- **下書き**: `unverified` なら、検証の行に「未検証。確かめていない仮説として送る」と添える。
- **元の記録**: Project の記録を一般化した下書きなら、その識別子を書く。複数なら並べる。新しく書いた下書きなら、「無い」と書く。
- **語の照合**: 照合した語ごとに、一致の件数を書く。
  - 元のプロジェクトのリポジトリから得た語（リポジトリの名前と所有者の名前）は、語を書く。報告の読み手は、そのリポジトリを読める。
  - 利用規則が挙げた語と、利用者が挙げた語は、語を書かない。出所ごとに1行にまとめ、語の列に「<語の数>語」と書き、一致を合計する。プロジェクトのリポジトリに無いことがある語であり、公開のプロジェクトでは、書くと漏れる。
  - 位置の列に、一致ごとの、下書きか報告の節の名前と行を書く。取り除いた一致も含める。語の文字列は書かない。読みが `未実施` のとき、承認する人間が一致の箇所を確かめる材料になる。
  - 一致した箇所を書き換えて取り除いたら、取り除いた件数を書く。残した一致は、件数と根拠を表の後に書く。取り除いた文字列は書かない。
- **読み**: 別の文脈で行えなければ、文脈に `未実施` と理由を書く。指摘が無ければ、指摘を `0`、位置を「無い」と書く。位置は、節の名前と行で示す。指摘された文字列は書かない。やり直しても残った指摘は、件数と位置に「残っている」と添える。
- **重なりの照合**: 照らした相手を、Global の記録・Global の候補・Project の `outbox/` の下書きのうち、照らしたものだけ挙げる。照らせなかった相手は、理由を添えて挙げる。文脈は、別の文脈（サブエージェントの名前）か、同じ文脈かを書く。結果は、「重なる」「食い違う」「関わる」の件数と、「重なる」「食い違う」の相手の識別子である。補う相手が無ければ「無い」と書く。
- **書かないもの**: 利用規則と利用者が挙げた語、読みが指摘した文字列、取り除いた文字列。書くと、報告そのものが混入の経路になる。

## 書く順序

1. 下書きを書き、形式の検査を通した後に、「下書き」と「元の記録」の節を書く。
2. 語の照合を、下書きと報告の両方に掛ける。報告の「下書き」の節に在るパスで、下書きのファイル名も照合に掛かる。手順は `confidentiality.md` の「語の照合」が定める。
3. 読みを、別の文脈へ委ねる。報告も、焦点のほかに読むファイルとして渡す。
4. 指摘と一致を扱う。下書きを書き換えたら、形式の検査からやり直す。
5. 残りの3つの節を書く。
6. 利用規則か利用者が語を挙げていれば、その語だけを、報告へ照合し直す。一致は、0件になるまで書き換える。元のプロジェクトのリポジトリから得た語は、この照合に掛けない。「語の照合」の節に書いたので、当たるためである。

## 下書きを取り下げるとき

下書きを `outbox/` から消すときは、同じ変更で、その報告も消す。元の記録の `sent-as` から、その識別子を外す（`format.md`）。直すときは、新しい識別子の下書きと、その報告を足す。
