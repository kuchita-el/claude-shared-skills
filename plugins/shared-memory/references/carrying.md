# 下書きを運ぶ

承認済みの送り出しの下書きを、手を加えずに Global Memory の `candidates/` へ運ぶ手順を定める。写すのは検査器の `carry` であり、その判定と出力の形は `format.md` の「下書きを運ぶ」が定める。ここへ写さない。

## 前提

- Project Memory の根と、Global Memory の根が、どちらも在る。
- 2つの根が、別々の git のリポジトリに在る。
- 検査器（このプラグインの `scripts/memory.mjs`）と、それを動かす Node が在る。

- Global の根の利用規則が、`candidates/` と運ぶことを定めている。定めが無ければ、取り直しも写しもせずに止まり、「利用規則が運ぶことを定めていない」と報告する。

どれかが欠ければ、運ばずに止まる。検査器を使えないホストのために、git だけで運ぶ予備の手順は置かない。運び済みの判定を手順の文で再現すると、誤りが運び直しか取りこぼしになるためである。止まっても、承認済みの下書きは `outbox/` に残り、次に運ぶ者が運ぶ。

remote と既定のブランチの名前は、Project はプロジェクトの指示ファイルが、Global はその根の利用規則が名指す。名指しが無ければ `origin` と `main` とする。下の例は `origin` と `main` で書く。

## 手順

コマンドは、下に書いた形のまま、1回に1つずつ実行する。`git` には、いつも `-C <根>` を付ける。根がリポジトリの下位に在っても、git はそのリポジトリを使う。

1. **2つのリポジトリを確かめる。** `git -C <Project の根> rev-parse --show-toplevel` と `git -C <Global の根> rev-parse --show-toplevel` を実行する。どちらかが失敗するか、2つが一致すれば止まる。
2. **既定のブランチを取り直す。** 次の2つを実行する。取り直しの規則は、`format.md` の「記録の版」に従う。どちらかが失敗すれば止まる。

   ```bash
   git -C <Project の根> fetch --deepen=1000 origin main
   git -C <Global の根> fetch --deepen=1000 origin main
   ```

   続けて、**写す前に**、push するブランチの名前を決める。名前は `carry/<UTC の年月日時分秒>` とし、時刻は `date -u +%Y%m%d%H%M%S` で得る。次の2つを実行し、どちらかが成功すれば（その名前のブランチが既に在れば）、何も写さずに止まる。

   ```bash
   git -C <Global の根> rev-parse --verify --quiet refs/heads/<名前>
   git -C <Global の根> rev-parse --verify --quiet refs/remotes/origin/<名前>
   ```

   - 運ぶ手順が push するのは、新しく切る `carry/*` のブランチだけである。Global の根が居る作業中のブランチ（クラウドのセッションの作業用のブランチなど）へは push しない。取り込む CI が、取り込んだブランチを消すためである。ホストが、セッションの既存の作業用のブランチへの push しか許さないなら、運ばずに止まり、運ぶには新しい `carry/*` のブランチを push する許可が要ると報告する。
   - ホストか利用者が別の名前を定めていても、その名前が既に在れば、同じく写さずに止まる。写した後に `switch -c` が失敗すると、写したファイルが作業ツリーに残るためである。

3. **Global の作業ツリーを、判定の起点へ合わせる。**
   - `git -C <Global の根> status --porcelain` を実行する。何か出れば止まる。運ぶ変更に、ほかの変更を混ぜないためである。
   - `git -C <Global の根> branch --show-current` を実行し、出力を元のブランチとして控える。
   - `git -C <Global の根> switch --detach FETCH_HEAD` を実行する。
4. **写す。** 次を実行する。

   ```bash
   node scripts/memory.mjs carry <Project の根> <Global の根> --project-ref FETCH_HEAD --global-ref FETCH_HEAD
   ```

   `scripts/memory.mjs` は、このプラグインの根からの相対パスである。スキルから実行するときは、スキルが示す検査器のパスに置き換える。

   - 終了コード 0 か 1 なら、出た行を全て控える。`stopped` の下書きは、検査器が書いていないので、運ばれない。
   - 終了コード 2 で、検査器が取り直し方を示したら、その取り直しを、示されたリポジトリの `git -C <根>` の形で1回だけ行い、手順3 の `switch --detach FETCH_HEAD` からやり直す。もう一度 2 なら止まる。
   - `copied` の行が無ければ、手順8 へ進む。
5. **ブランチを切り、コミットする。** 名前は、手順2 で決めたものを使う。`carry/*` 以外の名前への `switch -c` は、事前に許可されないので、ホストの許可の確認に任せる。

   ```bash
   git -C <Global の根> switch -c <名前>
   git -C <Global の根> add -- candidates/<写したファイル名> ...
   git -C <Global の根> commit -m "候補を運ぶ: <識別子> ..."
   ```

   - `add` には、`copied` の行が示したファイルだけを並べる。
   - ブランチの名前とコミットのメッセージに、元のプロジェクトの固有名を書かない（`confidentiality.md`）。
   - `switch -c`・`add`・`commit` のどれかが許可されないか失敗したら、手順8 の戻しを行わずに止まる。写したファイルが、作業ツリーかインデックスに残っているためである。
6. **push する。** `git -C <Global の根> push origin <名前>` を実行する。
   - commit と push を、手順は事前に許可しない。了承は、ホストの許可の確認に任せる。応答の中で尋ねて止まらない。
   - 許可されない、非対話の実行で拒まれる、手段が無い、push が失敗した、のどれかなら、運ばずに止まる。元のブランチへ戻さず、いまの場所（`<名前>` か、切れていなければ detached）に留まる。作ったブランチ・コミット・写したファイルは消さずに、「手元に残したもの」として報告する。
   - API を介してファイルの中身を渡すコミット（GitHub の MCP の道具など）では運ばない。中身が手を通り、バイトの単位で一致することを保てないためである。
7. **取り込まれたかを確かめる。** Global の CI が、候補を足すだけのブランチを既定のブランチへ取り込み、ブランチを消す。`git -C <Global の根> fetch --deepen=1000 origin main` を実行し、続けて `git -C <Global の根> ls-tree --name-only FETCH_HEAD -- candidates/<写したファイル名> ...` を実行する。
   - 出たファイルは、取り込まれた。
   - 出なかったファイルは、取り込みを確かめていない。CI が終わる前か、取り込めずにジョブが失敗したかである。取り込めなかったブランチは、Global に残る。取り込まれなかった下書きは、運び済みの判定に当たらないので、次に運ぶ者が運び直す。
   - 取り直しは1回とする。待つためのコマンドは使わない。
8. **元へ戻す。** `git -C <Global の根> status --porcelain` を実行する。何か出れば、戻さずに、手順5 か6 で止まったときと同じく、「手元に残したもの」を報告して終える。出なければ、手順3 で控えた元のブランチが在るとき、`git -C <Global の根> switch <元のブランチ>` を実行する。このコマンドは事前に許可されないので、ホストの許可の確認に任せる。拒まれたら、再試行せず、戻していないと報告する。元のブランチが無ければ（detached だったとき）、戻さずに、そう報告する。

手順3 の後で止まったときも、作業ツリーが汚れていなければ、手順8 を行ってから終える。汚れていれば、戻さない。戻すと、写したファイルを持ったまま元のブランチへ移り、次に運ぶ者が手順3 で止まるためである。

## 報告

次を1項目ずつ書く。該当が無い項目も「無い」と書く。

- 写した結果: `carry` が出した行を、全てそのまま。`stopped` の行は、人間が決めることとして示す。
- ブランチ: 名前と、push したか。push しなかったときは、理由。
- 手元に残したもの: 止まったときに Global の根に残った、ブランチの名前、コミット、写したファイル（`git -C <Global の根> status --porcelain` の出力）、いま居る場所。人間が消すか、続きを行う。無ければ「無い」。元のブランチへ戻せなかったときは、そう書く。
- 取り込み: 手順7 で確かめたファイルと、確かめていないファイル。
- 止まったとき: 止まった手順と理由。下書きは `outbox/` に残り、次に運ぶ者が運ぶこと。

push の成功を、運んだ結果として報告しない。運んだと書いてよいのは、手順7 で既定のブランチに在ると確かめたファイルだけである。
