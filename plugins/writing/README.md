# writing プラグイン

日本語で書かれた文書の書き方を規約として定め、その執行と起草を担う基盤。書かれた語・文・文書が、読み手にとって意味を復元できる形になっているかを扱う。

## 構成

| 置き場所 | 内容 |
|---|---|
| `references/japanese-writing.md` | 共通規約（5条と、第5条に従属する補則）。一文の長さの計数規則もここが単一の出典 |
| `references/document-type-profiles.md` | 文書種別ごとの差分の既定（節構成・読み手の既定・一文長の上限） |
| `scripts/lint-ja.sh` | 機械検査。一文の長さを違反として検出し、不透明な識別子を候補として挙げる |
| `agents/doc-reviewer.md` | 独立レビュー。機械検査が測れない意味的な判定を担う |

## 執行の分担

規約の執行は機械検査と独立レビューの2手段に分かれる。分担の理由は検出可能性にある。

| 条 | 機械検査 | 独立レビュー |
|---|---|---|
| 第1条 語の接地 | 持たない | 唯一の執行手段 |
| 第2条 参照の自己完結 | 骨格位置の識別子を候補として挙げる。違反にはしない | 開かずに読めるかを確定する |
| 第3条 文書の自立 | 持たない | 唯一の執行手段 |
| 第4条 判断依頼の材料 | 持たない | 唯一の執行手段 |
| 第5条 根拠の同居 | 一文の長さの上限のみ。決定的に執行できる唯一の項目 | 結論と根拠の同居を確定する |

機械検査が決定的に執行するのは一文の長さだけである。他の項目を機械検査へ載せられない理由は条ごとに異なる。

**第1条**: 初出の語が読み手に通じるかは、人手で保守する語の登録簿なしには判定できない。登録簿を持つ選択もありうるが、規約が統治する文書群の語彙を覆う規模の登録簿を人手で保守し続けるコストに見合わないと判断した。字種で拾う素朴な検出では1文書あたり中央値176件の候補が出て、大半は通常の語になる。

**第2条**: 条文は説明の形式を問わず、括弧注・連体修飾・述部で内容を述べる形のいずれも認める。シェルスクリプトが判定できるのは識別子の直後が助詞かどうかまでであり、連体修飾と述部形は説明があっても誤検出になる。そのため機械検査は候補を挙げるに留め、終了コードへ寄与させない。候補を違反と同じ終了コードへ落とすと、書き手は独立レビューの確定を待たずに書き換える側へ倒れる。

**第3条・第4条**: 結論の骨格が本文で完結しているか、判断依頼に材料が揃っているかは、いずれも文書全体の意味を読まないと判定できない。

## サブエージェントの実行パラメータ

`model` と `effort` は定義ファイルの `front-matter` で明示している。呼び出し側では指定しない。値を省略すると、検証の精度が利用者の環境設定に従属し、見落としがプラグインの欠陥として現れる。

| サブエージェント | `model` | `effort` | 値の意図 |
|---|---|---|---|
| `doc-reviewer` | `opus` | `high` | 必要最小水準 |

`doc-reviewer` は使えるツールも定義側で `Read` ・ `Grep` ・ `Glob` の3つに絞っている。読み取り専用であることを命令文だけに委ねず、実際に効かせるためである。

`doc-reviewer` が求めているのは処理量ではなく分析の深さである。語の意味を読み手の水準で復元できるかという判定は、`effort` を上げて `model` を落とす形では代替できない。`effort` の `high` はモデル既定と同値であり、設定を下げている環境に対して下限として働く。

## 出力・成果物の分量についての不変条件

本プラグインの成果物とレビュー出力は、次の不変条件を保つ。

- 対象の分量と欠陥の数に見合う範囲に収める。同じ内容を言い換えて重ねない
- 求められていない修正の全文案を書かない
- 自分が書いたものを自分で読み直す型の確認ステップを、定義へ新たに足さない。この種の確認は指示がなくても行われるため、重ねて指示すると過剰な検証を誘発する。別の文脈が対象を初見で読む独立検証はこれに当たらない
