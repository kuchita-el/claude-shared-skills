# 文書種別プロファイル（本リポジトリ固有）

本リポジトリで起草する文書の種別プロファイル。ここに行がある種別は本ファイルの値を採り、行が無い種別は `writing` プラグイン同梱の既定へフォールバックする。既定の内容は本ファイルへ再掲しない。

## プロファイル

| 種別 | 節構成 | 読み手の既定 | 一文長の上限 |
|---|---|---|---|
| ADR | `adr` プラグインの `manage-adr` スキルが定める ADR 雛形の節に従う。手続き的な記述は `## Context` へ置く（下記「ADR の節構成」） | 本リポジトリで設計判断を追う読み手。過去の議論を記憶していないことを前提とする | 100字 |

## ADR の節構成

必須節の一覧は `manage-adr` スキルが持つ ADR 雛形が単一の出典である。スキルは `/adr:manage-adr` で起動する。本ファイルは節の一覧を持たない。

そのうえで、次の手続き的な記述を `## Context` に置くことを宣言する。

- 分割の経緯（多決定 ADR の分割により後継が生じた場合に、何が反転し何が生存したか）
- 原 ADR からの改変の開示（改変した箇所と、その理由）
- 改変しなかったことによる読み替えの開示（後継に残る原 ADR 内の決定番号などが、後継のどこを指すか）

**この宣言の根拠**: ADR-202607261501-01 は ADR の編集機構と ADR 分割を定める決定であり、承認済み・有効である。同 ADR の決定1 は、原 ADR から改変した箇所と理由を後継 ADR の `## Context` に記載する開示義務を持つ。この義務は `manage-adr` スキルの分割手順へ落ちている。改変の開示を後継の `## Context` へ書く段と、分割を締める側の検査の2箇所である。本プロファイルが置き場所を宣言することで、共通規約の第3条と、この検査とが衝突しなくなる。

## ADR の一文長の上限

100字を採る。既存 ADR の一文長の90パーセンタイルは117字であり、実測値に合わせて上限を緩めると規約が現状を追認するだけになる。共通規約の適用範囲は新しく起草する文書と編集で触れた箇所に限られるため、この値を採っても既存 ADR が一斉に違反にはならない。
