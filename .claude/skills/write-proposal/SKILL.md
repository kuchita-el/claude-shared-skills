# 提案書の執筆

## 文脈固有ルール

- **対象範囲**: 読み手が採否を判断する文書に限る。事実の記録だけが目的の調査報告と、決定後の記録（ADR）は対象外。
- **成果物**: 本文（結論・求める判断・前提・提案の中身・代替案・調査の概要）と付録（調査の詳細）に分かれた1文書。
- **停止条件**: 却下案に理由が付かない、前提に根拠の所在が無い、本文に残した表が採否判断に要る理由を言えない、のいずれかが残る間は確定しない。
- **変更境界**: 素材に無い事実・数値・出典を足さない。調査結果は置き場所を組み替える対象であり、内容を書き換える対象ではない。誤りを見つけたら直す前に列挙して報告する。

## 形式の出所

この構成は既知の形式の重ね合わせである。出典と引用は `${CLAUDE_SKILL_DIR}/references/form-sources.md` に置く。

| 借りる要素 | 出所 |
|---|---|
| 前提 → 目標と非目標 → 提案 → 却下した代替案、の骨格。前提は簡潔に、詳細はリンクへ | Google 式 Design Doc（Context and scope → Goals and non-goals → The actual design → Alternatives considered） |
| 結論を最初の段落に置く。細目は後ろへ、量が多ければ別添へ | 公用文作成の考え方（文化審議会建議 2022）、BLUF（米陸軍 AR 25-50） |
| 却下案は理由とともに残す。提案ほど詳細でなくてよい | PEP 1「Rejected Ideas」、KEP「Alternatives」 |
| 代替案は各案のトレードオフ（得るものと失うもの）で書く | Google 式 Design Doc「Alternatives considered」、MADR「Pros and Cons of the Options」 |
| 本文の筋の理解に不要な資料は付録へ。調査票・計算過程が典型 | 推奨報告書の層構造（MIT Sloan 15.279） |

「求める判断」の節だけは上の形式から借りていない。採否を仰ぐ文書では、読み手が決める論点を本文から拾えることが目的そのものであるため、本スキルが足す。

## 本文の構成（契約）

本文は次の順に置く。各節は冒頭の 1 文で要点を言う。分量の一般則（必要な分量を超えない）は `${CLAUDE_PROJECT_DIR}/docs/behavior-invariants.md` に従う。雛形は `${CLAUDE_SKILL_DIR}/references/template.md`。

| 順 | 節 | 置くもの | 置かないもの |
|---|---|---|---|
| 1 | 結論（題名の直下） | 提案を 3 文以内と、採否の箇条書き（採用／条件付き／退ける）。箇条書きは対象名と扱いだけを書き、理由は 4・5 節に置く | 根拠の表、調査の経緯、「本書は〜を述べる」型の前置き |
| 2 | 求める判断 | 読み手に決めてほしい論点ごとに、論点・選択肢・推奨・期限（素材にあれば）。提案全体の採否も 1 論点として数える。未決のまま残る論点もここに置く | 判断済みの事項の再説明 |
| 3 | 前提 | 適用範囲と背景（人数・対象・言語・現状の制約）、目標と非目標、判断軸、提案が依拠する事実の表（前提／根拠の要点／根拠の強さ／詳細の所在） | 出典ごとの確認事実、網羅的な比較表 |
| 4 | 提案の中身 | 原理 → 構成 → 運用の決め事 → 費用対効果。選択肢から 1 つを選ぶ提案では、採用後の形 → 運用の決め事 → 費用対効果と読み替える。各要素に根拠の所在（本文の節番号か付録の記号） | 却下案の議論 |
| 5 | 却下した代替案と条件付きの案 | 候補×判断軸の縮約した比較表と、案ごとの表（案／扱い（却下・条件付き・考え方のみ採用）／採れば得られたもの／採らない理由または条件／詳細の所在）。採らない理由は 3 節の判断軸に結びつけ、数値があれば 1〜2 個引く。方式レベルの案を先に置き、部品レベルの案は既出なら所在だけ | 提案と同じ粒度の説明 |
| 6 | 落とし穴と対処（任意） | 提案を採った場合に起きうる失敗と対処 | 一般論 |
| 7 | 調査の方法と限界（概要） | 範囲・分け方・進め方を各 1〜2 文と、文書全体に及ぶ限界。要素ごとの根拠の強さは 3 節の表に置き、ここで繰り返さない | 調査の経過の物語 |
| 付録 | A、B、C … | 確認した事実の表、手法の網羅的な比較表、実測の一覧、証拠の限界の全文、用語集、出典 | 本文にしか無い判断 |

本文の章番号参照（「3章」）は、付録送り後に付録の記号（「付録C」）か節番号（「4.2 節」）へ付け替える。根拠の強さ（例: 対照研究／大規模実測／自己申告）は、本文側で一括して「証拠から導いた」と書かず、3 節の表で要素ごとに書き分ける。

## 本文と付録の振り分け

振り分けの問いは「この表・段落が無いと、読み手は採否を判断できないか」。無くても判断できるなら付録へ送り、本文には要点（数値 1〜2 個と出典名）と所在だけを残す。

| 本文に残す | 付録へ送る |
|---|---|
| 前提の表（要点・根拠の強さ・所在） | 出典ごとの確認事実の表 |
| 候補×判断軸の縮約した比較表 | 手法の網羅的な比較表 |
| 採った部品と、採らなかった案の理由 | 実測の一覧（数値・条件・含意） |
| 提案の構成・運用の決め事・費用対効果 | 証拠の限界の全文、未確認事項の列挙 |
| 調査の方法と限界の概要 | 用語集、出典一覧 |

比較表は 2 層に分ける。採否に要るのは候補と判断軸の交点だけであり、本文の 5 節にはその縮約表を置く。判断軸に関係しない観点まで並べた網羅表は付録へ送る。数値を本文へ引くときは、出典の条件（母集団・比較の基準・単一モデル等）を付録の行に残し、本文は数値と出典名までに留める。

## 調査中心の下書きからの組み替え

下書きが「調べた順」に章立てされている場合の手順。

1. 下書きの各章を「事実（調査結果）」「判断（採否・設計）」「方法（調べ方・限界）」に分類する。
2. 「判断」を本文の 1・4・5 へ移す。採否の箇条書きは 1 へ、却下の理由は 5 へ集める。「注意」列や「落とし穴」に散っている却下理由も 5 へ寄せる。下書きに残る未決の論点は 2 へ集める。
3. 下書きの比較の観点のうち、採否を分けた観点を判断軸として 3 に立てる。素材に目標・非目標の記述が無ければ、補わずに不足として報告する。
4. 「事実」から、提案が依拠する前提だけを抜き出して 3 の表にし、表本体は付録へ送る。前提の各行に根拠の強さと付録の所在を付ける。
5. 「方法」は 7 に範囲・分け方・進め方と全体に及ぶ限界を残し、全文を付録へ送る。
6. 章番号参照を付け替え、付録の見出しを「付録A」から順に振る。
7. 独立検証（次節）へ本文を渡し、指摘が残る間は確定しない。

## 独立検証

確定前に、読み取り専用のサブエージェント（`adversary` 等）へ、本文の path と「本文の構成（契約）」の表だけを渡す。節ごとに「置くもの」が揃い「置かないもの」が無いかを判定させ、`ruleId,evidence,suggestion` の形で受け取る。素材と起草の経緯は渡さない。

出力契約:

```text
status=passed
writes=[outputPath]
unresolved=[]
```

```text
status=unresolved
writes=[]
draft=[outputPath]
unresolved=[{ruleId,evidence,suggestion}]
```

指摘が残る稿は確定稿ではないため `writes` に載せず、`draft` として path を返す。成功成果として表示しない。

## 文体

日本語の文体は writing プラグインの共通規約に従う。正本は `${CLAUDE_PROJECT_DIR}/plugins/writing/references/japanese-writing.md`。文書種別プロファイルに「提案書」は未登録のため、一文長は既定の 100 字以内を使う。結論を先に、評価語より数値。

## よくある失敗

次の症状は、手法調査の提案書 1 件を組み替えた際に観測したものであり、網羅ではない。

| 症状 | 直し方 |
|---|---|
| 冒頭が「〜を調べた」「〜という噂がある」で始まる | 冒頭を提案の 3 文に差し替え、噂や経緯は 3 か 7 へ |
| 「証拠が厚い手法」「自己申告の手法」の一覧表が本文の前半を占める | 表は付録へ。本文には「部品はここから採る」という判断と、採った部品名だけ |
| 却下案が「注意」列や「落とし穴」の表に散っている | 5 の表へ集め、1 案 1 行で理由と所在を付ける |
| 「いずれも証拠から導いた」と一括で書く | 3 の前提表で、要素ごとに根拠の所在と強さを書き分ける |
| 本文の数値が出典の条件（母集団・比較の基準・単一モデル）を落としている | 本文は数値と出典名まで。条件は付録の行に書く |
